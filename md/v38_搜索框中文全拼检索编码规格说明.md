# v38 搜索框中文全拼检索编码规格说明

## 1. 需求背景

v37 已经实现主界面搜索框的中文拼音首字母检索能力，例如：

```text
热贴机_012 -> rt / rtj / rtj012
银烧结_005 -> ysj
自动点锡机_012 -> zddxj
```

当前用户希望进一步增强搜索框，使其支持中文拼音全拼检索。

也就是说，用户不仅可以输入中文原文和拼音首字母，也可以输入完整拼音来搜索中文快捷项。

## 2. 需求目标

在现有搜索框中新增中文全拼匹配能力。

实现后搜索框应同时支持：

1. 原文搜索。
2. 英文、数字、路径普通搜索。
3. 中文拼音首字母搜索。
4. 中文拼音全拼搜索。
5. 中文全拼与英文、数字混合搜索。

示例：

| 字段原文 | 全拼搜索串 | 用户输入 | 预期结果 |
| --- | --- | --- | --- |
| `热贴机_012` | `retieji_012` | `retieji` | 匹配 |
| `热贴机_012` | `retieji_012` | `retieji012` | 匹配 |
| `热贴机_012` | `retieji_012` | `tieji` | 匹配 |
| `银烧结_005` | `yinshaojie_005` | `yinshaojie` | 匹配 |
| `自动点锡机_012` | `zidongdianxiji_012` | `zidong` | 匹配 |
| `银烧结NG抓取装置_003` | `yinshaojiengzhuaquzhuangzhi_003` | `yinshaojieng` | 匹配 |

## 3. 非目标范围

本次不实现以下内容：

1. 不修改搜索框 UI。
2. 不新增搜索模式切换按钮。
3. 不新增配置项。
4. 不改变目标路径搜索规则。
5. 不改变列表排序逻辑。
6. 不实现拼音模糊纠错，例如 `ratieji` 自动纠错为 `retieji`。
7. 不实现用户自定义多音字词典。
8. 不支持带声调拼音输入。

## 4. 当前代码现状

当前搜索服务：

`VSLoader/Models/Services/ShortcutSearchService.cs`

当前核心能力：

```csharp
public bool IsTextMatch(string source, string keyword)
{
    // 1. 空值判断
    // 2. 原文 Contains 匹配
    // 3. 使用 ToolGood.Words.FirstPinyin 生成首字母
    // 4. 首字母 Normalize 后 Contains 匹配
}
```

当前主界面接入位置：

`VSLoader/ViewModels/MainViewModel.cs`

当前字段规则：

```csharp
return _shortcutSearchService.IsTextMatch(shortcut.Name, keyword)
    || Contains(shortcut.TargetPath, keyword)
    || _shortcutSearchService.IsTextMatch(shortcut.Description, keyword);
```

本次应复用这个入口，只扩展 `ShortcutSearchService` 内部能力。

## 5. 推荐技术方案

在现有 `ShortcutSearchService` 上扩展全拼匹配。

推荐判断顺序：

1. 原文匹配。
2. 拼音首字母匹配。
3. 拼音全拼匹配。

伪代码：

```csharp
public bool IsTextMatch(string source, string keyword)
{
    if (string.IsNullOrWhiteSpace(source) || string.IsNullOrWhiteSpace(keyword))
    {
        return false;
    }

    if (source.Contains(keyword, StringComparison.OrdinalIgnoreCase))
    {
        return true;
    }

    var normalizedKeyword = NormalizeForPinyinSearch(keyword);

    if (InitialsMatch(source, normalizedKeyword))
    {
        return true;
    }

    if (FullPinyinMatch(source, normalizedKeyword))
    {
        return true;
    }

    return false;
}
```

## 6. NuGet 依赖建议

当前项目已引入：

```xml
<PackageReference Include="ToolGood.Words.FirstPinyin" Version="3.1.0.4" />
```

该包主要负责首字母转换。

若该包不能提供稳定全拼转换能力，应新增同系列全拼包：

```xml
<PackageReference Include="ToolGood.Words.Pinyin" Version="3.1.0.4" />
```

实现时优先选择 `ToolGood.Words.Pinyin`，原因：

1. 与现有 `ToolGood.Words.FirstPinyin` 同系列。
2. 支持现代 .NET。
3. API 风格接近。
4. 避免引入旧 .NET Framework 兼容警告。

编码 Agent 应避免重新引入 `NPinyin`，因为该包在当前项目中会出现旧框架兼容警告。

## 7. 匹配字段规则

保持 v37 规则不变：

1. `ShortcutItem.Name` 支持原文、首字母、全拼搜索。
2. `ShortcutItem.Description` 支持原文、首字母、全拼搜索。
3. `ShortcutItem.TargetPath` 只保留普通字符串搜索。

原因：

- 名称和备注更可能出现中文设备名。
- 路径通常是英文、数字、下划线、网络地址，不需要拼音转换。
- 避免对长路径做无意义拼音转换。

## 8. 规范化规则

全拼搜索应复用首字母搜索的规范化规则。

规范化时：

1. 英文统一转小写。
2. 保留数字。
3. 保留普通英文字母。
4. 忽略以下分隔符：
   - 空格
   - `_`
   - `-`
   - `.`

示例：

```text
热贴机_012 -> retieji012
```

用户输入：

```text
retieji012
```

应匹配。

## 9. 全拼生成规则

中文字符应转换为不带声调的普通拼音。

示例：

```text
热贴机 -> retieji
银烧结 -> yinshaojie
自动点锡机 -> zidongdianxiji
抓取装置 -> zhuaquzhuangzhi
```

非中文字符应保留原始含义：

```text
银烧结NG抓取装置_003
```

全拼搜索串应类似：

```text
yinshaojiengzhuaquzhuangzhi003
```

其中 `NG` 统一参与小写规范化为 `ng`。

## 10. 多音字处理

本次不做多音字人工纠错。

要求：

1. 多音字结果以拼音库默认输出为准。
2. 不新增自定义词典配置。
3. 不因个别多音字结果不符合用户预期而阻断搜索功能。

## 11. 异常处理

搜索功能不能导致主界面崩溃。

要求：

1. 拼音首字母转换异常时，不影响原文搜索。
2. 全拼转换异常时，不影响原文搜索和首字母搜索。
3. `IsTextMatch` 不应向外抛出异常。
4. 如果全拼转换失败，应退化为现有 v37 搜索能力。

## 12. 服务设计建议

`ShortcutSearchService` 建议拆分为清晰的小方法：

```csharp
public bool IsTextMatch(string source, string keyword)
```

主入口。

```csharp
private static bool IsOriginalMatch(string source, string keyword)
```

原文匹配。

```csharp
private static bool IsInitialsMatch(string source, string normalizedKeyword)
```

首字母匹配。

```csharp
private static bool IsFullPinyinMatch(string source, string normalizedKeyword)
```

全拼匹配。

```csharp
private static string NormalizeForPinyinSearch(string value)
```

统一规范化。
