# v157 工厂地图统一点线拓扑与独立对象编辑编码规格说明

## 1. 背景

当前工厂地图已经具备：

```text
设备节点自由布局
节点上、右、下、左四个连接端口
普通连接点（现有 Connector）
端口到端口连线
正交折线路径
折点与线段拖动
共线重叠线段显示合并
地图布局 JSON 保存与恢复
```

但当前底层仍然是“完整 Edge + 中间 Points”模型：

```text
FactoryMapDeviceEdge
  From / FromKind / FromPort
  To / ToKind / ToPort
  Points[]
```

该模型存在以下限制：

```text
1. 节点端口只在渲染时临时生成，不是稳定的拓扑对象。
2. 一条 Edge 是完整连接，路径中的线段不是独立对象。
3. 线段不能独立连接或断开。
4. 连接到线段中间只能通过“插入分支点”间接实现，语义不统一。
5. 节点、连接点、折点、线段分别使用不同选择和拖动状态。
6. 键盘方向键目前只支持移动节点。
7. 重叠线段只在显示层合并，缺少对应的逻辑线段命中映射。
8. 空白区域没有右键新增普通连接点入口。
```

本次目标是把地图升级为统一的点线拓扑编辑器。

## 2. 核心设计原则

### 2.1 点对点拓扑

底层连接关系必须统一为：

```text
连接点 ↔ 独立线段 ↔ 连接点
```

每条线段必须有且只有两个端点。

一个连接点可以被多条线段引用，因此自然支持：

```text
一对一
一对多
多对一
分叉
汇流
```

### 2.2 节点通过附属连接点参与连接

节点本体不直接保存线段引用。

每个节点固定拥有：

```text
Top
Right
Bottom
Left
```

四个附属连接点。

节点移动时，四个附属连接点位置随节点派生变化，连接关系保持不变。

附属连接点不能脱离所属节点单独移动或删除。

### 2.3 线段中间连接必须显式生成连接点

用户可以从线段中间发起连接，但底层禁止没有连接点的“线段直接连接线段”。

操作必须转换为：

```text
点击线段
投影到最近有效位置
网格吸附
创建普通连接点
拆分原线段
从新连接点继续连接
```

这样用户感知上是“线段可以连接”，底层仍然保持严格点对点模型。

### 2.4 视觉相交不代表拓扑连接

两条线垂直交叉、平行重叠或端点碰触时，默认都不自动产生连接关系。

只有交点位置存在明确连接点时，才代表真实拓扑连接。

## 3. 目标对象模型

### 3.1 节点

建议扩展持久化模型：

```csharp
public sealed class FactoryMapDeviceNode
{
    public string Id { get; set; } = string.Empty;
    public string Key { get; set; } = string.Empty;
    public string Name { get; set; } = string.Empty;
    public double X { get; set; }
    public double Y { get; set; }
}
```

字段语义：

```text
Id：地图内部稳定对象 ID。
Key：与快捷项匹配的业务键，继续保留现有路径语义。
Name：展示名称。
X/Y：节点左上角地图坐标。
```

不得继续把业务路径 `Key` 同时当作地图对象 ID。

### 3.2 连接点

新增：

```text
VSLoader/Models/FactoryMapConnectionPoint.cs
VSLoader/Models/FactoryMapConnectionPointKinds.cs
```

建议模型：

```csharp
public sealed class FactoryMapConnectionPoint
{
    public string Id { get; set; } = string.Empty;
    public string Kind { get; set; } = FactoryMapConnectionPointKinds.Free;
    public string OwnerNodeId { get; set; } = string.Empty;
    public string Side { get; set; } = string.Empty;
    public double X { get; set; }
    public double Y { get; set; }
}
```

连接点类型：

```csharp
public static class FactoryMapConnectionPointKinds
{
    public const string Attached = "attached";
    public const string Free = "free";
    public const string Bend = "bend";
}
```

类型语义：

```text
Attached：节点附属连接点，位置由 OwnerNodeId + Side 派生。
Free：普通连接点，位置独立保存，可见、可移动、可分支。
Bend：正交路径折弯点，位置独立保存，默认只控制路径形状。
```

### 3.3 附属连接点稳定 ID

附属连接点不需要重复保存 X/Y，但运行时必须表现为稳定对象。

建议 ID：

```text
{NodeId}:top
{NodeId}:right
{NodeId}:bottom
{NodeId}:left
```

位置继续由 `FactoryMapEndpointGeometryService` 根据节点尺寸计算。

### 3.4 独立线段

新增：

```text
VSLoader/Models/FactoryMapSegment.cs
```

建议模型：

```csharp
public sealed class FactoryMapSegment
{
    public string Id { get; set; } = string.Empty;
    public string FromPointId { get; set; } = string.Empty;
    public string ToPointId { get; set; } = string.Empty;
    public int ZIndex { get; set; }
}
```

规则：

```text
1. FromPointId 和 ToPointId 必须引用存在的连接点。
2. 两端不能引用同一个连接点。
3. 线段必须水平或垂直。
4. 禁止零长度线段。
5. 相同端点对之间不允许重复线段。
6. ZIndex 用于重叠线段命中与编辑优先级，不代表业务连接优先级。
```

## 4. 运行时统一对象语义

建议引入统一对象引用：

```csharp
public enum FactoryMapObjectKind
{
    Device,
    ConnectionPoint,
    Segment
}

public readonly record struct FactoryMapObjectRef(
    FactoryMapObjectKind Kind,
    string Id);
```

所有可交互对象必须具备：

```text
稳定 ID
对象类型
选择能力
右键菜单能力
删除或断开规则
移动规则
持久化规则
```

注意：

```text
“统一对象”不代表所有对象拥有完全相同的移动方式。
附属连接点仍必须服从节点所有权，不能独立脱离节点。
```

## 5. 拓扑服务

新增独立服务：

```text
VSLoader/Models/Services/FactoryMapTopologyService.cs
```

职责：

```text
连接两个连接点
断开一条线段
断开连接点的指定线段
断开连接点全部线段
断开节点全部连接
在线段中插入普通连接点
拆分线段
合并可安全合并的线段
删除孤立 Bend 点
校验拓扑引用
维护连接点邻接索引
```

建议核心接口：

```csharp
ConnectPoints(...)
DisconnectSegment(...)
DisconnectPoint(...)
SplitSegmentAt(...)
DeleteConnectionPoint(...)
ValidateTopology(...)
CleanupOrphanBendPoints(...)
```

所有连接、断开和拆分操作必须通过该服务执行，禁止在窗口事件中直接修改多个集合。

## 6. 连接规则

### 6.1 点与点连接

用户在连线模式中：

```text
点击起点连接点
点击终点连接点
拓扑服务生成正交路径所需 Bend 点
创建一组独立线段
保存布局
```

禁止：

```text
连接点连接自己
创建零长度线段
重复创建完全相同的端点连接
引用不存在的点
生成斜线
```

### 6.2 连接点连接数量

默认规则：

```text
附属连接点：允许连接多条线段。
普通连接点：允许连接多条线段。
Bend 点：默认只允许度数为 2，不作为用户分支点。
```

如果用户在线段 Bend 位置创建分支，应先把 Bend 点提升为 Free 点。

### 6.3 从线段发起连接

在连线模式点击线段：

```text
计算鼠标到线段的正交投影点
限制投影点在线段范围内
吸附到网格
距离端点过近时直接复用原端点
否则创建 Free 点
删除原线段
创建“原起点 → Free 点”线段
创建“Free 点 → 原终点”线段
将该 Free 点设为待连接起点
```

最小端点距离建议：

```text
不小于一个网格单位，即 10px。
```

避免在端点附近生成视觉上重叠的小线段。

## 7. 断开与删除规则

### 7.1 节点

节点右键菜单在编辑模式增加：

```text
开始连接
断开全部连接
```

断开全部连接时删除四个附属连接点关联的所有线段，但不删除节点。

### 7.2 附属连接点

右键菜单：

```text
开始连接
断开指定线段
断开全部
```

附属连接点不能删除。

### 7.3 普通连接点

右键菜单：

```text
开始连接
断开指定线段
断开全部
删除连接点
```

删除规则：

```text
度数为 0：直接删除。
度数大于 0：确认后删除连接点及所有关联线段。
```

### 7.4 Bend 点

默认只在选中路径或线段时显示。

右键菜单：

```text
转换为普通连接点
删除折弯点
```

删除 Bend 点后必须重新执行正交路径归一化。

### 7.5 线段

右键菜单：

```text
从此处开始连接
插入普通连接点
断开/删除线段
```

删除一条线段只删除该逻辑线段，不得根据视觉重叠关系删除其它线段。

## 8. 空白右键新增普通连接点

仅编辑模式生效。

交互流程：

```text
右键地图空白区域
显示地图空白菜单
选择“新增连接点”
Viewport 坐标转换为地图坐标
执行 10px 网格吸附
限制为有效地图坐标
生成唯一 ID
新增 Free 连接点
选中新连接点
保存布局
```

菜单项：

```text
新增连接点
```

冲突边界：

```text
右键节点、端口、连接点、线段时不得弹出空白菜单。
浏览模式不得显示新增菜单。
鼠标正在拖动、框选或连接时不得创建连接点。
```

## 9. 统一选择状态

当前窗口中存在：

```text
selectedDevices
selectedConnector
selectedEdge
selectedSegmentEdge
selectedSegmentIndex
```

建议逐步收束为：

```text
FactoryMapSelectionState
  SelectedObjects: HashSet<FactoryMapObjectRef>
  PrimaryObject: FactoryMapObjectRef?
```

规则：

```text
普通点击：单选。
Ctrl + 点击：追加或移除选择。
框选：默认选择节点和普通连接点。
线段点击：选择逻辑线段。
端口点击：连线模式用于连接，普通编辑模式用于选择端口。
Escape：取消当前待连接状态和选择。
```

第一阶段可以保留节点多选，线段与连接点单选，但必须通过统一选择服务管理，避免继续增加平行字段。

## 10. 移动与吸附

### 10.1 通用移动步长

```text
鼠标拖动：实时移动，释放时吸附。
方向键：10px。
Shift + 方向键：1px 精细移动，不强制网格吸附。
Ctrl + 方向键：50px 快速移动，最终吸附到 10px 网格。
```

保留最小防误触：

```text
鼠标移动距离未达到 DragThreshold 时不进入拖动状态。
建议 DragThreshold 为 4px 左右。
```

### 10.2 节点移动

```text
移动节点 X/Y。
四个 Attached 点位置自动变化。
关联线段端点同步更新。
路径服务重新计算受影响的起止局部路径。
```

不得直接把 Attached 点的派生位置写入布局文件。

### 10.3 附属连接点移动

附属连接点不能脱离节点单独移动。

用户选中附属连接点后按方向键，推荐行为：

```text
移动其所属节点。
```

状态栏必须提示：

```text
节点附属连接点随节点移动。
```

### 10.4 普通连接点移动

```text
直接移动 Free 点 X/Y。
所有引用该点的线段保持连接。
相邻线段经过正交归一化。
鼠标释放或键盘操作结束后保存布局。
```

### 10.5 Bend 点移动

```text
只调整路径形状。
不得改变业务连接关系。
移动后保持相邻线段水平或垂直。
```

### 10.6 线段移动

线段移动必须理解为“移动路径通道”，不能带动节点或普通连接点。

规则：

```text
水平线段上下移动：改变该通道 Y，调整两端相邻垂直段。
垂直线段左右移动：改变该通道 X，调整两端相邻水平段。
```

方向键沿线段自身方向移动时：

```text
如果两端存在可调整 Bend 点，则调整线段长度与相邻段。
如果两端都是固定连接点且路径会被归一化为原形，则不执行无意义移动，并提示用户移动端点或添加绕行段。
```

这是几何约束，不应为了满足“任意方向”制造零长度或重叠抖动线段。

## 11. 正交路径服务

现有：

```text
FactoryMapOrthogonalPathService
```

需要从 `Edge + Points` 输入改造成点线图输入。

新增或调整职责：

```text
在两个连接点之间生成正交段链
移动线段通道
移动 Bend 点
节点或 Free 点移动后的局部重路由
移除零长度线段
合并连续共线且拓扑允许合并的线段
保持 Free 分支点不被归一化删除
保持 Attached 点所有权
```

注意：

```text
Free 点即使只有两条共线线段，也不能自动删除。
只有 Bend 点可以在安全条件下自动合并或删除。
```

## 12. 重叠线段渲染

### 12.1 逻辑层与渲染层分离

逻辑层：

```text
每条 FactoryMapSegment 独立存在。
连接、删除、移动、保存都按 Segment.Id 操作。
```

渲染层：

```text
同轴、共线、重叠或首尾相接的区间执行区间合并。
合并后的可见区间只绘制一次。
```

禁止在保存时因为视觉重叠而合并不同拓扑线段。

### 12.2 可见线段索引

建议模型：

```csharp
public sealed class FactoryMapVisibleSegment
{
    public Point Start { get; init; }
    public Point End { get; init; }
    public IReadOnlyList<string> SourceSegmentIds { get; init; }
    public string TopSegmentId { get; init; }
}
```

用途：

```text
只渲染一份线条
命中时找回底层逻辑线段
选中时高亮正确线段
删除时只删除用户选中的逻辑对象
```

### 12.3 顶层线段规则

重叠区域默认选择：

```text
1. 当前已选中的线段。
2. ZIndex 更高的线段。
3. 创建时间或集合顺序更靠后的线段。
```

右键重叠区域时，如果存在多条来源线段，应提供子菜单或选择列表，不得静默删除全部来源线段。

### 12.4 交叉线显示

水平线与垂直线相交时：

```text
无连接点：只交叉，不连接。
存在 Free 点：连接点绘制在最上层，表示真实连接。
```

本次不新增跨线桥或跳线弧形效果。

## 13. 渲染层级

建议固定层级：

```text
0：背景网格
10：普通合并线段
20：透明线段命中区域
30：节点和普通连接点
40：节点附属连接点
50：选择高亮、拖动手柄、待连接状态
60：框选区域和临时预览线
```

连接点必须覆盖在线段之上，避免用户无法判断交叉位置是否真实连接。

## 14. 持久化格式 Version 4

当前布局版本：

```text
Version 3
```

新格式升级为：

```text
Version 4
```

建议结构：

```json
{
  "Version": 4,
  "Canvas": {},
  "Devices": [],
  "ConnectionPoints": [],
  "Segments": []
}
```

`ConnectionPoints` 只需要持久化：

```text
Free
Bend
```

Attached 点可以根据节点 ID 和方向稳定生成。

## 15. Version 3 到 Version 4 迁移

迁移必须由：

```text
FactoryMapLayoutService
```

集中执行。

迁移步骤：

```text
1. 为每个旧 Device 生成并保存稳定 Node.Id。
2. 为节点生成四个 Attached 点运行时引用。
3. 把旧 Connector 转换为 Free 点，尽量保留原 ID 和中心坐标。
4. 解析每条旧 Edge 的起点端口、Points 和终点端口。
5. 对路径执行正交归一化。
6. 把中间折点转换为 Bend 点。
7. 把相邻点转换为独立 Segment。
8. 跳过零长度、斜线、失效端点和重复线段。
9. 统计迁移警告。
10. 首次成功保存时写入 Version 4。
```

兼容要求：

```text
旧 Version 3 文件必须可以直接打开。
迁移前保留原文件备份。
迁移失败时不得覆盖旧文件。
导入/导出全局配置必须支持 Version 4 地图布局。
```

## 16. 性能约束

当前 `FactoryMapWindow` 在拖动部分对象时会频繁执行完整 `RenderCurrentMap`。

新模型对象数量增加后，必须控制性能：

```text
1. 建立 PointId → 相邻 SegmentIds 邻接索引。
2. 移动节点或连接点时只重算受影响线段。
3. 鼠标拖动过程中优先更新现有 Visual，不清空并重建全部 Canvas。
4. 重叠区间合并只重算受影响坐标轴分组。
5. 布局保存使用 150ms 左右防抖，不在每个键盘重复事件同步写文件。
6. 拖动结束必须立即保存最终状态。
7. 渲染命中线与可见线分离。
8. 不为每一帧创建大量临时 WPF Shape。
```

建议拆分：

```text
FactoryMapTopologyService
FactoryMapMovementService
FactoryMapRenderIndexService
FactoryMapSelectionState
FactoryMapLayoutMigrationService
```

避免继续把全部逻辑堆入 `FactoryMapWindow.xaml.cs`。

## 17. 操作事务与保存失败

连接、断开、拆线、删除连接点属于多集合事务。

要求：

```text
1. 操作前生成最小内存快照或可逆命令。
2. 拓扑修改完成后先校验，再保存。
3. 保存失败时恢复操作前状态，或明确提示当前仅内存生效。
4. 不允许出现点已删除但线段仍引用它的半完成状态。
```

推荐逐步引入地图命令模型，为后续撤销/重做预留接口，但本次不要求实现完整撤销栈。

## 18. 状态栏与提示

状态栏应根据选择对象显示：

```text
已选择节点：{名称}
已选择附属连接点：{节点名称} {方向}
已选择连接点：{Id}，连接数 {Degree}
```

## 21. 非目标

