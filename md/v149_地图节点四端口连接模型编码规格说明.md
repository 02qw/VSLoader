# v149 地图节点四端口连接模型编码规格说明

## 1. 背景

v148 已经把地图中的“分叉/汇流”从内部折点提升为用户可见的连接点。

这个方向是正确的，但实际继续思考后，还有一个更基础的连线问题没有解决：

```text
当前连线端点主要依赖程序根据节点相对位置自动判断。
用户想从上方连接，程序可能仍然从左右边连。
用户想表达明确的上下游方向时，连线入口和出口不受用户控制。
```

常见 UML、流程图、draw.io 类工具通常不会让连线随便吸到节点任意位置，而是给节点提供固定连接端口。

因此本阶段要引入：

```text
节点四端口连接模型。
```

每个可连接单位都有 4 个端口：

```text
上、右、下、左。
```

连线不再只是：

```text
节点 A -> 节点 B
```

而是：

```text
节点 A 的某个端口 -> 节点 B 的某个端口
```

这样可以避免“明明想上下连接，却自动变成左右连接”的问题。

## 2. 核心结论

从 v149 开始，地图连线的用户语义单位必须拆清楚：

```text
节点：设备节点、连接点。
端口：节点上的上/右/下/左 4 个连接入口。
连线：端口到端口的连接关系。
路径折点：只负责单条线的视觉走向。
```

不要再把“节点中心点”“自动边缘点”“路径折点”混在一起作为用户连线单位。

正确模型应该是：

```text
设备节点 A.right -> 设备节点 B.left
设备节点 A.bottom -> 连接点 J.top
连接点 J.right -> 设备节点 C.left
```

连线端点必须记录端口。

路径折点只调整线怎么走，不改变线连接到哪个端口。

## 3. 本阶段目标

本阶段目标：

```text
1. 为设备节点提供上、右、下、左 4 个连接端口。
2. 为连接点提供上、右、下、左 4 个虚拟连接端口。
3. 连线数据保存 fromPort 和 toPort。
4. 连线渲染从指定端口开始，到指定端口结束。
5. 连线模式下用户点击端口来创建连接，而不是点击整个节点自动猜测。
6. 旧布局没有端口字段时，按节点相对方向推断一次默认端口。
7. 右键连线添加连接点时，拆分后的两条线都必须有明确端口。
8. 路径折点拖动、删除、保存不能破坏端口信息。
9. 全局配置导入导出继续兼容新版地图布局。
10. 构建和现有地图相关测试通过。
```

用户体验目标：

```text
用户想从节点下边连出去，就点节点下端口。
用户想连到另一个节点上边，就点另一个节点上端口。
程序尊重用户选择，不再猜成左右连接。
```

## 4. 非目标

本阶段不做：

```text
1. 不做自动避障布线。
2. 不做端口数量自定义。
3. 不做端口命名。
4. 不做端口容量限制。
5. 不做端口颜色分类。
6. 不做连线箭头。
7. 不做自动整理全部连线。
8. 不做复杂边线捆绑。
9. 不做连接点业务属性。
10. 不重构地图窗口整体窗口逻辑。
```

说明：

```text
v149 只解决“线应该从节点哪里出来、连到节点哪里去”的问题。
```

## 5. 核心单位定义

### 5.1 节点

可连接节点包括：

```text
设备节点。
连接点。
```

设备节点是已有业务节点。

连接点是 v148 引入的轻量拓扑节点。

两者都可以作为连线端点。

### 5.2 端口

端口是节点上的固定连接位置。

端口固定 4 个：

```text
top
right
bottom
left
```

对应中文语义：

```text
top：上
right：右
bottom：下
left：左
```

端口不是单独业务节点。

端口不能被拖动。

端口位置由节点位置和节点尺寸计算得出。

### 5.3 连线

连线表达两个端口之间的关系。

连线必须包含：

```text
起点节点类型。
起点节点 Id。
起点端口。
终点节点类型。
终点节点 Id。
终点端口。
路径折点。
```

### 5.4 路径折点

路径折点只属于某一条连线。

路径折点不表达分叉。

路径折点不表达汇流。

路径折点不能替代端口。

## 6. 数据模型要求

### 6.1 新增端口常量

新增文件：

```text
VSLoader\Models\FactoryMapPortKinds.cs
```

建议内容：

```csharp
namespace VSLoader.Models;

public static class FactoryMapPortKinds
{
    public const string Top = "top";
    public const string Right = "right";
    public const string Bottom = "bottom";
    public const string Left = "left";
}
```

端口值必须统一使用常量。

不要在窗口代码里散落字符串。

### 6.2 持久化连线模型

修改：

```text
VSLoader\Models\FactoryMapDeviceEdge.cs
```

增加：

```csharp
public string FromPort { get; set; } = FactoryMapPortKinds.Right;
public string ToPort { get; set; } = FactoryMapPortKinds.Left;
```

保存后的布局示例：

```json
{
  "from": "A",
  "fromKind": "device",
  "fromPort": "bottom",
  "to": "B",
  "toKind": "device",
  "toPort": "top",
  "points": []
}
```

### 6.3 运行时连线视图模型

修改：

```text
VSLoader\Models\FactoryMapDeviceEdgeViewData.cs
```

建议结构：

```csharp
public sealed class FactoryMapDeviceEdgeViewData
{
    public FactoryMapEndpointViewData From { get; set; } = new();
    public string FromPort { get; set; } = FactoryMapPortKinds.Right;

    public FactoryMapEndpointViewData To { get; set; } = new();
    public string ToPort { get; set; } = FactoryMapPortKinds.Left;

    public List<FactoryMapPoint> Points { get; set; } = [];
}
```

端口建议放在 edge 上，而不是放在 endpoint 上。

原因：

```text
同一个节点可以通过不同端口连接多条线。
如果端口放在 endpoint 上，会让 endpoint 误以为自己只有一个固定端口。
```

## 7. 端口几何计算

修改：

```text
VSLoader\Models\Services\FactoryMapEndpointGeometryService.cs
```

新增或调整 API：

```csharp
public static WpfPoint GetPortPoint(
    FactoryMapEndpointViewData endpoint,
    string port);

public static string InferOutgoingPort(
    FactoryMapEndpointViewData from,
    FactoryMapEndpointViewData to);

public static string InferIncomingPort(
    FactoryMapEndpointViewData from,
    FactoryMapEndpointViewData to);

public static string NormalizePort(string? port);
```

### 7.1 设备节点端口位置

设备节点端口按节点矩形边中心计算：

```text
top    = (x + width / 2, y)
right  = (x + width, y + height / 2)
bottom = (x + width / 2, y + height)
left   = (x, y + height / 2)
```

### 7.2 连接点端口位置

连接点虽然很小，但仍然要有虚拟端口：

```text
top    = (centerX, centerY - radius)
right  = (centerX + radius, centerY)
bottom = (centerX, centerY + radius)
left   = (centerX - radius, centerY)
```

连接点端口显示可以更轻，但数据模型不能省略。

### 7.3 旧数据端口推断

旧布局没有 `fromPort/toPort` 时，加载时做一次兼容推断。

推断规则：

```text
dx = toCenterX - fromCenterX
dy = toCenterY - fromCenterY

如果 abs(dx) >= abs(dy)：
    dx >= 0：fromPort = right，toPort = left
    dx < 0 ：fromPort = left，toPort = right

否则：
    dy >= 0：fromPort = bottom，toPort = top
    dy < 0 ：fromPort = top，toPort = bottom
```

这个推断只用于兼容旧数据或非法端口，不用于覆盖用户已经选择的端口。

## 8. 连线渲染要求

地图绘制连线时：

```text
起点 = GetPortPoint(edge.From, edge.FromPort)
终点 = GetPortPoint(edge.To, edge.ToPort)
```

如果 edge 有路径折点：

```text
起点端口 -> 折点列表 -> 终点端口
```

如果 edge 没有路径折点：

```text
起点端口 -> 终点端口
```

严禁继续使用“根据另一个节点位置自动找边缘点”的逻辑作为正常渲染入口。

旧的 `GetEdgeStart/GetEdgeEnd` 如果保留，只能作为兼容层或内部转调，不应继续作为主路径。

## 9. 连线创建交互

### 9.1 端口显示规则

建议规则：

```text
浏览模式：默认不显示端口。
编辑模式：节点悬停或选中时显示该节点 4 个端口。
连线模式：显示所有可连接节点的 4 个端口。
拖动节点时：端口跟随节点移动。
```

端口视觉建议：

```text
设备节点端口：直径 7-8px。
连接点端口：直径 5-6px。
默认白色填充。
边框使用当前地图强调蓝。
悬停时填充强调蓝。
选中作为连线起点时显示外圈。
```

### 9.2 点击规则

连线模式中：

```text
点击端口：选择连线起点或终点。
点击节点本体：不创建连线。
点击空白：取消待连接状态。
按 Esc：取消待连接状态。
```

待连接状态要记录：

```csharp
private sealed record PendingConnectionEndpoint(
    FactoryMapEndpointViewData Endpoint,
    string Port);
```

不要只记录节点。

### 9.3 合法性校验

创建连线前必须校验：

```text
1. 起点节点存在。
2. 终点节点存在。
3. 起点端口合法。
4. 终点端口合法。
5. 不能连接同一个节点到自己。
6. 不能创建完全重复的端口连线。
```

重复判断建议包含端口：

```text
fromKind + from + fromPort + toKind + to + toPort
```

不要只用 from/to 判断重复。

同两个节点之间允许存在不同端口的多条线，但第一阶段可以先保守限制为“同方向同端口不重复”。

## 10. 连接点与端口的关系

连接点是节点。

连接点也有 4 个端口。

连接点不是“线上的一个可拖动折点”。

正确表达一对多：

```text
A.right -> J.left
J.top -> B.bottom
J.right -> C.left
J.bottom -> D.top
```

正确表达多对一：

```text
A.right -> J.left
B.bottom -> J.top
C.left -> J.right
J.bottom -> D.top
```

这样用户后续可以通过选择连接点不同端口控制分叉视觉方向。

## 11. 右键连线添加连接点

右键一条已有连线添加连接点时，原线拆成两条线。

原线：

```text
A.fromPort -> B.toPort
```

拆分后：

```text
A.fromPort -> J.inferredPort1
J.inferredPort2 -> B.toPort
```

连接点端口推断规则：

```text
J 面向 A 的端口使用 InferIncomingPort(A, J) 或方向相反端口。
J 面向 B 的端口使用 InferOutgoingPort(J, B)。
```

实现时要保证：

```text
1. 原始 A 的 fromPort 保留。
2. 原始 B 的 toPort 保留。
3. 新连接点 J 的两个端口根据空间方向推断。
4. 原线的路径折点不要无脑复制到两条新线导致视觉错乱。
```

第一阶段可以采用简单策略：

```text
拆分后的两条线默认不继承原路径折点。
后续用户可以重新调整路径。
```

## 12. 路径折点边界

路径折点继续存在，但边界要更严格：

```text
1. 拖动折点不能改变 fromPort/toPort。
2. 删除折点不能改变 fromPort/toPort。
3. 正交路径重新计算不能覆盖 fromPort/toPort。
4. 端口点永远是路径的第一点和最后一点。
5. 折点不能被保存为端口。
```

如果自动正交算法需要额外中间点：

```text
这些点只能作为渲染内部点。
不要作为用户主要操作对象显示出来。
```

## 14. 全局配置导入导出影响

全局配置导入导出已经包含当前工作区地图布局。

但必须保证：

```text

```

## 15. UI 风险控制

端口容易造成视觉拥挤，因此显示策略要克制。

必须避免：

```text
1. 浏览模式满屏端口点。
2. 连接点端口比连接点本体还抢眼。
3. 端口遮挡节点文字。
4. 拖动节点时端口残影。
5. 缩放地图时端口尺寸失控。
```

缩放建议：

```text
端口视觉大小可以保持屏幕像素稳定。
不要随着地图缩放无限变大或无限变小。
```

如果当前绘制体系暂时不方便做屏幕像素稳定，第一阶段至少要限制端口最小和最大显示尺寸。

## 16. 兼容策略

兼容旧数据必须遵循：

```text
旧数据能打开。
旧数据能保存成新版。
旧数据保存后不会丢节点、连接点、连线。
旧数据没有端口时只推断一次。
```

非法端口处理：

```text
null、空字符串、未知值，都视为缺失端口。
加载时 NormalizePort。
无法判断时使用 from=right、to=left 作为最后兜底。
```

## 21. 后续阶段

v149 只建立四端口模型。

后续可以继续考虑：

```text
1. 端口悬停吸附预览。
2. 拖动连线端点重新绑定端口。
3. 多条线在同一端口附近自动错位。
4. 端口方向影响默认正交路径。
5. 连线箭头和方向语义。
6. 更成熟的 draw.io 式连线编辑体验。
```

但这些不进入本阶段。

本阶段最重要的是先把连接单位从“节点猜边缘”升级为“明确端口到明确端口”。
