# v120 网络不可达时联网功能预检与防卡死编码规格说明

## 1. 背景

当前程序中有多类功能会访问网络资源：

- 软件更新：读取设置中的 `SoftwareUpdateManifestPath`，通常可能是共享目录中的 `manifest.json`。
- 手动/后台检测更新：读取 rules 文件、map 文件、软件更新 manifest。
- 批量新增识别：扫描目标父级目录，目标父级目录可能是网络共享路径。
- 自动获取 AdminUI 连接：通过 HTTP/HTTPS 请求服务器下载 JNLP。
- 单个获取 AdminUI 连接：通过 HTTP/HTTPS 请求服务器下载当前快捷项的 JNLP。
- 打开 VSCode：访问快捷项目标路径，该路径可能是网络共享路径。
- 打开 WebUI / 拼接 AdminUI：读取快捷项目标路径下的 properties 文件，该路径可能是网络共享路径。

其中，批量新增识别已经引入：

```text
VSLoader/Models/Services/PathAccessPreflightService.cs
```

用于在扫描前检查 UNC 网络路径主机连通性。

但软件更新、后台检测更新、快捷项目标路径访问等链路仍存在直接调用 `File.Exists`、`Directory.Exists`、`File.OpenRead`、`File.ReadAllText`、`File.ReadLines` 的情况。

## 2. 问题描述

用户在无网络或服务器不可达时点击“更新软件”，程序可能出现：

```text
界面长时间无响应
像崩溃一样卡住
```

当前 `UpdateSoftwareAsync()` 有外层 `try/catch`：

```text
VSLoader/ViewModels/MainViewModel.cs
```

但问题不完全是异常没有被捕获，而是访问断开的 UNC 网络路径时，系统文件 API 可能长时间阻塞。

典型风险点：

```csharp
File.Exists(manifestPath)
File.OpenRead(manifestPath)
File.ReadAllText(filePath)
Directory.Exists(shortcut.TargetPath)
File.ReadLines(propertiesPath)
```

当路径类似：

```text
\\server\share\manifest.json
\\192.168.15.67\instances\xxx
```

且服务器不可达、VPN 未连接、网络断开时，这些调用可能不会立刻失败。

## 3. 根因分析

当前代码中，“路径为空/文件不存在”和“网络不可达”没有被统一区分。

示例：

```text
VSLoader/Models/Services/SoftwareUpdateService.cs
CheckAvailabilityAsync()
```

当前先执行：

```csharp
if (!File.Exists(manifestPath))
{
    return SoftwareUpdateAvailabilityResult.Fail("manifest 文件不存在。");
}
```

如果 `manifestPath` 是断开的 UNC 网络路径，`File.Exists` 本身就可能卡住。

类似问题也存在于：

```text
VSLoader/Models/Services/UpdateCheckService.cs
VSLoader/Models/Services/VSCodeLauncherService.cs
VSLoader/Models/Services/AdminUiService.cs
VSLoader/Models/Services/WebUiService.cs
```

## 4. 目标

本次目标：

- 对网络共享路径访问增加统一预检，网络不可达时快速失败并提示。
- 软件更新按钮在无网络时不应卡死，不应启动更新器。
- 手动检测更新和后台检测更新在网络路径不可达时不应卡死。
- 打开 VSCode、打开 WebUI、打开/下载 AdminUI 访问快捷项目标路径前，应对 UNC 目标路径做快速预检。
- AdminUI HTTP 请求应设置明确超时，避免服务器不可达时长时间等待。
- 错误提示要可追溯，能让用户知道是网络、VPN、服务器或共享目录问题。
- 不破坏已有正常网络环境下的功能。

## 5. 非目标

本次不做以下事项：

- 不实现自动重试。
- 不实现离线缓存。
- 不改变更新包 manifest 格式。
- 不改变 AdminUI / WebUI URL 拼接规则。
- 不改变批量新增识别核心扫描算法。
- 不改变地图、工作区、窗口布局、UI 样式。
- 不把所有本地文件访问都改成异步。
- 不引入外部网络库。

## 6. 推荐方案

### 6.1 扩展 PathAccessPreflightService

修改：

```text
VSLoader/Models/Services/PathAccessPreflightService.cs
```

新增文件路径预检：

```csharp
public async Task<PathAccessPreflightResult> CheckFileAsync(string path, TimeSpan? timeout = null)
```

行为：

- 路径为空：返回失败。
- UNC 文件路径：先提取 host，并测试 `host:445`。
- 不能连接：快速返回网络失败，不执行 `File.Exists`。
- 可以连接：再用带超时的 `File.Exists` 检查文件是否存在。
- 本地文件路径：直接用带超时的 `File.Exists`。

建议错误文案：

```text
网络连接失败，无法连接到 {host}。请检查网络、VPN 或共享服务器状态。
文件不存在或不可访问：{path}
```

同时保留已有：

```csharp
CheckDirectoryAsync(...)
TryGetUncHost(...)
```

不破坏批量新增识别已有逻辑。

### 6.2 给 PathAccessPreflightService 增加通用可访问性方法

建议抽取内部方法：

```csharp
private async Task<PathAccessPreflightResult> CheckPathAsync(
    string path,
    string emptyMessage,
    string missingMessage,
    Func<string, bool> exists,
    TimeSpan timeout)
```

`CheckDirectoryAsync` 和 `CheckFileAsync` 都复用该方法。

这样避免目录和文件两套逻辑分叉。

### 6.3 软件更新读取 manifest 前增加预检

修改：

```text
VSLoader/Models/Services/SoftwareUpdateService.cs
```

给 `SoftwareUpdateService` 注入或内部持有：

```csharp
PathAccessPreflightService
```

构造函数建议：

```csharp
public SoftwareUpdateService()
    : this(new PathAccessPreflightService())
{
}

public SoftwareUpdateService(PathAccessPreflightService pathAccessPreflightService)
{
    _pathAccessPreflightService = pathAccessPreflightService;
}
```

在以下方法开头，替换直接 `File.Exists`：

```text
CheckAvailabilityAsync()
PrepareUpdateAsync()
```

改为：

```csharp
var manifestPreflight = await _pathAccessPreflightService.CheckFileAsync(manifestPath, cancellationToken: not required in v120);
if (!manifestPreflight.Success)
{
    return SoftwareUpdateAvailabilityResult.Fail(manifestPreflight.ErrorMessage ?? "manifest 文件不存在或不可访问。");
}
```

`PrepareUpdateAsync()` 中更新包文件也需要预检：

```csharp
var packagePreflight = await _pathAccessPreflightService.CheckFileAsync(packagePath);
```

避免 manifest 可读但更新包所在共享路径断开。

### 6.4 更新检测服务增加安全文件访问

修改：

```text
VSLoader/Models/Services/UpdateCheckService.cs
```

目标是避免后台检测线程长时间卡在网络路径上。

推荐最小方案：

- 给 `UpdateCheckService` 构造注入 `PathAccessPreflightService`。
- 将 `Check(...)` 保持同步签名不变的方案不推荐，因为预检是异步 TCP 探测。
- 推荐新增异步方法：

```csharp
public async Task<UpdateCheckResult> CheckAsync(
    UpdateCheckConfig config,
    string updateTimePath,
    Version currentVersion,
    string softwareUpdateManifestPath = "",
    CancellationToken cancellationToken = default)
```

`MainViewModel.CheckUpdatesOnceAsync()` 改为调用 `CheckAsync(...)`。

保留旧的 `Check(...)` 给现有测试或纯本地同步路径使用，内部可以不改或作为兼容入口。

异步检查规则：

- rules 文件路径不为空时，先 `CheckFileAsync`。
- map 文件路径不为空时，先 `CheckFileAsync`。
- manifest 文件路径不为空时，先 `CheckFileAsync`。
- 预检失败时，把错误加入 `result.Failures`，不继续读对应文件。

建议错误文案：

```text
批量规则文件不可访问：{原因}
地图配置文件不可访问：{原因}
软件更新 manifest 不可访问：{原因}
```

### 6.5 快捷项目标路径访问前增加目录预检

涉及：

```text
VSLoader/Models/Services/VSCodeLauncherService.cs
VSLoader/Models/Services/AdminUiService.cs
VSLoader/Models/Services/WebUiService.cs
```

当前风险：

```csharp
Directory.Exists(shortcut.TargetPath)
File.Exists(propertiesPath)
File.ReadLines(propertiesPath)
```

推荐方案：

- `VSCodeLauncherService` 增加异步方法：

```csharp
public async Task<LaunchResult> LaunchAsync(string vscodePath, string targetPath)
```

内部先对 `targetPath` 调用 `CheckDirectoryAsync` 或 `CheckFileAsync`。

- `MainViewModel.OpenShortcut()` 改为异步命令 `OpenShortcutAsync()`。

如果改命令影响较大，可以保留同步 `Launch()`，本次新增并使用异步版本。

- `AdminUiService.ResolveShortcutInfo` 当前是同步私有方法，建议新增异步版本：

```csharp
private async Task<AdminUiShortcutInfo> ResolveShortcutInfoAsync(...)
```

在 `DownloadOneCoreAsync()` 和 `DownloadOneAsync()` 中使用异步预检。

`OpenAdminUi()` 只是打开本地下载好的 JNLP，同时需要读取目标路径来推导本地 JNLP 名称，因此也建议新增：

```csharp
public async Task<LaunchResult> OpenAdminUiAsync(...)
```

并在 `MainViewModel.OpenAdminUiAsync()` 中调用。

- `WebUiService` 增加：

```csharp
public async Task<LaunchResult> OpenWebUiAsync(...)
```

并在 `MainViewModel.OpenWebUi` 改为异步命令。

### 6.6 AdminUI HTTP 请求设置超时

修改：

```text
VSLoader/Models/Services/AdminUiService.cs
```

`CreateHttpClient` 当前没有设置 `Timeout`。

建议新增常量：

```csharp
private static readonly TimeSpan DefaultHttpTimeout = TimeSpan.FromSeconds(5);
```

并设置：

```csharp
return new HttpClient(handler)
{
    Timeout = DefaultHttpTimeout
};
```

这样：

- `TestConnectionAsync()` 无网络时会更快失败。
- `DownloadAllAsync()` 单个请求不会无限等待。
- `DownloadOneAsync()` 单个请求不会无限等待。

错误已经由现有 try/catch 转换成用户可见消息。

## 8. 编码要求

### 8.1 错误必须返回结果，不允许抛到 UI 层

联网/网络路径失败时，应转为：

```text
LaunchResult.Fail(...)
SoftwareUpdateAvailabilityResult.Fail(...)
SoftwareUpdateResult.Fail(...)
UpdateCheckResult.Failures.Add(...)
PathAccessPreflightResult.Fail(...)
```

UI 层只负责展示，不应被异常打穿。

### 8.2 不要让 UI 线程执行网络路径探测

以下操作不得直接在 UI 线程同步执行：

```text
UNC File.Exists
UNC Directory.Exists
UNC File.OpenRead
UNC File.ReadAllText
UNC File.ReadLines
```

需要先走 `PathAccessPreflightService`。

### 8.3 后台检测失败不弹阻塞对话框

后台更新检测失败仍使用现有独立失败提示栏：

```text
HasUpdateFailure
UpdateFailureMessage
```

不要在后台检测中弹 `MessageBox`。

手动检测更新可以复用同一提示栏，也可以保留当前忙碌遮罩结束后的状态提示。

### 8.4 超时时间

建议默认：

```text
路径预检 TCP：3 秒
HTTP 请求：5 秒
```

不要把超时时间设得过长。

## 10. 验收标准

满足以下条件即完成：

- 无网络时点击“更新软件”，程序不崩溃、不长时间无响应。
- manifest 位于不可达共享路径时，快速提示网络连接失败。
- 更新包位于不可达共享路径时，快速提示网络连接失败。
- 手动检测更新遇到不可达 rules/map/manifest 时，不阻塞，不崩溃，提示更新检测失败。
- 后台检测更新遇到不可达路径时，不弹阻塞对话框，不崩溃。
- 批量新增识别现有路径预检能力不被破坏。
- 自动获取 AdminUI 连接无网络时，能在合理时间内失败并提示。
- 打开 VSCode 时目标路径不可达，能提示网络连接失败或目标路径不可访问。
- 打开 WebUI / AdminUI 时目标路径不可达，能提示网络连接失败或目标路径不可访问。
- `dotnet test .\VSLoader.Tests\VSLoader.Tests.csproj -c Debug --no-restore` 通过。
- `dotnet build .\VSLoader.sln -c Debug --no-restore` 通过。

## 11. 风险与注意事项

### 11.1 UNC 主机 445 端口检测是共享路径场景的快速兜底

共享目录通常依赖 SMB，检测 `host:445` 可以快速判断网络共享路径是否基本可达。

但这不是严格的权限校验。

因此 TCP 成功后仍需要继续执行 `File.Exists` / `Directory.Exists`。

### 11.2 HTTP 服务和共享目录是两种不同预检

AdminUI BaseUrl 是 HTTP/HTTPS，应使用 `HttpClient` 超时和 `TestConnectionAsync()`。

共享路径是 UNC，应使用 `PathAccessPreflightService`。

不要把两者混为一个检测。

### 11.3 不要后台无限重试

后台检测更新每 10 分钟一次，失败提示即可。

本次不增加自动重试，避免无网络时持续占用资源。

### 11.4 不要吞掉错误细节

提示中至少要说明：

```text
哪个功能失败
哪个路径或服务器不可达
建议检查网络、VPN 或服务器状态
```

否则用户无法判断是配置错了还是网络断了。
