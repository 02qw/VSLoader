# v51 工厂地图首次显示裁剪与适应时序修复编码规格说明

## 1. 问题背景

v50 实现了工厂地图轻量拖拽编辑器：

```text
单设备节点
锁定/编辑模式
滚轮缩放
空白区域拖动画布
编辑模式拖动设备并保存布局
```

当前发现一个显示问题：

```text
地图窗口打开后，右侧设备节点像被切割一样，只显示左半部分或部分内容。
```

从用户截图看：

```text
地图右侧区域出现明显空白。
右侧一列设备节点被裁剪。
节点文字和边框被截断。
```

## 2. 初步排查结论

已检查本机用户布局文件：

```text
%AppData%\VSLoader\factory-map.layout.json
```

当前布局数据：

```text
canvas = 1600 x 900
设备数量 = 53
设备最右边界约为 1280
右侧剩余空间约为 320
```

因此：

```text
不是 JSON 画布宽度不足。
不是设备坐标超出画布。
```

更可能的根因是：

```text
地图首次渲染时，地图窗口尚未完成 WPF 布局测量。
MapViewport.ActualWidth / ActualHeight 仍为 0 或未稳定。
ResetMapView() 过早计算 fitScale。
CalculateFitScale() 因 IsMapReady() 失败返回 1.0。
地图以原始 1:1 比例显示。
MapViewport 设置了 ClipToBounds=True。
超出当前窗口可视区域的部分被裁剪。
```

## 3. 当前相关代码

主窗口当前调用顺序：

```csharp
RefreshFactoryMap();
PositionFactoryMapWindow();
_factoryMapWindow.Show();
```

问题点：

```text
RefreshFactoryMap() 会调用 FactoryMapWindow.RenderMap()
RenderMap() 会触发 ResetMapView()
但此时地图窗口尚未 Show()
MapViewport 还没有真实可用尺寸
```

地图窗口当前适应逻辑：

```csharp
private void ResetMapView()
{
    userScale = 1.0;
    fitScale = CalculateFitScale();
    CenterMap();
    ApplyMapTransform();
}
```

```csharp
private double CalculateFitScale()
{
    if (!IsMapReady())
    {
        return 1.0;
    }

    var scaleX = MapViewport.ActualWidth / MapCanvas.Width;
    var scaleY = MapViewport.ActualHeight / MapCanvas.Height;
    return Math.Min(1.0, Math.Min(scaleX, scaleY));
}
```

裁剪区域：

```xml
<Grid x:Name="MapViewport"
      ClipToBounds="True">
```

`ClipToBounds=True` 本身是合理的，因为地图平移/缩放时不应溢出窗口；问题在于首次适配比例计算过早。

## 4. 需求目标

修复地图首次打开时右侧节点被裁剪的问题。

修复后应满足：

1. 地图窗口首次打开后，完整地图默认适应可视区域。
2. 不应出现右侧节点被截断。
3. `ClipToBounds=True` 继续保留，避免地图溢出污染窗口。
4. 滚轮缩放功能保持正常。
5. 空白区域拖动画布功能保持正常。
6. 编辑模式拖动设备并保存功能保持正常。
7. 主窗口最小化/恢复、地图窗口关闭/重新打开后，地图适配仍正常。

## 5. 推荐实现方案

推荐采用：

```text
延迟适配布局
```

也就是：

```text
RenderMap() 负责更新 Canvas 内容。
ResetMapView() 不在视口尺寸未稳定时立即计算最终 fitScale。
在 WPF 完成布局后，通过 Dispatcher.BeginInvoke 再执行一次 ResetMapView()。
```

推荐实现方式：

```csharp
private bool pendingFitToView;
```

在 `RenderCurrentMap(resetView: true)` 中：

```text
如果需要重置视图，不直接依赖当前 ActualWidth。
先调用 ScheduleResetMapView()。
```

新增方法：

```csharp
private void ScheduleResetMapView()
{
    pendingFitToView = true;
    Dispatcher.BeginInvoke(new Action(() =>
    {
        if (!pendingFitToView)
        {
            return;
        }

        pendingFitToView = false;
        ResetMapView();
    }), DispatcherPriority.Loaded);
}
```

说明：

```text
DispatcherPriority.Loaded 或 Render 都可以。
推荐 Loaded。
目标是等 MapViewport 完成测量后再计算 ActualWidth/ActualHeight。
```

需要增加命名空间：

```csharp
using System.Windows.Threading;
```

## 6. SizeChanged 处理策略

当前：

```csharp
private void MapViewport_SizeChanged(object sender, SizeChangedEventArgs e)
{
    ResetMapView();
}
```

这个逻辑会在窗口尺寸变化时重置地图。

本次建议保留，但增强保护：

1. 如果地图尚未加载，不处理。
2. 如果 `ActualWidth/ActualHeight` 仍为 0，不处理。
3. 如果当前正在拖拽设备或拖动画布，不立即重置，避免打断用户操作。

推荐：

```csharp
private void MapViewport_SizeChanged(object sender, SizeChangedEventArgs e)
{
    if (isDraggingMap || isDraggingDevice)
    {
        return;
    }

    ScheduleResetMapView();
}
```

注意：

```text
这会保持窗口尺寸变化后仍重新适应全局。
符合当前地图默认全局适应的设计。
```

## 7. IsMapReady 调整建议

当前 `IsMapReady()` 依赖：

```text
MapViewport.ActualWidth > 0
MapViewport.ActualHeight > 0
MapCanvas.Width > 0
MapCanvas.Height > 0
```

该判断可以保留。

但 `CalculateFitScale()` 在未 ready 时直接返回 `1.0` 会造成“错误地应用 1:1 比例”。

推荐修改为：

```text
ResetMapView() 如果 IsMapReady() 为 false，则不要 ApplyMapTransform。
而是 ScheduleResetMapView() 等待下一轮布局。
```

示例：

```csharp
private void ResetMapView()
{
    if (!IsMapReady())
    {
        ScheduleResetMapView();
        return;
    }

    userScale = 1.0;
    fitScale = CalculateFitScale();
    CenterMap();
    ApplyMapTransform();
}
```

这样避免：

```text
未 ready 时把 fitScale 错误设成 1.0
```

## 8. MainWindow 调用顺序可选优化

可选同时调整 `ShowFactoryMapIfNeeded()` 调用顺序：

当前：

```csharp
RefreshFactoryMap();
PositionFactoryMapWindow();
_factoryMapWindow.Show();
```

可改为：

```csharp
PositionFactoryMapWindow();
_factoryMapWindow.Show();
RefreshFactoryMap();
```

说明：

1. 先定位窗口。
2. 显示窗口。
3. 再刷新地图。

即使这样改，也仍建议保留 `ScheduleResetMapView()`。

原因：

```text
Show() 返回时 WPF 布局不一定已经完全稳定。
延迟适配更稳。
```
