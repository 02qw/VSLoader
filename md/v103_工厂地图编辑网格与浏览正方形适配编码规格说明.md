# v103 工厂地图编辑网格与浏览正方形适配编码规格说明

## 1. 背景

v102 已经通过调整画布背景和节点边框，提高了地图背景与节点之间的区分度。

下一步希望引入网格，但网格不能只是视觉装饰。它应服务于地图编辑的实用价值：

- 帮助用户拖拽节点时判断对齐关系。
- 与现有节点吸附算法一致。
- 不干扰浏览模式下阅读节点和连线。
- 不让连线和网格混在一起导致看不清。

同时用户提出另一个相关需求：

编辑时希望地图区域更像“可持续扩展的编辑画布”，不要很快碰到边界；浏览模式则不需要渲染超大区域，而应以有节点的内容范围为中心，形成一个舒适的正方形视图进行展示。

本次采用第一阶段方案：

```text
编辑模式淡网格 + 右下编辑缓冲区 + 浏览模式正方形适配
```

不做真正无限画布，不支持负坐标。

## 2. 目标

实现轻量、稳定、实用的地图编辑辅助能力：

- 绿色编辑模式显示淡网格。
- 红色锁定浏览模式隐藏网格。
- 网格单位与现有 `SnapGridSize = 10` 对齐。
- 每 50px 显示一条稍明显的主网格线。
- 节点吸附逻辑保持不变，继续按 10px 吸附。
- 编辑时画布右侧和底部增加更大的可操作缓冲区。
- 浏览模式按节点内容范围计算正方形 bounds，用于适配视图。
- 不改变地图 JSON 数据格式。
- 不改变节点坐标保存语义。

## 3. 非目标

本次不做：

- 真正无限画布。
- 负坐标支持。
- 节点中心吸附。
- 网格密度随缩放动态变化。
- 虚拟化无限网格。
- 将网格配置写入 JSON。
- 改变连线算法。
- 改变节点尺寸或字体。

## 4. 当前代码定位

### 4.1 吸附单位

当前吸附单位：

```csharp
private const double SnapGridSize = 10;
```

当前节点拖拽结束后执行：

```csharp
private static void SnapDeviceToGrid(FactoryMapDeviceViewNode device)
{
    device.X = FactoryMapEditMath.ClampAndSnapToGrid(device.X, SnapGridSize);
    device.Y = FactoryMapEditMath.ClampAndSnapToGrid(device.Y, SnapGridSize);
}
```

因此网格最小单位必须是 10px。

### 4.2 渲染顺序

当前 `RenderCurrentMap()` 中：

```csharp
MapCanvas.Children.Clear();
...
foreach (var edge in currentMap.Edges)
{
    DrawEdge(edge);
}

foreach (var device in currentMap.Devices)
{
    DrawDevice(device);
}
```

因此网格应在连线和节点之前绘制，作为最底层视觉元素。

### 4.3 当前画布尺寸

当前 `GetEffectiveCanvasSize()` 只根据节点右侧和底部扩展：

```csharp
var right = currentMap.Devices.Max(device => device.X + DeviceWidth + ViewPadding);
var bottom = currentMap.Devices.Max(device => device.Y + DeviceHeight + ViewPadding);
return (Math.Max(width, right), Math.Max(height, bottom));
```

这说明当前画布不是固定死大小，但只向右下扩展。

### 4.4 当前浏览适配范围

当前 `TryGetContentBounds()` 根据节点内容计算矩形：

```csharp
left, top, right, bottom
```

然后 `FitMapToView()` 将该矩形传给：

```csharp
FactoryMapViewportFitCalculator.Calculate(...)
```

本次需要在浏览模式下将该内容矩形扩展成正方形再适配。

## 5. 推荐设计

### 5.1 网格只在编辑模式显示

规则：

- `isEditMode == true`：显示网格。
- `isEditMode == false`：隐藏网格。

理由：

- 编辑模式下，网格是对齐辅助。
- 浏览模式下，网格会干扰工序连线和节点阅读。

### 5.2 网格单位

网格单位：

```text
小网格：10px
主网格：50px
```

对应：

```csharp
SmallGridSize = SnapGridSize
MajorGridSize = SnapGridSize * 5
```

这样网格和吸附算法天然一致。

### 5.3 网格颜色

基于当前画布背景：

```text
画布背景：#EEF2F7
```

推荐：

```text
小网格线：#E5EAF1
主网格线：#D7DEE8
```

连线当前为：

```text
#94A3B8
```

因此连线明显强于网格，用户不会把网格误认为工序连线。

### 5.4 网格渲染层级

层级必须是：

```text
画布底色
↓
网格线
↓
工序连线
↓
节点
↓
选中/高亮态
```

实现上应在 `RenderCurrentMap()` 中：

```csharp
MapCanvas.Children.Clear();
DrawGridIfNeeded();
DrawEdge(...);
DrawDevice(...);
```

### 5.5 网格渲染范围

第一阶段不做无限网格。

网格只绘制当前 `MapCanvas.Width` 和 `MapCanvas.Height` 范围。

这意味着：

- 画布多大，网格画多大。
- 画布动态扩展后，重新渲染时网格也跟着扩展。
- 不创建无限数量的 Line 元素。

### 5.6 编辑缓冲区

编辑模式下，画布右侧和底部应增加更大的可操作缓冲区。

建议新增常量：

```csharp
private const double EditCanvasBuffer = 500;
```

`GetEffectiveCanvasSize()` 中：

- 如果无节点，仍使用默认大小。
- 如果有节点：
  - 普通基础尺寸仍取 `currentMap.Canvas.Width/Height` 或默认 580x360。
  - 右侧范围使用 `right + EditCanvasBuffer`。
  - 底部范围使用 `bottom + EditCanvasBuffer`。

示意：

```csharp
var right = currentMap.Devices.Max(device => device.X + DeviceWidth);
var bottom = currentMap.Devices.Max(device => device.Y + DeviceHeight);
var buffer = isEditMode ? EditCanvasBuffer : ViewPadding;
return (Math.Max(width, right + buffer), Math.Max(height, bottom + buffer));
```

注意：

- 第一阶段不支持负坐标，因此左上仍然从 0,0 开始。
- 只增加右侧和底部空间。
- 不改保存格式。

### 5.7 浏览模式正方形适配

浏览模式下，`FitMapToView()` 应使用正方形 bounds。

建议新增方法：

```csharp
private static WpfRect ToSquareBounds(WpfRect bounds, double padding)
```

逻辑：

1. 计算节点内容 bounds 的中心点。
2. 宽高取最大值。
3. 加上适当 padding。
4. 以中心点扩展为正方形。

示意：

```csharp
var side = Math.Max(bounds.Width, bounds.Height) + padding * 2;
var centerX = bounds.Left + bounds.Width / 2;
var centerY = bounds.Top + bounds.Height / 2;
return new WpfRect(centerX - side / 2, centerY - side / 2, side, side);
```

应用规则：

- 浏览模式：使用正方形 bounds。
- 编辑模式：使用原始内容 bounds，避免编辑时视图被强行重构。

### 5.8 编辑模式切换时刷新

切换编辑模式时需要刷新地图显示：

- 进入编辑模式：显示网格，并扩展画布缓冲区。
- 退出编辑模式：隐藏网格，并按节点正方形范围重新适配浏览视图。

建议：

```csharp
UpdateEditModeVisual();
RenderCurrentMap(resetView: false);
if (!isEditMode)
{
    RequestFitMapToView();
}
```

具体实现需结合现有 `EditModeButton_Click` 逻辑，避免破坏用户已有视图状态。

## 6. 性能要求

### 6.1 控制网格线数量

网格绘制不能无限生成 Line。

建议保护：

```csharp
private const int MaxGridLineCount = 2000;
```

如果当前画布尺寸导致网格线超过上限：

- 可以跳过小网格，只绘制主网格。
- 或直接不绘制网格。

推荐第一阶段：

```text
优先绘制主网格，网格线总数不得超过上限。
```

### 6.2 不做每帧重绘

网格只在以下时机重绘：

- 地图首次渲染。
- 切换编辑模式。
- 节点拖拽结束导致地图重新渲染。
- 导入图文件或刷新地图。

不要在鼠标移动过程中反复重绘网格。

### 6.3 缩放和平移不重绘

网格作为 `MapCanvas` 子元素，随现有 `ScaleTransform` 和 `TranslateTransform` 变化。

滚轮缩放、拖拽平移只改变 transform，不重绘网格。

## 7. 行为要求

### 7.1 编辑模式

进入编辑模式后：

- 显示淡网格。
- 节点拖拽结束后仍按 10px 吸附。
- 节点左上角与网格对齐。
- 右侧和底部有更大的操作空间。
- 连线仍然清楚可见。

### 7.2 浏览模式

进入浏览模式后：

- 隐藏网格。
- 地图按节点内容正方形范围适配。
- 节点和连线是视觉主体。
- 不显示大范围空白编辑区域。

### 7.3 无节点

如果地图无节点：

- 使用默认画布尺寸。
- 编辑模式可显示默认范围网格。
- 浏览模式使用默认画布范围适配。

### 7.4 极大地图

如果节点被拖得很远，导致画布很大：

- 程序不能卡死。
- 网格线数量超过上限时，应降低网格绘制密度或跳过网格。
- 节点和连线仍正常渲染。

## 8. 测试建议

建议新增或调整测试：

1. 网格对齐尺寸测试：
   - `SnapGridSize` 与网格小格尺寸一致。

2. 正方形 bounds 测试：
   - 宽大于高时扩展高度。
   - 高大于宽时扩展宽度。
   - 中心点保持不变。

3. 编辑画布缓冲区测试：
   - 有节点时画布尺寸至少包含节点右下边界 + 编辑缓冲区。

4. 构建与回归：

```powershell
dotnet test .\VSLoader.sln -c Debug --no-restore
dotnet build .\VSLoader.sln -c Debug --no-restore
```

手动验证：

- 打开地图，浏览模式没有网格。
- 切换编辑模式，出现淡网格。
- 拖动节点后节点落在网格线上。
- 连线不会和网格混淆。
- 退出编辑模式后视图自动回到正方形适配范围。
- 大地图不会因为网格渲染明显卡顿。
