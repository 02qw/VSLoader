# v2 正则模板匹配编码规格说明

## 1. 文档目的

本文档用于指导编程 agent 或开发人员在当前 VSLoader 项目中扩展“批量新增识别”功能，实现可自定义正则规则的模板自动匹配能力。

v2 必须兼容 v1 已有 CSV 规则，不破坏当前 `Contains` 规则。

## 2. 用户确认的实现选择

| 项目 | 选择 |
| --- | --- |
| CSV 结构 | 保留现有表头，新增 `MatchType=Regex` |
| 模板数字捕获组 | 支持 `{Group1}`、`{Group2}`、`{Group3}` |
| 模板命名捕获组 | 支持 `{Code}`、`{Type}`、`{No}` 等命名组 |
| 正则大小写 | 忽略大小写 |
| 与 `Contains` 关系 | `Contains` 和 `Regex` 共存 |
| 正则规则错误 | 跳过错误规则，在预览中显示 `规则错误` |

## 3. CSV 格式

v2 继续使用 v1 的 CSV 表头：

```csv
MatchType,Pattern,DisplayName,NameTemplate
```

字段含义：

| 字段 | 说明 |
| --- | --- |
| `MatchType` | 匹配方式，支持 `Contains` 和 `Regex` |
| `Pattern` | `Contains` 时是关键字，`Regex` 时是正则表达式 |
| `DisplayName` | 显示名称 |
| `NameTemplate` | 生成快捷项名称的模板 |

## 4. MatchType 规则

### 4.1 Contains

保持 v1 行为不变。

示例：

```csv
MatchType,Pattern,DisplayName,NameTemplate
Contains,TSSM,xxx,{DisplayName}_{FolderName}
```

文件夹：

```text
8812_TSSM001
```

生成：

```text
xxx_8812_TSSM001
```

### 4.2 Regex

新增 `Regex` 匹配方式。

示例：

```csv
MatchType,Pattern,DisplayName,NameTemplate
Regex,^(\d+)_(TSSM)(\d+)$,xxx,{DisplayName}_{Group1}_{Group3}
```

文件夹：

```text
8812_TSSM001
```

正则捕获：

| 捕获组 | 值 |
| --- | --- |
| `{Group1}` | `8812` |
| `{Group2}` | `TSSM` |
| `{Group3}` | `001` |

生成：

```text
xxx_8812_001
```

## 5. 模板变量

v2 模板支持以下变量。

### 5.1 通用变量

`Contains` 和 `Regex` 都支持：

| 变量 | 含义 |
| --- | --- |
| `{DisplayName}` | CSV 中的 `DisplayName` |
| `{FolderName}` | 原始文件夹名称 |

### 5.2 Regex 数字捕获组变量

仅 `Regex` 支持：

```text
{Group1}
{Group2}
{Group3}
...
```

规则：

- `{Group1}` 对应正则第 1 个捕获组。
- `{Group2}` 对应正则第 2 个捕获组。
- 以此类推。
- `{Group0}` 不支持。
- 如果模板引用了不存在的数字捕获组，该预览项状态为 `规则错误`。

示例：

```csv
Regex,^(\d+)_(TSSM)(\d+)$,测试站,{DisplayName}_{Group1}_{Group3}
```

文件夹：

```text
8812_TSSM001
```

生成：

```text
测试站_8812_001
```

### 5.3 Regex 命名捕获组变量

仅 `Regex` 支持：

```text
{Code}
{Type}
{No}
```

变量名来自正则表达式中的命名捕获组。

示例：

```csv
Regex,^(?<Code>\d+)_(?<Type>TSSM)(?<No>\d+)$,测试站,{DisplayName}_{Code}_{No}
```

文件夹：

```text
8812_TSSM001
```

捕获结果：

| 命名组 | 值 |
| --- | --- |
| `{Code}` | `8812` |
| `{Type}` | `TSSM` |
| `{No}` | `001` |

生成：

```text
测试站_8812_001
```

如果模板引用了不存在的命名捕获组，该预览项状态为：

```text
规则错误
```

## 6. 匹配顺序

v2 继续沿用 v1 的顺序匹配规则：

- 程序从 CSV 第一条规则开始向下匹配。
- 一个文件夹命中第一条规则后，不再继续匹配后续规则。
- `Contains` 和 `Regex` 按 CSV 行顺序混合匹配。
- 匹配忽略大小写。

示例：

```csv
MatchType,Pattern,DisplayName,NameTemplate
Contains,TSS,大类,{DisplayName}_{FolderName}
Regex,^(\d+)_(TSSM)(\d+)$,具体类,{DisplayName}_{Group1}_{Group3}
```

文件夹：

```text
8812_TSSM001
```

会先命中 `Contains,TSS`，生成：

```text
大类_8812_TSSM001
```

不会继续执行下面的 Regex 规则。

如果希望 Regex 规则优先生效，应把 Regex 写在前面：

```csv
MatchType,Pattern,DisplayName,NameTemplate
Regex,^(\d+)_(TSSM)(\d+)$,具体类,{DisplayName}_{Group1}_{Group3}
Contains,TSS,大类,{DisplayName}_{FolderName}
```

## 7. 示例 CSV

### 7.1 基础兼容示例

```csv
MatchType,Pattern,DisplayName,NameTemplate
Contains,TSSM,xxx,{DisplayName}_{FolderName}
Regex,^(\d+)_(TRSM)(\d+)$,trsm,{DisplayName}_{Group1}_{Group3}
```

### 7.2 命名捕获组示例

```csv
MatchType,Pattern,DisplayName,NameTemplate
Regex,^(?<Code>\d+)_(?<Type>TSSM)(?<No>\d+)$,测试站,{DisplayName}_{Code}_{No}
Regex,^(?<Code>\d+)_(?<Type>TSSP)(?<No>\d+)$,探针站,{DisplayName}_{Code}_{No}
```

识别结果：

| 文件夹名 | 生成名称 |
| --- | --- |
| `8812_TSSM001` | `测试站_8812_001` |
| `3134_TSSP001` | `探针站_3134_001` |

### 7.3 保留原文件夹名示例

```csv
MatchType,Pattern,DisplayName,NameTemplate
Regex,^(?<Code>\d+)_(?<Type>TSSM)(?<No>\d+)$,测试站,{DisplayName}_{FolderName}
```

文件夹：

```text
8812_TSSM001
```

生成：

```text
测试站_8812_TSSM001
```

## 9. BatchImportService 修改规格

### 9.1 LoadRules

当前规则校验中 `MatchType` 只允许 `Contains`。

v2 修改为允许：

```text
Contains
Regex
```

如果 `MatchType=Regex`：

- 必须尝试编译 `Pattern`。
- 编译使用 `RegexOptions.IgnoreCase`。
- 如果正则表达式语法错误，该规则不加入有效规则。
- 错误信息加入 `errors`，后续在预览中显示为 `规则错误`。

### 9.2 BuildPreview

当前匹配逻辑只做：

```csharp
folderName.Contains(rule.Pattern, StringComparison.OrdinalIgnoreCase)
```

v2 需要改成：

- `Contains`：保持原逻辑。
- `Regex`：使用正则匹配 `folderName`。

建议内部建立匹配结果对象，例如：

```csharp
private sealed class RuleMatchResult
{
    public bool Success { get; init; }
    public BatchImportRule? Rule { get; init; }
    public Match? RegexMatch { get; init; }
    public string? ErrorMessage { get; init; }
}
```

匹配成功后：

- `Contains` 只替换 `{DisplayName}` 和 `{FolderName}`。
- `Regex` 除了替换通用变量，还要替换数字捕获组和命名捕获组。

### 9.3 GenerateName

当前 `GenerateName` 只支持：

```text
{DisplayName}
{FolderName}
```

v2 需要支持：

```text
{Group1}
{Group2}
...
{命名捕获组}
```

建议方法签名改为：

```csharp
private static string GenerateName(
    BatchImportRule rule,
    string folderName,
    Match? regexMatch,
    out string? errorMessage)
```

规则：

- 先替换 `{DisplayName}`。
- 再替换 `{FolderName}`。
- 如果是 Regex 匹配，再替换捕获组变量。
- 如果模板中仍存在无法识别的 `{xxx}`，返回错误。
- 错误项预览状态为 `规则错误`。

## 10. 捕获组替换规则

### 10.1 数字捕获组

使用正则匹配结果：

```text
match.Groups[1]
match.Groups[2]
```

模板：

```text
{Group1}
```

对应：

```text
match.Groups[1].Value
```

如果：

- 组编号不存在
- 组未成功匹配

则预览状态为：

```text
规则错误
```

说明：

```text
模板引用了不存在或未匹配的捕获组：Group1
```

### 10.2 命名捕获组

模板中的 `{Code}` 对应：

```csharp
match.Groups["Code"].Value
```

如果：

- 命名组不存在
- 命名组未成功匹配

则预览状态为：

```text
规则错误
```

说明：

```text
模板引用了不存在或未匹配的捕获组：Code
```

### 10.3 未识别变量

如果模板中出现：

```text
{Unknown}
```

且它不是：

- `DisplayName`
- `FolderName`
- 合法数字捕获组
- 合法命名捕获组

则预览状态为：

```text
规则错误
```

```

```

## 12. 错误处理

| 场景 | 处理方式 |
| --- | --- |
| Regex 语法错误 | 跳过该规则，预览显示 `规则错误` |
| Regex 不匹配文件夹名 | 继续尝试下一条规则 |
| 模板引用不存在的数字组 | 该文件夹预览项显示 `规则错误` |
| 模板引用不存在的命名组 | 该文件夹预览项显示 `规则错误` |
| 模板变量无法识别 | 该文件夹预览项显示 `规则错误` |
| 生成名称为空 | 该文件夹预览项显示 `规则错误` |
| 生成名称重复 | 该文件夹预览项显示 `名称重复` |

## 13. 验收标准

- v1 `Contains` CSV 仍然可以正常使用。
- CSV 中可以同时存在 `Contains` 和 `Regex`。
- `Regex,^(\d+)_(TSSM)(\d+)$,xxx,{DisplayName}_{Group1}_{Group3}` 可以把 `8812_TSSM001` 生成为 `xxx_8812_001`。
- `Regex,^(?<Code>\d+)_(?<Type>TSSM)(?<No>\d+)$,测试站,{DisplayName}_{Code}_{No}` 可以把 `8812_TSSM001` 生成为 `测试站_8812_001`。
- Regex 匹配忽略大小写。
- Regex 语法错误不会导致程序崩溃。
- Regex 语法错误规则在预览中显示为 `规则错误`。
- 模板引用不存在的捕获组时，该文件夹预览项显示 `规则错误`。
- 未匹配任何规则的文件夹仍显示为 `已跳过`。
- 重名项目仍显示为 `名称重复`。
- `dotnet build .\VSLoader.sln` 必须通过。
