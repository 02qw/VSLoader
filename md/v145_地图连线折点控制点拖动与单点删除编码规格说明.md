# v145 地图连线折点控制点拖动与单点删除编码规格说明

## 1. 背景

v143 已完成连线折点的数据模型、保存加载和渲染基础：

```text
FactoryMapDeviceEdge 支持 Points。
FactoryMapDeviceEdgeViewData 支持 Points。
factory-map.layout.json 可以保存/加载 points。
FactoryMapWindow 渲染时优先使用手动 points。
旧连线没有 points 时仍保持原自动中折线。
```

v144 已完成连线右键菜单的基础编辑能力：

```text
右键连线 -> 添加折点。
右键连线 -> 清除折点。
右键连线 -> 删除连线。
添加折点会按 10px 网格吸附并插入最近线段。
添加/清除折点后会保存布局并重新渲染。
```

当前还缺少一个关键交互：

```text
用户可以添加折点，但不能直接看见折点控制点，也不能拖动折点微调路径。
```

本阶段目标是补上“可视化编辑折点”的基础体验，让用户能够手动构造一对多、多对一场景下的视觉分叉/汇流路径。

## 2. 本阶段目标

本阶段实现：

```text
1. 编辑模式下点击连线可以选中该连线。
2. 选中连线后显示该连线的折点控制点。
3. 控制点只对应 edge.Points 中的手动折点，不显示起点/终点控制点。
4. 用户按住控制点拖动时，实时更新该折点坐标并重绘连线。
5. 拖动结束后按 10px 网格吸附并保存布局。
6. 右键折点控制点可以删除单个折点。
7. 删除单个折点后保存布局并重新渲染。
```

本阶段不做：

```text
1. 不做自动分叉/汇流识别。
2. 不做自动避障。
3. 不做连线端口选择。
4. 不做多个折点批量选择。
5. 不做折点对齐辅助线。
6. 不做“对齐到同一分叉点/汇流点”。
7. 不改变节点拖动、框选、多选、地图平移缩放的现有逻辑。
```

## 4. 交互设计

### 4.1 选中连线

编辑模式下，用户左键点击某条连线时：

```text
1. 将该连线记录为 selectedEdge。
2. 清除 pendingConnectionStart。
3. 不清除 selectedDevices，除非当前不是多选模式。
4. 重新渲染地图。
5. 状态栏提示“已选中连线，可拖动折点调整路径。”
```

说明：

```text
连线选中只是为了显示折点控制点。
不引入复杂的连线多选状态。
同一时间只允许一条 selectedEdge。
```

### 4.2 显示折点控制点

当满足以下条件时显示折点控制点：

```text
1. isEditMode == true。
2. selectedEdge 不为空。
3. selectedEdge.Points 有有效折点。
```

显示规则：

```text
1. 每个有效 FactoryMapPoint 显示一个小圆形控制点。
2. 控制点位于 MapCanvas 坐标系。
3. 控制点渲染在连线之上、节点之下或节点之上都可以，但必须可点击。
4. 控制点大小建议 10px 到 12px。
5. 控制点颜色使用现代蓝色或白底蓝边，不使用突兀的红色。
6. 鼠标悬停时 cursor 使用 SizeAll 或 Hand。
```

推荐视觉：

```text
普通状态：白色填充 + 蓝色边框。
悬停/拖动状态：蓝色填充 + 白色边框。
```

### 4.3 拖动折点

用户按住折点控制点左键拖动：

```text
1. 进入 isDraggingEdgePoint 状态。
2. 记录 activeEdgePointEdge。
3. 记录 activeEdgePointIndex。
4. CaptureMouse。
5. 鼠标移动时将当前位置转换成 MapCanvas 坐标。
6. 拖动过程中实时更新 edge.Points[index]。
7. 拖动过程中实时 RenderCurrentMap(resetView: false)。
8. 拖动过程中不保存布局。
```

拖动结束：

```text
1. ReleaseMouseCapture。
2. 对最终坐标执行 SnapEdgePointToGrid。
3. 更新 edge.Points[index]。
4. RenderCurrentMap(resetView: false)。
5. 调用 saveLayout(currentMap)。
6. 保存成功提示“折点已移动，地图布局已保存。”
7. 保存失败提示“折点已移动，但地图布局保存失败。”
8. 清空拖动状态。
```

### 4.4 删除单个折点

用户右键某个折点控制点：

```text
1. 弹出控制点右键菜单。
2. 菜单包含“删除折点”。
3. 点击后删除 edge.Points[index]。
4. 如果删除后 edge.Points 为空，连线恢复默认自动路径。
5. RenderCurrentMap(resetView: false)。
6. saveLayout(currentMap)。
7. 保存成功提示“折点已删除。”
8. 保存失败提示“折点已删除，但地图布局保存失败。”
```

说明：

```text
本阶段不做确认弹窗。
删除单个折点是轻量编辑动作，误删后用户可以右键连线重新添加折点。
```

### 4.5 退出编辑状态时的行为

当用户关闭编辑模式时：

```text
1. 清空 selectedEdge。
2. 清空折点拖动状态。
3. 不显示折点控制点。
4. 保留连线本身的 Points 数据。
```

### 4.6 连线删除后的行为

当删除 selectedEdge 本身时：

```text
1. 如果被删除连线等于 selectedEdge，则 selectedEdge = null。
2. 清空折点拖动状态。
3. RenderCurrentMap(resetView: false)。
```

## 5. 状态模型

在 `FactoryMapWindow.xaml.cs` 中新增私有字段：

```csharp
private FactoryMapDeviceEdgeViewData? selectedEdge;
private FactoryMapDeviceEdgeViewData? activeEdgePointEdge;
private int activeEdgePointIndex = -1;
private bool isDraggingEdgePoint;
```

建议新增内部 payload：

```csharp
private sealed record EdgePointHandlePayload(
    FactoryMapDeviceEdgeViewData Edge,
    int PointIndex);
```

字段含义：

```text
selectedEdge：当前被选中的连线，用于决定显示哪条线的折点控制点。
activeEdgePointEdge：当前正在拖动折点所属连线。
activeEdgePointIndex：当前正在拖动 edge.Points 中的索引。
isDraggingEdgePoint：当前是否正在拖动折点。
```

边界要求：

```text
1. activeEdgePointIndex 必须每次使用前检查范围。
2. 如果 edge.Points 被清空或删除，拖动状态必须清空。
3. RenderCurrentMap 会重建 UI 元素，因此拖动过程中要谨慎处理 CaptureMouse。
```

## 6. 渲染结构

### 6.1 RenderCurrentMap 调整

当前顺序大致为：

```text
清空 MapCanvas。
绘制网格。
绘制连线。
绘制设备节点。
更新状态栏。
```

本阶段建议调整为：

```text
清空 MapCanvas。
绘制网格。
绘制连线。
绘制折点控制点。
绘制设备节点。
更新状态栏。
```

或者：

```text
清空 MapCanvas。
绘制网格。
绘制连线。
绘制设备节点。
绘制折点控制点。
更新状态栏。
```

推荐第二种：

```text
折点控制点在最上层，便于点击和拖动。
```

注意：

```text
控制点可能落在节点附近时，显示在最上层更容易编辑。
```

### 6.2 新增 DrawSelectedEdgePointHandles

新增方法：

```csharp
private void DrawSelectedEdgePointHandles()
```

行为：

```text
1. 如果 !isEditMode，return。
2. 如果 selectedEdge is null，return。
3. 遍历 selectedEdge.Points。
4. 只为有效点创建控制点。
5. 控制点 Tag 设置为 EdgePointHandlePayload(edge, index)。
6. 绑定 MouseLeftButtonDown、MouseMove、MouseLeftButtonUp、PreviewMouseRightButtonDown。
```

控制点元素建议使用：

```csharp
Ellipse
```

建议尺寸：

```csharp
private const double EdgePointHandleSize = 12;
```

定位：

```csharp
Canvas.SetLeft(handle, point.X - EdgePointHandleSize / 2);
Canvas.SetTop(handle, point.Y - EdgePointHandleSize / 2);
```

## 7. 鼠标事件实现

### 7.1 连线左键选中

当前 `DrawEdge` 中已有透明命中线 `hitPolyline`，当前绑定右键：

```csharp
hitPolyline.PreviewMouseRightButtonDown += Edge_PreviewMouseRightButtonDown;
```

本阶段新增：

```csharp
hitPolyline.PreviewMouseLeftButtonDown += Edge_PreviewMouseLeftButtonDown;
```

新增方法：

```csharp
private void Edge_PreviewMouseLeftButtonDown(object sender, MouseButtonEventArgs e)
```

逻辑：

```text
1. 非编辑模式 return。
2. 如果 sender.Tag 不是 FactoryMapDeviceEdgeViewData，return。
3. selectedEdge = edge。
4. ClearPendingConnectionStart。
5. 如果不是多选模式，可保留 selectedDevices，不强制清空，避免影响用户节点选择。
6. RenderCurrentMap(resetView: false)。
7. SetStatusText("已选中连线，可拖动折点调整路径。")
8. e.Handled = true。
```

### 7.2 控制点左键按下

新增方法：

```csharp
private void EdgePointHandle_MouseLeftButtonDown(object sender, MouseButtonEventArgs e)
```

逻辑：

```text
1. 非编辑模式 return。
2. 从 Tag 获取 EdgePointHandlePayload。
3. 检查 payload.PointIndex 是否在 edge.Points 范围内。
4. selectedEdge = payload.Edge。
5. activeEdgePointEdge = payload.Edge。
6. activeEdgePointIndex = payload.PointIndex。
7. isDraggingEdgePoint = true。
8. CaptureMouse。
9. e.Handled = true。
```

### 7.3 控制点拖动

新增方法：

```csharp
private void EdgePointHandle_MouseMove(object sender, WpfMouseEventArgs e)
```

逻辑：

```text
1. 如果 !isDraggingEdgePoint，return。
2. 如果 activeEdgePointEdge is null，结束拖动状态。
3. 如果 activeEdgePointIndex 越界，结束拖动状态。
4. 如果 e.LeftButton != Pressed，调用 EndEdgePointDrag。
5. var point = e.GetPosition(MapCanvas)。
6. 实时更新 activeEdgePointEdge.Points[activeEdgePointIndex].X/Y。
7. RenderCurrentMap(resetView: false)。
8. e.Handled = true。
```

注意：

```text
拖动过程中不做网格吸附，保证跟手。
拖动结束后再吸附，减少拖动顿挫。
```

### 7.4 控制点左键释放

新增方法：

```csharp
private void EdgePointHandle_MouseLeftButtonUp(object sender, MouseButtonEventArgs e)
```

逻辑：

```text
1. 如果 !isDraggingEdgePoint，return。
2. 调用 EndEdgePointDrag(save: true)。
3. e.Handled = true。
```

### 7.5 结束拖动

新增方法：

```csharp
private void EndEdgePointDrag(bool save)
```

逻辑：

```text
1. 保存局部 edge/index。
2. 清空 isDraggingEdgePoint、activeEdgePointEdge、activeEdgePointIndex。
3. ReleaseMouseCapture。
4. 如果 save == false，return。
5. 如果 currentMap is null，return。
6. 如果 edge/index 无效，return。
7. 对 edge.Points[index] 执行 SnapEdgePointToGrid。
8. RenderCurrentMap(resetView: false)。
9. saveLayout(currentMap)。
10. 保存成功/失败给出提示。
```

### 7.6 鼠标离开或失焦

地图已有 MouseUp / MouseMove / LostMouseCapture 类似处理时，应补充折点拖动状态。

如果当前文件已有：

```csharp
MapViewport_MouseLeftButtonUp
MapViewport_MouseMove
MapViewport_MouseLeave
```

则在这些入口中优先处理：

```text
if (isDraggingEdgePoint)
{
    EndEdgePointDrag(save: true);
    return;
}
```

要求：

```text
折点拖动不能卡在 isDraggingEdgePoint=true。
```

样式：


删除逻辑：

```text

2. 检查 currentMap。

4. edge.Points.RemoveAt(index)。
```

```text

```

## 9. 保存策略

### 9.1 拖动中不保存

拖动过程中只更新内存和渲染：

```text
MouseMove -> 更新 point -> RenderCurrentMap(false)
```

不调用：

```text
saveLayout(currentMap)
```

原因：

```text
每一帧保存 JSON 会造成卡顿和文件写入压力。
```

### 9.2 拖动结束后保存一次

拖动结束：

```text
MouseLeftButtonUp / 鼠标丢失 / 左键不再按下 -> Snap -> Render -> Save
```

### 9.3 保存失败不回滚

保持与 v144 一致：

```text
内存先更新。
保存失败时弹窗提示。
不自动回滚。
```

原因：

```text
当前节点移动、添加折点、删除连线也采用此策略。
保持行为一致。
```

## 10. 性能与稳定性边界

### 10.1 控制点数量

单条连线折点数量通常很少。

本阶段不设置硬上限，但渲染时必须：

```text
1. 跳过 NaN / Infinity。
2. pointIndex 必须对应原始 edge.Points 的真实 index。
3. 不为无效点创建控制点。
```

### 10.2 拖动重绘频率

本阶段允许每次 MouseMove 调用：

```csharp
RenderCurrentMap(resetView: false)
```

原因：

```text
地图节点数量和折点数量通常不大。
实现简单，和现有节点拖动重绘模式一致。
```

如果后续出现卡顿，再做局部更新优化。

### 10.3 RenderCurrentMap 重建控制点导致 CaptureMouse 丢失

这是本阶段最需要注意的 WPF 边界。

推荐策略：

```text
1. 控制点 MouseMove 中更新数据后 RenderCurrentMap。
2. Render 后旧 handle 可能被移除。
3. 因此也应在 MapViewport_MouseMove 中补充 isDraggingEdgePoint 的拖动处理。
4. activeEdgePointEdge/index 保存在窗口字段中，不依赖旧控件实例。
```

也就是说：

```text
控制点开始拖动后，后续移动逻辑可以由 MapViewport_MouseMove 继续接管。
```

### 10.4 与地图平移冲突

如果 isDraggingEdgePoint 为 true：

```text
MapViewport_MouseMove 不应进入地图平移逻辑。
MapViewport_MouseLeftButtonUp 应优先结束折点拖动。
```

优先级：

```text
折点拖动 > 节点框选 > 多节点拖动 > 单节点拖动 > 地图平移
```

### 10.5 与连线模式冲突

如果 isConnectMode 为 true：

```text
点击连线仍可选中连线，但不建议显示折点拖动控制点。
```

本阶段推荐规则：

```text
只有 isEditMode == true 且 isConnectMode == false 时显示折点控制点。
```

原因：

```text
连线模式下用户主要任务是点设备建线。
显示折点控制点会增加误触。
```

### 10.6 与多选模式冲突

如果 isMultiSelectMode 为 true：

```text
折点控制点仍可拖动。
空白区域拖动仍用于框选节点。
```

点击控制点时：

```text
控制点事件 e.Handled = true，避免触发框选。
```

## 14. 验收清单

人工验收时按以下流程：

```text
1. 打开 VSLoader。
2. 打开工厂地图。
3. 进入编辑模式。
4. 右键一条连线，添加两个折点。
5. 左键点击该连线。
6. 确认能看到两个折点控制点。
7. 拖动其中一个折点，确认连线实时变化。
8. 松开鼠标，确认折点吸附到网格。
9. 关闭地图后重新打开，确认折点位置已保存。
10. 右键某个折点，点击删除折点。
11. 确认只删除该折点，不删除整条线。
12. 删除最后一个折点后，确认连线恢复自动路径。
13. 退出编辑模式，确认控制点消失。
```
