# v35 批量新增预览状态优先排序编码规格说明

## 1. 需求背景

当前 `批量新增识别` 独立窗口点击 `扫描预览` 后，预览列表会展示扫描结果。

预览结果状态包括：

```text
可新增
已跳过
名称重复
规则错误
```

当前列表排序主要按照：

```text
规则顺序 -> 机器编号 -> 生成名称
```

当扫描目录中已有大量快捷项时，`名称重复` 数量会很多，容易占据列表前部，导致真正需要用户关注的项目不容易看到。

用户希望：

```text
可新增 / 已跳过 / 规则错误 等需要关注的项目放在最前面。
名称重复放在最后。
```

## 2. 需求目标

本次开发目标：

1. 扫描预览结果按状态优先级排序。
2. `可新增` 排在最前面。
3. `已跳过` 排在 `可新增` 后面。
4. `规则错误` 排在 `已跳过` 后面。
5. `名称重复` 排在最后。
6. 每个状态组内部仍保留原有排序逻辑。
7. 不改变扫描逻辑。
8. 不改变匹配规则逻辑。
9. 不改变重复判断逻辑。
10. 不改变勾选逻辑。
11. 不改变最终确认新增逻辑。

## 4. 状态优先级规则

新增状态排序优先级：

```text
0: 可新增
1: 已跳过
2: 规则错误
3: 名称重复
4: 其他未知状态
```

对应当前常量：

```csharp
public const string StatusImportable = "可新增";
public const string StatusSkipped = "已跳过";
public const string StatusDuplicate = "名称重复";
public const string StatusRuleError = "规则错误";
```

排序优先级：

```csharp
private static int GetPreviewStatusSortPriority(string status)
{
    return status switch
    {
        StatusImportable => 0,
        StatusSkipped => 1,
        StatusRuleError => 2,
        StatusDuplicate => 3,
        _ => 4
    };
}
```

## 5. 推荐排序实现

将当前排序：

```csharp
return items
    .OrderBy(item => item.SortRuleIndex)
    .ThenBy(item => item.SortNo ?? int.MaxValue)
    .ThenBy(item => item.SortName, StringComparer.CurrentCultureIgnoreCase)
    .ToList();
```

修改为：

```csharp
return items
    .OrderBy(item => GetPreviewStatusSortPriority(item.Status))
    .ThenBy(item => item.SortRuleIndex)
    .ThenBy(item => item.SortNo ?? int.MaxValue)
    .ThenBy(item => item.SortName, StringComparer.CurrentCultureIgnoreCase)
    .ToList();
```

说明：

- 第一层按状态排序。
- 后续仍保留原有规则内排序。
- 不破坏 v3 中“同类机器聚集展示”的排序效果。
- `名称重复` 会整体沉到底部。

## 6. 状态组内部排序

状态组内部继续使用现有字段：

```text
SortRuleIndex
SortNo
SortName
```

也就是说：

```text
可新增组内部：仍按规则顺序、编号、名称排序
已跳过组内部：仍按现有 SortRuleIndex / SortNo / SortName 排序
规则错误组内部：仍按现有 SortRuleIndex / SortNo / SortName 排序
名称重复组内部：仍按规则顺序、编号、名称排序
```

## 9. 预期效果

扫描完成后列表展示顺序：

```text
可新增
可新增
...
已跳过
已跳过
...
规则错误
规则错误
...
名称重复

...
```

这样用户打开扫描预览后，可以优先看到：

- 能新增的项目
- 没匹配规则的项目
- 规则有问题的项目

大量 `名称重复` 项目会放到列表最后，减少干扰。

## 10. 验收标准

### 10.1 可新增排最前

准备：

扫描结果中同时包含：

```text
可新增
名称重复
```

期望：

```text
所有可新增项位于名称重复项前面。
```

### 10.2 已跳过排在名称重复前

准备：

扫描结果中同时包含：

```text
已跳过
名称重复
```

期望：

```text
已跳过项位于名称重复项前面。
```

### 10.3 规则错误排在名称重复前

准备：

扫描结果中同时包含：

```text
规则错误
名称重复
```

期望：

```text
规则错误项位于名称重复项前面。
```

### 10.4 名称重复排最后

准备：

扫描结果中包含大量 `名称重复`。

期望：

```text
名称重复整体位于列表最后。
```

### 10.5 状态组内部排序不变

准备：

多个 `可新增` 项属于不同规则、不同编号。

期望：

```text
可新增组内部仍按原有规则顺序、编号、名称排序。
```

### 10.6 统计数字不变

操作：

1. 点击 `扫描预览`。

期望：

- `扫描`
- `可新增`
- `已选择`
- `已跳过`
- `名称重复`
- `规则错误`

统计数字与优化前逻辑一致。

### 10.7 编译验收

执行：

```powershell
dotnet build .\VSLoader.sln
```

期望：

```text
0 warnings
0 errors
```

如果提示 `VSLoader.exe` 被占用，说明程序正在运行，应先通过托盘菜单 `退出` 或结束进程后重新构建。
