# v32 自动获取连接后台执行防卡顿优化编码规格说明

## 1. 需求背景

当前点击主界面 `自动获取连接` 后，程序会显示忙碌遮罩、进度条和当前处理进度。

用户反馈：

```text
点击“自动获取连接”后，鼠标会出现卡顿/丢帧现象。
下载完成后又恢复正常。
```

经过代码排查，主要原因不是鼠标钩子，也不是进度条动画本身，而是 AdminUI 下载流程中包含同步文件系统访问：

```csharp
Directory.Exists(shortcut.TargetPath)
File.Exists(propertiesPath)
File.ReadLines(propertiesPath)
```

当快捷项目标路径是网络路径、共享目录、VPN 路径或不可达路径时，这些同步调用可能阻塞当前线程。

当前 `DownloadAdminUiLinksAsync()` 虽然是 `async`，但在调用 `AdminUiService.DownloadAllAsync()` 后，`DownloadAllAsync()` 内部进入真正的网络下载 `await` 之前，仍会同步执行路径检查和 `INSTANCE.properties` 读取。

如果这些同步操作运行在 UI 线程，就会导致界面和鼠标观感卡顿。

## 2. 需求目标

本次开发目标：

1. 保持现有 `自动获取连接` UI 交互不变。
2. 保持现有忙碌遮罩不变。
3. 保持现有进度条不变。
4. 保持现有进度文字不变。
5. 保持现有完成弹窗不变。
6. 保持过程中屏蔽用户操作的逻辑不变。
7. 将耗时的路径检查、properties 读取、URL 拼接、下载和文件写入移到后台线程执行。
8. 避免 UI 线程被网络路径或文件系统同步访问阻塞。
9. 不重构 AdminUI 下载业务逻辑。
10. 不改变配置结构。

## 3. 当前问题代码

主要入口位于：

```text
VSLoader\ViewModels\MainViewModel.cs
```

当前逻辑大致为：

```csharp
var progress = new Progress<AdminUiDownloadProgress>(downloadProgress =>
{
    BusyProgressValue = downloadProgress.CompletedCount;
    BusyProgressMaximum = downloadProgress.TotalCount;
    BusyProgressText = $"当前进度：...";
    BusyCurrentItemText = ...;
});

var result = await _adminUiService.DownloadAllAsync(Shortcuts, _config.AdminUi, progress);
```

问题点：

```csharp
Shortcuts
```

是 WPF 绑定使用的 `ObservableCollection`。

`_config.AdminUi` 是当前 ViewModel 配置对象。

`DownloadAllAsync()` 内部存在同步文件系统访问，如果直接从 UI 线程调用，会让 UI 线程参与执行这些同步操作。

## 4. AdminUiService 中的同步操作

位于：

```text
VSLoader\Models\Services\AdminUiService.cs
```

`DownloadAllAsync()` 内部每个快捷项会调用：

```csharp
var info = ResolveShortcutInfo(shortcut, config);
```

`ResolveShortcutInfo()` 中包含：

```csharp
Directory.Exists(shortcut.TargetPath)
File.Exists(propertiesPath)
File.ReadLines(propertiesPath)
```

这些操作访问网络路径时可能明显变慢。

本次不要求重写这些方法为异步文件 API，而是通过后台线程承载它们，避免阻塞 UI。

## 5. 推荐技术方案

采用最小改动方案：

```text
UI 线程负责：
- 设置 IsBusy
- 显示遮罩
- 显示进度
- 显示完成弹窗
- 最终恢复 UI 状态

后台线程负责：
- 遍历快捷项
- 检查目标路径
- 读取 INSTANCE.properties
- 拼接 AdminUI URL
- 下载 .jnlp
- 写入本地文件
```

使用：

```csharp
Task.Run(...)
```

把下载主流程切换到线程池执行。

## 7. 快照原则

后台线程不应直接遍历 WPF 绑定集合：

```csharp
Shortcuts
```

因此在进入后台线程之前，需要在 UI 线程创建快照：

```csharp
var shortcutSnapshot = Shortcuts.ToList();
```

说明：

- `Shortcuts` 是 `ObservableCollection<ShortcutItem>`。
- 它主要属于 UI 绑定数据。
- 后台线程直接枚举 UI 集合有潜在线程风险。
- 使用 `ToList()` 快照可以避免后台线程访问 UI 集合本体。

## 8. 配置快照

后台线程不应直接使用可能被 UI 后续修改的配置对象。

因此在进入后台线程之前创建 AdminUI 配置快照：

```csharp
var adminUiConfig = _config.AdminUi.Clone();
```

说明：

- `AdminUiConfig.Clone()` 当前已经存在。
- 后台线程使用快照，避免设置窗口未来修改配置时造成状态不一致。

## 9. 推荐代码修改

将当前：

```csharp
var result = await _adminUiService.DownloadAllAsync(Shortcuts, _config.AdminUi, progress);
```

改为：

```csharp
var shortcutSnapshot = Shortcuts.ToList();
var adminUiConfig = _config.AdminUi.Clone();

var result = await Task.Run(async () =>
{
    return await _adminUiService.DownloadAllAsync(shortcutSnapshot, adminUiConfig, progress);
});
```

或更简洁：

```csharp
var result = await Task.Run(() =>
    _adminUiService.DownloadAllAsync(shortcutSnapshot, adminUiConfig, progress)).Unwrap();
```

推荐使用第一种写法，可读性更好。

## 10. Progress 回调保持不变

继续使用：

```csharp
var progress = new Progress<AdminUiDownloadProgress>(downloadProgress =>
{
    BusyProgressValue = downloadProgress.CompletedCount;
    BusyProgressMaximum = downloadProgress.TotalCount;
    BusyProgressText = ...;
    BusyCurrentItemText = ...;
});
```

说明：

- `Progress<T>` 会捕获创建它时的同步上下文。
- 当前它在 UI 线程创建。
- 后台线程调用 `progress.Report(...)` 时，回调会自动回到 UI 线程执行。
- 因此现有进度条和进度文字无需改动。

## 11. TestConnectionAsync 是否后台执行

当前流程中，下载前会执行：

```csharp
var testResult = await _adminUiService.TestConnectionAsync(_config.AdminUi);
```

该方法内部是异步 HTTP 请求：

```csharp
await httpClient.GetAsync(...)
```

它不会像同步文件系统访问那样长期占用 UI 线程。

本次不强制改动该部分。

如需更稳，也可以使用配置快照：

```csharp
var adminUiConfig = _config.AdminUi.Clone();
var testResult = await _adminUiService.TestConnectionAsync(adminUiConfig);
```

并在后续下载中复用同一个 `adminUiConfig`。

推荐做法：

```text
进入 try 后，先创建 adminUiConfig 快照。
TestConnectionAsync 使用 adminUiConfig。
DownloadAllAsync 也使用 adminUiConfig。
```

## 12. 推荐最终流程

`DownloadAdminUiLinksAsync()` 推荐结构：

```csharp
try
{
    IsBusy = true;
    BusyMessage = "...";
    BusyProgressValue = 0;
    BusyProgressMaximum = Shortcuts.Count;
    BusyProgressText = "...";
    BusyCurrentItemText = string.Empty;

    var shortcutSnapshot = Shortcuts.ToList();
    var adminUiConfig = _config.AdminUi.Clone();

    var testResult = await _adminUiService.TestConnectionAsync(adminUiConfig);
    if (!testResult.Success)
    {
        ...
        return;
    }

    var progress = new Progress<AdminUiDownloadProgress>(...);

    var result = await Task.Run(async () =>
    {
        return await _adminUiService.DownloadAllAsync(shortcutSnapshot, adminUiConfig, progress);
    });

    ...
}
finally
{
    IsBusy = false;
    ...
}
```

注意：

- `shortcutSnapshot` 要在 UI 线程创建。
- `adminUiConfig` 要在 UI 线程创建。
- `progress` 要在 UI 线程创建。
- `DownloadAllAsync` 要在 `Task.Run` 里执行。
- `finally` 保持原样，确保 UI 状态恢复。

## 13. 不建议的方案

本次不建议：

```text
大规模重构 AdminUiService 为全异步文件 IO
```

原因：

- `Directory.Exists` 和 `File.Exists` 没有真正异步版本。
- 网络路径不可达时，异步文件 IO 也未必能完全解决等待问题。
- 本需求目标是减少 UI 卡顿，不是改写业务层。

本次不建议：

```text
关闭进度条更新
```

原因：

- 用户需要知道当前下载进度。
- 当前进度频率不算高。
- UI 卡顿主因不是进度回调，而是同步路径访问。

本次不建议：

```text
修改鼠标钩子逻辑
```

原因：

- 鼠标侧键钩子只处理 Mouse4/Mouse5 按下事件。
- 不处理普通鼠标移动。
- 不是本次鼠标移动卡顿的主要原因。
