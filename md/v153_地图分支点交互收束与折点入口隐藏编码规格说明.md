# v153 地图分支点交互收束与折点入口隐藏编码规格说明

## 1. 背景

当前地图连线已经经过多轮改造，具备以下能力：

```text
1. 节点上下左右四个端口连接。
2. 连线可以从端口连接到端口。
3. 地图中存在可见连接点 FactoryMapConnectorViewNode。
4. 连线支持 edge.Points 路径折点。
5. 右键连线可以添加连接点、清除路径折点、删除连线。
```

用户实际体验后反馈：

```text
节点上下左右四个连接触点很好用。
右键菜单里的添加折点 / 路径折点相关功能不好用。
添加折点之后不知道下一步该做什么。
当前状态不是好用的逻辑，人机交互体验差。
```

结合当前代码确认，地图中存在两类容易混淆的中间概念：

```text
折点：edge.Points，只是控制一条线怎么拐弯。
连接点：FactoryMapConnectorViewNode，是可见的小节点，可作为分叉 / 汇流单位。
```

本阶段目标是收束交互模型：

```text
节点四端口负责连接方向。
分支点负责一对多 / 多对一 / 中转。
折点作为内部路径细节，不再暴露给普通用户作为主要操作。
```

## 3. 目标

本阶段目标：

```text
1. 弱化并隐藏普通用户对“折点”的直接操作入口。
2. 将右键连线主操作从“添加连接点”改为更清晰的“插入分支点”。
3. 插入分支点后，让用户明确知道下一步应该从分支点端口继续连线。
4. 保留节点和连接点的上下左右四端口交互。
5. 保留历史地图中 edge.Points 的读取、保存和渲染兼容。
6. 不破坏已有连接点数据和布局文件。
7. 不删除底层折点模型，只从普通 UI 入口中移除或隐藏。
```

用户体验目标：

```text
用户右键一条线。
看到“插入分支点”。
点击后线中间出现一个小分支点。
原来的一条线自动拆成两条线。
分支点被选中，并显示上下左右四个端口。
用户可以继续点击分支点端口连接其他节点。
```

## 4. 非目标

本阶段不做：

```text
1. 不重写地图布局文件格式。
2. 不删除 edge.Points 数据字段。
3. 不删除 FactoryMapOrthogonalPathService。
4. 不实现复杂 UML 自动布线算法。
5. 不做自动避障绕线。
6. 不修改节点四端口几何算法。
7. 不修改地图导入导出全局配置逻辑。
8. 不修改主窗口、工作区、更新器等非地图功能。
```

说明：

```text
折点相关底层能力可以保留给自动路径或后续高级模式。
但普通编辑路径不再把折点作为主要功能暴露给用户。
```

## 5. 正确交互模型

### 5.1 地图连线中的单位

后续地图编辑只向用户强调四类单位：

```text
设备节点：真实业务节点。
分支点：连线上的中转、分叉、汇流节点。
端口：节点 / 分支点上下左右四个连接触点。
连线：两个端口之间的关系。
```

不再向普通用户强调：

```text
折点
路径折点
绕行段
线段控制点
```

### 5.2 分支点语义

分支点对应当前代码中的：

```text
FactoryMapConnectorViewNode
```

显示文案统一使用：

```text
分支点
```

除非内部变量名暂时保留 `Connector`，用户可见文案不再使用“连接点”作为主叫法。

建议：

```text
代码模型名短期可以不改。
UI 文案统一改成“分支点”。
```

### 5.3 折点语义

折点保留为：

```text
内部路径控制数据。
历史布局兼容数据。
自动路径算法输入输出。
```

普通 UI 不再主动展示：

```text
清除路径折点
删除折点
折点已移动
绕行段已添加
```

如果保留历史折点渲染，应只作为线的形态，不要求用户理解它。

## 6. 右键菜单规范

### 6.1 连线右键菜单

当前菜单：

```text
添加连接点
清除路径折点
删除连线
```

应改为：

```text
插入分支点
删除连线
```

顺序：

```text
1. 插入分支点
2. 删除连线
```

说明：

```text
不再显示“清除路径折点”。
删除连线保持危险语义。
```

### 6.2 分支点右键菜单

当前连接点右键菜单：

```text
删除连接点
```

应改为：

```text
删除分支点
```

删除确认文案应改为：

```text
删除该分支点会同时删除所有连接到它的连线，是否继续？
```

删除成功状态文案：

```text
分支点已删除，相关连线已同步删除。
```

### 6.3 折点右键菜单

普通用户不应再看到折点菜单。

处理规则：

```text
不再绘制可交互折点控制点，或至少不再给折点控制点挂右键菜单。
```

建议本阶段采用更彻底、更清晰的方式：

```text
编辑模式下不再调用 DrawSelectedEdgePointHandles。
```

如果考虑历史布局仍需展示折线路径：

```text
edge.Points 继续参与 DrawEdge。
但不显示可拖动折点圆点。
```

## 7. 插入分支点后的行为

### 7.1 基础行为

点击“插入分支点”后：

```text
1. 在用户右键点击位置创建 FactoryMapConnectorViewNode。
2. 坐标按 SnapGridSize 对齐。
3. 从 currentMap.Edges 移除原连线。
4. 新增 原起点 -> 分支点 的连线。
5. 新增 分支点 -> 原终点 的连线。
6. 自动选中新分支点。
7. 清空原连线选择。
8. 清空设备多选。
9. 清空 pendingConnectionStart。
10. 重绘地图。
11. 保存布局。
```

当前 `AddConnectorOnEdge_Click` 已经基本具备以上能力。

### 7.2 新增引导行为

插入分支点后，应明确引导用户下一步。

建议状态提示：

```text
已插入分支点，请点击它的端口继续连接其他节点。
```

建议同时执行：

```text
isConnectMode = true
pendingConnectionStart = null
selectedConnector = connector
UpdateConnectModeVisual()
RefreshMapModeStatus()
RenderCurrentMap(resetView: false)
```

目的：

```text
插入后立即进入可继续连线的上下文。
用户看到分支点四端口，就知道下一步是从端口出线。
```

如果不自动进入连线模式，至少必须高亮分支点端口并给出提示。

本规格推荐：

```text
自动进入连线模式。
```

### 7.3 防重复和边界

插入分支点时必须保持：

```text
如果原连线已经不存在，直接返回。
如果 currentMap 为 null，直接返回。
如果保存失败，弹出错误提示但保持当前编辑结果。
分支点 Id 必须唯一。
分支点坐标不能小于 0。
```

### 8.3 端口显示

保留当前四端口显示逻辑：

```text

```

如果当前端口一直显示导致干扰，可以后续再做“编辑模式 / 连线模式显示策略”优化。
本阶段不强行调整。

## 13. 人工验收

人工检查步骤：

```text

2. 进入编辑模式。
3. 确认节点上下左右四端口仍然可用。

5. 菜单应显示“插入分支点”和“删除连线”。
```

## 14. 风险与边界

### 14.1 旧折点数据

旧布局可能包含：

```text
edge.Points
```

本阶段必须继续兼容。

不能因为隐藏折点入口导致旧地图打不开。

### 14.2 自动进入连线模式

插入分支点后自动进入连线模式可能改变用户习惯。

但这是本阶段推荐行为，因为它能补上用户最困惑的“然后呢”。

如用户后续反馈太主动，可改为：

```text
只选中分支点并显示端口，不自动进入连线模式。
```

### 14.3 内部命名

本阶段不强制将 `Connector` 全部重命名为 `BranchPoint`。

原因：

```text
重命名范围大，容易影响序列化、测试和历史数据。
```

短期策略：

```text
代码内部仍叫 Connector。
用户可见 UI 叫 分支点。
```

## 15. 完成标准

满足以下条件才算完成：

```text
1. 连线右键菜单不再出现折点相关普通入口。
2. 连线右键菜单提供“插入分支点”。
3. 插入分支点后原连线拆分为两条线。
4. 插入后用户能明确继续从分支点四端口连线。
5. 分支点右键菜单使用“删除分支点”文案。
6. 折点数据仍兼容旧布局。
7. 节点和分支点四端口功能不受影响。
8. 地图相关测试通过。
9. Debug 构建通过。
```

本阶段核心原则：

```text
用户只需要理解节点、分支点、端口和连线；不要再让用户理解折点。
```
