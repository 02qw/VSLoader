# v110 设置页输入框文字下沉与现代输入控件模板修复编码规格说明

## 1. 背景

v109 引入了全应用现代化视觉主题：

```text
VSLoader/Styles/ModernTheme.xaml
```

并在设置窗口等页面中使用：

```text
ModernTextBoxStyle
ModernPasswordBoxStyle
ModernReadOnlyTextBoxStyle
```

当前发现设置窗口中的输入框出现明显 UI bug：

- 输入框内文字下沉。
- 部分文字几乎不可见，只剩下点状或上边缘。
- 聚焦状态下问题依旧存在。
- 密码框暂时看起来较轻，但属于同类模板风险。

该问题出现在 v109 UI 重构之后，属于自定义输入控件模板导致的显示异常。

## 2. 目标

修复现代输入控件模板导致的文字下沉问题：

- 设置页所有输入框文字必须垂直居中、完整可见。
- `TextBox`、`PasswordBox`、只读快捷键框都要一起修复。
- 主窗口搜索框、批量新增路径框、快捷项编辑弹窗、工作区命名弹窗不能出现同类问题。
- 保留 v109 的现代化视觉风格。
- 不改变任何业务逻辑、绑定、命令、校验和滚轮转交逻辑。

## 3. 非目标

本次不做：

- 不重新设计设置页布局。
- 不改变设置项字段。
- 不改变配置保存逻辑。
- 不改变快捷键录制逻辑。
- 不改变批量新增、主窗口、地图等业务逻辑。
- 不引入第三方 UI 库。
- 不改变 v109 的整体配色方向。

## 4. 根因分析

当前问题根因位于：

```text
VSLoader/Styles/ModernTheme.xaml
```

当前 `ModernTextBoxStyle` 模板中使用：

```xml
<ScrollViewer x:Name="PART_ContentHost"
              Margin="{TemplateBinding Padding}" />
```

`ModernPasswordBoxStyle` 也有同类写法。

同时设置窗口中大量输入框显式写了：

```xml
Height="30"
Padding="8,4"
```

或使用样式默认：

```xml
Padding="10,6"
```

这会导致：

1. 自定义模板没有正确利用 WPF 默认 `TextBox` 内容布局。
2. `PART_ContentHost` 使用 `Padding` 作为 `Margin` 后压缩可用内容区域。
3. 设置页很多输入框高度只有 30，内容区域进一步不足。
4. `VerticalContentAlignment="Center"` 在当前自定义模板中没有真正控制文本垂直居中。

因此最终表现为文字被挤压、下沉、不可见。

## 5. 影响范围

必须检查以下文件：

```text
VSLoader/Styles/ModernTheme.xaml
VSLoader/Views/SettingsWindow.xaml
VSLoader/MainWindow.xaml
VSLoader/Views/BatchImportWindow.xaml
VSLoader/Views/ShortcutEditWindow.xaml
VSLoader/Views/WorkspaceNameDialog.xaml
```

### 5.1 高风险区域

最高风险：

```text
VSLoader/Views/SettingsWindow.xaml
```

原因：

- 大量 `TextBox` 使用 `ModernTextBoxStyle`。
- 多数输入框显式 `Height="30"`。
- 有 `PasswordBox`。
- 有只读快捷键输入框。

### 5.2 中风险区域

中风险：

```text
VSLoader/MainWindow.xaml
VSLoader/Views/BatchImportWindow.xaml
VSLoader/Views/ShortcutEditWindow.xaml
VSLoader/Views/WorkspaceNameDialog.xaml
```

原因：

- 这些地方也使用了 `ModernTextBoxStyle`。
- 当前高度多为 34 或 36，问题可能不明显，但模板根因相同。

## 6. 修复方案

### 6.1 修复共享输入控件模板

优先修改：

```text
VSLoader/Styles/ModernTheme.xaml
```

修复原则：

- `PART_ContentHost` 不再直接使用 `{TemplateBinding Padding}` 作为 `Margin`。
- 使用固定、保守、适配 34 高度的内容边距。
- 保证单行输入框文字完整显示。
- 保持聚焦边框、禁用态、只读态视觉不变。

建议方案：

```xml
<ScrollViewer x:Name="PART_ContentHost"
              Margin="10,0"
              VerticalAlignment="Center" />
```

或：

```xml
<Border ... Padding="10,0">
    <ScrollViewer x:Name="PART_ContentHost"
                  VerticalAlignment="Center" />
</Border>
```

推荐采用第二种，因为内容内边距由外层 Border 管理，更容易保持一致。

### 6.2 TextBox 样式建议

`ModernTextBoxStyle` 推荐调整为：

```text
Height：34
Padding：10,0
VerticalContentAlignment：Center
FontSize：13
```

模板内：

- 外层 Border 负责背景、边框、圆角。
- 内层 `ScrollViewer PART_ContentHost` 只负责文本承载。
- 不再把上下 Padding 叠加到 `PART_ContentHost`。

### 6.3 PasswordBox 样式建议

`ModernPasswordBoxStyle` 必须和 `TextBox` 同步调整。

原因：

- `PasswordBox` 同样依赖 `PART_ContentHost`。
- 密码点显示正常不代表模板安全。

推荐：

```text
Height：34
Padding：10,0
PART_ContentHost 不使用 Padding 作为 Margin
```

### 6.4 ReadOnly 样式

`ModernReadOnlyTextBoxStyle` 继承 `ModernTextBoxStyle`。

修复父样式后，应自动受益。

仍需手动检查：

- 地图快捷键输入框。
- 程序快捷键输入框。

## 7. 设置页同步调整

文件：

```text
VSLoader/Views/SettingsWindow.xaml
```

建议将设置页中所有套用了现代输入样式的：

```xml
Height="30"
```

统一改为：

```xml
Height="34"
```

或直接删除显式 `Height`，使用 `ModernTextBoxStyle` 默认高度。

推荐使用：

```text
删除显式 Height，交给 Style 控制
```

但如果为了最小改动，也可统一改为：

```text
Height="34"
```

本次建议选择“统一改为 34”，原因：

- 修改范围清晰。
- 不会意外改变某些控件在 Grid 中的测量行为。
- 和 v109 其他页面输入框高度一致。

必须保留：

```xml
PreviewMouseWheel="SettingsInput_PreviewMouseWheel"
```

不能因为调整输入框高度和样式而删除滚轮事件。

## 8. 全项目同类问题检查

修复后必须检查以下模式：

```powershell
rg 'ModernTextBoxStyle|ModernPasswordBoxStyle|ModernReadOnlyTextBoxStyle|Height="30"' VSLoader\Views VSLoader\MainWindow.xaml
```

检查目标：

- 是否还有现代输入框高度为 30。
- 是否还有输入框使用旧 Padding 导致内容压缩。
- 是否有多行备注框因为新模板受到影响。

### 8.1 多行 TextBox 注意事项

`ShortcutEditWindow.xaml` 中备注框：

```xml
AcceptsReturn="True"
VerticalScrollBarVisibility="Auto"
```

如果该多行框使用 `ModernTextBoxStyle` 后出现滚动或输入异常，应为它单独建立：

```text
ModernMultilineTextBoxStyle
```

多行样式不强制垂直居中，内容应从顶部开始。

本次优先观察构建和手动验证结果。如果发现多行备注框异常，再增加该样式。

## 12. 验收标准

满足以下条件即完成：

- 设置页所有输入框文字完整可见。
- 设置页所有输入框文字垂直位置自然，不下沉。
- 密码框显示正常。
- 只读快捷键框显示正常。
- 主窗口、批量新增、快捷项编辑、工作区命名弹窗没有同类问题。
- 设置页滚轮转交外层滚动逻辑不回归。
- 不改变任何业务逻辑。
- `dotnet test .\VSLoader.sln -c Debug --no-restore` 通过。
- `dotnet build .\VSLoader.sln -c Debug --no-restore` 通过。
