# v42 批量新增识别历史重复快捷项清理编码规格说明

## 1. 需求背景

v40 已经实现：

```text
批量新增识别按 TargetPath 去重，路径已存在时更新而不是新增。
```

v41 已经实现：

```text
路径已存在但结果无变化时显示已跳过，不再全量显示可更新。
```

但如果在 v40/v41 实现之前，用户已经产生了历史重复快捷项，当前逻辑无法自动清理这些旧数据。

例如主列表中存在：

```text
amx银烧结_001    批量新增：3134_TSSP001    2026-06-05 00:44:25
amx银烧结_001    批量新增：3134_TSSP001    2026-06-04 18:44:56
```

它们实际上指向同一个源文件夹：

```text
3134_TSSP001
```

用户希望在批量新增识别时，程序可以顺带修正这些历史重复项，只保留一份最新、最符合当前 CSV 规则的快捷项。

## 2. 需求目标

在批量新增识别流程中，增加历史重复快捷项清理能力。

目标：

1. 只处理当前扫描父目录下的子文件夹对应的快捷项。
2. 如果主列表中存在多个归一化 `TargetPath` 相同的快捷项，识别为历史重复组。
3. 每个重复组只保留一条快捷项。
4. 保留项应按当前 CSV 规则更新为最新映射结果。
5. 其他重复项在用户确认导入后删除。
6. 用户确认后提示：

```text
已新增 X 个，已更新 Y 个，已清理 Z 个重复快捷项。
```

## 3. 非目标范围

本次不实现：

1. 不全局扫描所有快捷项去重。
2. 不新增独立“清理重复项”按钮。
3. 不清理当前扫描父目录之外的重复项。
4. 不清理 `TargetPath` 不同但名称相同的快捷项。
5. 不修改手动新增/编辑页面逻辑。
6. 不改变主列表列显示。

说明：

本功能只服务于“批量新增识别”当前扫描范围，避免误删非当前 CSV 管理范围内的快捷项。

## 5. 重复项判定规则

重复组定义：

```text
NormalizePathKey(shortcut.TargetPath) 相同的快捷项数量 > 1
```

其中 `NormalizePathKey` 沿用 v40/v41 逻辑：

1. `Trim()`。
2. `/` 转 `\`。
3. 移除末尾多余 `\`。
4. 不区分大小写比较。

示例视为相同：

```text
\\192.168.15.69\instances\3134_TSSP001
\\192.168.15.69\instances\3134_TSSP001\
\\192.168.15.69/instances/3134_TSSP001
```

## 6. 当前扫描范围限制

本次只清理当前扫描父目录下的子文件夹。

也就是说：

```text
Directory.EnumerateDirectories(parentFolderPath)
```

得到的每个目录 `directory`，如果它对应的路径在主列表中存在多条，才参与清理。

不在本次扫描结果中的快捷项，即使重复，也不处理。

## 7. 保留项选择规则

对于同一路径重复组，需要选择一条保留。

推荐规则：

### 7.1 优先保留符合当前 CSV 规则生成结果的项

当前 CSV 规则会生成：

```text
GeneratedName
GeneratedDescription = 批量新增：{FolderName}
GeneratedTargetPath
```

如果重复组中某些项已经满足：

```text
Name == GeneratedName
Description == GeneratedDescription
TargetPath 归一化后 == GeneratedTargetPath 归一化后
```

优先从这些项中选择。

### 7.2 多条都符合时保留 UpdatedAt 最新的

如果有多条都符合最新规则：

```text
保留 UpdatedAt 最新的那条
```

### 7.3 没有任何一条符合时保留 UpdatedAt 最新的

如果重复组里没有任何一条完全符合当前 CSV 规则：

```text
保留 UpdatedAt 最新的那条
```

并在确认导入时把它更新为当前 CSV 规则结果。

### 7.4 CreatedAt 处理

保留项的 `CreatedAt` 保持原值。

删除项被移除。

更新保留项时：

```text
UpdatedAt = 当前时间
```

如果保留项本来已经完全符合当前规则，理论上不需要刷新 `UpdatedAt`。

但如果本次发生重复清理，为了记录清理时间，可以接受刷新保留项 `UpdatedAt`。

推荐策略：

```text
只要发生清理重复项，就更新保留项 UpdatedAt。
```

## 9. 模型改造

### 9.1 BatchImportPreviewItem

建议新增字段：

```csharp
public List<string> DuplicateTargetPaths { get; set; } = new();
public int DuplicateCleanupCount { get; set; }
```

含义：

- `DuplicateTargetPaths`：确认导入时需要删除的重复项路径列表。
- `DuplicateCleanupCount`：用于 UI 提示和最终统计。

如果担心路径不足以唯一定位重复项，也可以使用更明确的临时标识。

但当前 `ShortcutItem` 没有 Id，所以仍然以 `TargetPath + Name + UpdatedAt` 或对象引用处理更准确。

推荐更稳的做法：

在 `BatchImportApplyItem` 中保存需要删除的快捷项快照：

```csharp
public IReadOnlyList<ShortcutItem> DuplicateShortcutsToRemove { get; set; } = Array.Empty<ShortcutItem>();
```

由于 `BatchImportViewModel` 持有的是主列表快捷项对象引用，`existingShortcuts.ToList()` 中的对象仍然是原对象引用，可以在确认导入时用引用或路径/名称/时间匹配删除。

### 9.2 BatchImportApplyItem

建议扩展：

```csharp
public IReadOnlyList<ShortcutItem> DuplicateShortcutsToRemove { get; set; } = Array.Empty<ShortcutItem>();
```

或者：

```csharp
public List<ShortcutItem> DuplicateShortcutsToRemove { get; set; } = new();
```

同时保留：

```csharp
IsUpdate
ExistingTargetPath
Shortcut
```

## 10. BatchImportService 改造

### 10.1 建立 existingByPathGroups

当前 v40 建立的是：

```csharp
existingByPath = group.First()
```

本次需要保留完整分组：

```csharp
var existingGroupsByPath = existingList
    .Where(shortcut => !string.IsNullOrWhiteSpace(shortcut.TargetPath))
    .GroupBy(shortcut => NormalizePathKey(shortcut.TargetPath), StringComparer.OrdinalIgnoreCase)
    .ToDictionary(group => group.Key, group => group.ToList(), StringComparer.OrdinalIgnoreCase);
```

### 10.2 判断重复组

扫描目录时：

```csharp
var existingGroup = existingGroupsByPath.TryGetValue(pathKey, out var group)
    ? group
    : [];
```

如果：

```text
existingGroup.Count > 1
```

则进入清理逻辑。

### 10.3 选择保留项

新增辅助方法：

```csharp
private static ShortcutItem SelectShortcutToKeep(
    IReadOnlyList<ShortcutItem> duplicates,
    string generatedName,
    string generatedTargetPath,
    string generatedDescription)
```

逻辑：

```text
1. 找出符合当前生成结果的项。
2. 如果存在，取 UpdatedAt 最新。
3. 如果不存在，取 UpdatedAt 最新。
```

### 10.4 构建可清理预览项

如果重复组存在：

1. 选出 keepShortcut。
2. 其余为 removeShortcuts。
3. 判断 keepShortcut 是否需要按当前规则更新。
4. 预览项状态设为 `可清理`。
5. 预览项中记录：

```text
ExistingTargetPath = keepShortcut.TargetPath
ExistingName = keepShortcut.Name
IsUpdate = true
DuplicateCleanupCount = removeShortcuts.Count
```

对应的 apply item 中记录：

```text
DuplicateShortcutsToRemove = removeShortcuts
```

## 11. MainViewModel 应用逻辑

当前逻辑：

```text
新增
更新
```

本次增加：

```text
清理重复项
```

应用顺序建议：

1. 如果是更新或清理，先找到保留项并更新。
2. 删除 `DuplicateShortcutsToRemove` 中的快捷项。
3. 如果是新增，直接新增。
4. 保存配置。
5. 刷新列表。

删除时需要避免删除保留项。

建议以对象引用优先删除：

```csharp
Shortcuts.Remove(duplicateShortcut)
```

如果引用匹配失败，再使用：

```text
TargetPath + Name + UpdatedAt
```

作为兜底匹配。

最终提示文案：

```text
已新增 X 个快捷项，已更新 Y 个快捷项，已清理 Z 个重复快捷项。
```

只显示大于 0 的部分。

## 12. 与 v41 的关系

如果路径只存在一条：

```text
结果无变化 -> 已跳过
结果有变化 -> 可更新
```

如果路径存在多条：

```text
可清理
```

即使保留项本身无变化，也要允许清理其余重复项。

## 14. 验收场景

手工验收：

1. 主列表中存在同一目标路径的历史重复快捷项。
2. 打开批量新增识别。
3. 选择包含该目标路径的父目录和当前 CSV。
4. 点击扫描预览。
5. 重复项应显示 `可清理`。
6. 点击确认。
7. 主列表中该路径只剩一条。
8. 保留项名称和备注符合当前 CSV 规则。
9. 弹窗提示清理数量。
10. 关闭重启后重复项不再出现。
