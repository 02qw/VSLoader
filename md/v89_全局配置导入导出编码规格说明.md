# v89 全局配置导入导出编码规格说明

## 1. 背景

当前 VSLoader 已经支持多工作区，每个工作区拥有独立的：

```text
config.json
factory-map.layout.json
updateTime.json
UIdownload
window-layout.json
```

实际使用中，如果一个新用户第一次使用软件，需要手动配置：

1. VSCode 路径。
2. AdminUI 配置。
3. WebUI 配置。
4. 软件更新路径。
5. 更新检测路径。
6. 批量新增识别目标父级文件夹路径。
7. 批量新增识别 CSV 规则文件路径。
8. 快捷项列表。
9. 地图布局。

这些配置如果逐项手动设置，容易漏配，也容易因为路径错误导致功能不可用。

因此需要新增“导入/导出全局配置”能力：

```text
导出：将当前工作区的可共享配置打包成一个 JSON 文件。
导入：其他用户选择这个 JSON 文件后，将配置导入到当前工作区，并进行严格校验。
```

注意：

```text
本功能面向用户叫“全局配置”，但技术边界不是覆盖整个 VSLoader。
技术边界是：当前工作区配置包 + 受控程序级辅助配置。
```

## 2. 总体目标

### 2.1 用户目标

主界面第二行工具区新增两个按钮：

```text
导出全局配置
导入全局配置
```

用户 A 配好一个工作区后，点击“导出全局配置”，得到一个 JSON 配置包。

用户 B 首次使用软件时：

1. 进入自己的目标工作区。
2. 点击“导入全局配置”。
3. 选择用户 A 提供的 JSON 配置包。
4. 程序导入配置。
5. 程序提示哪些内容已导入，哪些路径在当前电脑上无效。
6. 用户可以直接开始使用，或根据提示补充少量本机路径。

### 2.2 技术目标

1. 导出当前工作区 `config.json`。
2. 导出当前工作区 `factory-map.layout.json`。
3. 导出受控程序级辅助配置：
   - `VSCodePath`
   - `SoftwareUpdateManifestPath`
4. 导入时只写当前工作区，不污染其他工作区。
5. 导入时只允许受控修改程序级辅助配置，不覆盖工作区列表。
6. 导入前必须预检。
7. 导入前必须备份当前工作区被覆盖文件。
8. 导入失败时必须给出可追溯错误。
9. 导入完成后必须刷新主界面、地图状态、设置状态和快捷键注册状态。

## 3. 边界定义

### 3.1 “全局配置”的用户含义

用户侧含义：

```text
一个文件包含当前工作区能直接开工所需的大部分配置。
```

### 3.2 “全局配置”的技术含义

技术侧含义：

```text
当前工作区配置包 + 少量受控程序级辅助配置。
```

导入默认写入：

```text
%AppData%\VSLoader\Workspaces\<当前工作区>\config.json
%AppData%\VSLoader\Workspaces\<当前工作区>\factory-map.layout.json
```

导入可受控写入：

```text
%AppData%\VSLoader\app-settings.json
```

但只允许修改：

```text
VSCodePath
SoftwareUpdateManifestPath
```

绝对不能修改：

```text
Workspaces
LastWorkspaceId
OpenLastWorkspaceOnStartup
MigrationCompleted
```

### 3.3 不污染其他工作区

导入时不得写入任何非当前工作区目录。

示例：

如果当前打开工作区是：

```text
%AppData%\VSLoader\Workspaces\work2
```

则导入只能写入：

```text
%AppData%\VSLoader\Workspaces\work2\config.json
%AppData%\VSLoader\Workspaces\work2\factory-map.layout.json
```

不能写入：

```text
%AppData%\VSLoader\Workspaces\default
%AppData%\VSLoader\Workspaces\work1
%AppData%\VSLoader\Workspaces\work3
```

## 4. 导出范围

### 4.1 必须导出的内容

#### 当前工作区 config.json

包含：

```text
Shortcuts
AdminUi
Hotkey
BatchImport
WebUi
UpdateCheck
```

其中 `BatchImport` 必须包含：

```text
LastParentFolderPath
LastCsvPath
```

这两个字段对应用户提出的：

```text
新增批量识别中的目标父级文件夹路径
CSV 规则文件配置项路径
```

#### 当前工作区 factory-map.layout.json

包含地图节点位置、连线关系、布局信息。

导出该文件后，其他用户导入配置包时可以直接获得相同地图布局。

#### 受控程序级辅助配置

包含：

```text
VSCodePath
SoftwareUpdateManifestPath
```

注意：

1. `VSCodePath` 是所有工作区共享的程序级配置。
2. `SoftwareUpdateManifestPath` 也是所有工作区共享的程序级配置。
3. 导入这两个字段会影响所有工作区共用能力，必须在导入结果中明确提示。

### 4.2 不导出的内容

不得导出：

```text
Workspaces
LastWorkspaceId
OpenLastWorkspaceOnStartup
MigrationCompleted
updateTime.json
window-layout.json
UIdownload
```

原因：

1. `Workspaces` 是当前用户本机工作区列表，导入会污染用户自己的工作区结构。
2. `LastWorkspaceId` 会改变用户启动进入哪个工作区。
3. `OpenLastWorkspaceOnStartup` 是本机使用习惯。
4. `MigrationCompleted` 是程序迁移状态。
5. `updateTime.json` 是当前用户已知更新基线，不适合共享。
6. `window-layout.json` 是当前电脑屏幕布局，不适合共享。
7. `UIdownload` 是 jnlp 缓存，不适合共享。

## 5. 配置包格式

### 5.1 文件后缀

推荐使用 `.json`。

默认导出文件名：

```text
VSLoader_GlobalConfig_yyyyMMdd_HHmmss.json
```

### 5.2 JSON 根结构

新增模型建议：

```csharp
public sealed class GlobalConfigPackage
{
    public int SchemaVersion { get; set; } = 1;

    public string AppName { get; set; } = "VSLoader";

    public string ExportedAt { get; set; } = string.Empty;

    public GlobalProgramSettings ProgramSettings { get; set; } = new();

    public AppConfig WorkspaceConfig { get; set; } = new();

    public FactoryMapLayout? FactoryMapLayout { get; set; }
}
```

程序级辅助配置模型：

```csharp
public sealed class GlobalProgramSettings
{
    public string VSCodePath { get; set; } = string.Empty;

    public string SoftwareUpdateManifestPath { get; set; } = string.Empty;
}
```

说明：

1. `SchemaVersion` 用于后续兼容升级。
2. `AppName` 用于识别这是否是 VSLoader 配置包。
3. `WorkspaceConfig` 存放当前工作区配置。
4. `FactoryMapLayout` 存放地图布局。
5. `ProgramSettings` 只存放允许共享的程序级辅助配置。

### 5.3 不直接复制原始文件

不要让用户导出多个文件。

不要直接输出原始 `config.json`。

必须输出统一配置包，原因：

1. 以后可扩展。
2. 可以校验 `SchemaVersion`。
3. 可以清楚区分工作区配置和程序级辅助配置。
4. 可以避免误导入普通 JSON。

## 6. 主界面 UI 规格

### 6.1 按钮位置

在主界面第二行工具区新增两个按钮：

```text
导出全局配置
导入全局配置
```

要求：

1. 按钮尺寸遵循现有第二行按钮风格。
2. 不破坏当前第二行按钮均匀分布策略。
3. 窗口缩小时按钮不能丢边框。
4. 按钮文字不换行。

### 6.2 按钮行为

#### 导出全局配置

点击后：

1. 弹出保存文件对话框。
2. 默认文件名为 `VSLoader_GlobalConfig_yyyyMMdd_HHmmss.json`。
3. 用户取消则不做任何操作。
4. 用户确认后执行导出。
5. 导出成功弹窗提示保存路径。
6. 导出失败弹窗显示详细错误。

#### 导入全局配置

点击后：

1. 弹出打开文件对话框。
2. 用户选择 JSON 配置包。
3. 程序预检。
4. 如果存在严重错误，阻止导入并弹窗显示原因。
5. 如果只有非阻塞问题，继续导入并在结果报告中提示。
6. 导入成功后刷新主界面。

### 6.3 Busy 状态

导入导出期间建议复用现有 `IsBusy` 遮罩：

```text
正在导出全局配置...
正在导入全局配置...
```

目的：

1. 防止用户重复点击。
2. 防止导入中途编辑快捷项。
3. 防止导入中途打开地图导致状态不一致。

## 7. 导出流程

### 7.1 导出步骤

导出逻辑：

```text
1. 读取当前内存中的 AppConfig。
2. 将当前 Shortcuts 同步回 AppConfig。
3. 读取当前工作区 factory-map.layout.json。
4. 读取 AppSettings 中 VSCodePath 和 SoftwareUpdateManifestPath。
5. 构造 GlobalConfigPackage。
6. 序列化为 JSON。
7. 写入用户选择的目标路径。
```

### 7.2 地图布局不存在

如果当前工作区没有 `factory-map.layout.json`：

1. 允许导出。
2. `FactoryMapLayout = null`。
3. 导出结果提示：

```text
当前工作区没有地图布局文件，本次未包含地图布局。
```

不应视为失败。

### 7.3 导出失败

可能失败原因：

1. 用户选择的保存路径无权限。
2. 文件被占用。
3. 目标磁盘不可用。
4. 地图布局文件损坏但无法读取。

推荐：

1. 如果地图文件损坏，导出可以继续，但不包含地图布局，并提示。
2. 如果目标文件写入失败，导出失败。

## 8. 导入流程

### 8.1 总体流程

导入逻辑必须分阶段：

```text
1. 选择配置包文件。
2. 读取 JSON。
3. 解析 GlobalConfigPackage。
4. 基础格式校验。
5. 内容预检。
6. 生成导入计划。
7. 备份当前工作区 config.json。
8. 备份当前工作区 factory-map.layout.json。
9. 写入当前工作区 config.json。
10. 写入当前工作区 factory-map.layout.json。
11. 受控更新 app-settings.json 的 VSCodePath 和 SoftwareUpdateManifestPath。
12. 重新加载当前工作区配置。
13. 刷新主界面列表。
14. 刷新地图窗口状态。
15. 重新注册快捷键。
16. 更新标题栏状态提示。
17. 弹出导入结果报告。
```

### 8.2 严重错误

以下问题必须阻止导入：

```text
文件不存在
文件无法读取
JSON 格式损坏
AppName 不是 VSLoader
SchemaVersion 不支持
WorkspaceConfig 缺失
WorkspaceConfig 无法反序列化
当前工作区 config.json 无法备份
当前工作区 config.json 无法写入
当前工作区目录不存在
当前工作区目录不可写
```

弹窗示例：

```text
导入失败：
配置包格式无效，缺少 workspaceConfig。

文件：
C:\xxx\VSLoader_GlobalConfig_20260617.json
```

### 8.3 非阻塞问题

以下问题不阻止导入，但必须在导入结果报告中列出：

```text
VSCode 路径不存在
软件更新 manifest 路径不存在
批量识别父级文件夹不存在
批量识别 CSV 文件不存在
UpdateCheck rules 文件不存在
UpdateCheck map 文件不存在
UpdateCheck 软件版本文件不存在
部分快捷项目标路径不存在
地图布局为空
地图布局中部分节点无法匹配快捷项
快捷键注册失败或冲突
```

### 8.4 备份文件命名

导入前备份当前工作区文件。

备份命名：

```text
config.import-backup.yyyyMMdd_HHmmss_fff.json
factory-map.layout.import-backup.yyyyMMdd_HHmmss_fff.json
```

备份位置：

```text
当前工作区目录
```

### 8.5 写入策略

必须先备份再写入。

如果 `config.json` 写入失败：

1. 尝试恢复备份。
2. 弹窗显示失败原因。
3. 不继续写地图布局。

如果 `factory-map.layout.json` 写入失败：

1. 保留已经写入的 `config.json`。
2. 尝试恢复地图备份。
3. 导入结果报告提示地图布局导入失败。

原因：

```text
config.json 是核心配置。
地图布局是附属配置。
```

## 9. VSCode 路径处理

### 9.1 导入优先级

导入 VSCode 路径时按以下顺序：

```text
1. 配置包中的 VSCodePath 有效，则使用。
2. 配置包中的 VSCodePath 无效，但当前本机已有有效 VSCodePath，则保留当前本机路径。
3. 配置包中的 VSCodePath 无效，当前本机也无有效路径，则尝试自动识别 VSCode。
4. 自动识别成功，则写入识别到的路径。
5. 自动识别失败，则清空或保留当前无效值，并标题栏公告提示。
```

推荐第 5 步：

```text
保留当前值，不强行清空。
```

但标题栏必须提示：

```text
导入完成，但未找到有效 VSCode 路径，请进入设置配置。
```

### 9.2 有效性判断

复用：

```csharp
VSCodeLauncherService.IsValidExecutablePath(path)
```

要求：

1. 路径非空。
2. 文件存在。
3. 后缀为 `.exe`。

### 9.3 自动识别建议

新增轻量服务方法：

```csharp
public sealed class VSCodePathResolver
{
    public string Resolve();
}
```

搜索顺序建议：

```text
%LocalAppData%\Programs\Microsoft VS Code\Code.exe
%ProgramFiles%\Microsoft VS Code\Code.exe
%ProgramFiles(x86)%\Microsoft VS Code\Code.exe
PATH 中可找到的 Code.exe
```

注意：

```text
不要把 code.cmd 写入 VSCodePath。
当前启动器要求 .exe。
```

## 10. 软件更新 manifest 路径处理

`SoftwareUpdateManifestPath` 是程序级配置，会影响所有工作区。

导入策略：

1. 如果配置包路径存在，写入 `app-settings.json`。
2. 如果配置包路径不存在：
   - 不覆盖当前已有有效路径。
   - 如果当前也没有有效路径，允许保持为空或无效。
   - 导入结果报告提示。

导入结果必须明确说明：

```text
软件更新路径属于程序级配置，导入后会影响所有工作区。
```

## 11. 批量新增识别路径处理

字段来自：

```text
AppConfig.BatchImport.LastParentFolderPath
AppConfig.BatchImport.LastCsvPath
```

导入策略：

1. 原样写入当前工作区 `config.json`。
2. 如果父级路径不存在，不阻止导入。
3. 如果 CSV 文件不存在，不阻止导入。
4. 导入结果报告列出。

原因：

```text
这些路径可能是共享盘或产线目录。
用户当前电脑暂时访问不到，不代表配置包无效。
```

## 12. UpdateCheck 路径处理

字段来自：

```text
AppConfig.UpdateCheck.RulesFilePath
AppConfig.UpdateCheck.MapFilePath
AppConfig.UpdateCheck.SoftwareVersionFilePath
```

导入策略：

1. 原样写入当前工作区。
2. 文件不存在不阻止导入。
3. 后续自动检测更新时仍按现有逻辑显示“更新检测失败”栏。
4. 导入结果报告中提前提示。

## 13. 快捷项处理

### 13.1 导入快捷项

配置包中的 `Shortcuts` 作为当前工作区完整快捷项列表导入。

导入后替换当前工作区快捷项列表。

### 13.2 快捷项目标路径不存在

如果部分快捷项 `TargetPath` 不存在：

1. 不阻止导入。
2. 统计数量。
3. 导入结果报告显示。

示例：

```text
有 12 个快捷项目标路径当前不可访问。
```

不建议在报告中列出所有路径，避免弹窗过长。

可以列出前 5 条，并提示总数。

## 14. 地图布局处理

### 14.1 导入地图布局

如果配置包中包含 `FactoryMapLayout`：

1. 写入当前工作区 `factory-map.layout.json`。
2. 如果地图窗口已打开，刷新或提示重新打开地图。
3. 如果地图窗口未打开，下次打开地图时使用新布局。

### 14.2 地图布局为空

如果配置包不包含地图布局：

1. 不覆盖当前工作区已有地图布局。
2. 导入结果提示：

```text
配置包不包含地图布局，已保留当前地图布局。
```

### 14.3 地图节点无法匹配快捷项

导入后检查地图节点和快捷项的对应关系。

如果部分节点无法匹配快捷项：

1. 不阻止导入。
2. 导入结果报告提示。

示例：

```text
地图中有 3 个节点未匹配到快捷项。
```

## 15. 快捷键处理

导入配置包可能包含 `Hotkey`。

导入后需要尝试重新注册快捷键。

规则：

1. 如果快捷键未启用，不注册。
2. 如果快捷键启用，调用现有注册逻辑。
3. 如果注册失败，不回滚导入。
4. 导入结果报告提示快捷键注册失败原因。

原因：

```text
快捷键冲突是当前电脑运行环境问题，不应导致整个配置导入失败。
```

## 16. 导入结果报告

导入完成后必须显示弹窗。

### 16.1 完全成功

示例：

```text
全局配置导入完成。

已导入：
1. 工作区配置
2. 地图布局
3. VSCode 路径
4. 软件更新路径
```

### 16.2 有非阻塞问题

示例：

```text
全局配置导入完成，但存在需要检查的问题：

1. VSCode 路径无效，已保留当前本机路径。
2. 批量识别 CSV 文件不存在：C:\xxx\rules.csv
3. 有 12 个快捷项目标路径当前不可访问。
4. 地图中有 3 个节点未匹配到快捷项。
5. 软件更新路径属于程序级配置，导入后会影响所有工作区。
```

### 16.3 标题栏公告

如果存在关键路径问题，标题栏公告显示短提示：

```text
配置导入完成，但部分路径无效，请检查设置。
```

如果 VSCode 路径最终无效，优先显示：

```text
导入完成，但未找到有效 VSCode 路径，请进入设置配置。
```

## 17. 服务设计建议

### 17.1 新增服务

建议新增：

```text
VSLoader\Models\Services\GlobalConfigPackageService.cs
```

职责：

```text
导出配置包
读取配置包
预检配置包
导入配置包
生成导入结果报告
```

### 17.2 新增模型

建议新增：

```text
VSLoader\Models\GlobalConfigPackage.cs
VSLoader\Models\GlobalConfigImportResult.cs
VSLoader\Models\GlobalConfigExportResult.cs
VSLoader\Models\GlobalProgramSettings.cs
```

### 17.3 MainViewModel 职责

`MainViewModel` 只负责：

1. 响应按钮命令。
2. 弹出选择/保存文件对话框。
3. 设置 Busy 状态。
4. 调用服务。
5. 刷新 UI。
6. 弹出结果。

不要把导入导出细节写进 `MainViewModel`。

## 18. DialogService 需求

## 22. 风险与注意事项

### 22.1 名称“全局配置”可能误导

用户看到“全局配置”可能以为会覆盖所有工作区。

导入确认或结果报告中建议明确：

```text
本次导入只会覆盖当前工作区配置和地图布局。
VSCode 路径、软件更新路径属于程序级配置，导入后会影响所有工作区。
```

### 22.2 程序级辅助配置的影响

`VSCodePath` 和 `SoftwareUpdateManifestPath` 会影响所有工作区。

因此：

1. 只在路径有效或有保底策略时写入。
2. 写入结果必须提示。
3. 不允许导入工作区列表。

### 22.3 地图布局和快捷项匹配

地图布局依赖快捷项。

如果配置包中快捷项和地图布局不匹配：

1. 不阻止导入。
2. 地图可打开。
3. 结果报告提示未匹配节点数量。

### 22.4 导入失败回滚

核心原则：

```text
不能让导入失败后当前工作区 config.json 处于半损坏状态。
```

必须先备份，再写入。

如果写入失败，尽力恢复备份。
