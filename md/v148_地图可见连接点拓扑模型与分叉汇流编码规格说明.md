# v148 地图可见连接点拓扑模型与分叉汇流编码规格说明

## 1. 背景

v143 到 v147 已经把地图连线从“普通直线”推进到“可保存折点、正交路径、线段控制”。

但实际试用后发现一个更根本的问题：

```text
当前暴露给用户的是内部几何点。
用户右键添加一个折点后，程序为了画出正交绕行，会生成多个内部点。
这些点对算法有意义，但对用户没有清晰语义。
```

用户看到的问题是：

```text
我只是想在线上加一个点。
结果界面上突然出现 2-3 个点。
我不知道每个点后续能做什么。
我也不知道它和一对多、多对一有什么关系。
```

这说明 v147 的“线段/通道编辑”理念是有价值的，但它还没有解决真正的业务结构问题。

一对多、多对一不是路径折点问题，而是地图拓扑问题。

因此本阶段要引入一个新的用户可见单位：

```text
连接点。
```

连接点不是某条线内部的折点，而是地图上的轻量节点。

它的意义是：

```text
多条连线可以连接到它。
它可以被拖动。
它可以作为分叉点、汇流点、中继点。
```

## 2. 核心结论

从 v148 开始，地图编辑要区分两类单位：

```text
拓扑单位：设备节点、连接点。
视觉路径单位：连线、路径折点、内部几何点。
```

边界必须清楚：

```text
连接点负责表达关系结构。
路径折点只负责调整单条线怎么绕。
内部几何点只服务渲染和正交算法，不直接作为主要用户操作对象。
```

一对多应该表达为：

```text
设备 A -> 连接点 J
连接点 J -> 设备 B
连接点 J -> 设备 C
连接点 J -> 设备 D
```

多对一应该表达为：

```text
设备 A -> 连接点 J
设备 B -> 连接点 J
设备 C -> 连接点 J
连接点 J -> 设备 D
```

不要再用一条线内部的多个折点去假装表达分叉/汇流。

## 3. 本阶段目标

本阶段目标：

```text
1. 新增“连接点”数据模型。
2. 连接点在地图上可见，尺寸适中，不抢设备节点视觉。
3. 连接点可以被选中、拖动、保存、加载。
4. 连线端点支持设备节点和连接点。
5. 右键连线可添加连接点，并把原连线拆成两条连线。
6. 连线模式支持从设备连到连接点、从连接点连到设备、连接点连到连接点。
7. 连接点被拖动时，所有接入它的连线自动跟随。
8. 路径折点和连接点在 UI、数据、行为上明确分离。
9. 旧版 factory-map.layout.json 可继续读取。
10. 新版 layout 保存后包含连接点数据。
```

用户体验目标：

```text
用户在线上添加一个连接点。
原来的 A -> B 自动变成 A -> J 和 J -> B。
用户可以继续从 J 拉线到 C/D，从而表达一对多。
```

## 4. 非目标

本阶段不做：

```text
1. 不做自动判断哪里应该分叉。
2. 不做自动合并相近连接点。
3. 不做自动避障。
4. 不做复杂布线算法。
5. 不做连接点分组、命名、备注。
6. 不做连接点和设备节点之间的业务属性绑定。
7. 不做路径折点的完整重构。
8. 不做“连接点吸附到某条线后自动维护共享线段”的高级能力。
9. 不做多选连接点批量移动。
10. 不做连接点层级、颜色分类、流程方向箭头。
```

说明：

```text
v148 只建立正确的拓扑单位。
让一对多、多对一有清晰的数据和交互基础。
```

## 5. 单位定义

### 5.1 设备节点

设备节点是当前已有节点：

```text
FactoryMapDeviceViewNode
FactoryMapDeviceNode
```

设备节点来源于快捷项/工作区配置。

设备节点特征：

```text
1. 有 Key。
2. 有 Name。
3. 有 Shortcut。
4. 可打开 AdminUI/WebUI 等业务功能。
```

### 5.2 连接点

连接点是新增轻量节点。

连接点特征：

```text
1. 有 Id。
2. 有 X/Y 坐标。
3. 没有 Shortcut。
4. 不打开任何业务程序。
5. 可作为连线 From/To。
6. 可拖动。
7. 可删除。
```

连接点的用户语义：

```text
分叉点。
汇流点。
中继点。
```

连接点的视觉建议：

```text
默认直径：10px。
选中直径：12px。
白色填充。
蓝色边框。
选中时轻微蓝色外圈。
不要像设备卡片一样大。
不要显示文字。
```

### 5.3 连线

连线表达两个拓扑单位之间的连接关系。

可连接组合：

```text
设备 -> 设备
设备 -> 连接点
连接点 -> 设备
连接点 -> 连接点
```

不允许：

```text
同一个拓扑单位连到自己。
重复连线。
空端点。
指向不存在的设备或连接点。
```

### 5.4 路径折点

路径折点只属于某一条连线。

路径折点作用：

```text
调整该条线怎么绕。
不表达分叉。
不表达汇流。
不被其他连线共享。
```

本阶段可以暂时弱化路径折点入口，避免用户混淆。


```text
所有连接到该连接点的连线自动重绘。
不需要修改连线 points。
```

如果连接点拖动后导致某些旧 points 视觉奇怪：

```text
本阶段只保证不崩溃。
```

```text

```

删除规则：

```text
删除连接点前弹确认框。
确认后删除该连接点。
同时删除所有连接到该连接点的连线。
保存布局。
```

确认文案：

```text
删除该连接点会同时删除所有连接到它的连线，是否继续？
```

原因：

```text
不允许留下指向不存在连接点的无效连线。
```

## 9. 在线上添加连接点

### 9.1 菜单入口

连线右键菜单调整为：

```text
添加连接点
添加路径折点
清除路径折点
删除连线
```

说明：

```text
添加连接点：改变拓扑结构。
添加路径折点：只改变当前线形状。
清除路径折点：只清当前线 points。
删除连线：只删当前线。
```

如果为了降低复杂度，本阶段可以先隐藏“添加路径折点”，但不能把它和连接点混用。

推荐本阶段菜单：

```text
添加连接点
清除路径折点
删除连线
```

路径折点后续再重做。

### 9.2 添加连接点行为

用户右键某条连线，点击“添加连接点”。

原始结构：

```text
A -> B
```

新增连接点：

```text
J
```

保存结果：

```text
A -> J
J -> B
```

原连线删除。

新增两条连线。

连接点坐标：

```text
优先使用右键点击位置。
坐标吸附到网格。
坐标限制 >= 0。
```

### 9.3 原连线 points 处理

本阶段采用保守规则：

```text
拆线后两条新线 points 均为空。
让它们走默认正交路径。
```

原因：

```text
把旧 points 自动切分到两条新线会引入复杂几何算法。
当前用户最需要的是拓扑结构清楚。
```

状态提示：

```text
已添加连接点，原连线已拆分为两条连线。
```

## 10. 连线模式扩展

当前连线模式只支持设备到设备。

v148 要支持：

```text
设备 -> 设备
设备 -> 连接点
连接点 -> 设备
连接点 -> 连接点
```

### 10.1 待连接起点状态

当前可能有：

```csharp
private FactoryMapDeviceViewNode? pendingConnectionStart;
```

需要替换为：

```csharp
private FactoryMapEndpointViewData? pendingConnectionStart;
```

或者新增更轻量状态：

```csharp
private string? pendingConnectionStartKind;
private string? pendingConnectionStartId;
```

推荐使用 `FactoryMapEndpointViewData`，保持类型清晰。

### 10.2 点击设备

连接模式下点击设备：

```text
如果没有起点：设置设备为起点。
如果已有起点：尝试创建 起点 -> 当前设备 连线。
```

### 10.3 点击连接点

连接模式下点击连接点：

```text
如果没有起点：设置连接点为起点。
如果已有起点：尝试创建 起点 -> 当前连接点 连线。
```

### 10.4 重复连接检查

重复规则：

```text
FromKind + FromId + ToKind + ToId 完全相同视为重复。
```

是否允许反向：

```text
本阶段沿用当前方向语义。
A -> B 和 B -> A 视为两条不同方向连线。
如果当前项目旧逻辑禁止反向重复，则保持旧逻辑，并在测试中写清。
```

建议保持当前旧逻辑的方向规则，不在 v148 改业务方向语义。

### 11.2 加载

加载时：

```text
1. config.Connectors ??= []。
2. 过滤空 Id 连接点。
3. 对重复 Id 只保留第一个。
4. 过滤 NaN/Infinity 坐标。
5. 坐标小于 0 时夹到 0。
```

边加载时：

```text
1. FromKind/ToKind 为空时默认 device。
2. 根据 Kind 到设备表或连接点表找端点。
3. 任一端点找不到则 invalidEdgeCount++。
4. 自连接则 invalidEdgeCount++。
5. 重复连接则 invalidEdgeCount++。
```

### 11.3 旧数据兼容

旧 JSON 示例：

```json
{
  "version": 2,
  "devices": [],
  "edges": [
    { "from": "A", "to": "B", "points": [] }
  ]
}
```

读取结果：

```text
Connectors = []
edge.FromKind = device
edge.ToKind = device
```

必须无异常。

## 17. 人工验收

验收流程：

```text
1. 打开 VSLoader。
2. 打开工厂地图。
3. 进入编辑模式。
4. 选择两个设备建立一条连线 A -> B。
5. 右键该连线，点击“添加连接点”。
6. 确认界面只出现一个适中大小的小连接点。
7. 确认原连线变为 A -> J 和 J -> B 两条连线。
8. 进入连线模式，从 J 连到设备 C。
9. 确认形成 J -> C，视觉上表达一对多。
10. 再从设备 D 连到 J。
11. 确认形成 D -> J，视觉上表达多对一。
12. 拖动 J，确认接入 J 的所有线跟随移动。
13. 删除 J，确认关联连线被删除，并有确认弹窗。
14. 保存、关闭地图、重新打开，确认连接点和连线关系保留。
15. 打开旧版无 connectors 的地图，确认不报错。
```

## 18. 实现顺序建议

推荐按阶段实现：

```text
第一阶段：数据模型和布局服务。
第二阶段：端点几何服务和连线渲染适配。
第三阶段：连接点绘制、选中、拖动、删除。
第四阶段：在线上添加连接点并拆线。
第五阶段：连线模式支持设备/连接点混连。
第六阶段：测试、构建、人工验证。
```

不要先做 UI，再回头补数据模型。

原因：

```text
连接点是拓扑单位，必须先让保存/加载和 edge endpoint 类型成立。
```
