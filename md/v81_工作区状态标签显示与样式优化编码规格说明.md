# v81 工作区状态标签显示与样式优化编码规格说明

## 1. 文档目的

本文件用于指导编程 Agent 优化“选择工作区”窗口中每个工作区条目右侧状态标签的显示逻辑与视觉样式。

本次需求的核心目标：

```text
1. 有状态文字时才显示状态标签。
2. 没有状态文字时不显示空白标签框。
3. 状态标签样式不再出现突兀灰色底纹。
```

## 2. 背景说明

当前选择工作区窗口中，每个工作区列表项右侧都有一个状态标签区域。

当前状态文字来源：

```text
VSLoader\ViewModels\WorkspaceListItemViewModel.cs
```

当前逻辑：

```csharp
public string StatusText
{
    get
    {
        if (!IsUsable)
        {
            return "路径不存在";
        }

        return IsLastWorkspace ? "上次使用" : string.Empty;
    }
}
```

当前 XAML 中状态标签无论 `StatusText` 是否为空都会渲染：

```xml
<Border Grid.Row="0"
        Grid.Column="1"
        Margin="10,0,0,0"
        Padding="8,2"
        CornerRadius="4"
        Background="#F3F4F6">
    <TextBlock Text="{Binding StatusText}" />
</Border>
```

因此当 `StatusText` 为空字符串时，界面仍会显示一个小灰色方块。  
用户截图中红框标出的灰色小块就是这个空状态标签的背景。

## 3. 需求目标

完成后应满足：

```text
1. 如果工作区是上次使用的工作区，显示“上次使用”标签。
2. 如果工作区路径不可用，显示“路径不存在”标签。
3. 如果工作区没有任何状态文字，不显示右侧标签。
4. 不再出现空白灰色小方块。
5. 状态标签背景不使用突兀灰底，视觉上与白色列表更融合。
6. 不影响工作区选择、打开、重命名、删除功能。
```

## 4. 非目标范围

本阶段不实现：

```text
1. 不修改工作区创建逻辑。
2. 不修改工作区真实目录命名逻辑。
3. 不修改工作区删除逻辑。
4. 不修改工作区重命名逻辑。
5. 不修改主窗口 UI。
6. 不修改 AdminUI、WebUI、批量新增、地图功能。
7. 不新增新的工作区状态类型。
8. 不改变列表选中态蓝色背景。
```

## 6. 逻辑设计

### 6.1 新增 HasStatus 属性

在 `WorkspaceListItemViewModel` 中新增只读属性：

```csharp
public bool HasStatus => !string.IsNullOrWhiteSpace(StatusText);
```

含义：

```text
StatusText 有实际文字时，HasStatus 为 true。
StatusText 为空或空白时，HasStatus 为 false。
```

### 6.2 状态显示规则

保持现有 `StatusText` 语义：

```text
路径不可用：路径不存在
上次使用：上次使用
普通工作区：空字符串
```

新增显示判断：

```text
路径不可用：显示标签
上次使用：显示标签
普通工作区：不显示标签
```

### 6.3 不建议用空白背景遮盖问题

虽然把背景改成白色也能让用户看不见灰色小方块，但更合理的逻辑是：

```text
没有内容就不渲染标签。
```

因此本次应同时做：

```text
1. HasStatus 控制 Visibility。
2. 状态标签样式改得更轻。
```

## 7. XAML 改造要求

目标文件：

```text
VSLoader\Views\WorkspaceSelectorWindow.xaml
```

### 7.1 状态标签绑定 Visibility

当前状态标签 Border 需要增加 `Visibility` 控制。

推荐写法一：使用 DataTrigger。

示例：

```xml
<Border x:Name="StatusBadge"
        Grid.Row="0"
        Grid.Column="1"
        Margin="10,0,0,0"
        Padding="8,2"
        CornerRadius="4"
        Background="White"
        BorderBrush="#E5E7EB"
        BorderThickness="1">
    <TextBlock Foreground="#4B5563"
               FontSize="12"
               Text="{Binding StatusText}" />
</Border>
```

并在 `DataTemplate.Triggers` 中增加：

```xml
<DataTrigger Binding="{Binding HasStatus}" Value="False">
    <Setter TargetName="StatusBadge" Property="Visibility" Value="Collapsed" />
</DataTrigger>
```

也可以在 Border 上默认设置：

```xml
Visibility="Collapsed"
```

然后对 `HasStatus=True` 时显示。  
两种方式都可以，但必须确保无状态时不占用右侧空间。

### 7.2 状态标签视觉样式

状态标签不再使用原来的突兀灰底：

```xml
Background="#F3F4F6"
```

推荐改为：

```xml
Background="White"
BorderBrush="#E5E7EB"
BorderThickness="1"
```

这样标签仍然可识别，但不会像灰色块一样突出。

可选更轻样式：

```xml
Background="Transparent"
BorderBrush="#E5E7EB"
BorderThickness="1"
```

如果使用透明背景，应确认在选中行蓝底上仍能看清文字和边框。

本规格推荐使用：

```text
白色背景 + 浅灰边框
```

### 7.3 保持布局不抖动

由于右侧标签在无状态时 `Collapsed`，名称列会获得更多空间。

要求：

```text
1. 名称仍然在第一列。
2. 标签仍然在右侧第二列。
3. 标签消失时不保留灰色空块。
4. 标签消失时不影响下面路径和时间行布局。
```

## 9. 手工验收

### 场景一：普通工作区

操作：

```text
打开选择工作区窗口。
查看不是“上次使用”、并且路径存在的普通工作区。
```

预期：

```text
该行右侧不显示任何状态标签。
不会出现灰色小方块。
```

### 场景二：上次使用工作区

操作：

```text
打开选择工作区窗口。
查看上次使用的工作区。
```

预期：

```text
右侧显示“上次使用”标签。
标签为白底浅边框或等价轻量样式。
不再是突兀灰底。
```

### 场景三：路径不存在工作区

操作：

```text
制造一个路径不存在的工作区记录，或删除某工作区真实文件夹后打开选择窗口。
```

预期：

```text
右侧显示“路径不存在”标签。
标签可见但不突兀。
```

## 10. 风险点

### 10.1 空标签仍占位

风险：

```text
只把背景改成白色，但 Border 仍然存在，后续在选中态或 hover 态仍可能露出异常区域。
```

规避：

```text
必须使用 HasStatus 控制标签 Visibility。
```

### 10.2 标签不可见但内容还占布局

风险：

```text
使用 Hidden 会隐藏内容但保留空间。
```

规避：

```text
无状态时使用 Collapsed。
```

### 10.3 影响上次使用提示

风险：

```text
状态标签隐藏逻辑写反，导致“上次使用”不显示。
```

规避：

```text
用 HasStatus 测试覆盖上次使用和路径不存在。
```

## 11. 验收标准

本需求完成必须满足：

```text
1. 普通工作区右侧不显示空白状态标签。
2. 普通工作区右侧不出现灰色小方块。
3. 上次使用工作区仍显示“上次使用”。
4. 路径不存在工作区仍显示“路径不存在”。
5. 状态标签样式不使用突兀灰底。
6. 选择、打开、重命名、删除工作区功能不受影响。
7. dotnet build 通过。
8. dotnet test 通过。
```
