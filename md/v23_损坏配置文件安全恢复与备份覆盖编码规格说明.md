# v23 损坏配置文件安全恢复与备份覆盖编码规格说明

## 1. 需求背景

当前 VSLoader 配置文件位于：

```text
%AppData%\VSLoader\config.json
```

如果用户手动将 `config.json` 内容删空，或文件内容变成无效 JSON，程序可能无法正常启动，或者在启动过程中弹窗/报错导致体验不稳定。

配置文件损坏属于可恢复问题，不应该导致程序无法启动。

本次 v23 需求需要设计一套安全恢复策略：

```text
坏配置不阻止启动
坏文件不立刻覆盖
首次保存新配置前自动备份坏文件
然后写入新的有效 config.json
```

## 2. 需求目标

本次开发目标：

1. `config.json` 为空时，程序仍可正常启动。
2. `config.json` 是无效 JSON 时，程序仍可正常启动。
3. 启动时使用内存默认配置兜底。
4. 启动阶段不弹自定义模态错误弹窗。
5. 顶部状态栏显示配置读取失败提示。
6. 不在启动时立即覆盖坏的 `config.json`。
7. 用户首次保存有效配置时，先备份坏的 `config.json`。
8. 备份完成后写入新的有效 `config.json`。
9. 保存成功后清除配置读取失败状态。
10. 不影响正常配置文件的读取和保存。

## 3. 修改范围

可能涉及文件：

- `VSLoader\Models\Services\ConfigService.cs`
- `VSLoader\Models\Services\ConfigLoadResult.cs`
- `VSLoader\ViewModels\MainViewModel.cs`

原则上不需要修改：

- `DialogService`
- 主窗口 XAML
- 自定义提示弹窗
- AdminUI 服务
- 批量识别服务
- 数据模型结构

## 4. 当前问题来源

当前 `ConfigService.Load()` 在配置文件不存在时会创建默认配置。

但当配置文件存在且内容为空/损坏时：

- `JsonSerializer.Deserialize<AppConfig>(json)` 可能抛异常。
- 当前逻辑返回 `Success=false` 和默认配置。
- `MainViewModel.LoadConfig()` 可能在启动阶段直接调用 `_dialogService.ShowError(...)`。

启动阶段直接弹自定义窗口不安全，因为主窗口可能尚未完整加载完成。

因此需要：

```text
启动阶段只记录失败状态，不弹窗。
```

## 5. 配置损坏的定义

以下情况都视为配置损坏：

1. `config.json` 文件存在，但内容为空。
2. `config.json` 内容不是合法 JSON。
3. JSON 合法但无法反序列化为 `AppConfig`。
4. 反序列化结果为 `null`。

注意：

如果 JSON 合法，但某些字段缺失，例如：

```json
{
  "VSCodePath": ""
}
```

这不应视为损坏，应通过默认值补齐：

```csharp
config.Shortcuts ??= new List<ShortcutItem>();
config.AdminUi ??= new AdminUiConfig();
config.VSCodePath ??= string.Empty;
```

## 6. Load 行为要求

### 6.1 文件不存在

如果 `config.json` 不存在：

- 创建默认配置。
- 保存默认配置到文件。
- 返回 `Success=true`。

保持当前行为。

### 6.2 文件存在但为空/损坏

如果 `config.json` 存在但为空/损坏：

- 返回默认内存配置。
- 返回 `Success=false`。
- 返回错误信息。
- 标记本次加载来自损坏配置文件。
- 不覆盖原文件。
- 不删除原文件。

## 7. ConfigLoadResult 扩展

建议扩展 `ConfigLoadResult`，增加：

```csharp
public bool HasInvalidConfigFile { get; }
```

构造函数调整为：

```csharp
public ConfigLoadResult(
    AppConfig config,
    bool success,
    string? errorMessage,
    bool hasInvalidConfigFile = false)
```

含义：

- `Success=false`
- `HasInvalidConfigFile=true`

表示：

```text
配置文件存在，但内容损坏；后续首次保存前应备份旧文件。
```

## 8. ConfigService 备份策略

### 8.1 新增备份方法

建议在 `ConfigService` 中新增：

```csharp
public SaveResult BackupInvalidConfigFile()
```

或：

```csharp
public SaveResult BackupConfigFileIfExists()
```

职责：

- 检查 `ConfigPath` 是否存在。
- 如果存在，将其复制为备份文件。
- 不删除原文件。
- 如果备份失败，返回失败结果。

### 8.2 备份文件命名

推荐格式：

```text
config.invalid.yyyyMMdd_HHmmss.json
```

示例：

```text
config.invalid.20260530_231500.json
```

路径仍在：

```text
%AppData%\VSLoader
```

### 8.3 备份冲突处理

使用时间戳通常不会冲突。

如果极端情况下目标备份文件已存在，可追加毫秒或 GUID：

```text
config.invalid.20260530_231500_fff.json
```

可选实现：

```csharp
DateTime.Now.ToString("yyyyMMdd_HHmmss_fff")
```

## 9. MainViewModel 状态要求

在 `MainViewModel` 中新增字段：

```csharp
private bool _hasInvalidConfigFile;
```

加载配置时：

```csharp
_hasInvalidConfigFile = result.HasInvalidConfigFile;
_configLoadFailed = !result.Success;
```

启动时如果失败：

- 不调用 `_dialogService.ShowError(...)`。
- 只调用 `UpdateStatusMessage()` 显示顶部状态栏。

## 10. 保存时备份并覆盖

当前保存入口大概率集中在：

```csharp
SaveCurrentConfig()
```

建议在保存前增加：

```csharp
if (_hasInvalidConfigFile)
{
    var backupResult = _configService.BackupInvalidConfigFile();
    if (!backupResult.Success)
    {
        _dialogService.ShowError($"备份损坏配置文件失败：{backupResult.ErrorMessage}");
        return;
    }

    _hasInvalidConfigFile = false;
}
```

然后再执行：

```csharp
var result = _configService.Save(_config);
```

保存成功后：

```csharp
_configLoadFailed = false;
UpdateStatusMessage();
```

注意：

- 如果备份失败，不应覆盖原坏文件。
- 如果备份成功但保存失败，需要显示保存失败提示。

## 11. 顶部状态栏提示

当配置读取失败时，顶部状态栏继续显示：

```text
配置文件读取失败，请检查 %AppData%\VSLoader\config.json。
```

可选增强文案：

```text
配置文件读取失败，当前已使用默认配置。下次保存时将自动备份旧配置并生成新配置。
```

本次可保留现有文案，避免改动过多。

## 12. 不允许改变的内容

本次不允许改变：

- 配置文件路径。
- 配置 JSON 结构。
- 正常配置读取逻辑。
- 文件不存在时自动创建默认配置的行为。
- ViewModel 业务功能。
- 自定义弹窗组件。
- 主界面布局。
- AdminUI 逻辑。
- 批量识别逻辑。

## 13. 验收标准

### 13.1 空 config.json

操作：

1. 打开 `%AppData%\VSLoader\config.json`。
2. 删除全部内容并保存。
3. 启动 VSLoader。

期望：

- 程序正常启动。
- 不崩溃。
- 不在启动阶段弹错误窗口。
- 顶部状态栏提示配置读取失败。
- 列表为空或使用默认配置。

### 13.2 无效 JSON

将 `config.json` 改为：

```text
abc
```

期望同上：

- 程序正常启动。
- 顶部状态栏提示配置读取失败。
- 不覆盖原文件。

### 13.3 首次保存

在配置损坏状态下：

1. 进入设置保存，或新增快捷项触发保存。

期望：

- 先生成备份文件：

```text
config.invalid.yyyyMMdd_HHmmss_fff.json
```

- 再写入新的有效 `config.json`。
- 顶部配置读取失败提示消失。

### 13.4 备份内容

备份文件内容应与原损坏 `config.json` 内容一致。

### 13.5 备份失败

如果备份失败：

- 不覆盖原 `config.json`。
- 显示错误提示。
- 保留配置读取失败状态。

### 13.6 正常配置

当 `config.json` 正常时：

- 程序正常读取。
- 不创建 invalid 备份。
- 保存逻辑正常。

### 13.7 编译验收

执行：

```powershell
dotnet build .\VSLoader.sln
```

期望：

```text
0 warnings
0 errors
```

如果提示 `VSLoader.exe` 被占用，说明程序正在运行，应先关闭 VSLoader 后重新构建。

## 14. 建议实施步骤

1. 修改 `ConfigLoadResult`，增加 `HasInvalidConfigFile`。
2. 修改 `ConfigService.Load()`：
   - 空文件返回默认配置 + `HasInvalidConfigFile=true`。
   - JSON 异常返回默认配置 + `HasInvalidConfigFile=true`。
   - 不覆盖坏文件。
3. 新增 `ConfigService.BackupInvalidConfigFile()`。
4. 修改 `MainViewModel.LoadConfig()`：
   - 记录 `_hasInvalidConfigFile`。
   - 启动失败时不弹窗。
5. 修改 `MainViewModel.SaveCurrentConfig()`：
   - 保存前备份损坏配置。
   - 备份成功后再保存。
   - 保存成功后清理失败状态。
6. 编译项目。
7. 手动验证空文件、坏 JSON、首次保存。

## 15. 明确不做的事情

本次不做：

- 自动修复坏 JSON。
- 解析损坏 JSON 中的部分数据。
- 启动时覆盖坏文件。
- 启动时弹模态错误窗口。
- 改变配置结构。
