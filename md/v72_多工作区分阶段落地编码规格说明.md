# v72 多工作区分阶段落地编码规格说明

## 1. 文档目的

本文件用于指导编程 Agent 在现有 VSLoader 项目上实现“多工作区数据解耦”能力。

本规格是在 `v71_多工作区数据解耦架构编码规格说明.md` 的基础上进一步细化出来的落地版本。  
`v71` 负责定义大方向，本文件负责回答：

```text
1. 先改哪里，后改哪里。
2. 哪些数据属于程序级，哪些数据属于工作区级。
3. 旧数据如何安全迁移。
4. 如何避免一次性大改导致程序启动失败。
5. 编程 Agent 可以按哪些阶段逐步提交和验证。
```

## 2. 当前项目现状

当前 VSLoader 是 WPF / .NET 8 桌面程序，主要代码位于：

```text
C:\Users\shee_\OneDrive\Desktop\VSLoader\VSLoader
```

当前程序已经具备：

```text
1. VSCode 快捷项打开。
2. 批量新增识别。
3. AdminUI 连接获取和打开。
4. WebUI 打开。
5. 工厂地图窗口。
6. 托盘最小化。
7. 全局快捷键。
8. 窗口位置、地图视图、主列表列宽持久化。
```

当前用户数据主要集中在：

```text
%AppData%\VSLoader
```

典型文件包括：

```text
%AppData%\VSLoader\config.json
%AppData%\VSLoader\window-layout.json
%AppData%\VSLoader\factory-map.layout.json
%AppData%\VSLoader\UIdownload
```

当前关键代码特征：

```text
1. AppConfig 里仍包含 VSCodePath。
2. ConfigService 默认读写 %AppData%\VSLoader\config.json。
3. WindowLayoutService 默认读写 %AppData%\VSLoader\window-layout.json。
4. AdminUiService 默认下载到 %AppData%\VSLoader\UIdownload。
5. MainWindow.ResolveFactoryMapLayoutPath() 当前写死 %AppData%\VSLoader\factory-map.layout.json。
6. MainWindow 当前无参构造，窗口内直接创建固定路径服务。
7. MainViewModel 当前默认无参构造时使用默认 ConfigService / AdminUiService。
```

这些点就是本次改造的主要风险源。

## 3. 最终目标

改造后，VSLoader 不再固定绑定一套用户数据，而是支持多个独立工作区。

可以理解为：

```text
VSLoader 程序本体 = 程序壳
app-settings.json = 程序壳自己的设置
Workspaces = 用户数据大箱子
每个工作区目录 = 一个小箱子
```

每个工作区独立保存：

```text
1. 快捷项。
2. 批量新增历史路径。
3. AdminUI 配置。
4. AdminUI 密码。
5. WebUI 配置。
6. 热键配置。
7. 主窗口位置。
8. 地图窗口位置。
9. 地图缩放和偏移。
10. 主列表列宽。
11. 工厂地图节点和连线。
12. 下载得到的 jnlp 文件。
```

程序级共享保存：

```text
1. VSCode.exe 路径。
2. 工作区列表。
3. 上次打开的工作区。
4. 是否自动打开上次工作区。
5. 旧数据迁移状态。
```

## 5. 数据归属边界

### 5.1 程序级数据

保存到：

```text
%AppData%\VSLoader\app-settings.json
```

字段建议：

```json
{
  "VSCodePath": "",
  "LastWorkspaceId": "default",
  "OpenLastWorkspaceOnStartup": true,
  "MigrationCompleted": true,
  "Workspaces": [
    {
      "Id": "default",
      "Name": "默认工作区",
      "Path": "C:\\Users\\xxx\\AppData\\Roaming\\VSLoader\\Workspaces\\Default",
      "CreatedAt": "2026-06-13T10:00:00",
      "UpdatedAt": "2026-06-13T10:00:00"
    }
  ]
}
```

程序级数据只描述“程序自身如何找到工作区”，不保存具体快捷项。

### 5.2 工作区级数据

每个工作区保存：

```text
workspace.json
config.json
window-layout.json
factory-map.layout.json
UIdownload
```

其中 `config.json` 保存：

```text
1. Shortcuts
2. AdminUi
3. Hotkey
4. BatchImport
5. WebUi
```

注意：

```text
config.json 中可以暂时保留旧字段 VSCodePath 用于兼容旧文件。
但是运行时不得再使用工作区 config.json 的 VSCodePath 作为真实 VSCode 路径。
真实 VSCode 路径只能来自 app-settings.json。
```

## 7. 新增服务

### 7.1 AppSettingsService

新增：

```text
C:\Users\shee_\OneDrive\Desktop\VSLoader\VSLoader\Models\Services\AppSettingsService.cs
```

职责：

```text
1. 读取 app-settings.json。
2. app-settings.json 不存在时创建默认。
3. app-settings.json 损坏时备份并恢复默认。
4. 保存 VSCodePath。
5. 保存工作区列表。
6. 保存 LastWorkspaceId。
```

默认路径：

```text
%AppData%\VSLoader\app-settings.json
```

建议公开属性：

```csharp
public string AppDataDirectory { get; }

public string SettingsPath { get; }
```

建议方法：

```csharp
public AppSettings LoadOrCreate(out string? warningMessage);

public SaveResult Save(AppSettings settings);
```

损坏处理要求：

```text
1. 备份为 app-settings.broken.yyyyMMdd_HHmmss_fff.json。
2. 创建默认 AppSettings。
3. 不让程序因为 app-settings 损坏而无法启动。
```

### 7.2 WorkspaceService

新增：

```text
C:\Users\shee_\OneDrive\Desktop\VSLoader\VSLoader\Models\Services\WorkspaceService.cs
```

职责：

```text
1. 确保 Workspaces 根目录存在。
2. 创建默认工作区。
3. 创建新工作区。
4. 根据 WorkspaceInfo 构造 WorkspaceContext。
5. 验证工作区目录可用。
6. 解析启动时应该打开哪个工作区。
```

建议方法：

```csharp
public WorkspaceContext EnsureDefaultWorkspace(AppSettings settings);

public WorkspaceContext ResolveStartupWorkspace(AppSettings settings);

public WorkspaceContext CreateWorkspace(AppSettings settings, string displayName);

public bool IsWorkspaceUsable(WorkspaceInfo workspace);
```

默认工作区约定：

```text
Id: default
Name: 默认工作区
DirectoryName: Default
```

创建工作区时必须生成：

```text
workspace.json
config.json
UIdownload
```

`window-layout.json` 和 `factory-map.layout.json` 可以由现有服务按需创建。

### 7.3 LegacyWorkspaceMigrationService

新增：

```text
C:\Users\shee_\OneDrive\Desktop\VSLoader\VSLoader\Models\Services\LegacyWorkspaceMigrationService.cs
```

职责：

```text
1. 检测旧版单数据源。
2. 把旧数据复制到 Workspaces\Default。
3. 从旧 config.json 提取 VSCodePath。
4. 写入 app-settings.json。
5. 设置 MigrationCompleted = true。
6. 保留旧文件。
```

旧数据来源：

```text
%AppData%\VSLoader\config.json
%AppData%\VSLoader\window-layout.json
%AppData%\VSLoader\factory-map.layout.json
%AppData%\VSLoader\UIdownload
```

迁移目标：

```text
%AppData%\VSLoader\Workspaces\Default\config.json
%AppData%\VSLoader\Workspaces\Default\window-layout.json
%AppData%\VSLoader\Workspaces\Default\factory-map.layout.json
%AppData%\VSLoader\Workspaces\Default\UIdownload
```

重要规则：

```text
1. 只能复制，不能移动。
2. 不能删除旧文件。
3. 目标文件已存在时不覆盖。
4. 迁移失败要返回错误信息，不能吞掉。
5. MigrationCompleted 为 true 后不能重复迁移。
```

## 8. 现有服务改造要求

### 8.1 ConfigService

当前 `ConfigService` 已经支持传入 `configDirectory`。

改造要求：

```text
1. MainViewModel 必须使用当前 WorkspaceContext.RootPath 创建 ConfigService。
2. 不再在主流程中使用 new ConfigService() 默认路径。
3. ConfigService 继续读写 config.json。
4. AppConfig.VSCodePath 保留兼容，但业务运行时不再使用。
```

### 8.2 WindowLayoutService

当前 `WindowLayoutService` 已经支持传入 `configDirectory`。

改造要求：

```text
1. MainWindow 必须使用当前 WorkspaceContext.RootPath 创建 WindowLayoutService。
2. 主窗口位置、地图窗口位置、地图视图、主列表列宽保存到当前工作区 window-layout.json。
3. 不再使用默认 %AppData%\VSLoader\window-layout.json。
```

### 8.3 FactoryMapLayoutService

当前 `FactoryMapLayoutService` 本身接收 layoutPath。

改造要求：

```text
1. 删除 MainWindow.ResolveFactoryMapLayoutPath() 中的固定 AppData 路径。
2. 改为返回 WorkspaceContext.FactoryMapLayoutPath。
3. 工厂地图节点和连线跟随工作区。
```

### 8.4 AdminUiService

当前 `AdminUiService.DownloadDirectory` 固定为：

```text
%AppData%\VSLoader\UIdownload
```

改造要求：

```text
1. AdminUiService 支持构造时传入 downloadDirectory。
2. MainViewModel 使用 WorkspaceContext.UiDownloadDirectory 创建 AdminUiService。
3. 每个工作区拥有自己的 UIdownload。
```

建议构造：

```csharp
public AdminUiService()
    : this(Path.Combine(
        Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData),
        "VSLoader",
        "UIdownload"))
{
}

public AdminUiService(string downloadDirectory)
{
    _downloadDirectory = downloadDirectory;
}
```

### 8.5 WebUiService

`WebUiService` 不需要保存文件，主要读取快捷项对应目录下的 `INSTANCE.properties`。

改造要求：

```text
无需路径级改造。
WebUiConfig 跟随工作区 config.json 即可。
```


### 10.1 构造函数

当前 MainViewModel 默认使用：


改造后必须支持程序级设置和工作区上下文：

```csharp
public MainViewModel(
    AppSettings appSettings,

    WorkspaceContext workspaceContext,
    ConfigService configService,
```

### 10.2 VSCodePath 来源

当前打开 VSCode 使用：

```csharp
_launcherService.Launch(_config.VSCodePath, SelectedShortcut.TargetPath);
```

改造后必须改为：

```csharp
_launcherService.Launch(_appSettings.VSCodePath, SelectedShortcut.TargetPath);
```

当前状态提示：

```csharp
VSCodeLauncherService.IsValidExecutablePath(_config.VSCodePath)
```

改造后必须使用：

```csharp
VSCodeLauncherService.IsValidExecutablePath(_appSettings.VSCodePath)
```

### 10.3 设置窗口保存拆分

当前设置窗口保存后写入：

```csharp
_config.VSCodePath = viewModel.VSCodePath.Trim();
_config.AdminUi = viewModel.AdminUi.Clone();
_config.Hotkey = viewModel.Hotkey.Clone();
SaveCurrentConfig();
```

改造后：

```text
1. VSCodePath 保存到 app-settings.json。
2. AdminUi 保存到当前工作区 config.json。
3. Hotkey 保存到当前工作区 config.json。
```

伪代码：

```csharp
_appSettings.VSCodePath = viewModel.VSCodePath.Trim();
_appSettingsService.Save(_appSettings);

_config.AdminUi = viewModel.AdminUi.Clone();
_config.Hotkey = viewModel.Hotkey.Clone();

```

## 11. App 启动流程

当前 `App.xaml.cs` 基本为空。

改造后建议在 `App.OnStartup` 中完成启动编排。

启动流程：

```text
1. 创建 AppSettingsService。
2. LoadOrCreate app-settings.json。
3. 创建 WorkspaceService。
4. 执行 LegacyWorkspaceMigrationService.TryMigrate。
5. 根据 appSettings.LastWorkspaceId 解析启动工作区。
6. 如果没有可用工作区，创建 Default。
7. 创建 MainWindow(appSettings, appSettingsService, workspaceContext)。
8. 显示 MainWindow。
```

第一阶段不强制实现完整工作区选择窗口。  
如果没有选择窗口，启动时默认使用 LastWorkspace 或 Default。

## 12. 工作区选择功能分期

### 12.1 第一阶段：隐藏式多工作区底座

目标：


此阶段不做完整工作区选择 UI。


### 12.2 第二阶段：工作区选择窗口

新增：

```text

VSLoader\Views\WorkspaceSelectorWindow.xaml.cs
VSLoader\ViewModels\WorkspaceSelectorViewModel.cs
```

功能：

```text

```

## 13. 旧数据迁移规则

### 13.1 迁移触发条件

满足以下条件时触发迁移：

```text
1. app-settings.json 不存在，或 MigrationCompleted = false。
2. 旧版 %AppData%\VSLoader\config.json 存在。
```

### 13.2 迁移行为

复制：

```text
%AppData%\VSLoader\config.json
  -> %AppData%\VSLoader\Workspaces\Default\config.json

%AppData%\VSLoader\window-layout.json
  -> %AppData%\VSLoader\Workspaces\Default\window-layout.json

%AppData%\VSLoader\factory-map.layout.json
  -> %AppData%\VSLoader\Workspaces\Default\factory-map.layout.json

%AppData%\VSLoader\UIdownload
  -> %AppData%\VSLoader\Workspaces\Default\UIdownload
```

提取：

```text
旧 config.json 中的 VSCodePath
  -> app-settings.json 的 VSCodePath
```

注册：

```text
app-settings.json 中加入 Default 工作区。
LastWorkspaceId = default。
MigrationCompleted = true。
```

### 13.3 迁移安全要求

```text
1. 不删除旧文件。
2. 不覆盖已存在的新工作区文件。
3. 复制失败时，不标记 MigrationCompleted。
4. 迁移失败时允许用户看到明确错误。
5. 迁移成功后，运行时必须使用 Workspaces\Default 下的新文件。
```

## 19. 风险与规避

### 19.1 风险：程序启动链路变复杂

规避：

```text
1. AppSettings 损坏时备份并恢复默认。
2. 工作区缺失时创建 Default。
3. 迁移失败时不删除旧数据。
4. 主窗口创建前必须确保 WorkspaceContext 可用。
```

### 19.2 风险：数据写到旧路径

规避：

```text
所有工作区级路径必须从 WorkspaceContext 派生。
实现后必须用 rg 搜索硬编码路径。
```

### 19.3 风险：VSCodePath 双来源

规避：

```text
1. 旧 config.json 中的 VSCodePath 只用于迁移。
2. 运行时只读 app-settings.json。
3. 设置窗口保存 VSCodePath 时只写 app-settings.json。
```

### 19.4 风险：一次性实现工作区选择窗口导致主流程不稳

规避：

```text
先实现隐藏式 Default 工作区底座。
等底层稳定后，再做选择窗口。
```
