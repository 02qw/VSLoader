# 独立代码差异对比工具设计规格说明

## 1. 文档状态

- 日期：2026-08-10
- 状态：待用户审核
- 当前范围：只实现独立 WPF 程序，不修改 VSLoader，不实现右键入口
- 目标程序名：`UpAndown.CodeCompare.exe`

## 2. 背景与目标

工具用于比较本地开发模块与 Windows 共享文件夹中的已部署模块，重点覆盖 Groovy、XML、Properties 等代码和配置文件，并把选中的文件交给 VS Code 或 IDEA 打开差异。

本地实例示例：

`C:\Users\shee_\OneDrive\Desktop\macmic.eap.sic\eap-sic-AMX-Sintering`

线上实例示例：

`\\192.168.15.69\instances\3134_TSSP001`

第一版必须支持两侧任选其一作为编辑侧。线上文件编辑前先在本机生成备份，文件保存仍由用户选择的 IDE 完成。

## 3. 非目标

第一版不包含：

- VSLoader 内建按钮或右键菜单接入
- 自动把本地代码同步到线上或把线上代码同步回本地
- 自动部署、重启服务或运行时健康检查
- 内置代码编辑器
- 通用 DLL 插件系统
- 对 JAR、日志、转储和完整运行时目录做默认内容比较

## 4. 技术与程序边界

使用 .NET 8 WPF，生成可直接启动的独立 Windows EXE。比较逻辑、XML 解析、备份和 IDE 启动放在独立服务类中，窗口只负责输入、状态展示和用户操作。

程序支持两种启动方式：

1. 无参数启动，用户在窗口中选择本地目录和线上目录。
2. 命令行启动：

```text
UpAndown.CodeCompare.exe --local <localRoot> --remote <remoteRoot> [--scope <relativePath>] [--ide vscode|idea]
```

`--local` 和 `--remote` 是目录根；`--scope` 默认是 `config\deo`。参数不完整或路径不可访问时，程序打开窗口并保留可修正的输入状态。

## 5. 对比模型

### 5.1 路径配对

两侧以相对路径作为配对键，比较时使用 Windows 不区分大小写的路径规则。默认只扫描选定范围，不把线上实例下的 `config\common-deo`、`lib`、`log`、`tmp`、`dumps` 等运行时目录混入模块结果。

第一版默认关注的文本扩展名：`.groovy`、`.xml`、`.properties`、`.java`、`.json`、`.yaml`、`.yml`、`.sql`、`.html`、`.css`、`.js`、`.ts`。未知扩展名允许在高级设置中加入；JAR、GZ、日志和二进制文件默认排除。

### 5.2 文件状态

每个相对路径产生一个结果：

- `Same`：两侧 SHA-256 相同
- `Changed`：两侧都存在但内容不同
- `LocalOnly`：仅本地存在
- `RemoteOnly`：仅线上存在
- `ReadError`：任一侧读取失败，保留错误原因

最终一致性判断使用 SHA-256，不使用修改时间作为依据。扫描结果包含本地路径、线上路径、文件大小、修改时间、哈希和读取错误。

### 5.3 DeoWiringConfig 专门解析

`config\deo\config\DeoWiringConfig_1.xml` 先作为普通 XML 做文本差异，再额外生成语义摘要：

- `deoWiring@id` 的新增、删除和修改
- 每个 `deoReferenceSequence` 的 DEO 顺序变化
- `deoUuid`、`deoId`、`owner`、`shared`、`asynchron`、`stopOnError`、`execute` 变化
- 输入绑定、结果绑定和绑定参数变化

UUID 只作为 DEO 身份关联键，不把 UUID 当成文件内容哈希。XML 解析失败时仍保留普通文本差异，并显示解析错误。

## 6. 界面与交互

主窗口包含：

- 本地目录输入框和选择按钮
- 线上目录输入框和选择按钮，允许 UNC 路径
- 对比范围输入或预设选择，默认 `config\deo`
- 扫描、取消、重新扫描按钮
- 状态计数：一致、变化、仅本地、仅线上、读取失败
- 差异列表，支持按状态、扩展名和相对路径筛选
- 详情区域，显示选中文件的两侧路径、哈希、XML 语义摘要和错误信息
- `编辑本地`、`编辑线上`、`打开所在目录` 操作

扫描使用异步任务和取消令牌，窗口线程不能因 UNC 读取或哈希计算卡住。扫描期间禁止重复启动同一组目录对比。

## 7. IDE 与保存安全

VS Code 使用 `Code.exe --diff <left> <right>` 启动，并根据编辑目标调整左右顺序，使可编辑侧位于右侧。IDEA 作为可选适配器，路径由设置指定；未配置时不影响 VS Code 使用。

点击 `编辑线上` 时：

1. 再次确认目标完整路径和“直接修改共享文件”的风险。
2. 对已有线上文件读取原始字节并保存到本机备份目录。
3. 记录备份的原始 SHA-256、时间、相对路径和线上根目录。
4. 备份成功后才启动 IDE。

扫描不写入任何一侧。第一版不自动把 IDE 保存后的文件复制到另一侧，由用户明确选择编辑侧并手工保存。

## 8. 配置与日志

用户设置存放在 `%APPDATA%\UpAndown\CodeCompare`，包括最近目录、默认范围、忽略规则、IDE 路径和备份目录。日志只记录扫描耗时、文件状态统计、失败原因和 IDE 启动结果，不记录文件内容。

## 9. 错误处理

- 本地路径不存在：阻止扫描并指出路径。
- UNC 不可达或权限不足：保留本地结果，线上文件标为 `ReadError`，显示可操作原因。
- 单个文件读取失败：不中断整次扫描。
- XML 结构错误：普通文件状态仍然有效，语义摘要显示解析失败。
- IDE 启动失败：显示已生成的备份路径和完整错误信息。
- 线上文件在备份后被其他进程修改：启动前再次比较原始哈希，发现变化则要求用户重新确认。

## 10. 测试与验收

### 10.1 自动化测试

使用临时目录覆盖 Same、Changed、LocalOnly、RemoteOnly、ReadError、大小写路径和忽略规则；XML 测试覆盖 DEO 顺序、绑定参数和属性变化；备份测试验证原始字节、哈希和恢复结果。

### 10.2 真实目录只读验收

对给出的本地和线上目录执行一次独立 PowerShell 哈希清单，再与程序结果逐项对照。当前基线预期包括：两个 `DeoWiringConfig_1.xml` 字节一致，以及线上 `config\deo` 的额外 Groovy 文件被标为 `RemoteOnly`。实际验收以执行时的独立清单为准。

### 10.3 IDE 手工验收

使用临时目录中的 Changed 文件验证本地编辑、线上编辑确认、备份生成、保存后重新扫描和备份恢复。生产共享目录只做读取和打开差异验证，除非提供明确的共享测试目录写权限。

### 10.4 完成标准

- 自动化测试通过。
- 独立哈希清单与 UI 统计、逐文件状态一致。
- UNC 读取失败、取消和单文件错误不会导致窗口崩溃。
- 线上编辑永远先备份后启动 IDE。
- 真实示例目录扫描不会产生文件写入。
- 发布目录包含可独立启动的 EXE 和必要运行时文件。

## 11. 后续接入 VSLoader 的预留

独立程序暂不引用 VSLoader 程序集，只通过命令行参数工作。后续接入时，VSLoader 只需新增一个内建入口并传入现有快捷项的 `TargetPath`、`SourceModuleName` 和工作区信息；比较服务和 UI 不需要依赖 `MainViewModel`。
