# v97 更新器外部运行副本防止文件锁定编码规格说明

## 1. 背景

其他电脑使用软件自动更新时，更新器报错日志显示：

```text
Step: 替换程序文件
TargetDirectory: D:\AAA\VSLoader_3.0.6_win-x64
StagingDirectory: C:\Users\wenlong\AppData\Local\VSLoader\Updates\staging\3.0.7

System.IO.IOException:
The process cannot access the file
'D:\AAA\VSLoader_3.0.6_win-x64\clrjit.dll'
because it is being used by another process.
```

结合当前代码，主程序启动 updater 的路径是：

```csharp
var updaterPath = Path.Combine(AppContext.BaseDirectory, "VSLoader.Updater.exe");
```

也就是说，`VSLoader.Updater.exe` 是从当前待更新的程序目录里启动的。

当 updater 自己运行时，它可能会加载同目录下的运行时文件，例如：

- `clrjit.dll`
- `coreclr.dll`
- `hostfxr.dll`
- `hostpolicy.dll`
- 其他 .NET runtime 相关文件

随后 updater 又要覆盖同一个程序目录，于是出现：

```text
旧目录里的 updater 正在运行
旧目录里的 runtime dll 被 updater 锁定
updater 又尝试覆盖旧目录
Windows 拒绝覆盖被占用的 dll
```

这就是本次更新失败的根因。

## 2. 目标

本次修复目标：

- updater 不再从待覆盖的原程序目录直接运行。
- 用户确认更新后，主程序先创建一个外部 updater 运行副本。
- 从外部副本启动 `VSLoader.Updater.exe`。
- 外部 updater 等待主程序退出后，再覆盖原程序目录。
- 每次更新前清空旧的外部副本目录，避免临时 updater 文件越积越多。
- 不破坏现有更新主流程、manifest 校验、SHA 校验、解压、回滚、更新完成确认弹窗等逻辑。

## 3. 方案概述

采用最稳方案：

```text
复制整个当前程序目录到外部 UpdaterRunner
从 UpdaterRunner 启动 VSLoader.Updater.exe
由外部 updater 覆盖原程序目录
```

示例：

原程序目录：

```text
D:\AAA\VSLoader_3.0.6_win-x64
```

外部 updater 运行副本：

```text
%LocalAppData%\VSLoader\UpdaterRunner
```

启动链路：

```text
VSLoader.exe
  -> 清空 %LocalAppData%\VSLoader\UpdaterRunner
  -> 复制当前程序目录全部文件到 UpdaterRunner
  -> 启动 UpdaterRunner\VSLoader.Updater.exe
  -> VSLoader.exe 退出
  -> UpdaterRunner\VSLoader.Updater.exe 等待 VSLoader 进程退出
  -> 覆盖原程序目录
  -> 启动新版 VSLoader.exe
```

## 4. 为什么复制整个目录

不要只复制：

```text
VSLoader.Updater.exe
```

原因：

updater 运行时不仅需要 exe，还可能需要：

- `VSLoader.Updater.dll`
- `VSLoader.Updater.deps.json`
- `VSLoader.Updater.runtimeconfig.json`
- .NET self-contained runtime dll
- 图标资源
- 其他运行依赖

本次故障中的 `clrjit.dll` 正是 runtime 文件。为了避免外部 updater 又回到原程序目录加载 runtime 文件，必须让外部副本拥有完整运行环境。

因此采用复制整个程序目录的方式，牺牲少量复制时间，换取最高稳定性。

## 5. 影响范围

主要修改：

- `VSLoader/ViewModels/MainViewModel.cs`

可能新增：

- `VSLoader/Models/Services/UpdaterRunnerService.cs`

可能新增或调整测试：

- `VSLoader.Tests/MainViewModelSoftwareUpdateTests.cs`
- 新增 `UpdaterRunnerServiceTests.cs`

不修改：

- `VSLoader.Updater/Services/UpdaterUpdateService.cs` 的下载、解压、SHA 逻辑
- `VSLoader.Updater/Services/UpdaterApplyService.cs` 的复制、回滚主逻辑
- `manifest.json` 格式
- 更新完成确认弹窗逻辑

## 6. 详细设计

### 6.1 新增 UpdaterRunnerService

新增服务：

```csharp
public sealed class UpdaterRunnerService
```

职责：

- 计算外部 updater 运行目录
- 清空旧的 `UpdaterRunner`
- 复制当前程序目录到 `UpdaterRunner`
- 返回外部副本中的 `VSLoader.Updater.exe` 路径

建议接口：

```csharp
public PrepareUpdaterRunnerResult Prepare(string sourceDirectory, string updaterExeName = "VSLoader.Updater.exe");
```

结果模型：

```csharp
public sealed class PrepareUpdaterRunnerResult
{
    public bool Success { get; init; }
    public string RunnerUpdaterPath { get; init; } = string.Empty;
    public string ErrorMessage { get; init; } = string.Empty;
}
```

### 6.2 UpdaterRunner 目录位置

固定使用：

```text
%LocalAppData%\VSLoader\UpdaterRunner
```

代码：

```csharp
Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
    "VSLoader",
    "UpdaterRunner")
```

每次更新前：

- 如果目录存在，先删除
- 然后重新创建
- 再复制当前程序目录内容

这样不会留下：

```text
UpdaterRunner_1
UpdaterRunner_2
UpdaterRunner_3
```

不会随着更新次数增多产生垃圾目录。

### 6.3 复制策略

从当前程序目录复制全部内容到 `UpdaterRunner`。

源目录：

```csharp
AppContext.BaseDirectory
```

目标目录：

```text
%LocalAppData%\VSLoader\UpdaterRunner
```

复制要求：

- 递归复制所有文件夹
- 递归复制所有文件
- 保留相对目录结构
- 如果复制失败，返回失败结果，不启动 updater，不退出主程序

注意：

- 不需要复制 `UpdaterRunner` 自己，因为它在 `%LocalAppData%`，不在程序目录下。
- 如果未来程序目录下存在极大缓存或用户数据，再考虑排除；本次优先稳定，不做复杂排除。

### 6.4 MainViewModel 启动更新器逻辑调整

当前逻辑：

```csharp
var updaterPath = Path.Combine(AppContext.BaseDirectory, "VSLoader.Updater.exe");
StartUpdater(updaterPath, arguments);
```

改为：

```text
Prepare UpdaterRunner
拿到 runnerUpdaterPath
StartUpdater(runnerUpdaterPath, arguments)
```

逻辑要求：

1. 用户确认更新后才复制 runner。
2. 复制 runner 失败时：
   - 显示错误弹窗
   - 不启动 updater
   - 不退出主程序
3. 启动 runner updater 失败时：
   - 显示错误弹窗
   - 不退出主程序
4. 启动成功后：
   - 调用 `RequestApplicationExit()`

### 6.5 参数保持不变

传给 updater 的参数不变：

- `--mode update`
- `--processId`
- `--targetDir`
- `--mainExeName`
- `--manifestPath`
- `--currentVersion`
- `--updatesRoot`

其中 `--targetDir` 仍然指向原程序目录：

```text
D:\AAA\VSLoader_3.0.6_win-x64
```

这点非常重要：

外部 updater 的运行目录是 `UpdaterRunner`，但它要覆盖的目标目录仍然是原程序目录。

### 6.6 updater 侧无需大改

`VSLoader.Updater` 侧已经会：

- 等待主程序进程退出
- 读取 manifest
- 解压更新包
- 替换 `TargetDirectory`
- 回滚
- 写错误日志

因此本次原则上不需要大改 updater 侧逻辑。

### 6.7 清理策略

每次更新前由主程序清理：

```text
%LocalAppData%\VSLoader\UpdaterRunner
```

更新完成后不强制让 updater 删除自身所在目录。

原因：

- 运行中的 updater 删除自身目录有额外复杂度
- 固定目录下次更新前会被清空
- 不会无限堆积
- 失败时保留 runner 有利于排查

## 7. 异常处理

### 7.1 清理旧 runner 失败

可能原因：

- 上一次 updater 仍在运行
- 文件被杀毒软件扫描占用
- 权限不足

处理：

- 返回失败
- 弹窗提示：

```text
准备更新器运行副本失败：{具体错误}
```

- 不退出主程序

### 7.2 复制 runner 失败

可能原因：

- 当前程序目录文件被占用
- 磁盘空间不足
- 权限不足

处理同上。

### 7.3 runner 中缺少 updater exe

复制完成后检查：

```text
UpdaterRunner\VSLoader.Updater.exe
```

如果不存在：

- 返回失败
- 不启动 updater
- 不退出主程序

### 7.4 启动 runner updater 失败

沿用现有逻辑：

- `StartUpdater(...)` 返回 false
- 显示“更新器启动失败，主程序不会退出。”
- 不退出主程序

## 8. 测试要求

### 8.1 UpdaterRunnerService 测试

覆盖：

1. 能复制完整目录结构
   - 源目录有子目录和文件
   - runner 目录中存在同样结构

2. 每次准备前会清空旧 runner
   - runner 中预先放一个旧文件
   - prepare 后旧文件不存在

3. 返回外部 updater 路径
   - 返回路径位于 runner 目录
   - 文件名是 `VSLoader.Updater.exe`

4. 源目录缺少 updater exe 时失败
   - 返回 `Success = false`
   - ErrorMessage 清晰

### 8.2 MainViewModel 更新启动测试

覆盖：

1. 用户确认更新后会使用 runner updater 路径启动
2. runner 准备失败时不启动 updater
3. runner 准备失败时不退出主程序
4. runner 准备成功但启动失败时不退出主程序
5. runner 启动成功后才退出主程序

### 8.3 回归测试

执行：

```powershell
dotnet test .\VSLoader.sln -c Debug
dotnet build .\VSLoader.sln -c Debug
```

要求：

- 测试通过
- 构建通过
- 无新增警告

## 9. 验收标准

满足以下条件即完成：

- 点击更新后，实际启动的 updater 路径位于：

```text
%LocalAppData%\VSLoader\UpdaterRunner
```

- updater 不再从原程序目录运行
- 更新时不再因为原目录中的 `clrjit.dll` / runtime dll 被 updater 自己占用而失败
- 每次更新前会清空旧 `UpdaterRunner`
- 复制或启动 runner 失败时，主程序不会退出
- 原有更新完成确认、releaseNotes 展示、错误日志机制不被破坏
