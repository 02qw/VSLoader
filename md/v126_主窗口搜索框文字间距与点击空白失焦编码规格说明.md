# v126 主窗口搜索框文字间距与点击空白失焦编码规格说明

## 1. 背景

主窗口顶部搜索框用于按名称、路径、备注筛选快捷项。

当前用户反馈两个体验问题：

```text
1. 搜索框里的文字太靠右，输入框左边空白太多。
2. 搜索框获得焦点后，点击输入框以外的地方，输入框好像不会失焦。
```

本次需求只处理主窗口搜索框体验，不扩展到设置页、编辑快捷项弹窗、工作区弹窗等其它输入场景。

## 2. 当前相关代码

主窗口搜索框位于：

```text
VSLoader/MainWindow.xaml
```

当前写法：

```xml
<TextBox Grid.Column="0"
         Style="{StaticResource ModernTextBoxStyle}"
         Height="36"
         Padding="10,7"
         VerticalContentAlignment="Center"
         Text="{Binding SearchText, UpdateSourceTrigger=PropertyChanged}"
         ToolTip="按名称、路径、备注搜索" />
```

统一输入框样式位于：

```text
VSLoader/Styles/ModernTheme.xaml
```

当前 `ModernTextBoxStyle` 里模板内容区：

```xml
<ScrollViewer x:Name="PART_ContentHost"
              Margin="10,0"
              VerticalAlignment="Center" />
```

也就是说搜索框有两层横向内边距：

```text
TextBox.Padding = 10
PART_ContentHost.Margin = 10
```

最终视觉上左边空白叠加，导致文字明显靠右。

## 3. 问题描述

### 3.1 文字靠右

当前搜索框文字位置由两处共同决定：

- `MainWindow.xaml` 搜索框自身的 `Padding="10,7"`。
- `ModernTextBoxStyle` 模板中的 `PART_ContentHost Margin="10,0"`。

由于模板已经提供了统一输入框内容边距，主窗口搜索框再单独设置 `Padding` 会造成重复。

### 3.2 点击空白区域不失焦

WPF 默认行为中：

```text
TextBox 获得键盘焦点后，如果用户点击的是不可聚焦区域，TextBox 不一定自动失去键盘焦点。
```

主窗口当前没有统一的“点击非输入区域时清除输入焦点”逻辑。

因此搜索框获得焦点后，用户点击表格空白、按钮旁空白、页面空白时，搜索框可能仍保持输入状态。

## 4. 目标

本次目标：

- 搜索框文字左侧空白恢复到正常现代输入框间距。
- 搜索框不要因为双层边距导致文字过度靠右。
- 点击主窗口中非输入控件区域时，搜索框应失去键盘焦点。
- 点击搜索框内部时，搜索框仍可正常输入。
- 点击其它可输入控件时，不应被强制清除焦点。
- 不影响主窗口搜索过滤逻辑。
- 不影响主窗口按钮点击。
- 不影响表格选择、滚动、右键菜单。
- 不影响设置页、编辑快捷项弹窗、工作区弹窗等其它窗口输入。

## 5. 非目标

本次不做以下事项：

- 不重构 `ModernTextBoxStyle` 全局模板。
- 不调整设置页输入框样式。
- 不调整编辑快捷项弹窗输入框样式。
- 不调整工作区命名弹窗输入框样式。
- 不修改搜索算法。
- 不修改快捷项列表筛选规则。
- 不修改地图快捷键逻辑。
- 不新增配置项。

## 6. 推荐方案

### 6.1 搜索框移除重复 Padding

只修改：

```text
VSLoader/MainWindow.xaml
```

将搜索框中的局部：

```xml
Padding="10,7"
VerticalContentAlignment="Center"
```

删除。

修改后：

```xml
<TextBox Grid.Column="0"
         Style="{StaticResource ModernTextBoxStyle}"
         Height="36"
         Text="{Binding SearchText, UpdateSourceTrigger=PropertyChanged}"
         ToolTip="按名称、路径、备注搜索" />
```

原因：

- `ModernTextBoxStyle` 已经定义了统一 `Padding`、字体、垂直对齐和模板内容区域。
- 只移除主窗口搜索框局部覆盖，影响范围最小。
- 不动全局样式，避免影响其它窗口输入框。

### 6.2 主窗口增加点击空白失焦处理

在：

```text
VSLoader/MainWindow.xaml.cs
```

构造函数中增加：

```csharp
PreviewMouseDown += MainWindow_PreviewMouseDown;
```

新增方法：

```csharp
private void MainWindow_PreviewMouseDown(object sender, MouseButtonEventArgs e)
{
    if (Keyboard.FocusedElement is not DependencyObject focusedElement)
    {
        return;
    }

    if (!IsTextInputElement(focusedElement))
    {
        return;
    }

    if (IsTextInputElement(e.OriginalSource as DependencyObject))
    {
        return;
    }

    Keyboard.ClearFocus();
}
```

该逻辑含义：

- 只有当前焦点在输入控件里时才处理。
- 如果本次点击目标仍然是输入控件，不清焦。
- 如果本次点击目标不是输入控件，则清除键盘焦点。

### 6.3 复用现有输入控件判断

当前 `MainWindow.xaml.cs` 已有：

```csharp
private static bool IsTextInputElement(DependencyObject? source)
```

该方法已经判断：

```csharp
source is TextBox
    or PasswordBox
    or RichTextBox
```

以及：

```csharp
ComboBox { IsEditable: true }
```

本次应复用该方法，不新增第二套输入控件判断。

## 8. 测试要求

### 8.1 搜索框不重复设置 Padding

新增或更新测试文件：

```text
VSLoader.Tests/MainWindowSearchBoxTests.cs
```

测试内容：

```csharp
namespace VSLoader.Tests;

public sealed class MainWindowSearchBoxTests
{
    [Fact]
    public void Main_search_box_uses_modern_textbox_spacing_without_extra_local_padding()
    {
        var xaml = File.ReadAllText(TestProjectPaths.GetProjectFilePath(
            "VSLoader",
            "MainWindow.xaml"));

        Assert.Contains("Text=\"{Binding SearchText, UpdateSourceTrigger=PropertyChanged}\"", xaml);
        Assert.DoesNotContain("Padding=\"10,7\"", xaml);
        Assert.DoesNotContain("VerticalContentAlignment=\"Center\"\r\n                             Text=\"{Binding SearchText", xaml);
    }
}
```

如果担心 `Padding="10,7"` 在主窗口其它控件中仍然合法，可以把测试写得更精确：

```csharp
var searchTextIndex = xaml.IndexOf("Text=\"{Binding SearchText", StringComparison.Ordinal);
var textBoxStart = xaml.LastIndexOf("<TextBox", searchTextIndex, StringComparison.Ordinal);
var textBoxEnd = xaml.IndexOf("/>", searchTextIndex, StringComparison.Ordinal);
var searchBoxBlock = xaml[textBoxStart..textBoxEnd];

Assert.DoesNotContain("Padding=", searchBoxBlock);
Assert.DoesNotContain("VerticalContentAlignment=", searchBoxBlock);
```

推荐使用更精确的第二种写法。

## 11. 风险与边界

### 11.1 不改全局 ModernTextBoxStyle 的原因

`ModernTextBoxStyle` 被多个窗口复用：

- 主窗口搜索框。
- 设置页输入框。
- 编辑快捷项窗口输入框。
- 工作区命名弹窗输入框。

如果直接调整模板中的 `PART_ContentHost Margin`，可能改变所有输入框视觉。

本次问题来自主窗口搜索框局部重复设置 `Padding`，因此应只删除主窗口搜索框局部覆盖。

### 11.2 为什么清焦只在 MainWindow 做

用户反馈发生在主窗口搜索框。

其它窗口可能有自己的输入交互逻辑，例如：

- 设置页快捷键录制。
- 编辑快捷项弹窗路径输入。
- 工作区命名弹窗输入。

本次只给主窗口增加点击空白清焦，避免扩大影响范围。

### 11.3 为什么点击按钮时可以清焦

点击按钮时：

```text
PreviewMouseDown 先清除搜索框焦点
随后按钮自己的 Click 仍继续触发
```

不要设置：

```csharp
e.Handled = true;
```

否则会吞掉按钮点击，这是本次实现必须避免的点。

## 12. 验收标准

实现完成后必须满足：

- 主窗口搜索框不再包含局部 `Padding="10,7"`。
- 主窗口搜索框不再包含局部 `VerticalContentAlignment="Center"`。
- `MainWindow.xaml.cs` 订阅 `PreviewMouseDown`。
- `MainWindow.xaml.cs` 存在 `MainWindow_PreviewMouseDown(...)`。
- 点击非输入区域时调用 `Keyboard.ClearFocus()`。
- 点击输入控件本身时不清焦。
- `MainWindow_PreviewMouseDown(...)` 不设置 `e.Handled = true`。
- 定向测试通过。
- 全量测试通过。
- Debug 构建通过。
