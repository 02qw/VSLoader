# v141 现代输入框内容左侧空白与垂直裁切修复编码规格说明

## 1. 背景

用户反馈：程序中凡是涉及输入框的位置，文本内容前面都有明显空白。

典型表现：

```text
1. 主界面搜索框中，光标离左边框过远。
2. 设置窗口中 AdminUI、WebUI、VSCode 路径等输入框，文本起点整体偏右。
3. 初步修复后，设置窗口 VSCode 路径输入框出现文字下沉 / 被裁切。
```

截图现象说明：

```text
主界面搜索框：
  左侧留白过大，光标不贴近合理的 8px - 12px 内边距。

设置窗口 VSCode 路径输入框：
  文本不只偏右，还出现垂直方向下沉，长路径上半部分被遮挡。
```

## 3. 根因分析

### 3.1 第一层问题：内容宿主硬编码 Margin

原始模板中有类似写法：

```xml
<Setter Property="Padding" Value="10,0" />

<ScrollViewer x:Name="PART_ContentHost"
              Margin="10,0"
              VerticalAlignment="Center" />
```

这会导致文本内容起点被重复推开：

```text
TextBox.Padding
+
PART_ContentHost.Margin
=
视觉上过大的左侧空白
```

### 3.2 第二层问题：把 Padding 绑定到外层 Border 也不正确

一次不完整修法可能会写成：

```xml
<Border Padding="{TemplateBinding Padding}">
    <ScrollViewer x:Name="PART_ContentHost"
                  VerticalAlignment="Center" />
</Border>
```

这仍然会造成 `Padding` 被二次消费：

```text
TextBox 自身 Padding 参与内部文本布局
+
外层 Border.Padding 再次挤压内容区域
```

尤其设置页中存在局部覆盖：

```xml
Padding="8,6"
```

如果外层 `Border` 再吃一次 `Padding="8,6"`，高度为 34 的输入框就容易出现垂直空间不足，导致文字下沉或被裁切。

### 3.3 结论

输入框模板里不能再二次处理 `Padding`。

最终原则：

```text
TextBox.Padding / PasswordBox.Padding 只由控件自身负责。
ControlTemplate 里的 Border 只负责背景、边框、圆角。
PART_ContentHost 不写死 Margin。
PART_ContentHost 不绑定 Padding。
```

## 6. 设计原则

### 6.1 单一内边距来源

输入框文本内边距只允许来自控件自身的 `Padding`。

禁止：

```xml
<ScrollViewer x:Name="PART_ContentHost" Margin="10,0" />
<ScrollViewer x:Name="PART_ContentHost" Margin="10,8" />
<Border Padding="{TemplateBinding Padding}">
```

允许：

```xml
<Setter Property="Padding" Value="10,0" />

<Border ...>
    <ScrollViewer x:Name="PART_ContentHost"
                  VerticalAlignment="Center" />
</Border>
```

多行输入框允许：

```xml
<Setter Property="Padding" Value="10,8" />

<Border ...>
    <ScrollViewer x:Name="PART_ContentHost" />
</Border>
```

### 6.2 单行输入框垂直稳定

单行输入框：

```text
Height = 34
Padding = 10,0
VerticalContentAlignment = Center
PART_ContentHost VerticalAlignment = Center
```

页面局部如果覆盖：

```xml
Padding="8,6"
```

模板不能再额外使用这个 Padding。否则会出现文字被挤压。

### 6.3 多行输入框不要强行居中

多行输入框：

```text
Height = Auto
MinHeight = 96
Padding = 10,8
VerticalContentAlignment = Top
PART_ContentHost 不设置 VerticalAlignment=Center
```

### 6.4 PasswordBox 同步修复

虽然当前 AdminUI 密码已经改为明文 TextBox，但 `ModernPasswordBoxStyle` 仍然是全局样式资源，必须同步修复，避免后续窗口重新使用时复现。

## 7. 具体改动规格

### 7.1 修改 ModernTextBoxStyle

文件：

```text
VSLoader/Styles/ModernTheme.xaml
```

目标结构：

```xml
<Style x:Key="ModernTextBoxStyle" TargetType="TextBox">
    <Setter Property="Height" Value="34" />
    <Setter Property="Padding" Value="10,0" />
    <Setter Property="VerticalContentAlignment" Value="Center" />
    ...
    <Setter Property="Template">
        <Setter.Value>
            <ControlTemplate TargetType="TextBox">
                <Border x:Name="Root"
                        Background="{TemplateBinding Background}"
                        BorderBrush="{TemplateBinding BorderBrush}"
                        BorderThickness="{TemplateBinding BorderThickness}"
                        CornerRadius="6"
                        SnapsToDevicePixels="True">
                    <ScrollViewer x:Name="PART_ContentHost"
                                  VerticalAlignment="Center" />
                </Border>
                ...
            </ControlTemplate>
        </Setter.Value>
    </Setter>
</Style>
```

必须移除：

```xml
Margin="10,0"
Padding="{TemplateBinding Padding}"
```

## 8. 局部页面处理要求

### 8.1 SettingsWindow.xaml

设置页存在局部覆盖：

```xml
Padding="8,6"
Padding="8,4"
```

本次不强制移除这些局部 Padding。

原因：

```text
局部 Padding 可以表达该页面希望的内部距离。
真正的问题是模板二次消费 Padding。
只要模板不再用 Border.Padding 或 PART_ContentHost.Margin，局部 Padding 不会造成双重空白或垂直裁切。
```

但执行后必须人工检查：

```text
VSCode 路径输入框文字不下沉。
AdminUI 各项输入框文字垂直居中。
WebUI 各项输入框文字垂直居中。
```

### 8.2 MainWindow.xaml

主界面搜索框不需要单独改 XAML。

验收重点：

```text
光标左侧距离约为 10px 左右。
不应出现接近 20px 以上的明显空白。
```

### 8.3 ShortcutEditWindow / BatchImportWindow / WorkspaceNameDialog

这些窗口使用同一全局样式，原则上自动受益。

执行后需要快速启动检查或用 XAML 测试覆盖。

## 9. 测试规格

### 9.1 修改 ModernThemeResourceTests

文件：

```text
VSLoader.Tests/ModernThemeResourceTests.cs
```

新增或调整测试：

```csharp
[Fact]
public void Modern_input_templates_do_not_double_apply_text_padding()
{
    var xaml = ReadModernThemeXaml();

    Assert.DoesNotContain("Margin=\"10,0\"", xaml);
    Assert.DoesNotContain("Margin=\"10,8\"", xaml);
    Assert.DoesNotContain("Padding=\"{TemplateBinding Padding}\"", xaml);
    Assert.Contains("x:Key=\"ModernTextBoxStyle\"", xaml);
    Assert.Contains("x:Key=\"ModernMultilineTextBoxStyle\"", xaml);
    Assert.Contains("x:Key=\"ModernPasswordBoxStyle\"", xaml);
}
```

如果已有类似测试，需要把旧断言：

```csharp
Assert.Contains("Padding=\"{TemplateBinding Padding}\"", xaml);
```

改为：

```csharp
Assert.DoesNotContain("Padding=\"{TemplateBinding Padding}\"", xaml);
```

### 9.2 保留 SettingsWindowModernInputTests

文件：

```text
VSLoader.Tests/SettingsWindowModernInputTests.cs
```

现有测试应继续通过：

```text
Settings 窗口仍使用 ModernTextBoxStyle。
仍保留 SettingsInput_PreviewMouseWheel。
不重新引入 PasswordBox。
```

### 9.3 可选增加 XAML 局部覆盖保护

可在 `SettingsWindowModernInputTests` 中增加轻量断言：

```csharp
Assert.Contains("Padding=\"8,6\"", xaml);
Assert.Contains("Style=\"{StaticResource ModernTextBoxStyle}\"", xaml);
```

目的不是要求必须有局部 Padding，而是确认局部 Padding 与全局模板不再冲突。

如果实现过程中决定统一移除局部 Padding，则不要加这个断言。
