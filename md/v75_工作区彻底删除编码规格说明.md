# v75 工作区彻底删除编码规格说明

## 1. 文档目的

本文件用于指导编程 Agent 在现有 VSLoader 多工作区功能上增加：

```text
选择工作区窗口中的“删除”功能。
```

用户确认的关键规则：

```text
1. 删除是彻底删除。
2. 删除工作区时必须删除该工作区对应的整个磁盘文件夹。
3. 当前正在使用的工作区不能删除。
4. 最后一个工作区不能删除。
5. 默认工作区没有特殊保护，只要不是当前正在使用、也不是最后一个，就可以删除。
6. 删除前必须弹出确认窗口，用户确认后才执行。
```

当前已经存在多工作区底座：

```text

VSLoader\Views\WorkspaceSelectorWindow.xaml.cs
VSLoader\App.xaml.cs
VSLoader\MainWindow.xaml.cs
```

当前工作区配置位置：

```text
%AppData%\VSLoader\app-settings.json
```

当前每个工作区数据目录：

```text
%AppData%\VSLoader\Workspaces\<WorkspaceFolder>\
```

工作区目录内可能包含：

```text
workspace.json
config.json
window-layout.json
factory-map.layout.json
UIdownload
```

删除工作区时，上述整个工作区目录都要删除。

## 3. 需求目标

完成后用户应该可以：

```text
1. 在“选择工作区”窗口选中一个工作区。
2. 点击“删除”按钮。
3. 程序判断该工作区是否允许删除。
4. 如果不允许删除，给出提示。
5. 如果允许删除，弹出确认窗口。
6. 用户取消时不做任何修改。
7. 用户确认时，删除该工作区整个文件夹。
8. 从 app-settings.json 的 Workspaces 列表中移除该工作区。
9. 刷新工作区列表。
10. 如果 LastWorkspaceId 指向被删除工作区，则切换到剩余工作区中的一个可用工作区。
```

## 4. 非目标范围

本阶段不实现：

```text
1. 不实现回收站恢复。
2. 不实现删除撤销。
3. 不实现软删除。
4. 不保留被删除工作区的备份。
5. 不实现批量删除。
6. 不实现删除当前正在使用的工作区后自动切换。
7. 不实现默认工作区特殊保护。
8. 不实现云同步或导出归档。
```

## 5. 删除语义

### 5.1 必须彻底删除文件夹

删除工作区必须删除：

```text
WorkspaceInfo.Path
```

指向的整个目录。

示例：

```text
%AppData%\VSLoader\Workspaces\LineA
```

删除后：

```text
Directory.Exists("%AppData%\VSLoader\Workspaces\LineA") == false
```

不能只删除 `app-settings.json` 中的记录。  
原因：

```text
如果只移除列表记录但保留磁盘目录，后续新建或恢复同名目录时可能误读旧数据，导致快捷项、地图、下载文件混入新工作区。
```

### 5.2 必须从 app-settings.json 移除

删除后必须更新：

```text
%AppData%\VSLoader\app-settings.json
```

从：

```json
{
  "Workspaces": [
    {
      "Id": "line-a",
      "Name": "产线A",
      "Path": "..."
    }
  ]
}
```

移除被删除的工作区对象。

### 5.3 LastWorkspaceId 处理

如果：

```text
appSettings.LastWorkspaceId == deletedWorkspace.Id
```

删除成功后应该更新为剩余工作区中的一个可用工作区 Id。

推荐优先级：

```text
1. 第一个 IsWorkspaceUsable == true 的工作区。
2. 如果没有可用工作区，则第一个剩余工作区。
3. 如果没有剩余工作区，理论上不会发生，因为最后一个工作区禁止删除。
```

## 6. 删除限制

### 6.1 当前正在使用的工作区不能删除

当用户从主窗口点击“工作区”进入选择窗口时，程序需要知道当前主窗口正在使用的工作区 Id。

如果选中的工作区 Id 等于当前正在使用的工作区 Id：

```text
禁止删除。
```

提示建议：

```text
当前正在使用的工作区不能删除。请先切换到其他工作区后再删除。
```

### 6.2 最后一个工作区不能删除

如果当前：

```text
appSettings.Workspaces.Count <= 1
```

禁止删除。

提示建议：

```text
至少需要保留一个工作区，不能删除最后一个工作区。
```

### 6.3 默认工作区没有特殊保护

不要写类似：

```text
if workspace.Id == "default" then cannot delete
```

默认工作区应该和普通工作区一样。  
只要它不是当前正在使用的工作区，也不是最后一个工作区，就允许删除。

### 8.3 新增删除方法

新增公开方法：

```csharp
public SaveResult DeleteSelectedWorkspace()
```

职责：

```text
1. 校验是否选中了工作区。
2. 校验是否是最后一个工作区。
3. 校验是否是当前正在使用的工作区。
4. 调用 WorkspaceService 删除工作区目录。
5. 从 appSettings.Workspaces 移除工作区。
6. 修正 LastWorkspaceId。
7. 保存 app-settings.json。
8. 刷新列表。
9. 选择剩余工作区中的一个。
```

推荐伪代码：

```csharp
public SaveResult DeleteSelectedWorkspace()
{
    if (SelectedWorkspace is null)
    {
        return SaveResult.Fail("请选择要删除的工作区。");
    }

    if (appSettings.Workspaces.Count <= 1)
    {
        return SaveResult.Fail("至少需要保留一个工作区，不能删除最后一个工作区。");
    }

    var selectedId = SelectedWorkspace.Id;
    if (!string.IsNullOrWhiteSpace(activeWorkspaceId)
        && string.Equals(selectedId, activeWorkspaceId, StringComparison.OrdinalIgnoreCase))
    {
        return SaveResult.Fail("当前正在使用的工作区不能删除。请先切换到其他工作区后再删除。");
    }

    var selectedInfo = SelectedWorkspace.Info;
    var deleteResult = workspaceService.DeleteWorkspace(selectedInfo);
    if (!deleteResult.Success)
    {
        return deleteResult;
    }

    appSettings.Workspaces.RemoveAll(workspace =>
        string.Equals(workspace.Id, selectedId, StringComparison.OrdinalIgnoreCase));

    if (string.Equals(appSettings.LastWorkspaceId, selectedId, StringComparison.OrdinalIgnoreCase))
    {
        appSettings.LastWorkspaceId = appSettings.Workspaces.FirstOrDefault(workspace =>
            workspaceService.IsWorkspaceUsable(workspace))?.Id
            ?? appSettings.Workspaces.FirstOrDefault()?.Id
            ?? string.Empty;
    }

    var saveResult = appSettingsService.Save(appSettings);
    if (!saveResult.Success)
    {
        return saveResult;
    }

    RefreshWorkspaces();
    return SaveResult.Ok();
}
```

注意：

```text
必须先成功删除目录，再从 app-settings.json 移除记录。
如果目录删除失败，不要修改 app-settings.json。
```

## 9. WorkspaceService 改造

修改文件：

```text
VSLoader\Models\Services\WorkspaceService.cs
```

新增方法：

```csharp
public SaveResult DeleteWorkspace(WorkspaceInfo workspace)
```

职责：

```text
1. 校验 workspace.Path 不为空。
2. 校验目录存在。
3. 删除 workspace.Path 指向的整个目录。
4. 不修改 appSettings.Workspaces。
5. 不处理 LastWorkspaceId。
```

推荐实现：

```csharp
public SaveResult DeleteWorkspace(WorkspaceInfo workspace)
{
    try
    {
        if (string.IsNullOrWhiteSpace(workspace.Path))
        {
            return SaveResult.Fail("工作区路径为空，无法删除。");
        }

        if (!Directory.Exists(workspace.Path))
        {
            return SaveResult.Fail("工作区文件夹不存在，无法删除。");
        }

        Directory.Delete(workspace.Path, recursive: true);
        return SaveResult.Ok();
    }
    catch (Exception ex)
    {
        return SaveResult.Fail($"删除工作区文件夹失败：{ex.Message}");
    }
}
```

说明：

```text
Directory.Delete(..., recursive: true) 会删除整个工作区目录。
如果文件被占用、权限不足、路径异常，返回失败并交给 UI 提示。
```

## 11. WorkspaceSelectorWindow code-behind 改造

修改文件：

```text
VSLoader\Views\WorkspaceSelectorWindow.xaml.cs
```

订阅事件：

```csharp
viewModel.RequestDeleteWorkspace += ShowDeleteWorkspaceConfirmation;
```

新增方法：

```csharp
private void ShowDeleteWorkspaceConfirmation()
{
    if (DataContext is not WorkspaceSelectorViewModel viewModel || viewModel.SelectedWorkspace is null)
    {
        return;
    }

    var workspaceName = viewModel.SelectedWorkspace.Name;
    var message = $"确定要彻底删除工作区“{workspaceName}”吗？\n\n该操作会删除此工作区下的全部配置、快捷项、地图、下载文件，且不可恢复。";
    var confirmation = MessageBox.Show(
        this,
        message,
        "删除工作区",
        MessageBoxButton.YesNo,
        MessageBoxImage.Warning);

    if (confirmation != MessageBoxResult.Yes)
    {
        return;
    }

    var result = viewModel.DeleteSelectedWorkspace();
    if (!result.Success)
    {
        MessageBox.Show(this, result.ErrorMessage ?? "删除工作区失败。", "VSLoader", MessageBoxButton.OK, MessageBoxImage.Warning);
    }
}
```

注意：

```text
确认弹窗只负责二次确认。
真正的权限校验仍然必须在 ViewModel 的 DeleteSelectedWorkspace 中做，不能只靠 UI。
```

## 13. 手工验收场景

### 场景一：删除普通非当前工作区

操作：

```text
1. 创建两个工作区：产线A、产线B。
2. 打开产线A。
3. 点击主窗口“工作区”。
4. 选中产线B。
5. 点击“删除”。
6. 确认删除。
```

预期：

```text
1. 产线B 从列表消失。
2. app-settings.json 中没有产线B。
3. 产线B 对应工作区文件夹被删除。
4. 当前主窗口仍然是产线A。
```

### 场景二：禁止删除当前工作区

操作：

```text
1. 打开产线A。
2. 点击主窗口“工作区”。
3. 选中产线A。
4. 点击“删除”。
```

预期：

```text
提示当前正在使用的工作区不能删除。
不弹出真正删除确认，或确认后仍然由 ViewModel 拦截。
产线A 文件夹仍然存在。
app-settings.json 不变。
```

### 场景三：禁止删除最后一个工作区

操作：

```text
1. 只保留一个工作区。
2. 在选择窗口选中它。
3. 点击“删除”。
```

预期：

```text
提示至少需要保留一个工作区。
工作区不被删除。
```

### 场景四：默认工作区可以删除

操作：

```text
1. 有默认工作区和产线A。
2. 当前打开产线A。
3. 进入工作区选择窗口。
4. 选中默认工作区。
5. 点击删除并确认。
```

预期：

```text
默认工作区被删除。
Workspaces\Default 文件夹不存在。
app-settings.json 不再包含 default。
```

### 场景五：用户取消确认

操作：

```text
1. 选中可删除工作区。
2. 点击删除。
3. 在确认弹窗点取消。
```

预期：

```text
不删除文件夹。
不修改 app-settings.json。
列表不变化。
```

## 14. 风险点

### 14.1 误删当前工作区

风险：

```text
当前主窗口仍在使用该工作区的数据文件，如果删除会导致运行期状态混乱。
```

规避：

```text
App.SwitchWorkspace 调用选择窗口时传入 currentWindow.WorkspaceId。
ViewModel 删除前强制判断 activeWorkspaceId。
```

### 14.2 只删配置不删目录

风险：

```text
旧目录残留会造成后续同名目录冲突或旧数据混入。
```

规避：

```text
DeleteWorkspace 必须 Directory.Delete(workspace.Path, recursive: true)。
```

### 14.3 删除目录成功但保存 app-settings 失败

风险：

```text
磁盘目录已删，但 app-settings 仍保留记录，列表会显示路径不存在。
```

建议处理：

```text
如果保存 app-settings 失败，提示用户“工作区文件夹已删除，但程序配置保存失败”。
```

最小实现可以返回保存失败信息。后续如果需要更强一致性，可以在删除前先备份配置文件。

### 14.4 文件被占用导致删除失败

风险：

```text
UIdownload 中的 jnlp 或其他文件被占用，Directory.Delete 失败。
```

规避：

```text
捕获异常并提示用户关闭占用该工作区文件的程序后重试。
不要修改 app-settings.json。
```
