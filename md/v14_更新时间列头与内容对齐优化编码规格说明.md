# v14 更新时间列头与内容对齐优化编码规格说明

## 1. 需求背景

当前 VSLoader 主列表中，`更新时间` 列存在一个视觉问题：

用户调整或观察 `更新时间` 列头时，会感觉列头位置和每一行的时间内容没有同步移动。

从代码结构分析，这不是数据错位，而是列头与单元格内容的对齐方式不一致造成的视觉错觉：

- 表头样式当前统一偏左对齐。
- `更新时间` 列内容使用右对齐。

因此 `更新时间` 表头文字和下面的时间文本不在同一视觉轴线上，看起来像“父列头可以动，但子内容还留在原地”。

本次 v14 需求需要修正该列的视觉一致性。

## 2. 需求目标

本次优化目标：

1. 让 `更新时间` 列头和时间内容在视觉上对齐。
2. 保留时间内容右对齐的整齐感。
3. 避免用户误以为列头和列内容脱节。
4. 可选禁用列重排，降低误操作。
5. 不改变数据展示内容。
6. 不改变列表业务逻辑。

## 3. 修改范围

主要修改文件：

- `VSLoader\MainWindow.xaml`

原则上不需要修改：

- `VSLoader\ViewModels\MainViewModel.cs`
- `VSLoader\MainWindow.xaml.cs`
- 任何服务层和模型层代码

本次属于 DataGrid 列样式优化。

## 4. 当前问题来源

当前 `DataGrid.ColumnHeaderStyle` 类似：

```xml
<Setter Property="HorizontalContentAlignment" Value="Left" />
<Setter Property="Padding" Value="12,0" />
```

而 `更新时间` 列内容样式类似：

```xml
<Setter Property="TextAlignment" Value="Right" />
```

结果：

```text
表头：更新时间       靠左或偏中
内容：2026-05-29... 靠右
```

当列宽变化或用户观察列头时，会产生错位感。

## 5. 推荐实现方案

### 5.1 保留时间内容右对齐

时间类字段适合右对齐，因为：

- 多行时间文本末端更整齐。
- 扫描时视觉稳定。
- 与当前列表的产品化样式一致。

因此不建议把时间内容改成左对齐。

### 5.2 将更新时间列头右对齐

给 `更新时间` 列单独设置 `HeaderStyle`，覆盖全局表头左对齐。

推荐写法：

```xml
<DataGridTextColumn Header="更新时间"
                    Binding="{Binding UpdatedAt, StringFormat=yyyy-MM-dd HH:mm:ss}"
                    Width="180">
    <DataGridTextColumn.HeaderStyle>
        <Style TargetType="DataGridColumnHeader"
               BasedOn="{StaticResource ...}">
            <Setter Property="HorizontalContentAlignment" Value="Right" />
            <Setter Property="Padding" Value="12,0" />
        </Style>
    </DataGridTextColumn.HeaderStyle>
</DataGridTextColumn>
```

如果当前全局 `DataGrid.ColumnHeaderStyle` 没有资源 key，无法直接 `BasedOn`，可以直接在列内定义完整 HeaderStyle。

列内 HeaderStyle 至少需要保持：

```xml
<Setter Property="Background" Value="#F9FAFB" />
<Setter Property="Foreground" Value="#6B7280" />
<Setter Property="FontSize" Value="13" />
<Setter Property="FontWeight" Value="SemiBold" />
<Setter Property="Padding" Value="12,0" />
<Setter Property="HorizontalContentAlignment" Value="Right" />
<Setter Property="BorderBrush" Value="#E5E7EB" />
<Setter Property="BorderThickness" Value="0,0,0,1" />
```

### 5.3 内容继续右对齐

保持 `更新时间` 列 `ElementStyle`：

```xml
<Setter Property="TextAlignment" Value="Right" />
```

不要改成左对齐。

## 6. 列拖拽/调整策略

### 6.1 推荐禁用列重排

用户当前反馈中提到“父列头可以随意调整”，其中一部分可能来自列头可拖动/可调整的默认行为。

为了降低误操作，建议禁用列重排：

```xml
CanUserReorderColumns="False"
```

理由：

- 当前应用不是表格编辑器。
- 快捷项列表列结构固定。
- 禁用列重排可以避免表头被拖到不同位置造成困惑。

### 6.2 是否禁用列宽调整

建议本次暂时不禁用列宽调整，或者根据实际体验决定。

可选方案：

```xml
CanUserResizeColumns="False"
```

如果禁用列宽调整：

- 列表整体更稳定。
- 用户不会把列拖乱。

但缺点是：

- 如果某些机器名称或备注较长，用户无法临时拉宽查看。

本次推荐：

```text
必须禁用列重排：CanUserReorderColumns="False"
暂不禁用列宽调整：不设置 CanUserResizeColumns 或保持 True
```

## 7. 具体修改要求

### 7.1 DataGrid 增加禁止列重排

在主列表 `DataGrid` 上增加：

```xml
CanUserReorderColumns="False"
```

### 7.2 更新时间列增加 HeaderStyle

在 `更新时间` 列上增加单独 `HeaderStyle`。

目标：

- `更新时间` 表头右对齐。
- 表头背景、字体、边框仍与其他列一致。

### 7.3 不改变更新时间列内容样式

保持：

```xml
TextAlignment="Right"
```

### 7.4 不改变列宽策略

保持 v13 之后的列宽策略：

```text
名称：2*
备注：3*
更新时间：180
```

## 8. 不允许改变的内容

本次不允许改变：

- 顶部工具区布局。
- 第二行按钮布局。
- 主列表行高。
- 主列表列数量。
- 是否显示目标路径列。
- 搜索逻辑。
- 排序逻辑。
- 双击打开逻辑。
- 右键菜单逻辑。
- AdminUI 功能。
- 自动获取连接功能。
- 配置保存逻辑。

## 9. 验收标准

### 9.1 视觉验收

启动应用后：

- `更新时间` 表头与下方时间内容视觉上对齐。
- 时间内容仍然右对齐。
- 表头样式与其他列保持一致。
- 不再产生“列头动了，内容不动”的明显错觉。

### 9.2 交互验收

- 用户不能将列头拖拽换位置。
- 用户仍可正常查看列表。
- 如保留列宽调整，调整列宽时表头与内容仍保持一致的右对齐关系。

### 9.3 功能验收

以下功能必须保持正常：

1. 搜索过滤正常。
2. 单击选中正常。
3. 双击打开 VSCode 正常。
4. 右键菜单正常。
5. `AdminUI`、`打开`、`编辑`、`删除` 按钮正常。
6. 列表排序和展示不变。

### 9.4 编译验收

执行：

```powershell
dotnet build .\VSLoader.sln
```

期望：

```text
0 warnings
0 errors
```

如果提示 `VSLoader.exe` 被占用，说明程序正在运行，应先关闭 VSLoader 后重新构建。

## 10. 建议实施步骤

1. 打开 `VSLoader\MainWindow.xaml`。
2. 找到主列表 `DataGrid`。
3. 增加 `CanUserReorderColumns="False"`。
4. 找到 `更新时间` 的 `DataGridTextColumn`。
5. 在该列内增加独立 `HeaderStyle`。
6. 保持该列内容 `ElementStyle` 的 `TextAlignment="Right"` 不变。
7. 编译项目。
8. 手动确认表头和时间内容对齐。

## 11. 明确不做的事情

本次不做：

- 将时间内容改成左对齐。
- 调整顶部按钮布局。
- 修改列表列宽。
- 禁用所有列表交互。
- 修改数据模型。
- 修改业务逻辑。
