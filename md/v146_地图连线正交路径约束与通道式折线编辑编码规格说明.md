# v146 地图连线正交路径约束与通道式折线编辑编码规格说明

## 1. 背景

v143 到 v145 已经完成了地图连线的自由折点能力：

```text
v143：连线支持 points 保存、加载和渲染。
v144：连线右键支持添加折点、清除折点、删除连线。
v145：选中连线后显示折点控制点，支持拖动折点和删除单个折点。
```

但当前模型仍然存在一个核心问题：

```text
折点只是一个普通坐标点。
它只约束“线经过哪里”，没有约束“线从哪个方向来、往哪个方向走、转角如何形成”。
```

因此用户添加或拖动折点后，连线可能出现斜线或空间语义不清晰的弯折：

```text
A -> P -> B
```

这类自由折线对于工厂地图并不理想。工厂地图的连线更像流程线、管线或接线图，用户期望的是：

```text
横平竖直。
转角明确。
分叉/汇流可以通过多条线共享同一段通道来表达。
```

本阶段要把“自由点模型”升级为“正交路径模型”：

```text
连线仍然保存 points。
但渲染、添加、拖动时必须保证路径由水平段和垂直段组成。
```

## 2. 目标

本阶段目标：

```text
1. 连线渲染永远保持正交路径，不出现斜线。
2. 右键添加折点时，不再只是添加一个孤立点，而是根据点击线段生成一个正交通道段。
3. 拖动折点时，联动相邻点，保持相邻线段横平竖直。
4. 删除单个折点后，重新规范化路径，避免残留斜线或重复点。
5. 旧数据继续兼容；旧的自由 points 进入地图后会被规范化为正交路径。
```

最终用户感受应当是：

```text
不是“放一个点让线自己猜怎么弯”，
而是“拉出一段明确的横向/纵向通道，让线从这里绕过去”。
```

## 3. 非目标

本阶段不做：

```text
1. 不做自动避障。
2. 不做自动寻找最短路径。
3. 不做智能分叉/汇流识别。
4. 不做多个连线的折点自动吸附到同一点。
5. 不做连线端口选择。
6. 不新增业务意义上的中间节点。
7. 不改变 factory-map.layout.json 中 edge.points 的字段结构。
8. 不改变节点拖动、框选、多选、地图缩放平移逻辑。
```

说明：

```text
本阶段只解决“单条连线内部路径必须横平竖直”的问题。
多条线共享同一段通道仍由用户手动拖动/对齐实现。
```

## 5. 空间模型

### 5.1 路径点定义

一条连线在空间中由以下点组成：

```text
P0 = From 节点右侧中心点
P1..Pn = edge.Points 中保存的手动点
P(n+1) = To 节点左侧中心点
```

正交路径要求：

```text
任意相邻两点 Pi 和 P(i+1)，必须满足：
Pi.X == P(i+1).X
或
Pi.Y == P(i+1).Y
```

也就是说，每一段只能是：

```text
水平线
或
垂直线
```

不允许出现斜线。

### 5.2 通道段

用户想“绕一下”时，通常不是添加一个点，而是添加一段通道。

如果用户在水平线段上添加绕行：

```text
原路径：
A -------- B

添加后：
A ---- C
       |
       D ---- B
```

这里实际新增两个点：

```text
C = 通道入口
D = 通道出口
```

如果用户在垂直线段上添加绕行：

```text
原路径：
A
|
|
B

添加后：
A
|
C ---- D
     |
     B
```

这里同样新增两个点：

```text
C = 通道入口
D = 通道出口
```

### 5.3 转角点

正交路径中的单个折点也可以存在，但它必须是明确转角：

```text
上一段水平，下一段垂直
或
上一段垂直，下一段水平
```

如果某个折点导致：

```text
上一段斜线
或
下一段斜线
```

则必须通过规范化算法补点或调整点，消除斜线。

## 6. 数据结构策略

本阶段不新增新的持久化字段。

继续使用：

```csharp
public List<FactoryMapPoint> Points { get; set; } = [];
```

但从 v146 开始，`Points` 的语义调整为：

```text
Points 不再是任意自由点集合。
Points 表示一条正交路径中的中间路径点。
```

要求：

```text
1. 保存前尽量保证 points 已经规范化。
2. 渲染时也要防御性规范化，避免旧数据或异常数据产生斜线。
3. 不修改 JSON 字段名，避免破坏已有工作区。
```

## 7. 正交规范化算法

### 7.1 新增 helper

建议新增：

```csharp
internal static List<FactoryMapPoint> NormalizeOrthogonalEdgePoints(
    FactoryMapDeviceEdgeViewData edge)
```

作用：

```text
输入 edge 的 From / To / Points。
输出规范化后的中间 points。
```

输入路径：

```text
start + valid edge.Points + end
```

输出要求：

```text
1. 过滤 NaN / Infinity。
2. 相邻重复点删除。
3. 任意相邻点如果不是同 X 或同 Y，自动插入一个中转点。
4. 删除连续共线的冗余中间点。
5. 返回值只包含中间 points，不包含 start/end。
```

### 7.2 斜线补点规则

当发现相邻两点 `A` 和 `B` 既不同 X 又不同 Y：

```text
A.X != B.X
A.Y != B.Y
```

需要插入一个中转点 `M`。

推荐规则：

```text
优先保持上一段方向。
如果无法判断上一段方向，则默认先水平后垂直。
```

具体规则：

```text
如果 A 的上一段是水平段：
    M = (B.X, A.Y)
    路径：A -> M -> B

如果 A 的上一段是垂直段：
    M = (A.X, B.Y)
    路径：A -> M -> B

如果没有上一段方向：
    M = (B.X, A.Y)
    路径：A -> M -> B
```

说明：

```text
这个规则不是智能避障。
它只是保证路径正交，并尽量减少用户已有路径形状被大幅改变。
```

### 7.3 共线点压缩

如果连续三点：

```text
A -> B -> C
```

满足：

```text
A.X == B.X == C.X
或
A.Y == B.Y == C.Y
```

则 B 是冗余点，应删除。

目的：

```text
避免用户多次编辑后路径点越来越多。
避免拖动/删除后产生无意义点。
```

### 7.4 重复点压缩

如果相邻点坐标相同：

```text
A.X == B.X && A.Y == B.Y
```

删除后一个点。

## 8. 渲染规则调整

### 8.1 CreateEdgePoints

当前有手动 points 时：

```text
start -> edge.Points -> end
```

调整为：

```text
start -> NormalizeOrthogonalEdgePoints(edge) -> end
```

注意：

```text
渲染时可以使用规范化结果，但不要每次渲染都写回 edge.Points。
```

原因：

```text
RenderCurrentMap 频繁调用，渲染阶段不应隐式修改数据并触发用户困惑。
```

写回时机应当是：

```text
添加折点后。
拖动折点结束后。
删除折点后。
保存布局前的编辑动作中。
```

### 8.2 CreateVisibleEdgePoints

仍然保持：

```text
可见线使用 insetEndpoints=true。
命中线使用完整端点。
```

区别只是中间路径使用正交规范化结果。

## 9. 添加折点逻辑调整

### 9.1 当前问题

当前 v144 添加折点逻辑是：

```text
在最近线段处插入一个点。
```

这会产生：

```text
上一点 -> 新点 -> 下一点
```

如果新点不在同一水平/垂直线上，就会出现斜线。

### 9.2 新规则：添加通道段

新增 helper：

```csharp
internal static List<FactoryMapPoint> InsertOrthogonalDetourAtSegment(
    FactoryMapDeviceEdgeViewData edge,
    WpfPoint clickPoint)
```

行为：

```text
1. 获取正交化后的完整路径：start + points + end。
2. 找到 clickPoint 最近的线段。
3. 判断该线段方向。
4. 在该线段中插入两个点，形成一段可拖动通道。
5. 返回新的中间 points。
```

### 9.3 水平线段插入规则

如果最近线段是水平线段：

```text
A(x1, y) -> B(x2, y)
```

用户点击点：

```text
C(cx, cy)
```

按网格吸附后：

```text
sx = Snap(cx)
sy = Snap(cy)
```

生成：

```text
P1 = (sx, y)
P2 = (sx, sy)
```

路径变为：

```text
A -> P1 -> P2 -> B
```

但如果 `sy == y`：

```text
用户点击仍在原线附近，没有实际绕行高度。
```

此时需要给默认偏移：

```text
sy = y + 2 * MapGridSize
```

最终：

```text
A ---- P1
       |
       P2 ---- B
```

### 9.4 垂直线段插入规则

如果最近线段是垂直线段：

```text
A(x, y1) -> B(x, y2)
```

用户点击点：

```text
C(cx, cy)
```

按网格吸附后：

```text
sx = Snap(cx)
sy = Snap(cy)
```

生成：

```text
P1 = (x, sy)
P2 = (sx, sy)
```

路径变为：

```text
A -> P1 -> P2 -> B
```

如果 `sx == x`：

```text
用户点击仍在原线附近，没有实际横向绕行。
```

此时需要给默认偏移：

```text
sx = x + 2 * MapGridSize
```

最终：

```text
A
|
P1 ---- P2
       |
       B
```

### 9.5 插入后的规范化

插入两个点后必须调用：

```csharp
NormalizeOrthogonalEdgePoints(edge)
```

并写回：

```csharp
edge.Points = normalizedPoints;
```

然后：

```text
RenderCurrentMap(resetView: false)
saveLayout(currentMap)
```

## 10. 拖动折点逻辑调整

### 10.1 当前问题

当前 v145 拖动单个折点时，只更新该点坐标：

```text
edge.Points[index].X = newX
edge.Points[index].Y = newY
```

这会导致相邻线段可能变成斜线。

### 10.2 新规则：拖动时保持相邻正交

新增 helper：

```csharp
internal static List<FactoryMapPoint> MoveOrthogonalEdgePoint(
    FactoryMapDeviceEdgeViewData edge,
    int pointIndex,
    WpfPoint targetPoint,
    bool snapToGrid)
```

行为：

```text
1. 输入 edge、被拖动折点 index、目标坐标。
2. 根据前后相邻点判断该点的角色。
3. 更新当前点，并联动相邻点，保持正交。
4. 返回新的中间 points。
```

### 10.3 折点角色判断

对于完整路径：

```text
prev -> current -> next
```

判断：

```text
prev-current 是水平还是垂直。
current-next 是水平还是垂直。
```

常见情况：

```text
水平 -> 垂直：current 是转角点。
垂直 -> 水平：current 是转角点。
水平 -> 水平：current 是同一水平通道上的冗余或中间控制点。
垂直 -> 垂直：current 是同一垂直通道上的冗余或中间控制点。
```

### 10.4 转角点拖动规则

如果 current 是转角点：

```text
prev-current 水平，current-next 垂直：
    current.Y 必须等于 prev.Y
    current.X 必须等于 next.X
```

拖动 target 后：

```text
current.X = target.X
current.Y = target.Y
```

但为了保持正交，需要同步：

```text
如果 prev-current 原来水平：
    prev.Y 不动
    current.Y = prev.Y
    next.X = current.X

如果 prev-current 原来垂直：
    prev.X 不动
    current.X = prev.X
    next.Y = current.Y
```

更直观地说：

```text
拖动一个转角点时，它只能沿着能保持相邻两段正交的位置移动。
相邻的另一个控制点必要时跟着改一个轴。
```

### 10.5 通道段拖动规则

对于用户通过“添加通道段”生成的两个点：

```text
水平线段新增：A -> P1 -> P2 -> B
P1/P2 之间是垂直通道。
```

用户实际拖动 P1 或 P2 时，最符合直觉的是拖动整段通道：

```text
拖动垂直通道：
    P1.X 和 P2.X 同步变化。
    P1.Y 保持原主线高度。
    P2.Y 使用目标 Y。

拖动水平通道：
    P1.Y 和 P2.Y 同步变化。
    P1.X 保持原主线 X。
    P2.X 使用目标 X。
```

本阶段可以先采用简化规则：

```text
拖动任意折点后，立即调用 NormalizeOrthogonalEdgePoints。
```

但必须避免重新生成与用户意图相反的绕行方向。

推荐实现：

```text
拖动过程中只更新目标点一个坐标或两个坐标。
拖动结束后 NormalizeOrthogonalEdgePoints。
```

如果拖动过程中出现短暂斜线，可以接受吗？

```text
不接受。
```

因此本阶段要求：

```text
拖动过程中也必须使用 MoveOrthogonalEdgePoint 的结果重绘。
```

## 11. 删除折点逻辑调整

删除单个折点后：

```text
1. RemoveAt(index)。
2. 调用 NormalizeOrthogonalEdgePoints。
3. 写回 edge.Points。
4. RenderCurrentMap(resetView: false)。
5. saveLayout(currentMap)。
```

目的：

```text
删除某个折点后，如果前后两点无法直接正交连接，就自动补一个中转点。
如果前后已经共线，就自动压缩冗余点。
```

## 12. 清除折点逻辑

清除折点仍保持 v144 行为：

```text
edge.Points.Clear()
RenderCurrentMap(resetView: false)
saveLayout(currentMap)
```

没有手动 points 时，连线恢复默认自动中折线。

默认自动中折线本身必须是正交路径。

## 13. 控制点显示策略

v145 已经实现折点控制点。

v146 需要调整用户理解：

```text
控制点不是自由点。
控制点是正交路径中的通道点或转角点。
```

控制点显示仍然保持：

```text
白底蓝边圆点。
悬停蓝底白边。
右键删除折点。
```

可选增强：

```text
拖动时鼠标样式根据当前可移动方向变化。
```

本阶段建议先不做复杂光标方向：

```text
仍用 SizeAll。
```

## 14. 正交路径工具类建议

当前 `FactoryMapWindow.xaml.cs` 已经很大。

本阶段建议新增一个独立工具类：

```text
VSLoader/Models/Services/FactoryMapOrthogonalPathService.cs
```

职责：

```text
1. 路径规范化。
2. 正交通道插入。
3. 折点移动后保持正交。
4. 重复点和共线点压缩。
```

建议 public/internal API：

```csharp
internal static class FactoryMapOrthogonalPathService
{
    public static List<FactoryMapPoint> Normalize(
        WpfPoint start,
        IReadOnlyList<FactoryMapPoint> points,
        WpfPoint end);

    public static List<FactoryMapPoint> InsertDetour(
        WpfPoint start,
        IReadOnlyList<FactoryMapPoint> points,
        WpfPoint end,
        WpfPoint clickPoint,
        double gridSize);

    public static List<FactoryMapPoint> MovePoint(
        WpfPoint start,
        IReadOnlyList<FactoryMapPoint> points,
        WpfPoint end,
        int pointIndex,
        WpfPoint targetPoint,
        double gridSize,
        bool snapToGrid);
}
```

说明：

```text
这个类不依赖 Window。
方便单元测试。
避免继续把路径算法塞进 FactoryMapWindow.xaml.cs。
```

## 16. 旧数据兼容策略

旧布局中可能已经存在自由 points：

```json
"points": [
  { "x": 230, "y": 110 },
  { "x": 310, "y": 260 }
]
```

加载时不强制改写文件。

但渲染时：

```text
显示为正交路径。
```

用户一旦执行以下编辑动作：

```text
添加折点。
拖动折点。
删除折点。
清除折点。
```

则保存时写回规范化后的正交 points。

这样可以做到：

```text
旧数据不崩。
旧数据打开后显示不出斜线。
用户编辑后自然升级为正交数据。
```

```text
1. CreateVisibleEdgePoints 对自由 points 也输出正交路径。
2. AddEdgePoint_Click 不再使用单点 Insert，而是调用 InsertDetour。
3. UpdateActiveEdgePointPosition 调用 MovePoint。
4. DeleteEdgePoint_Click 删除后调用 Normalize。
```

建议新增 helper：

```csharp
private static void AssertOrthogonal(IReadOnlyList<FactoryMapPoint> points)
```

或对完整路径：

```csharp
private static void AssertOrthogonal(IReadOnlyList<WpfPoint> path)
```

检查：

```text
任意相邻点同 X 或同 Y。
```

## 19. 人工验收

验收流程：

```text
1. 打开 VSLoader。
2. 打开工厂地图。
3. 进入编辑模式。
4. 对一条默认连线右键添加折点。
5. 确认不是出现一条斜线，而是出现横平竖直的绕行通道。
6. 拖动折点，确认连线始终横平竖直。
7. 删除某个折点，确认不会残留斜线。
8. 关闭地图再打开，确认路径保存。
9. 用已有旧 points 的地图打开，确认显示时不出现斜线。
10. 清除折点后，确认恢复默认自动中折线。
```
