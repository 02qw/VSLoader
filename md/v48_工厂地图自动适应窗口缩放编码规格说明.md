# v48 工厂地图自动适应窗口缩放编码规格说明

## 1. 需求背景

v47 已经实现工厂地图附属窗口：

```text
地图按钮
右侧地图窗口
JSON 节点坐标
Canvas 绘制节点和连线
点击地图机器节点联动主列表快捷项
```

当前问题：

```text
地图比例太大。
打开地图后必须拖动横向/纵向滚动条才能看到后续节点。
无法一眼看到完整流程图。
```

用户希望：

```text
地图打开后默认能看到全局大图。
不需要先拖动滚动条才能理解整体流程。
```

## 2. 需求目标

地图窗口默认启用：

```text
适应窗口显示
```

也就是说：

1. JSON 中的地图逻辑坐标和画布尺寸不变。
2. 程序显示时自动根据当前窗口可用区域计算缩放比例。
3. 整张地图默认缩放到当前窗口可见范围内。
4. 用户不需要滚动条也能看到完整地图。

示例：

```text
JSON canvas: 1200 x 720
窗口可视区域: 880 x 640
自动缩放比例: min(880/1200, 640/720) = 0.733
地图按 0.733 倍显示
```

## 3. 非目标范围

本次不实现：

1. 不做地图拖拽编辑。
2. 不做节点连线编辑。
3. 不做鼠标滚轮缩放。
4. 不做缩放滑块。
5. 不做小地图预览。
6. 不改变 JSON 坐标含义。
7. 不改变地图点击联动逻辑。

本次只解决：

```text
默认比例太大，看不全地图
```

## 4. 当前代码现状

地图窗口：

```text
VSLoader/Views/FactoryMapWindow.xaml
VSLoader/Views/FactoryMapWindow.xaml.cs
```

当前结构：

```xml
<ScrollViewer>
    <Canvas x:Name="MapCanvas" />
</ScrollViewer>
```

当前绘制逻辑：

```text
MapCanvas.Width = map.Canvas.Width
MapCanvas.Height = map.Canvas.Height
节点使用 JSON x/y 原始坐标
连线使用 JSON points 原始坐标
```

因此当逻辑画布宽度大于窗口宽度时，必须使用滚动条。

## 5. 推荐实现方案

在地图 Canvas 外层增加：

```xml
Viewbox
```

使用 WPF 自带缩放能力：

```xml
<Viewbox Stretch="Uniform">
    <Canvas x:Name="MapCanvas" />
</Viewbox>
```

推荐结构：

```xml
<Grid>
    <Viewbox x:Name="MapViewbox"
             Stretch="Uniform"
             StretchDirection="DownOnly">
        <Canvas x:Name="MapCanvas" />
    </Viewbox>
</Grid>
```

说明：

```text
Stretch="Uniform" 保持宽高比例。
StretchDirection="DownOnly" 只在地图太大时缩小，不在地图较小时强行放大。
```

如果希望小图也填充窗口，可使用：

```text
StretchDirection="Both"
```

第一版推荐：

```text
DownOnly
```

避免地图被强行放大导致按钮和文字显得粗糙。

## 6. ScrollViewer 处理策略

当前有滚动条。

自动适应窗口后，默认不应依赖滚动条。

推荐改为：

```xml
<Grid>
    <Viewbox>
        <Canvas />
    </Viewbox>
</Grid>
```

即第一版可以移除 ScrollViewer。

原因：

1. 用户当前目标是“不需要拖动滚动条看全局”。
2. Viewbox 会保证整张地图进入可视区域。
3. ScrollViewer 和 Viewbox 叠加时，布局容易出现可用区域计算不直观。

如果担心极端小窗口看不清，可以保留窗口最小尺寸。

当前地图窗口已有：

```xml
MinWidth="460"
MinHeight="360"
```

可继续保留。

## 7. 节点大小策略

当前节点宽度和按钮高度在代码中固定：

```csharp
NodeWidth = 150
MachineButtonHeight = 26
```

本次不修改逻辑大小。

缩放由 Viewbox 统一处理。

也就是说：

```text
节点、文字、按钮、连线一起缩放。
```

好处：

1. 实现简单。
2. 不需要重新计算坐标。
3. JSON 配置继续有效。

## 8. 状态栏不缩放

地图窗口底部状态栏：

```text
节点：6 | 连线：6 | 未匹配快捷项：44
```

不应该跟着地图缩放。

因此 Viewbox 只包裹地图区域，不包裹底部状态栏。

结构保持：

```xml
<DockPanel>
    <Border DockPanel.Dock="Bottom">状态栏</Border>
    <Viewbox>地图 Canvas</Viewbox>
</DockPanel>
```

## 9. 点击联动要求

地图缩放后：

```text
机器按钮仍然可以点击。
点击后仍然选中左侧主列表快捷项。
```

WPF Viewbox 会自动处理点击坐标转换，因此代码逻辑无需特殊处理。

## 10. 视觉要求

缩放后应满足：

1. 打开地图窗口后，完整地图默认可见。
2. 右侧节点不应被裁切。
3. 底部状态栏可见。
4. 不出现横向滚动条。
5. 不出现纵向滚动条。
6. 地图整体居中显示。

如果地图内容太小：

```text
保持原始大小并居中
```

## 11. 可选增强

如果 Viewbox 缩小后仍然出现窗口内留白过大，可以在地图外层加居中容器：

```xml
<Grid HorizontalAlignment="Center"
      VerticalAlignment="Center">
    <Viewbox Stretch="Uniform"
             StretchDirection="DownOnly">
        <Canvas />
    </Viewbox>
</Grid>
```

但第一版可以先用 Viewbox 默认居中。
