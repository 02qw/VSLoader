# v92 更新器已是最新版本确认恢复主程序编码规格说明

## 1. 背景

v90 已将软件版本检测统一为读取 `manifest.json` 的 `version` 字段。

v91 在 updater 中增加了：

1. 更新过程中展示 `manifest.json` 的 `releaseNotes`。
2. 更新完成后弹出确认窗口。
3. 用户点击确认后再启动新版 `VSLoader.exe`。

但当前发现一个逻辑漏洞：

当用户已经更新到最新版本后，再次点击主程序中的“更新软件”，updater 能正确判断：

```text
当前已是最新版本。
```

但界面没有弹出确认提示，也没有恢复启动 VSLoader，用户体验像“卡住”或“没有下文”。

## 2. 根因分析

当前并不是旧 `txt` 逻辑导致。

主程序点击“更新软件”时，当前链路是：

```text
MainViewModel.UpdateSoftwareAsync
  -> BuildUpdaterArguments(...)
  -> --manifestPath
  -> VSLoader.Updater.exe
  -> UpdaterUpdateService.RunAsync(...)
  -> 读取 manifest.version
```

`UpdaterUpdateService` 中当前判断：

```csharp
if (remoteVersion <= options.CurrentVersion)
{
    return UpdaterUpdateResult.Ok("当前已是最新版本。", restartMainApp: false, manifest.ReleaseNotes);
}
```

问题发生在 updater 窗口处理结果时：

```csharp
if (!result.RestartMainApp)
{
    isUpdating = false;
    HasError = true;
    ReleaseNotesText = result.ReleaseNotes;
    SetProgress(100, result.Message);
    return;
}
```

这里把“当前已是最新版本”当成了类似错误/终止状态：

1. 没有弹确认提示。
2. 没有启动 VSLoader。
3. 设置了 `HasError = true`。
4. 用户只能看到 updater 停在窗口里，主程序已经退出。

因此根因是：

```text
v91 没有覆盖 updater 的“无更新但流程正常完成”分支。
```

## 3. 需求目标

### 3.1 用户目标

当用户点击“更新软件”，但当前已经是最新版本时：

1. updater 应明确提示：

```text
当前已是最新版本
```

2. 提示中可展示当前 manifest 的 `releaseNotes`。
3. 用户点击确认后，启动原来的 `VSLoader.exe`。
4. updater 关闭。
5. 不应把该状态当成错误。

### 3.2 技术目标

1. 不改版本比较规则。
2. 不恢复旧 `SoftwareVersionFilePath` 或 txt 逻辑。
3. 保持 `manifest.version` 作为唯一软件版本判断来源。
4. 明确区分三类 updater 结果：
   - 更新成功，需要确认启动 VSLoader。
   - 已是最新版本，需要确认恢复启动 VSLoader。
   - 更新失败，需要显示错误，不启动 VSLoader。
5. 避免 updater 留在无操作状态。

## 4. 行为规格

### 4.1 版本高于当前版本

manifest 中：

```json
"version": "2.3.0"
```

当前程序：

```text
2.2.0
```

行为：

1. 正常执行复制、校验、解压、替换。
2. 更新成功后显示“更新完成”确认弹窗。
3. 弹窗中展示 `releaseNotes`。
4. 用户确认后启动新版 VSLoader。

该行为沿用 v91。

### 4.2 版本等于当前版本

manifest 中：

```json
"version": "2.2.0"
```

当前程序：

```text
2.2.0
```

行为：

1. updater 不执行复制、校验、解压、替换。
2. updater 显示：

```text
当前已是最新版本。
```

3. 弹出确认窗口。
4. 确认窗口标题建议：

```text
当前已是最新版本
```

5. 确认窗口正文建议：

```text
当前 VSLoader 已经是最新版本，点击确认后返回程序。
```

6. 确认窗口中展示 `releaseNotes`。
7. 用户点击确认后启动原来的 VSLoader。
8. updater 关闭。

### 4.3 版本低于当前版本

manifest 中：

```json
"version": "2.1.0"
```

当前程序：

```text
2.2.0
```

行为和“版本等于当前版本”一致：

1. 不执行更新。
2. 提示当前已是最新版本。
3. 确认后启动 VSLoader。

原因：

远端版本不高于当前版本，都不需要更新。用户点击更新后主程序已经退出，updater 必须负责把程序恢复启动。

### 4.4 失败状态

如果发生以下情况：

1. manifest 读取失败。
2. manifest version 无效。
3. 更新包不存在。
4. SHA256 校验失败。
5. 解压失败。
6. 替换失败且回滚。

行为：

1. 显示错误状态。
2. 保留“打开日志目录”和“关闭”按钮。
3. 不启动 VSLoader。
4. 不弹“当前已是最新版本”确认。
5. 不弹“更新完成”确认。

## 5. 代码修改范围

### 5.1 UpdaterUpdateService

文件：

```text
VSLoader.Updater\Services\UpdaterUpdateService.cs
```

当前逻辑已经能返回：

```csharp
UpdaterUpdateResult.Ok("当前已是最新版本。", restartMainApp: false, manifest.ReleaseNotes);
```

本次原则上不需要修改版本判断逻辑。

可选增强：

在 `UpdaterUpdateResult` 中增加更明确的结果类型，例如：

```csharp
public UpdaterUpdateOutcome Outcome { get; init; }
```

但为了最小改动，本次不强制新增枚举。

### 5.2 MainWindow.xaml.cs

文件：

```text
VSLoader.Updater\MainWindow.xaml.cs
```

当前问题代码：

```csharp
if (!result.RestartMainApp)
{
    isUpdating = false;
    HasError = true;
    ReleaseNotesText = result.ReleaseNotes;
    SetProgress(100, result.Message);
    return;
}
```

需要改为：

```csharp
if (!result.RestartMainApp)
{
    ReleaseNotesText = result.ReleaseNotes;
    SetProgress(100, result.Message);
    isUpdating = false;
    ConfirmAndStartMainApp(options, title: "当前已是最新版本", message: "当前 VSLoader 已经是最新版本，点击确认后返回程序。");
    return;
}
```

注意：

1. 不设置 `HasError = true`。
2. 必须启动 VSLoader。
3. 必须关闭 updater。
4. 如果启动 VSLoader 失败，仍走 `ShowError(...)`。

### 5.3 UpdateCompletedDialog 泛化

当前 v91 新增的确认窗口语义偏“更新完成”。

建议将构造函数扩展为：

```csharp
public UpdateCompletedDialog(
    string titleText,
    string messageText,
    string releaseNotesText)
```

窗口绑定：

1. `TitleText`
2. `MessageText`
3. `ReleaseNotesText`

用于两个场景：

#### 场景 A：更新完成

```text
TitleText = 更新完成
MessageText = VSLoader 已更新完成，点击确认后启动新版程序。
```

#### 场景 B：已是最新版本

```text
TitleText = 当前已是最新版本
MessageText = 当前 VSLoader 已经是最新版本，点击确认后返回程序。
```

这样可以复用同一个轻量弹窗，不引入第二套 UI。

### 5.4 ConfirmAndStartMainApp 方法调整

当前：

```csharp
private void ConfirmAndStartMainApp(UpdaterOptions options)
```

建议改为：

```csharp
private void ConfirmAndStartMainApp(
    UpdaterOptions options,
    string title,
    string message)
```

内部：

```csharp
var dialog = new UpdateCompletedDialog(title, message, ReleaseNotesText)
{
    Owner = this
};
dialog.ShowDialog();
StartMainApp(options);
Close();
```

## 7. 严谨性要求

### 7.1 不要再把无更新当错误

`remoteVersion <= currentVersion` 是正常状态。

禁止：

```csharp
HasError = true;
```

### 7.2 主程序退出后必须有恢复路径

因为主程序在启动 updater 后会执行：

```csharp
RequestApplicationExit();
```

所以 updater 在正常完成状态下必须负责重新启动 VSLoader。

正常完成状态包括：

1. 更新成功。
2. 当前已是最新版本。

### 7.3 失败状态不要自动启动

失败状态下不能自动启动 VSLoader，避免用户误以为更新成功。

### 7.4 不改旧 txt 兼容字段

本次不碰：

```csharp
UpdateCheckConfig.SoftwareVersionFilePath
```

该字段仍作为历史兼容字段保留，但不参与软件更新按钮逻辑。

## 8. 测试要求

### 8.1 服务层测试

已有：

```text
UpdaterUpdateServiceTests.RunAsync_returns_no_update_when_remote_version_is_not_newer
```

需要继续保证：

1. `Success == true`
2. `RestartMainApp == false`
3. `Message` 包含 `当前已是最新版本`
4. `ReleaseNotes` 能保留 manifest 中的 releaseNotes

### 8.2 窗口逻辑测试

如果当前 WPF 窗口不方便直接单元测试，可至少通过拆分方法增强可测性。

建议增加可测试方法或用现有构造方式保证：

1. `UpdateCompletedDialog` 能接收不同标题。
2. `UpdateCompletedDialog` 能接收不同正文。
3. `UpdateCompletedDialog` 能展示 releaseNotes。

### 8.3 手工验证

准备 manifest：

```json
{
  "version": "当前程序版本号",
  "packageFile": "VSLoader_xxx_win-x64.zip",
  "sha256": "xxx",
  "releaseNotes": "1. 测试已是最新版本提示"
}
```

操作：

1. 打开 VSLoader。
2. 点击“更新软件”。
3. 确认更新。
4. VSLoader 退出。
5. updater 打开。
6. updater 显示当前版本和服务器版本一致。
7. updater 显示“当前已是最新版本”确认弹窗。
8. 弹窗中展示 releaseNotes。
9. 点击确认。
10. VSLoader 被重新启动。
11. updater 关闭。

## 9. 验收标准

满足以下条件视为完成：

1. 点击“更新软件”时仍读取 manifest，不读取旧 txt。
2. manifest version 等于当前版本时，updater 提示“当前已是最新版本”。
3. “当前已是最新版本”状态不显示为错误状态。
4. “当前已是最新版本”确认弹窗展示 releaseNotes。
5. 用户点击确认后启动 VSLoader。
6. updater 随后关闭。
7. manifest version 低于当前版本时行为同样稳定。
8. 更新失败状态仍不启动 VSLoader。
9. 更新成功状态仍显示“更新完成”确认弹窗。
10. `dotnet test .\VSLoader.sln -c Debug` 通过。
11. `dotnet build .\VSLoader.sln -c Debug` 通过。
