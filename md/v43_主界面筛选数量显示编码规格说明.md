# v43 主界面筛选数量显示编码规格说明

## 1. 需求背景

当前 VSLoader 主界面支持通过搜索框筛选快捷项，但用户无法直观看到：

```text
当前筛选后列表显示了多少条快捷项
当前程序一共保存了多少条快捷项
```

当快捷项数量较多时，用户输入搜索关键字后，需要一个轻量数字反馈来判断筛选范围是否正确。

## 2. 需求目标

在主界面搜索框所在行增加一个数量显示区域，显示格式固定为：

```text
当前显示数量 / 总快捷项数量
```

示例：

```text
12 / 240
```

含义：

```text
12 = 当前搜索、筛选条件下主列表实际显示的快捷项数量
240 = 当前程序保存的全部快捷项数量
```

## 3. 显示位置

推荐放置在主界面顶部第一行：

```text
[搜索框]    [12 / 240]    [设置]
```

具体位置：

`VSLoader/MainWindow.xaml`

当前顶部第一行结构为：

```xml
<Grid Grid.Row="0">
    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="*" />
        <ColumnDefinition Width="Auto" />
    </Grid.ColumnDefinitions>

    <TextBox Grid.Column="0" ... />

    <Button Grid.Column="1" Content="设置" ... />
</Grid>
```

需要调整为三列：

```xml
<ColumnDefinition Width="*" />
<ColumnDefinition Width="Auto" />
<ColumnDefinition Width="Auto" />
```

放置关系：

```text
Grid.Column=0 搜索框
Grid.Column=1 数量显示 TextBlock
Grid.Column=2 设置按钮
```

## 4. UI 样式要求

数量显示只做轻量提示，不要抢主功能按钮视觉层级。

建议样式：

```text
字体：Microsoft YaHei UI
字号：13 或 14
颜色：#64748B 或接近当前列表辅助文字颜色
水平居中
垂直居中
最小宽度：80
外边距：12,0,0,0
```

建议显示内容只保留数字：

```text
12 / 240
```

不显示：

```text
当前显示：12 / 240
```

原因：

1. 顶部空间有限。
2. 数字语义靠搜索框位置即可理解。
3. 保持界面简洁。

建议添加 ToolTip：

```text
当前筛选显示数量 / 总快捷项数量
```

## 5. 数据定义

在 `MainViewModel` 中新增只读显示属性：

```csharp
public string ShortcutCountText { get; private set; } = "0 / 0";
```

也可以使用 CommunityToolkit 的 `[ObservableProperty]`：

```csharp
[ObservableProperty]
private string shortcutCountText = "0 / 0";
```

推荐使用 `[ObservableProperty]`，与当前 ViewModel 风格一致。

## 6. 计数规则

### 6.1 总快捷项数量

来源：

```csharp
Shortcuts.Count
```

含义：

```text
程序当前保存的全部快捷项数量
```

### 6.2 当前显示数量

来源：

```csharp
ShortcutsView.Cast<object>().Count()
```

或：

```csharp
ShortcutsView.OfType<ShortcutItem>().Count()
```

含义：

```text
经过当前搜索框筛选后，主列表实际显示的快捷项数量
```

注意：

不能直接使用 `Shortcuts.Count` 作为显示数量，否则搜索筛选后数字不会变化。

## 7. 刷新时机

需要新增统一方法：

```csharp
private void UpdateShortcutCountText()
```

逻辑：

```csharp
var visibleCount = ShortcutsView.OfType<ShortcutItem>().Count();
var totalCount = Shortcuts.Count;
ShortcutCountText = $"{visibleCount} / {totalCount}";
```

所有会改变列表内容或筛选结果的位置，都需要调用该方法。

必须覆盖以下场景：

1. 程序启动加载配置后。
2. 搜索框内容变化后。
3. 新增快捷项后。
4. 编辑快捷项后。
5. 删除快捷项后。
6. 批量新增识别确认后。
7. 批量新增识别清理重复项后。
8. 排序刷新后如果当前代码调用了 `ShortcutsView.Refresh()`，也可以顺手调用，保证状态稳定。

推荐封装一个刷新列表的方法：

```csharp
private void RefreshShortcutsView()
{
    ShortcutsView.Refresh();
    UpdateShortcutCountText();
}
```

然后逐步替换当前散落的：

```csharp
ShortcutsView.Refresh();
```

避免后续遗漏。

## 8. 与搜索功能的关系

搜索框使用：

```csharp
partial void OnSearchTextChanged(string value)
{
    ShortcutsView.Refresh();
}
```

需要改为：

```csharp
partial void OnSearchTextChanged(string value)
{
    RefreshShortcutsView();
}
```

这样用户输入或清空搜索内容时，计数实时变化。

## 9. 与排序功能的关系

排序不会改变总数量，也不会改变筛选条件。

但是当前排序方法中会刷新列表：

```csharp
ShortcutsView.Refresh();
```

建议同步调用 `UpdateShortcutCountText()` 或改用 `RefreshShortcutsView()`。

这样即使未来排序逻辑改动，也不会出现计数不刷新。

## 10. 与忙碌状态的关系

当前主界面在 `IsBusy=true` 时会禁用主操作区域。

数量显示为只读文本，不需要单独禁用逻辑。

它会随主 `DockPanel` 一起禁用，但视觉上仍然可以显示。

## 11. 空数据状态

当没有任何快捷项时：

```text
0 / 0
```

当有快捷项但搜索结果为空时：

```text
0 / 240
```

当没有搜索筛选时：

```text
240 / 240
```

## 12. 性能说明

当前主列表数量规模较小到中等，使用：

```csharp
ShortcutsView.OfType<ShortcutItem>().Count()
```

可以接受。

如果后续快捷项数量达到数万级，再考虑在 `FilterShortcut` 中维护计数或使用更细的集合变更监听。

本次不做复杂优化，避免引入额外状态同步风险。

## 14. 验收场景

### 14.1 程序启动

已有 240 条快捷项时，启动后显示：

```text
240 / 240
```

### 14.2 搜索命中部分结果

搜索框输入关键字后，如果列表显示 12 条，总数 240 条，应显示：

```text
12 / 240
```

### 14.3 搜索无结果

搜索框输入一个不存在的关键字，应显示：

```text
0 / 240
```

### 14.4 清空搜索框

清空搜索框后，应恢复：

```text
240 / 240
```

### 14.5 新增快捷项

新增 1 个快捷项后，总数和显示数应同步增加。

无筛选时：

```text
241 / 241
```

有筛选时：

```text
当前筛选命中数 / 241
```

### 14.6 删除快捷项

删除 1 个快捷项后，总数和显示数应同步减少。

### 14.7 批量新增识别

批量新增、更新、清理重复项后，数量显示应和主列表实际数量一致。

主界面搜索框右侧会显示一个简洁的数量反馈：

```text
12 / 240
```

用户可以直观看到当前筛选结果数量和程序总快捷项数量，尤其在搜索、批量导入后更容易判断数据是否符合预期。
