# v68 工厂地图节点显示原始机型名编码规格说明

## 1. 需求背景

当前 VSLoader 的工厂地图节点只显示快捷项名称，例如：

```text
灌胶载盘切换机_003
```

用户希望地图节点除了显示快捷项名称之外，还能在下一行显示该设备的原始机型名，例如：

```text
灌胶载盘切换机_003
TCDE003
```

这里的“原始机型名”不是 `SourceModuleName`，也不是 ZAM 中的模块名，而是从快捷项目标路径最后一级文件夹名中提取出的设备编号。

示例：

```text
TargetPath = \\192.168.15.69\instances\5534_TCDE003
```

提取结果：

```text
TCDE003
```

## 2. 需求目标

完成后：

```text
1. 工厂地图节点第一行显示快捷项名称。
2. 工厂地图节点第二行显示原始机型名。
3. 原始机型名从 ShortcutItem.TargetPath 的最后一级文件夹名中解析。
4. 如果最后一级文件夹名为 5534_TCDE003，则只显示 TCDE003。
5. 如果无法解析出原始机型名，则只显示快捷项名称，不显示空白第二行。
6. 不读取网络文件，不访问 ZAM-DEPLOY.xml，不增加额外网络 IO。
7. 不修改主界面列表，不修改批量新增算法，不修改地图布局 JSON 文件结构。
```

### 4.1 输入数据

### 4.2 提取规则

从目标路径最后一级文件夹名中提取。

示例一：

```text

```

最后一级文件夹名：

```text

```

存在 `_`，取最后一个 `_` 后面的内容：

```text
TCDE003
```

示例二：

```text

```

显示：

```text

```

示例三：

```text

```

文件夹名没有 `_`，但本身符合设备编号格式，可以显示：

```text

```

示例四：

```text

```

如果无法识别为设备编号，则返回空字符串，不显示第二行。

## 5. 原始机型名识别规则

为了避免把无关文件夹名误显示为原始机型名，建议增加一个轻量正则校验。

推荐规则：

```regex
^[A-Za-z]+[0-9]+$
```

处理流程：

```text
1. 取路径最后一级文件夹名。
2. 如果文件夹名包含 `_`，取最后一个 `_` 后面的内容作为候选值。
3. 如果文件夹名不包含 `_`，用完整文件夹名作为候选值。
4. candidate.Trim()。
5. 如果 candidate 匹配 ^[A-Za-z]+[0-9]+$，返回 candidate。
6. 否则返回空字符串。
```

示例：

```text
5534_TCDE003       -> TCDE003
12190_TAOI007      -> TAOI007
TCDE003            -> TCDE003
5534_TCDE003_backup -> 空字符串
InvalidFolder      -> 空字符串
```

## 7. 推荐实现方案

### 7.1 新增解析类

新增文件：

```text
C:\Users\shee_\OneDrive\Desktop\VSLoader\VSLoader\Models\Services\FactoryMapDeviceCodeParser.cs
```

职责：

```text
从快捷项 TargetPath 或节点 Key 中解析原始机型名。
不访问文件系统。
不判断路径是否存在。
只做字符串解析。
```

建议代码结构：

```csharp
using System.IO;
using System.Text.RegularExpressions;

namespace VSLoader.Services;

public static class FactoryMapDeviceCodeParser
{
    private static readonly Regex DeviceCodeRegex = new(@"^[A-Za-z]+[0-9]+$", RegexOptions.Compiled);

    public static string Parse(string? targetPath)
    {
        if (string.IsNullOrWhiteSpace(targetPath))
        {
            return string.Empty;
        }

        var normalizedPath = targetPath.Trim().TrimEnd(Path.DirectorySeparatorChar, Path.AltDirectorySeparatorChar);
        var folderName = Path.GetFileName(normalizedPath);
        if (string.IsNullOrWhiteSpace(folderName))
        {
            return string.Empty;
        }

        var separatorIndex = folderName.LastIndexOf('_');
        var candidate = separatorIndex >= 0 && separatorIndex < folderName.Length - 1
            ? folderName[(separatorIndex + 1)..]
            : folderName;

        candidate = candidate.Trim();
        return DeviceCodeRegex.IsMatch(candidate) ? candidate : string.Empty;
    }
}
```

说明：

```text
1. 使用 LastIndexOf('_')，兼容前缀中可能还有其他下划线的情况。
2. 不使用 Directory.Exists。
3. 不访问网络路径。
4. 只做字符串解析，因此性能开销极低。
```


## 12. 风险点

### 12.1 节点文字过挤

风险：

```text
节点尺寸固定，增加第二行后文字可能显得拥挤。
```

规避：

```text
优先使用紧凑字体和行距。
不修改节点尺寸，避免影响地图布局和连线。
```

### 12.2 错误显示无关文件夹名

风险：

```text
如果没有校验规则，可能把 InvalidFolder 误显示为原始机型名。
```

规避：

```text
使用 ^[A-Za-z]+[0-9]+$ 校验候选值。
```

### 12.3 网络卡顿

风险：

```text
如果为了获取原始机型名访问网络路径，会导致地图打开卡顿。
```

规避：

```text
只解析路径字符串，不访问文件系统。
```
