# v33 批量新增识别路径持久化配置编码规格说明

## 1. 需求背景

当前 `批量新增识别` 独立窗口中有两个用户输入路径：

```text
目标父级文件夹
CSV 规则文件
```

当前这两个路径只保存在当前窗口内存中。

用户关闭批量新增识别窗口后，下次再次打开，需要重新选择：

- 目标父级文件夹
- CSV 规则文件

用户希望程序能够记住上一次有效操作后的这两个路径。

这样后续目标父级文件夹中有新增内容时，用户可以：

```text
打开批量新增识别 -> 直接点击扫描预览 -> 快速导入新增快捷项
```

不用反复重新选择路径。

## 2. 需求目标

本次开发目标：

1. 持久化保存上一次成功扫描使用的目标父级文件夹路径。
2. 持久化保存上一次成功扫描使用的 CSV 规则文件路径。
3. 下次打开批量新增识别窗口时，自动回填这两个路径。
4. 用户可以直接点击 `扫描预览`。
5. 配置保存到现有 `%AppData%\VSLoader\config.json`。
6. 不新增单独配置文件。
7. 不改变批量新增识别算法。
8. 不改变 CSV 规则格式。
9. 不改变扫描预览结果表格。
10. 不改变确认新增逻辑。

## 3. 技术方案选择

采用方案 A：

```text
由 MainViewModel 统一管理配置读写。
BatchImportViewModel 只负责接收初始路径、执行扫描、向外暴露当前路径。
```

选择原因：

- 当前项目配置统一由 `MainViewModel` 和 `ConfigService` 管理。
- `BatchImportViewModel` 不直接依赖 `ConfigService`，职责更清晰。
- 避免子窗口自行读写主配置造成状态不一致。
- 符合当前项目已有结构。

## 5. 新增配置模型

新增文件：

```text
VSLoader\Models\BatchImportConfig.cs
```

内容：

```csharp
namespace VSLoader.Models;

public sealed class BatchImportConfig
{
    public string LastParentFolderPath { get; set; } = string.Empty;

    public string LastCsvPath { get; set; } = string.Empty;

    public BatchImportConfig Clone()
    {
        return new BatchImportConfig
        {
            LastParentFolderPath = LastParentFolderPath,
            LastCsvPath = LastCsvPath
        };
    }
}
```

说明：

- `LastParentFolderPath` 保存上一次成功扫描的目标父级文件夹。
- `LastCsvPath` 保存上一次成功扫描的 CSV 规则文件。
- `Clone()` 用于向窗口传递配置快照，避免子窗口直接持有主配置对象。

## 9. BatchImportViewModel 扫描成功标记

为了让 `MainViewModel` 知道窗口中是否发生过有效扫描，新增属性：

```csharp
public bool HasSuccessfulScan { get; private set; }
```

在 `ScanPreview()` 成功完成扫描后设置：

```csharp
HasSuccessfulScan = true;
```

推荐设置位置：

```csharp
var previewItems = _batchImportService.BuildPreview(...);

...

RefreshStatistics();
HasSuccessfulScan = true;
```

注意：

- 只有路径校验通过、CSV 文件存在、规则能正常读取、预览构建完成后，才设置为 `true`。
- 如果因为路径为空、路径不存在、CSV 不存在、CSV 表头错误等提前 return，不应设置为 `true`。

## 10. 保存时机

本次推荐保存时机：

```text
扫描预览成功后保存路径。
```

原因：

- 扫描成功说明这两个路径是有效组合。
- 用户即使没有点击确认新增，也可能只是本次没有新增项，但路径仍然应该被记住。
- 用户点击取消窗口时，不应清空已保存路径。

## 12. MainViewModel 保存扫描成功路径

`OpenBatchImport()` 中，在窗口关闭后检查：

```csharp
if (viewModel.HasSuccessfulScan)
{
    _config.BatchImport.LastParentFolderPath = viewModel.ParentFolderPath.Trim();
    _config.BatchImport.LastCsvPath = viewModel.CsvPath.Trim();
    SaveCurrentConfig();
}
```

注意：

- 该逻辑应该在 `window.ShowDialog()` 返回后执行。
- 无论 `ShowDialog()` 返回 `true` 还是 `false`，只要 `HasSuccessfulScan == true`，就保存路径。
- 如果用户打开窗口后没有成功扫描，关闭窗口不修改已保存路径。

推荐结构：

```csharp
var dialogResult = window.ShowDialog();

if (viewModel.HasSuccessfulScan)
{
    _config.BatchImport.LastParentFolderPath = viewModel.ParentFolderPath.Trim();
    _config.BatchImport.LastCsvPath = viewModel.CsvPath.Trim();
    SaveCurrentConfig();
}

if (dialogResult == true)
{
    ...
}
```

## 13. 避免重复保存说明

当前 `OpenBatchImport()` 在确认新增成功后也会调用：

```csharp
SaveCurrentConfig();
```

新增路径保存后，可能出现：

```text
扫描成功 -> 保存路径一次
确认新增 -> 保存快捷项一次
```

为了减少重复保存，推荐使用一个局部变量判断：

```csharp
var shouldSaveConfig = false;

if (viewModel.HasSuccessfulScan)
{
    _config.BatchImport.LastParentFolderPath = viewModel.ParentFolderPath.Trim();
    _config.BatchImport.LastCsvPath = viewModel.CsvPath.Trim();
    shouldSaveConfig = true;
}

if (dialogResult == true)
{
    ...
    shouldSaveConfig = true;
}

if (shouldSaveConfig)
{
    SaveCurrentConfig();
}
```

说明：

- 扫描成功但取消：保存路径。
- 扫描成功并确认新增：路径和快捷项一起保存一次。
- 未扫描直接取消：不保存。

## 14. 路径不存在时的行为

如果上次保存的路径下次打开时已经不存在：

```text
窗口仍显示旧路径。
点击扫描预览时沿用现有校验提示。
```

不在窗口打开时自动清空。

原因：

- 网络路径可能临时不可达。
- 自动清空会让用户失去上次路径信息。
- 现有扫描校验已经能给出明确错误提示。

- 不需要加密。
- 不需要单独文件。

## 16. 不允许改变的功能

本次不允许改变：

- 批量新增识别 CSV 规则格式。
- Regex/Contains 匹配逻辑。
- 名称模板逻辑。
- 预览列表字段。
- 确认新增逻辑。
- 跳过重复项逻辑。
- 主窗口快捷项保存逻辑。
- 配置文件路径。
- AdminUI 功能。
- VSCode 打开功能。

## 17. 验收标准

### 17.1 首次打开

操作：

1. 删除或使用没有 `BatchImport` 字段的旧配置。
2. 打开批量新增识别窗口。

期望：

- `目标父级文件夹` 输入框为空。
- `CSV 规则文件` 输入框为空。
- 程序不报错。

### 17.2 扫描成功后保存路径

操作：

1. 输入有效目标父级文件夹。
2. 输入有效 CSV 规则文件。
3. 点击 `扫描预览`。
4. 关闭窗口或点击取消。
5. 重新打开批量新增识别窗口。

期望：

- 两个输入框自动回填上次成功扫描的路径。

### 17.3 确认新增后保存路径

操作：

1. 输入有效路径。
2. 点击 `扫描预览`。
3. 点击 `确认新增`。
4. 再次打开批量新增识别窗口。

期望：

- 两个输入框自动回填。
- 新增快捷项仍正常保存。

### 17.4 扫描失败不覆盖旧路径

操作：

1. 先保存一组有效路径。
2. 再打开窗口，输入不存在的父级路径。
3. 点击 `扫描预览`，触发错误提示。
4. 关闭窗口。
5. 再次打开窗口。

期望：

- 仍显示之前保存的有效路径。
- 不被失败路径覆盖。

### 17.5 旧路径临时不可达

操作：

1. 保存一个网络路径。
2. 断开网络或让路径不可达。
3. 打开批量新增识别窗口。

期望：

- 输入框仍显示旧路径。
- 点击扫描预览时提示路径不存在或不可访问。
- 程序不自动清空路径。

### 17.6 编译验收

执行：

```powershell
dotnet build .\VSLoader.sln
```

期望：

```text
0 warnings
0 errors
```

如果提示 `VSLoader.exe` 被占用，说明程序正在运行，应先通过托盘菜单 `退出` 或结束进程后重新构建。

## 18. 建议实施步骤

1. 新增 `VSLoader\Models\BatchImportConfig.cs`。
2. 修改 `AppConfig`，新增 `BatchImport` 字段。
3. 修改 `ConfigService.Load()`，兼容旧配置。
4. 修改 `BatchImportViewModel` 构造函数，接收初始配置。
5. 打开窗口时回填 `ParentFolderPath` 和 `CsvPath`。
6. 在扫描预览成功后设置 `HasSuccessfulScan = true`。
7. 修改 `MainViewModel.OpenBatchImport()`，传入 `_config.BatchImport.Clone()`。
8. 在窗口关闭后，如扫描成功则同步路径回 `_config.BatchImport`。
9. 用 `shouldSaveConfig` 避免重复保存。
10. 编译项目。
11. 手动验证首次打开、扫描成功保存、取消后保存、扫描失败不覆盖旧路径。

## 19. 明确不做的事情

本次不做：

- 多组批量导入路径配置。
- 最近路径历史列表。
- CSV 规则文件收藏。
- 路径有效性后台自动检测。
- 打开窗口时自动扫描。
- 自动清理不可达路径。
- 单独配置文件。
- 设置窗口中的批量导入路径配置入口。
