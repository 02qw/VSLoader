# v87 软件更新器前置接管与全流程进度显示编码规格说明

## 1. 背景

当前自动更新逻辑经历了 v85、v86 两个阶段：

1. v85 实现了自动更新基础能力。
2. v86 修复了 updater 可见性、runner 启动目录、启动失败不退出等问题。

但当前整体体验仍然不是最理想：

1. 用户点击“更新软件”后，VSLoader 仍然会先执行读取 manifest、复制 zip、校验 SHA、解压等耗时准备工作。
2. updater 只有在 VSLoader 完成准备工作之后才启动。
3. 用户感知上仍然会觉得“主程序先忙一会儿，然后退出，再等 updater 接管”。

用户期望的新体验是：

> 点击“更新软件”后，先由 VSLoader 弹确认框。用户确认后，立即启动 updater 窗口，updater 窗口先显示出来，然后 VSLoader 退出。后续所有更新步骤都在 updater 窗口中执行并显示进度。

因此 v87 要把更新控制权从 VSLoader 前置交给 updater：

1. VSLoader 只负责确认和启动 updater。
2. updater 负责完整更新流程。
3. updater 负责显示进度条和滚动进度详情。

## 2. 总体目标

### 2.1 用户操作流程

目标流程：

```text
用户点击“更新软件”
  ↓
VSLoader 弹确认框：“确定要更新软件吗？”
  ↓
用户点击确定
  ↓
VSLoader 启动 updater 窗口
  ↓
updater 窗口立即显示
  ↓
VSLoader 退出
  ↓
updater 执行完整更新流程
  ↓
updater 显示进度条 + 实时滚动详情
  ↓
更新完成后 updater 启动新版 VSLoader
```

### 2.2 核心体验要求

1. updater 必须先可见，再让 VSLoader 退出。
2. VSLoader 不再执行耗时更新准备动作。
3. updater 显示完整更新过程。
4. updater 成功时自动启动新版 VSLoader。
5. updater 失败时窗口停留，显示错误原因，并提供打开日志目录。
6. 如果 updater 检测到当前已是最新版本，显示“当前已是最新版本”，不自动关闭，让用户自己关闭。

## 3. 新旧职责划分

### 3.1 当前职责

当前 VSLoader 负责：

```text
读取 manifest
检查版本
复制更新 zip
校验 SHA256
解压到 staging
准备 runner
启动 updater
退出
```

当前 updater 负责：

```text
等待 VSLoader 退出
备份旧版本
替换文件
清理临时文件
启动新版 VSLoader
```

### 3.2 v87 后职责

VSLoader 只负责：

```text
弹确认框
定位当前可用 updater
启动 updater
确认 updater 进程启动成功
退出 VSLoader
```

updater 负责：

```text
显示窗口
读取 manifest
检查版本
复制更新 zip
校验 SHA256
解压到 staging
等待 VSLoader 退出
备份旧版本
替换文件
清理临时文件
启动新版 VSLoader
```

## 4. 主程序 VSLoader 修改规格

### 4.1 点击“更新软件”先确认

在 `MainViewModel.UpdateSoftwareAsync` 中，点击“更新软件”后，先弹确认框。

推荐提示文案：

```text
确定要更新 VSLoader 吗？
更新过程中主程序会暂时关闭，并由更新器接管。
```

按钮：

```text
确定 / 取消
```

要求：

1. 用户点击取消：不做任何更新动作。
2. 用户点击确定：继续启动 updater。
3. 确认弹窗放在 VSLoader 中。

如果当前 `DialogService` 没有确认弹窗接口，需要新增轻量方法：

```csharp
public virtual bool Confirm(string message, string title = "VSLoader")
```

确认弹窗必须以主窗口为 Owner 居中显示，遵循现有自定义弹窗规范。

### 4.2 VSLoader 不再执行 PrepareUpdateAsync

v87 后，VSLoader 点击确认后不再调用：

```csharp
SoftwareUpdateService.PrepareUpdateAsync(...)
```

也不再显示主程序的长时间更新准备遮罩。

VSLoader 只负责构造 updater 参数并启动 updater。

### 4.3 VSLoader 启动 updater 的来源

VSLoader 应从当前程序目录启动随程序发布的 updater：

```text
AppContext.BaseDirectory\VSLoader.Updater.exe
```

原因：

1. 此时还没有下载新版 zip。
2. runner/staging 还未生成。
3. 当前版本内置 updater 是唯一稳定可用的启动器。

如果当前程序目录缺少 `VSLoader.Updater.exe`：

1. 不退出 VSLoader。
2. 弹出错误：

```text
当前程序目录缺少 VSLoader.Updater.exe，无法启动更新器。
```

### 4.4 VSLoader 传给 updater 的参数

VSLoader 启动 updater 时需要传入：

```text
--mode update
--processId 当前 VSLoader 进程 ID
--targetDir 当前 VSLoader 程序目录
--mainExeName VSLoader.exe
--manifestPath 软件更新 manifest 路径
--currentVersion 当前 VSLoader 版本
--updatesRoot %LocalAppData%\VSLoader\Updates
```

示例：

```text
VSLoader.Updater.exe
  --mode update
  --processId 12345
  --targetDir "C:\Program Files\VSLoader"
  --mainExeName VSLoader.exe
  --manifestPath "\\server\VSLoaderUpdate\manifest.json"
  --currentVersion 2.1.0
  --updatesRoot "C:\Users\xxx\AppData\Local\VSLoader\Updates"
```

注意：

1. `manifestPath` 来自程序级配置 `AppSettings.SoftwareUpdateManifestPath`。
2. `currentVersion` 来自 `Assembly.GetExecutingAssembly().GetName().Version`。
3. `targetDir` 继续使用 `AppContext.BaseDirectory`。

### 4.5 VSLoader 退出时机

VSLoader 只有在 `Process.Start` 返回成功后才退出。

如果启动失败：

1. 不退出 VSLoader。
2. 弹出错误。

当前 `StartUpdater` 建议继续使用：

```csharp
Func<string, string, bool>
```

启动成功后：

```csharp
RequestApplicationExit();
```

## 5. updater 参数模型修改规格

### 5.1 UpdaterOptions 扩展

当前 `UpdaterOptions` 需要扩展为支持完整更新流程。

新增字段：

```csharp
public string Mode { get; init; } = "apply";
public string ManifestPath { get; init; } = string.Empty;
public Version CurrentVersion { get; init; } = new(0, 0);
```

保留字段：

```csharp
public int ProcessId { get; init; }
public string TargetDirectory { get; init; } = string.Empty;
public string StagingDirectory { get; init; } = string.Empty;
public string MainExeName { get; init; } = "VSLoader.exe";
public string UpdatesRoot { get; init; } = string.Empty;
```

### 5.2 mode 兼容策略

为了最小风险，updater 可以支持两种 mode：

#### mode=update

v87 新流程。

updater 自己读取 manifest、下载/复制 zip、校验、解压、替换。

#### mode=apply

兼容旧流程。

如果传入了 `stagingDir`，updater 只做等待退出、备份、替换、清理。

如果不需要兼容旧流程，也可以内部只使用 update，但测试中保留旧 parser 用例时建议保留 apply。

## 6. updater 完整更新服务规格

### 6.1 新增服务建议

建议在 updater 项目中新增：

```text
VSLoader.Updater\Services\UpdaterUpdateService.cs
VSLoader.Updater\Services\UpdaterProgress.cs
```

职责：

```text
读取 manifest
检查版本
复制更新包
校验 SHA256
解压 staging
调用 UpdaterApplyService 替换文件
```

### 6.2 manifest 模型复用

当前主程序已有：

```text
VSLoader\Models\SoftwareUpdateManifest.cs
```

不建议 updater 项目直接引用主程序项目，避免循环和体积问题。

建议在 updater 项目中新增独立同名模型：

```text
VSLoader.Updater\Services\SoftwareUpdateManifest.cs
```

字段：

```csharp
public sealed class SoftwareUpdateManifest
{
    public string Version { get; set; } = string.Empty;
    public string PackageFile { get; set; } = string.Empty;
    public string Sha256 { get; set; } = string.Empty;
    public string ReleaseNotes { get; set; } = string.Empty;
}
```

### 6.3 更新包路径规则

与 v85 保持一致：

1. 如果 `packageFile` 是绝对路径，直接使用。
2. 如果 `packageFile` 是相对路径，则相对于 `manifest.json` 所在目录解析。

示例：

```text
manifest: \\server\VSLoaderUpdate\manifest.json
packageFile: VSLoader_2.1.0_win-x64.zip
实际包路径: \\server\VSLoaderUpdate\VSLoader_2.1.0_win-x64.zip
```

### 6.4 临时目录

updater 使用：

```text
UpdatesRoot\download
UpdatesRoot\staging\版本号
UpdatesRoot\backup
```

v87 中 updater 自己就是当前程序目录里的旧 updater，不再需要 runner 作为执行目录。

但为了兼容 v86 遗留，`UpdatesRoot\runner` 可以保留不处理。

### 6.5 完整 update 流程

updater 执行：

```text
1. 显示窗口：正在读取更新信息
2. 读取 manifest
3. 校验 manifest
4. 检查 remoteVersion 是否大于 currentVersion
5. 如果没有新版本：显示“当前已是最新版本”，停止并允许关闭
6. 解析更新包路径
7. 清理 download
8. 清理 staging\版本号
9. 复制更新包到 download
10. 计算 SHA256
11. 校验 SHA256
12. 解压 zip 到 staging\版本号
13. 检查 staging 中包含 VSLoader.exe
14. 检查 staging 中包含 VSLoader.Updater.exe
15. 等待 VSLoader 主进程退出
16. 备份旧版本
17. 替换程序文件
18. 清理 download 和 staging
19. 启动新版 VSLoader
20. 显示更新完成并关闭 updater
```

## 7. updater 窗口 UI 规格

### 7.1 窗口内容

窗口应包含：

1. 标题：

```text
正在更新 VSLoader
```

2. 进度条。
3. 当前步骤文本。
4. 实时滚动详情区域。
5. 失败时显示：
   - 打开日志目录
   - 关闭

### 7.2 实时滚动详情

详情区域显示每一步日志。

示例：

```text
[12:30:01] 正在读取更新信息...
[12:30:02] 当前版本：2.0.1
[12:30:02] 发现新版本：2.1.0
[12:30:03] 正在复制更新包...
[12:30:05] 正在校验 SHA256...
[12:30:06] 正在解压更新包...
[12:30:09] 正在等待 VSLoader 退出...
[12:30:10] 正在备份旧版本...
[12:30:12] 正在替换程序文件...
[12:30:15] 更新完成，正在启动新版 VSLoader...
```

实现方式建议：

```csharp
public ObservableCollection<string> DetailLines { get; } = new();
```

XAML 可使用：

```xml
<ListBox ItemsSource="{Binding DetailLines}" />
```

或 `TextBox` 绑定完整字符串。

优先建议 `ListBox`，滚动到最新一行可以在 code-behind 中处理。

### 7.3 进度比例建议

推荐进度：

```text
5   读取 manifest
10  检查版本
20  复制更新包
35  校验 SHA256
50  解压更新包
60  等待主程序退出
70  备份旧版本
85  替换文件
95  启动新版程序
100 完成
```

### 7.4 关闭规则

更新进行中：

1. 用户点击关闭时阻止关闭。
2. 显示提示：

```text
正在更新，暂时不能关闭。
```

失败或无更新：

1. 允许用户关闭。

成功：

1. updater 自动关闭。

## 8. 错误处理规格

### 8.1 失败窗口

任何失败都不能静默退出。

失败时：

1. 停留在 updater 窗口。
2. `HasError = true`。
3. 显示错误原因。
4. 写入错误日志。
5. 提供“打开日志目录”按钮。

### 8.2 错误日志

继续写入：

```text
%LocalAppData%\VSLoader\errorLog
```

日志文件名：

```text
yyyyMMdd_HHmmss_fff.log
```

日志内容至少包含：

```text
Time
Step
ManifestPath
TargetDirectory
StagingDirectory
ProcessId
Exception
RollbackException 如果存在
```

## 9. 旧服务处理策略

### 9.1 主程序 SoftwareUpdateService

v87 后主程序不再需要在正常更新路径调用：

```csharp
SoftwareUpdateService.PrepareUpdateAsync
```

但为了最小风险，可以暂时保留服务和测试，不删除。

后续确认 v87 稳定后，再考虑清理。

### 9.2 v86 runner 逻辑

runner 逻辑也可以暂时保留，不作为新流程使用。

但新流程中 VSLoader 启动 updater 时，应优先使用：

```text
AppContext.BaseDirectory\VSLoader.Updater.exe
```

而不是：

```text
Updates\runner\VSLoader.Updater.exe
```

### 11.1 正常更新验证

1. 准备一个低版本 VSLoader。
2. 设置 manifest 路径。
3. 点击“更新软件”。
4. VSLoader 弹确认框。
5. 点击确定。
6. updater 窗口立即出现。
7. VSLoader 退出。
8. updater 窗口显示完整进度详情。
9. 更新完成后新版 VSLoader 启动。

### 11.2 取消验证

1. 点击“更新软件”。
2. 确认框点击取消。
3. VSLoader 不退出。
4. updater 不启动。

### 11.3 已是最新版本验证

1. manifest 版本小于或等于当前版本。
2. 点击更新并确认。
3. updater 显示窗口。
4. updater 显示“当前已是最新版本”。
5. updater 不自动关闭，用户可手动关闭。
6. VSLoader 是否退出：
   - 按本规格，VSLoader 已在 updater 启动后退出。
   - updater 关闭后不重启 VSLoader。

### 11.4 失败验证

1. 故意修改 manifest sha256。
2. 点击更新并确认。
3. updater 显示 SHA256 校验失败。
4. 窗口停留。
5. 可以打开日志目录。

## 13. 风险与注意事项

### 13.1 updater 运行的是旧版本 updater

v87 中 updater 是从当前程序目录启动的，所以执行更新逻辑的是旧版本 updater。

这正是自更新程序的常见模式。

要求：

1. updater 必须足够稳定。
2. manifest 格式变化要谨慎，因为旧 updater 只能理解旧格式。

### 13.2 VSLoader 会先退出

新流程中，updater 显示后 VSLoader 就会退出。

如果 updater 发现没有新版本，默认显示“当前已是最新版本”，不自动重启 VSLoader。

这是本规格接受的行为。

### 13.3 日志区域性能

详情日志不需要记录每个文件复制。

只记录关键步骤，避免几百个 dll 导致 UI 卡顿。

### 13.4 替换 updater 自身

updater 从旧程序目录运行，替换目标目录时会遇到旧 updater 文件正在运行。

因此替换逻辑需要注意：

1. 如果直接覆盖正在运行的 `VSLoader.Updater.exe` 失败，应该跳过当前 updater 自身文件，或者延迟到下次更新。
2. 推荐策略：替换主程序和依赖文件时，跳过当前正在运行的 `VSLoader.Updater.exe`。
3. 新版 updater 会随安装包或下次完整覆盖进入程序目录。

此点是 v87 实现时必须特别处理的风险。

## 14. 验收标准

满足以下条件视为完成：

1. 点击“更新软件”先弹确认框。
2. 取消后不启动 updater，不退出 VSLoader。
3. 确认后 updater 窗口先显示。
4. updater 显示后 VSLoader 退出。
5. manifest 读取、zip 复制、SHA 校验、解压、备份、替换等过程都在 updater 窗口展示。
6. updater 有进度条。
7. updater 有实时滚动详情。
8. 失败时窗口停留并写日志。
9. 已是最新版本时窗口提示且不自动关闭。
10. `dotnet test .\VSLoader.sln` 通过。
11. `.\build-release.ps1` 通过。
