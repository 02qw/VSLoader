# v85 软件自动更新编码规格说明

## 1. 文档目的

本文件用于指导编程 Agent 为 VSLoader 增加“软件自动更新”功能。

目标是让用户无需手动去服务器下载新版 zip 或安装包，只需要在 VSLoader 中点击：

```text
更新软件
```

程序即可自动从配置的更新路径读取最新版本信息、复制更新包、校验完整性、解压并启动独立更新器完成程序文件替换。

## 2. 核心结论

本功能采用：

```text
自研轻量更新方案
```

整体由两个程序配合完成：

```text
1. VSLoader.exe
   负责检查更新、复制更新包、校验 SHA256、解压、启动更新器、退出自身。

2. VSLoader.Updater.exe
   负责等待 VSLoader 退出、备份旧程序、替换程序文件、失败回滚、写错误日志、重启 VSLoader。
```

关键原则：

```text
VSLoader.exe 不能直接覆盖自己正在运行的 exe/dll 文件。
```

因此必须由独立的：

```text
VSLoader.Updater.exe
```

在主程序退出后执行文件替换。

## 3. 功能范围

本阶段实现：

```text
1. 程序全局配置中新增软件更新 manifest 路径。
2. 设置窗口新增软件更新路径配置。
3. 主界面新增“更新软件”按钮。
4. 点击按钮后显示遮罩进度，禁止用户继续操作主界面。
5. 读取 manifest.json。
6. 判断远端版本是否高于当前程序版本。
7. 复制更新 zip 到本地临时目录。
8. 校验 zip 的 SHA256。
9. 解压 zip 到 staging 目录。
10. 检查解压目录中存在 VSLoader.exe 和 VSLoader.Updater.exe。
11. 启动 VSLoader.Updater.exe。
12. 主程序退出。
13. Updater 显示独立进度窗口。
14. Updater 等待主程序退出。
15. Updater 备份当前程序目录。
16. Updater 替换程序文件。
17. Updater 成功后清理 download/staging 临时目录。
18. Updater 成功后重启新版 VSLoader。
19. Updater 失败后回滚旧版本。
20. Updater 失败后写错误日志到 %LocalAppData%\VSLoader\errorLog。
```

本阶段不实现：

```text
1. 增量更新。
2. 后台静默自动更新。
3. 多版本选择。
4. 在线 release notes 富文本展示。
5. 数字签名校验。
6. 自动上传/生成 manifest。
7. 自动生成 SHA256 的发布脚本增强。
```

其中第 7 项可以后续单独做打包脚本优化。

## 4. 配置归属

软件更新路径属于：

```text
程序全局配置
```

不是工作区配置。

原因：

```text
1. 软件更新更新的是 VSLoader 程序本体。
2. 不应该每个工作区都重复配置软件更新地址。
3. 切换工作区不应该影响 VSLoader 自身更新来源。
```

因此配置应保存到：

```text
%AppData%\VSLoader\app-settings.json
```

不能保存到：

```text
%AppData%\VSLoader\Workspaces\<工作区>\config.json
```

## 5. 新增全局配置字段

目标文件：

```text
VSLoader\Models\AppSettings.cs
```

新增字段：

```csharp
public string SoftwareUpdateManifestPath { get; set; } = string.Empty;
```

含义：

```text
软件更新 manifest.json 的完整路径。
```

示例：

```text
\\192.168.15.67\VSLoaderUpdate\manifest.json
```

或：

```text
D:\Share\VSLoaderUpdate\manifest.json
```

旧配置兼容要求：

```text
旧 app-settings.json 没有 SoftwareUpdateManifestPath 字段时，应自动补为空字符串。
```

## 6. manifest.json 规范

服务器或共享目录中放置：

```text
manifest.json
VSLoader_2.0.2_win-x64.zip
```

manifest.json 示例：

```json
{
  "version": "2.0.2",
  "packageFile": "VSLoader_2.0.2_win-x64.zip",
  "sha256": "这里填写 zip 文件的 SHA256",
  "releaseNotes": "修复问题并优化体验"
}
```

字段说明：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| version | 是 | 最新软件版本号 |
| packageFile | 是 | zip 更新包文件名或相对路径 |
| sha256 | 是 | zip 文件 SHA256 |
| releaseNotes | 否 | 更新说明 |

规则：

```text
1. version 必须能被 Version.TryParse 解析。
2. packageFile 为空时视为 manifest 无效。
3. sha256 为空时视为 manifest 无效。
4. packageFile 如果是相对路径，则相对于 manifest.json 所在目录解析。
5. 第一版只支持本地路径/网络共享路径，不强制支持 http 下载。
```

## 7. 发布包结构要求

更新 zip 解压后必须包含：

```text
VSLoader.exe
VSLoader.Updater.exe
```

建议发布目录结构：

```text
VSLoader_2.0.2_win-x64\
    VSLoader.exe
    VSLoader.Updater.exe
    VSLoader.dll
    VSLoader.deps.json
    VSLoader.runtimeconfig.json
    Config\
        batch-rules.example.csv
        ...
```

zip 中可以是：

```text
根目录直接是 VSLoader.exe
```

也可以是：

```text
外层文件夹\VSLoader.exe
```

但第一版建议约定为：

```text
zip 根目录直接包含 VSLoader.exe 和 VSLoader.Updater.exe
```

这样实现更简单，减少路径猜测。

## 8. 临时目录设计

更新临时文件放到：

```text
%LocalAppData%\VSLoader\Updates
```

建议结构：

```text
%LocalAppData%\VSLoader\Updates\
    download\
        VSLoader_2.0.2_win-x64.zip
    staging\
        2.0.2\
            VSLoader.exe
            VSLoader.Updater.exe
            ...
    backup\
        20260617_153000\
            VSLoader.exe
            VSLoader.dll
            ...
```

错误日志放到：

```text
%LocalAppData%\VSLoader\errorLog
```

错误日志文件名：

```text
yyyyMMdd_HHmmss_fff.log
```

示例：

```text
%LocalAppData%\VSLoader\errorLog\20260617_153000_123.log
```

## 9. 临时文件清理策略

主程序开始更新前：

```text
1. 清理旧 download 目录。
2. 清理旧 staging 目录。
3. 创建新的 download 目录。
4. 创建新的 staging\<version> 目录。
```

Updater 更新成功后：

```text
1. 删除 download 目录。
2. 删除 staging 目录。
3. backup 保留最近 1 份。
4. 删除更老的 backup。
```

Updater 更新失败后：

```text
1. 尽量回滚旧版本。
2. 不强制删除本次 staging，方便排查。
3. 写错误日志。
4. 显示错误信息。
```

说明：

```text
backup 不建议成功后立即全部删除。
至少保留最近 1 份，方便后续人工恢复或排查。
```

## 10. 主程序更新流程

入口：

```text
主界面按钮：更新软件
```

点击后流程：

```text
1. 如果 IsBusy = true，直接忽略。
2. 检查 SoftwareUpdateManifestPath 是否为空。
3. 为空则提示用户先进入设置配置软件更新路径。
4. 显示遮罩进度。
5. 设置 IsBusy = true，禁止主界面操作。
6. 读取 manifest.json。
7. 校验 manifest 字段。
8. 比较 manifest.version 与当前程序版本。
9. 如果 manifest.version <= 当前版本，提示“当前已是最新版本”。
10. 解析 packageFile 实际路径。
11. 检查 zip 文件存在。
12. 复制 zip 到 download 目录。
13. 计算本地 zip SHA256。
14. 与 manifest.sha256 比对。
15. 不一致则提示更新包校验失败。
16. 解压 zip 到 staging\<version>。
17. 检查 staging 中存在 VSLoader.exe。
18. 检查 staging 中存在 VSLoader.Updater.exe。
19. 启动 staging 中的 VSLoader.Updater.exe 或当前程序目录中的 VSLoader.Updater.exe。
20. 主程序主动退出。
```

推荐：

```text
启动 staging 中的 VSLoader.Updater.exe。
```

原因：

```text
1. 可以使用新版 Updater。
2. 避免旧版 Updater 缺少新参数能力。
3. 当前程序目录中的旧 Updater 可能需要被替换，运行它会占用旧文件。
```

```text
IsBusy

BusyProgressValue
BusyProgressMaximum
BusyProgressText

```

建议步骤显示：

```text
正在读取更新信息...
正在检查版本...
正在复制更新包...
正在校验更新包...
正在解压更新包...
正在启动更新器...
```

要求：

```text
1. 更新过程中主界面不可操作。
2. 不允许重复点击“更新软件”。
3. 不允许用户在更新准备过程中执行批量导入、地图、AdminUI 等操作。
4. 任何异常都要恢复 IsBusy = false。
5. 只有成功启动 Updater 后，主程序才退出。
```

## 12. Updater 程序要求

新增项目：

```text
VSLoader.Updater
```

类型：

```text
WPF/.NET 8 Windows 桌面程序
```

输出文件：

```text
VSLoader.Updater.exe
```

发布时必须和 VSLoader.exe 一起进入 publish 目录和更新 zip。

Updater 职责：

```text
1. 显示更新进度窗口。
2. 禁止用户在更新过程中随意关闭。
3. 等待主程序进程退出。
4. 备份旧程序目录。
5. 替换程序文件。
6. 失败时尽量回滚。
7. 失败时写错误日志。
8. 成功时清理临时文件。
9. 成功后启动新版 VSLoader.exe。
10. 自己退出。
```

## 13. Updater 启动参数

主程序启动 Updater 时传入：

```text
--processId <当前 VSLoader 进程 ID>
--targetDir <当前程序目录>
--stagingDir <解压后的新版目录>
--mainExeName VSLoader.exe
--updatesRoot <Updates 根目录>
```

示例：

```powershell
VSLoader.Updater.exe `
  --processId 12345 `
  --targetDir "D:\Tools\VSLoader" `
  --stagingDir "C:\Users\xxx\AppData\Local\VSLoader\Updates\staging\2.0.2" `
  --mainExeName "VSLoader.exe" `
  --updatesRoot "C:\Users\xxx\AppData\Local\VSLoader\Updates"
```

参数校验：

```text
1. processId 必须为有效整数。
2. targetDir 必须存在。
3. stagingDir 必须存在。
4. stagingDir 中必须存在 mainExeName。
5. updatesRoot 允许不存在，但应能创建。
```

参数无效时：

```text
1. 显示错误窗口。
2. 写错误日志。
3. 不执行替换。
```

## 14. Updater 进度窗口

窗口标题：

```text
正在更新 VSLoader
```

UI 内容：

```text
1. 当前步骤文字。
2. 进度条。
3. 错误信息区域。
```

步骤建议：

```text
0%   正在等待主程序退出...
20%  正在备份旧版本...
45%  正在替换程序文件...
75%  正在清理临时文件...
90%  正在启动新版程序...
100% 更新完成
```

交互要求：

```text
1. 更新过程中不提供取消按钮。
2. 更新过程中关闭窗口应被拦截。
3. 如果用户点击关闭按钮，提示“正在更新，暂时不能关闭”。
4. 成功后自动关闭 Updater。
5. 失败后保留窗口，显示错误信息。
6. 失败后可提供“打开错误日志目录”和“关闭”按钮。
```

## 15. 文件替换策略

Updater 等待主程序退出：

```text
Process.GetProcessById(processId).WaitForExit(timeout)
```

建议 timeout：

```text
30 秒
```

如果超时：

```text
1. 不强杀进程。
2. 显示“主程序未能退出，请手动退出后重试”。
3. 写错误日志。
4. 终止更新。
```

备份策略：

```text
1. 创建 backup\yyyyMMdd_HHmmss_fff。
2. 复制 targetDir 中除 Updates/errorLog 外的程序文件到 backup。
3. 不复制用户 AppData 数据。
```

替换策略：

```text
1. stagingDir 中所有文件复制到 targetDir。
2. 覆盖同名文件。
3. 对目录递归复制。
4. 不删除 targetDir 中不在 stagingDir 的未知文件，第一版减少误删风险。
```

说明：

```text
不删除未知文件可能留下旧文件，但比误删用户放在程序目录里的文件更安全。
如果后续需要更干净，可新增 manifest 文件清单再做精确删除。
```

## 16. 回滚策略

如果替换过程中失败：

```text
1. 记录失败异常。
2. 尝试把 backup 中的文件复制回 targetDir。
3. 回滚成功：提示更新失败，已恢复旧版本。
4. 回滚失败：提示更新失败，回滚也失败，请人工处理。
5. 写错误日志到 %LocalAppData%\VSLoader\errorLog。
```

错误日志内容至少包含：

```text
1. 发生时间。
2. targetDir。
3. stagingDir。
4. processId。
5. 当前步骤。
6. 异常 message。
7. 异常 stack trace。
8. 如果回滚失败，也记录回滚异常。
```

## 17. 当前程序目录定位

```csharp

```

```csharp

```


```text

正式给用户使用时，应让用户运行 publish 或安装目录中的 VSLoader.exe。
```

## 22. 错误处理

主程序阶段失败：

```text
1. 恢复 IsBusy = false。
2. 显示错误弹窗。
3. 不退出主程序。
```

Updater 阶段失败：

```text
1. 显示错误窗口。
2. 写错误日志。
3. 尝试回滚。
4. 不自动重启新版程序。
```

典型错误：

```text
1. 未配置 manifest 路径。
2. manifest 不存在。
3. manifest JSON 损坏。
4. version 无效。
5. packageFile 不存在。
6. sha256 为空。
7. sha256 不匹配。
8. zip 解压失败。
9. staging 缺少 VSLoader.exe。
10. staging 缺少 VSLoader.Updater.exe。
11. 主程序退出超时。
12. targetDir 无权限写入。
13. 文件被占用。
14. 回滚失败。
```

## 23. 测试要求

### 23.1 SoftwareUpdateService 单元测试

至少覆盖：

```text
1. manifest 路径为空时返回失败。
2. manifest 文件不存在时返回失败。
3. manifest JSON 损坏时返回失败。
4. version 无效时返回失败。
5. packageFile 为空时返回失败。
6. sha256 为空时返回失败。
7. 远端版本小于等于当前版本时返回无需更新。
8. packageFile 相对路径能基于 manifest 所在目录解析。
9. sha256 不匹配时返回失败。
10. zip 解压后缺少 VSLoader.exe 时返回失败。
11. zip 解压后缺少 VSLoader.Updater.exe 时返回失败。
```

### 23.2 AppSettingsService 兼容测试

确认旧 app-settings.json 没有：

```text
SoftwareUpdateManifestPath
```

时，加载后该字段为空字符串。

### 23.3 Updater 参数解析测试

如果 Updater 逻辑拆出可测试服务，至少覆盖：

```text
1. 参数缺失。
2. processId 无效。
3. targetDir 不存在。
4. stagingDir 不存在。
5. stagingDir 缺少 VSLoader.exe。
```

### 23.4 Updater 文件替换测试

建议将文件替换逻辑放到服务层，覆盖：

```text
1. 成功复制 staging 文件到 target。
2. 替换失败时尝试回滚。
3. 错误日志写入 errorLog。
4. 成功后清理 download/staging。
5. backup 只保留最近 1 份。
```

## 24. 手工验收

### 场景一：未配置更新路径

操作：

```text
点击“更新软件”
```

预期：

```text
提示请先配置软件更新 manifest 路径。
```

### 场景二：已是最新版

操作：

```text
manifest.version 等于当前程序版本。
点击“更新软件”。
```

预期：

```text
提示当前已是最新版本。
不启动 Updater。
```

### 场景三：SHA 不匹配

操作：

```text
manifest.sha256 写错。
点击“更新软件”。
```

预期：

```text
主程序提示更新包校验失败。
不启动 Updater。
不退出主程序。
```

### 场景四：正常更新

操作：

```text
manifest.version 高于当前版本。
sha256 正确。
zip 内容完整。
点击“更新软件”。
```

预期：

```text
1. 主程序显示准备更新进度。
2. 主程序启动 Updater 后退出。
3. Updater 显示替换进度。
4. Updater 替换成功。
5. Updater 清理 download/staging。
6. Updater 重启 VSLoader。
7. 新 VSLoader 标题栏显示新版本号。
```

### 场景五：替换失败

操作：

```text
人为制造 targetDir 文件占用或权限问题。
```

预期：

```text
1. Updater 显示更新失败。
2. Updater 尝试回滚。
3. %LocalAppData%\VSLoader\errorLog 生成时间戳日志。
4. 日志记录异常和路径信息。
```

## 25. 构建与发布要求

解决方案需要新增 Updater 项目后，发布脚本必须确保：

```text
1. VSLoader.Updater.exe 出现在 publish 目录。
2. 免安装 zip 中包含 VSLoader.Updater.exe。
3. manifest 对应的 zip 包中包含 VSLoader.Updater.exe。
```

如果当前 `build-installer.ps1` 只发布 VSLoader 项目，需要后续增强：

```text
1. 发布 VSLoader 主项目。
2. 发布 VSLoader.Updater 项目。
3. 将 Updater 输出复制进主 publish 目录。
4. 再生成安装包或 zip。
```

## 26. 实现阶段建议

建议按以下阶段实现：

```text
阶段一：AppSettings 配置字段和设置窗口。
阶段二：SoftwareUpdateService 读取 manifest、版本比较、复制、SHA、解压。
阶段三：主界面“更新软件”按钮和遮罩进度。
阶段四：新增 VSLoader.Updater 项目和参数解析。
阶段五：Updater 文件备份、替换、回滚、错误日志。
阶段六：发布脚本整合 Updater。
阶段七：完整联调和手工验收。
```

每个阶段都必须：

```text
1. 先写测试。
2. 再实现。
3. 跑对应测试。
4. 跑 dotnet build。
```

## 28. 验收标准

完成后必须满足：

```text
1. 设置中可以配置软件更新 manifest 路径。
2. 配置保存到程序全局 app-settings.json。
3. 主界面有“更新软件”按钮。
4. 点击更新时主界面显示遮罩进度并禁止操作。
5. manifest 能正确读取和校验。
6. 版本号能正确比较。
7. zip 能复制到本地临时目录。
8. SHA256 能正确校验。
9. zip 能解压到 staging。
10. 缺少 VSLoader.exe 或 VSLoader.Updater.exe 时阻止更新。
11. Updater 能显示独立进度窗口。
12. Updater 能等待主程序退出后替换文件。
13. 成功后能清理 download/staging。
14. 成功后能重启 VSLoader。
15. 失败后能尝试回滚。
16. 失败后能写入 %LocalAppData%\VSLoader\errorLog 时间戳日志。
17. dotnet build 通过。
18. dotnet test 通过。
```
