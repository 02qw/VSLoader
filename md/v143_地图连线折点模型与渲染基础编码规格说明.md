# v143 地图连线折点模型与渲染基础编码规格说明

## 1. 背景

当前工厂地图连线能力存在以下限制：

```text
1. 当前主地图连线只保存 From / To。
2. 连线渲染时由 FactoryMapWindow 自动计算中折线路径。
3. 用户无法保存自定义折点。
4. 一对多、多对一只能通过多条边表达，但视觉上无法方便形成分叉/汇流。
```

本次讨论后明确：

```text
一对多 / 多对一不需要表达复杂业务关系。
只需要在视觉上支持分叉和汇流。
```

因此本阶段不引入复杂图模型，不做真实中间节点，不做自动路由算法。

本阶段目标是先打通连线折点的基础能力：

```text
FactoryMapDeviceEdge 支持 Points。
保存/加载 factory-map.layout.json 时保留 Points。
渲染时优先使用 Points。
没有 Points 的旧连线继续使用当前自动中折线算法。
```

这样后续 v144 / v145 可以在此基础上继续做右键添加折点、拖动折点、视觉分叉/汇流编辑。

## 3. 目标行为

### 3.1 数据目标

`factory-map.layout.json` 中连线允许出现：

```json
{
  "from": "A",
  "to": "B",
  "points": [
    { "x": 300, "y": 180 },
    { "x": 300, "y": 260 }
  ]
}
```

说明：

```text
from / to 仍然表示真实连线两端。
points 只表示视觉折线路径点。
points 不表达业务语义。
points 可以为空或缺省。
```

### 3.2 渲染目标

渲染规则：

```text
如果 edge.Points 有有效点：
    起点 -> edge.Points -> 终点

如果 edge.Points 为空：
    使用当前自动中折线算法
```

其中：

```text
可见线继续使用 insetEndpoints=true，避免端点从节点边缘冒出小突点。
命中线继续使用完整端点，保证右键命中范围足够。
```

### 3.3 兼容目标

必须兼容旧布局：

```json
{
  "from": "A",
  "to": "B"
}
```

旧数据加载后：

```text
不报错。
不自动补写 points。
显示效果保持当前默认中折线。
```

## 5. 布局加载与保存

### 5.1 LoadConfig 兼容空 points

文件：

```text
VSLoader/Models/Services/FactoryMapLayoutService.cs
```

加载后应保证：

```csharp
foreach (var edge in config.Edges)
{
    edge.Points ??= [];
}
```

注意：

```text
System.Text.Json 反序列化旧 JSON 时 Points 会保持默认空集合。
但仍建议防御式处理，避免外部 JSON 显式写入 null。
```

### 5.2 BuildMap 传递 points

当前：

```csharp
edges.Add(new FactoryMapDeviceEdgeViewData
{
    From = from,
    To = to
});
```

调整为：

```csharp
edges.Add(new FactoryMapDeviceEdgeViewData
{
    From = from,
    To = to,
    Points = NormalizeEdgePoints(edge.Points)
});
```

### 5.3 SaveToFile 保存 points

当前：

```csharp
new FactoryMapDeviceEdge
{
    From = edge.From.Key,
    To = edge.To.Key
}
```

调整为：

```csharp
new FactoryMapDeviceEdge
{
    From = edge.From.Key,
    To = edge.To.Key,
    Points = NormalizeEdgePoints(edge.Points)
}
```

### 5.4 NormalizeEdgePoints

新增私有方法：

```csharp
private static List<FactoryMapPoint> NormalizeEdgePoints(IEnumerable<FactoryMapPoint>? points)
```

规则：

```text
1. null -> 空集合。
2. 过滤 NaN / Infinity。
3. X/Y 小于 0 时保留还是裁剪？
```

本阶段建议：

```text
只过滤 NaN / Infinity。
不裁剪负数。
```

理由：

```text
后续地图可能支持更大或近似无限画布。
负坐标不应在基础层被硬裁掉。
```

## 6. 连线渲染调整

文件：

```text
VSLoader/Views/FactoryMapWindow.xaml.cs
```

当前：

```csharp
private static PointCollection CreateEdgePoints(FactoryMapDeviceEdgeViewData edge, bool insetEndpoints)
{
    var points = new PointCollection();
    var start = GetDeviceRightCenter(edge.From);
    var end = GetDeviceLeftCenter(edge.To);
    ...
    var middleX = start.X + (end.X - start.X) / 2;
    points.Add(start);
    points.Add(new WpfPoint(middleX, start.Y));
    points.Add(new WpfPoint(middleX, end.Y));
    points.Add(end);
    return points;
}
```

调整为：

```text
1. 计算 start / end。
2. 如果 edge.Points 有有效点：
   points = start + edge.Points + end。
3. 如果 edge.Points 为空：
   使用当前自动中折线。
```

建议拆出：

```csharp
private static bool HasManualEdgePoints(FactoryMapDeviceEdgeViewData edge)

private static IEnumerable<WpfPoint> GetManualEdgePoints(FactoryMapDeviceEdgeViewData edge)
```

### 6.1 起点终点方向

本阶段保持当前行为：

```text
From 从右侧中心出线。
To 从左侧中心入线。
```

不引入 `fromPort / toPort`。

原因：

```text
端口选择属于后续体验优化。
本阶段只做 points 基础能力。
```

### 6.2 自动线兼容

没有 `points` 的线必须保持当前显示：

```text
右出 -> 中折 -> 左入
```

这保证旧地图不会突然改变连线外观。

## 7. 一对多 / 多对一边界

本阶段不新增“一对多边”或“多对一边”模型。

视觉分叉/汇流通过多条普通边共享折点实现：

```text
A -> B
A -> C
A -> D
```

每条边都可以拥有相同或接近的 `points`：

```json
[
  {
    "from": "A",
    "to": "B",
    "points": [{ "x": 320, "y": 200 }]
  },
  {
    "from": "A",
    "to": "C",
    "points": [{ "x": 320, "y": 200 }]
  }
]
```

说明：

```text
这是视觉分叉，不是业务分支模型。
删除其中一条边不影响其它边。
```

## 8. 本阶段不做的内容

本阶段不做：

```text
1. 不做右键添加折点。
2. 不做拖动折点。
3. 不做选中连线后的控制点显示。
4. 不做自动避障。
5. 不做自动分叉/汇流识别。
6. 不做 fromPort / toPort 端口选择。
7. 不改变连线模式按钮的现有交互。
8. 不改变节点拖动、框选、多选、缩放、平移逻辑。
```
