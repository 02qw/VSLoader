# v147 地图连线线段控制与右键结构菜单编码规格说明

## 1. 背景

v143 到 v146 已经完成了地图连线的折点模型、右键菜单、折点拖动、正交路径约束。

当前能力可以概括为：

```text
v143：连线支持 points 保存、加载和渲染。
v144：连线右键支持添加折点、清除折点、删除连线。
v145：选中连线后显示折点控制点，支持拖动折点和删除单个折点。
v146：连线通过 FactoryMapOrthogonalPathService 保持横平竖直。
```

但 v146 仍然存在一个核心体验问题：

```text
用户能添加折点，也能拖点。
但用户不能明确控制“这条线后续到底往哪个方向走、绕到什么程度、哪一段被整体移动”。
```

也就是说，当前模型仍然偏向：

```text
用户给一个点，程序猜一条路径。
```

用户真正想要的是：

```text
用户选中一段线。
用户决定在这段线上加一个绕行结构。
用户拖动某一段通道，让整段线按他的空间意图移动。
```

本阶段要从“折点控制”升级到“线段控制”：

```text
右键菜单负责结构动作。
拖动线段负责空间控制。
```

## 2. 本阶段目标

本阶段目标：

```text
1. 支持识别用户点击的是连线中的哪一段线段。
2. 支持选中连线中的某一段线段，并给出清晰的视觉反馈。
3. 支持拖动线段，而不是只拖动孤立折点。
4. 水平线段只能上下移动。
5. 垂直线段只能左右移动。
6. 线段拖动时同步移动该线段两端点，保持路径正交。
7. 右键菜单从“添加折点”升级为“添加绕行段”。
8. 添加绕行段时必须基于右键点击的线段和点击侧方向生成路径。
9. 保留现有 edge.points JSON 结构，不破坏旧地图数据。
10. 保留 v145 的折点控制点作为兼容能力，但主交互入口转向线段控制。
```

最终用户感受应当是：

```text
我不是在摆一个点让程序猜。
我是直接抓住一段线，把这一段通道挪到我想要的位置。
```

## 3. 非目标

本阶段不做：

```text
1. 不做自动避障。
2. 不做智能寻路。
3. 不做多条线自动共享同一段通道。
4. 不做连线端口选择。
5. 不改变 factory-map.layout.json 的 edge.points 字段结构。
6. 不新增新的 edge 持久化字段。
7. 不重构地图节点布局算法。
8. 不重构地图缩放、平移、框选、节点拖动逻辑。
9. 不做复杂的“删除某个绕行结构”能力。
10. 不做自动判断业务意义上的分叉/汇流。
```

说明：

```text
本阶段只解决单条连线内部的主观控制问题。
多条连线之间的组合效果仍由用户手动编辑实现。
```

## 5. 核心设计原则

### 5.1 右键菜单负责结构动作

右键菜单只做结构类操作：

```text
添加绕行段
清除全部折线
删除连线
```

右键菜单不负责细调空间位置。

空间位置由拖动线段完成。

### 5.2 拖动线段负责空间控制

用户拖动的不再是一个孤立点，而是一段通道。

如果拖动水平段：

```text
只能上下移动。
该水平段两个端点的 Y 同步变化。
X 不因为拖动而改变。
```

如果拖动垂直段：

```text
只能左右移动。
该垂直段两个端点的 X 同步变化。
Y 不因为拖动而改变。
```

这能让用户明确控制：

```text
这段线要向上绕。
这段线要向下绕。
这段线要向左让开。
这段线要向右让开。
```

### 5.3 points 数据结构保持不变

继续保存：

```json
{
  "from": "A",
  "to": "B",
  "points": [
    { "x": 320, "y": 180 },
    { "x": 320, "y": 260 }
  ]
}
```

本阶段只改变：

```text
points 的编辑解释方式。
points 的生成方式。
points 的拖动更新方式。
```

不改变：

```text
JSON 字段名。
JSON 层级结构。
旧布局文件兼容性。
```

## 6. 空间模型

一条连线的完整路径为：

```text
P0 = From 节点右侧中心点
P1..Pn = edge.Points 中保存的中间点
P(n+1) = To 节点左侧中心点
```

线段定义为：

```text
Segment0 = P0 -> P1
Segment1 = P1 -> P2
...
SegmentN = Pn -> P(n+1)
```

每个 Segment 必须是以下两种之一：

```text
水平线段：Start.Y == End.Y
垂直线段：Start.X == End.X
```

如果路径中存在斜线，必须先通过 `Normalize` 转成正交路径，再参与线段识别、右键、拖动。

## 7. 新增线段模型

在 `FactoryMapOrthogonalPathService.cs` 中新增：

```csharp
internal sealed record FactoryMapEdgeSegment(
    int SegmentIndex,
    WpfPoint Start,
    WpfPoint End,
    FactoryMapEdgeSegmentDirection Direction);

internal enum FactoryMapEdgeSegmentDirection
{
    Horizontal,
    Vertical
}
```

字段含义：

```text
SegmentIndex：完整路径中的线段下标。
Start：线段起点。
End：线段终点。
Direction：线段方向。
```

注意：

```text
SegmentIndex 是完整路径中的线段索引，不是 edge.Points 的点索引。
```

例如：

```text
完整路径：start, p0, p1, end

SegmentIndex 0：start -> p0
SegmentIndex 1：p0 -> p1
SegmentIndex 2：p1 -> end
```

## 9. 线段识别规则

### 9.1 GetSegments

`GetSegments` 行为：

```text
1. 调用 Normalize(start, points, end)。
2. 生成完整路径 start + normalizedPoints + end。
3. 遍历相邻点。
4. 跳过长度接近 0 的线段。
5. 判断方向。
6. 返回 FactoryMapEdgeSegment 列表。
```

方向判断：

```text
如果 Start.Y 接近 End.Y，则 Horizontal。
如果 Start.X 接近 End.X，则 Vertical。
```

理论上 Normalize 后不应存在斜线。

如果仍然遇到斜线：

```text
不要抛异常导致窗口崩溃。
跳过该异常线段，并让 Normalize 的测试覆盖修复。
```

### 9.2 FindNearestSegmentIndex

`FindNearestSegmentIndex` 行为：

```text
1. 获取 GetSegments(...)。
2. 计算 clickPoint 到每段线段的距离。
3. 返回距离最近的 SegmentIndex。
4. 如果没有任何线段，返回 -1。
```

距离算法沿用当前服务内已有的点到线段距离算法。

要求：

```text
不要继续使用 private FindNearestSegmentIndex(path, point) 作为唯一入口。
需要提供公开给窗口层调用的 start/points/end 版本。
```

## 10. 添加绕行段逻辑

### 10.1 菜单文案

连线右键菜单从：

```text
添加折点
清除折点
删除连线
```

改为：

```text
添加绕行段
清除全部折线
删除连线
```

原因：

```text
用户不是添加一个点，而是添加一个可拖动的绕行结构。
```

### 10.2 InsertDetourOnSegment 输入

方法签名：

```csharp
public static List<FactoryMapPoint> InsertDetourOnSegment(
    WpfPoint start,
    IReadOnlyList<FactoryMapPoint> points,
    WpfPoint end,
    int segmentIndex,
    WpfPoint clickPoint,
    double gridSize);
```

如果 `segmentIndex < 0`：

```text
返回 Normalize(start, points, end)。
不要抛异常。
```

如果 `segmentIndex` 超出路径范围：

```text
返回 Normalize(start, points, end)。
不要抛异常。
```

### 10.3 水平线段添加绕行

水平线段：

```text
A(x1, y) -> B(x2, y)
```

用户点击点：

```text
C(cx, cy)
```

生成规则：

```text
1. x = clickPoint.X 吸附到网格。
2. y2 = clickPoint.Y 吸附到网格。
3. 如果 y2 与原线段 y 太接近，则根据点击侧给默认偏移。
```

点击侧判断：

```text
clickPoint.Y < y：向上绕。
clickPoint.Y >= y：向下绕。
```

默认偏移：

```text
offset = Math.Max(gridSize * 2, gridSize)

向上绕：y2 = y - offset
向下绕：y2 = y + offset
```

插入点：

```text
P1 = (x, y)
P2 = (x, y2)
P3 = (B.X, y2)
```

路径变为：

```text
A -> P1 -> P2 -> P3 -> B
```

这样用户可以明确得到：

```text
从点击位置拐出去。
沿点击侧方向绕行。
再回到原线段终点。
```

### 10.4 垂直线段添加绕行

垂直线段：

```text
A(x, y1) -> B(x, y2)
```

用户点击点：

```text
C(cx, cy)
```

生成规则：

```text
1. y = clickPoint.Y 吸附到网格。
2. x2 = clickPoint.X 吸附到网格。
3. 如果 x2 与原线段 x 太接近，则根据点击侧给默认偏移。
```

点击侧判断：

```text
clickPoint.X < x：向左绕。
clickPoint.X >= x：向右绕。
```

默认偏移：

```text
offset = Math.Max(gridSize * 2, gridSize)

向左绕：x2 = x - offset
向右绕：x2 = x + offset
```

插入点：

```text
P1 = (x, y)
P2 = (x2, y)
P3 = (x2, B.Y)
```

路径变为：

```text
A -> P1 -> P2 -> P3 -> B
```

### 10.5 插入后处理

插入后必须：

```text
1. 调用 Normalize。
2. 删除重复点。
3. 删除连续共线冗余点。
4. 返回中间 points。
```

窗口层收到返回结果后：

```csharp
edge.Points = FactoryMapOrthogonalPathService.InsertDetourOnSegment(...);
selectedEdge = edge;
selectedSegmentEdge = edge;
selectedSegmentIndex = insertedSegmentIndex; // 如果实现成本高，可以先保留右键前的 segmentIndex。
RenderCurrentMap(resetView: false);
saveLayout(currentMap);
```

## 11. 线段拖动逻辑

### 11.1 MoveSegment 输入

方法签名：

```csharp
public static List<FactoryMapPoint> MoveSegment(
    WpfPoint start,
    IReadOnlyList<FactoryMapPoint> points,
    WpfPoint end,
    int segmentIndex,
    WpfPoint targetPoint,
    double gridSize,
    bool snapToGrid);
```

行为：

```text
1. Normalize 当前 points。
2. 生成完整路径。
3. 找到 segmentIndex 对应的 startPoint 和 endPoint。
4. 根据线段方向只移动一个轴。
5. 同步调整该线段两个端点。
6. Normalize 后返回中间 points。
```

### 11.2 水平线段拖动

水平线段：

```text
path[i] -> path[i + 1]
```

拖动目标：

```text
targetPoint
```

只使用：

```text
newY = targetPoint.Y
```

如果 `snapToGrid == true`：

```text
newY = ClampAndSnapToGrid(targetPoint.Y, gridSize)
```

更新：

```text
path[i].Y = newY
path[i + 1].Y = newY
```

不改变：

```text
path[i].X
path[i + 1].X
```

效果：

```text
整段水平通道上下平移。
左右相邻的垂直段自动拉伸或压缩。
```

### 11.3 垂直线段拖动

垂直线段：

```text
path[i] -> path[i + 1]
```

拖动目标：

```text
targetPoint
```

只使用：

```text
newX = targetPoint.X
```

如果 `snapToGrid == true`：

```text
newX = ClampAndSnapToGrid(targetPoint.X, gridSize)
```

更新：

```text
path[i].X = newX
path[i + 1].X = newX
```

不改变：

```text
path[i].Y
path[i + 1].Y
```

效果：

```text
整段垂直通道左右平移。
上下相邻的水平段自动拉伸或压缩。
```

### 11.4 端点线段处理

如果用户拖动的是首段或尾段：

```text
SegmentIndex == 0
或
SegmentIndex == path.Count - 2
```

原则：

```text
允许拖动，但不能改变节点锚点 start/end。
```

因此：

```text
首段拖动时，如果 path[0] 是 start，不直接修改 path[0]。
尾段拖动时，如果 path[^1] 是 end，不直接修改 path[^1]。
```

推荐处理：

```text
如果拖动首段或尾段会要求修改 start/end，则自动在靠近端点的位置补一个中间点，再移动可编辑段。
```

为了降低本阶段复杂度，也可以采用更保守规则：

```text
首段和尾段只允许被选中、右键添加绕行段，不允许直接拖动。
状态栏提示：端点连接段不能直接拖动，请先添加绕行段。
```

本阶段推荐采用保守规则。

原因：

```text
节点锚点不应被连线编辑改写。
先禁用端点段拖动更稳定，不会破坏节点连接语义。
```

## 14. 线段拖动事件

复用现有地图鼠标事件时要避免与节点拖动、折点拖动冲突。

优先级：

```text
节点拖动 > 折点拖动 > 线段拖动 > 地图平移
```

### 14.1 左键按下

`Edge_PreviewMouseLeftButtonDown` 调整为：

```text
1. 非编辑模式直接 return。
2. 获取 edge。
3. clickPoint = e.GetPosition(MapCanvas)。
4. segmentIndex = FindNearestSegmentIndex(...)。
5. 设置 selectedEdge/selectedSegmentEdge/selectedSegmentIndex。
6. 如果 segmentIndex 可拖动，则设置 activeSegmentEdge/activeSegmentIndex/isDraggingEdgeSegment。
7. CaptureMouse。
8. 设置 Cursor。
9. RenderCurrentMap(resetView: false)。
10. e.Handled = true。
```

### 14.2 MouseMove

在现有地图 MouseMove 中新增分支：

```text
如果 isDraggingEdgeSegment：
    调用 UpdateActiveEdgeSegmentPosition(mapPoint, snapToGrid: false)
    return
```

新增方法：

```csharp
private void UpdateActiveEdgeSegmentPosition(WpfPoint mapPoint, bool snapToGrid)
```

内部调用：

```csharp
activeSegmentEdge.Points = FactoryMapOrthogonalPathService.MoveSegment(
    GetDeviceRightCenter(activeSegmentEdge.From),
    activeSegmentEdge.Points ?? [],
    GetDeviceLeftCenter(activeSegmentEdge.To),
    activeSegmentIndex,
    mapPoint,
    MapGridSize,
    snapToGrid);
```

然后：

```text

```

### 14.3 MouseLeftButtonUp

鼠标释放时：

```text
如果 isDraggingEdgeSegment：
    调用 MoveSegment(..., snapToGrid: true)
    Normalize
    saveLayout(currentMap)
    释放鼠标捕获
    清理 activeSegment 状态
    保留 selectedSegment 状态
```

状态栏提示：

```text
已调整连线通道。
```

```text
2. FindNearestSegmentIndex。
3. 创建 payload(edge, clickPoint, segmentIndex)。
4. 打开菜单。
```


不要在本阶段加入“删除该绕行段”“反向绕行”等复杂项。

## 16. 与折点控制点的兼容关系

v145 的折点控制点暂时保留。

但本阶段要降低它的主入口地位：

```text
1. 左键点击连线优先选中线段。
2. 选中连线后仍可显示折点控制点。
3. 折点控制点用于精细修正。
4. 线段拖动用于主要空间调整。
```

折点拖动仍然调用现有：

```csharp
FactoryMapOrthogonalPathService.MovePoint(...)
```

如果线段拖动和折点拖动状态冲突：

```text

```

也就是说：

```text
用户按住折点控制点时，不应同时触发线段拖动。
```

## 17. 边界情况

### 17.1 没有 points 的默认连线

默认连线没有手动 points。

处理：

```text
GetSegments 应基于 Normalize 后的完整路径工作。
如果默认连线通过 CreateEdgePoints 生成中折线，则右键和线段识别必须使用同一套完整路径。
```

如果当前 `Normalize(start, [], end)` 只返回空中间点，导致完整路径只有 start/end 且可能是斜线：

```text
必须先修正 Normalize，使 start/end 不同 X/Y 时自动补正交中转点。
```

### 17.2 segmentIndex 失效

拖动过程中路径点变化可能导致原 segmentIndex 失效。

处理：

```text
MoveSegment 内部必须检查 segmentIndex 范围。
失效时返回 Normalize 后结果，不抛异常。
窗口层收到后结束拖动并提示：连线结构已变化，请重新选择线段。
```

### 17.3 连线被删除

如果 activeSegmentEdge 或 selectedSegmentEdge 已经不在 currentMap.Edges 中：

```text
清理线段状态。
停止拖动。
不要访问已删除对象。
```

### 17.4 退出编辑模式

退出编辑模式时：

```text
清理 selectedSegmentEdge。
清理 activeSegmentEdge。
释放鼠标捕获。
恢复默认 Cursor。
```

### 17.5 地图缩放和平移

线段拖动坐标必须使用地图坐标：

```text
e.GetPosition(MapCanvas)
```

不要使用窗口坐标。

否则缩放后拖动会偏移。

### 17.6 旧布局数据

旧布局可能有自由 points 或奇怪 points。

处理：

```text
所有 GetSegments / MoveSegment / InsertDetourOnSegment 都先 Normalize。
异常点过滤在 Normalize 中完成。
```

```csharp
private static void AssertOrthogonalPath(
    WpfPoint start,
    IReadOnlyList<FactoryMapPoint> points,
    WpfPoint end)
{
    var path = new List<WpfPoint> { start };
    path.AddRange(points.Select(point => new WpfPoint(point.X, point.Y)));
    path.Add(end);

    for (var i = 0; i < path.Count - 1; i++)
    {
        Assert.True(
            Math.Abs(path[i].X - path[i + 1].X) < 0.001
            || Math.Abs(path[i].Y - path[i + 1].Y) < 0.001,
            $"Segment {i} is not orthogonal.");
    }
}
```
