# v73 工作区选择窗口与切换入口编码规格说明

## 1. 文档目的

本文件用于指导编程 Agent 在现有 VSLoader 多工作区底座上继续实现下一阶段功能：

```text
工作区选择窗口 + 新建工作区 + 打开工作区 + 主界面切换入口。
```

`v72_多工作区分阶段落地编码规格说明.md` 已经完成底层数据解耦方向：

```text
1. 程序级 app-settings.json。
2. 工作区级 Workspaces\Default。
3. 启动时自动解析当前工作区。
4. Config / Layout / FactoryMap / UIdownload 跟随 WorkspaceContext。
5. VSCodePath 移到程序级配置。
```

本次 `v73` 的目标是让用户真正能够“进入大箱子，选择小箱子”。

## 2. 当前实现基础

当前已经存在以下模型和服务：

```text

VSLoader\Models\WorkspaceMetadata.cs

VSLoader\Models\Services\AppSettingsService.cs
VSLoader\Models\Services\WorkspaceService.cs
VSLoader\Models\Services\LegacyWorkspaceMigrationService.cs
```

当前启动流程位于：

```text
VSLoader\App.xaml.cs
```

当前流程大致是：

```text
1. LoadOrCreate app-settings.json。
2. 执行旧数据迁移。
3. ResolveStartupWorkspace。
4. new MainWindow(appSettings, appSettingsService, workspaceContext)。
5. mainWindow.Show()。
```

当前 MainWindow 构造函数已经接收：

```csharp

```

当前 MainWindow 标题已经可以显示：

```text
VSLoader vX.Y.Z - 工作区名称
```

因此 v73 不需要重做底层数据解耦，只需要在这个基础上增加选择和切换能力。

## 3. 需求目标

完成后用户应该可以：

```text
1. 启动程序时看到工作区选择窗口。
2. 在工作区选择窗口中选择已有工作区并打开。
3. 在工作区选择窗口中新建工作区。
4. 新建工作区后自动注册到 app-settings.json。
5. 打开工作区后保存 LastWorkspaceId。
6. 主界面提供“切换工作区”入口。
7. 主界面提供“打开当前工作区文件夹”入口。
8. 切换工作区时关闭当前主窗口，重新用目标工作区打开一个新的主窗口。
9. 不同工作区的数据互相隔离。
```

可以理解为：

```text
启动程序 -> 选择小箱子 -> 打开 VSLoader 主界面
主界面 -> 切换小箱子 -> 重新打开对应工作区的数据
```

## 4. 非目标范围

本阶段不实现：

```text
1. 删除工作区。
2. 重命名工作区。
3. 复制工作区。
4. 工作区 zip 导入导出。
5. 工作区云同步。
6. 多个工作区同时打开。
7. 跨工作区搜索。
8. 工作区权限。
9. 工作区图标。
10. 工作区模板市场。
```

说明：

```text
本阶段只做选择、新建、打开、切换。
不要把工作区管理器做成复杂系统。
```

## 5. UI 设计原则

工作区选择窗口应该是一个轻量、清晰、稳定的入口窗口。

不需要做复杂视觉设计，不要做营销式首页，不要做大面积装饰。

重点是：

```text
1. 用户能清楚看到有哪些工作区。
2. 用户能看出哪个是上次打开的工作区。
3. 用户能快速双击打开。
4. 用户能快速新建。
5. 用户能打开工作区所在目录。
```

整体风格应贴近当前 VSLoader：

```text
1. 白色/浅灰背景。
2. 简洁列表。
3. 8px 或更小圆角。
4. 文字信息清晰。
5. 按钮大小稳定。
6. 弹窗居中于 Owner。
```

## 8. 新建工作区交互

### 8.1 输入方式

本阶段推荐使用一个轻量自定义输入窗口，不使用系统 InputBox。

新增：

```text
VSLoader\Views\WorkspaceNameDialog.xaml
VSLoader\Views\WorkspaceNameDialog.xaml.cs
VSLoader\ViewModels\WorkspaceNameDialogViewModel.cs
```

也可以复用现有自定义轻量弹窗风格，但必须保持简单。

窗口标题：

```text
新建工作区
```

内容：

```text
工作区名称
[输入框]
[取消] [创建]
```

校验规则：

```text
1. 名称不能为空。
2. 名称去首尾空格。
3. 名称不能包含 Windows 路径非法字符：\ / : * ? " < > |
4. 名称不能和已有工作区名称忽略大小写重复。
5. 名称长度建议不超过 60 个字符。
```

非法时提示：

```text
请输入有效的工作区名称。
工作区名称不能包含：\ / : * ? " < > |
工作区名称已存在。
```

### 8.2 目录命名

当前 `WorkspaceService.CreateWorkspace` 会根据名称生成 Id，并把目录放在：

```text
%AppData%\VSLoader\Workspaces\<Id>
```

本阶段可以继续使用现有算法。

注意：

```text
中文名称可能导致当前 Id 算法过滤后变成 workspace。
如果用户创建多个中文名称工作区，可能变成 workspace、workspace-2、workspace-3。
这是可接受的。
```

如果要优化，可以把 `WorkspaceService.CreateWorkspaceId` 改为：

```text
中文名称目录使用 workspace-时间戳 或 workspace-短Guid。
```

推荐本阶段最小改动：

```text
保留当前算法，但确保不会重复。
```

## 9. App 启动流程改造

当前 `App.xaml.cs` 直接：

```csharp
var workspaceContext = workspaceService.ResolveStartupWorkspace(appSettings);
...
var mainWindow = new MainWindow(appSettings, appSettingsService, workspaceContext);
mainWindow.Show();
```

v73 改造为：

```text
1. 加载 appSettings。
2. 执行旧数据迁移。
3. 确保至少存在 Default 工作区。
4. 判断是否需要显示 WorkspaceSelectorWindow。
5. 用户选择工作区后再打开 MainWindow。
```

### 9.1 启动时是否显示选择窗口

推荐策略：

```text
启动时总是显示工作区选择窗口。
```

原因：

```text
用户明确希望“最外层先进入大箱子，然后选择小箱子”。
```

但为了后续扩展，可以保留：

```text
OpenLastWorkspaceOnStartup
```

本阶段建议行为：

```text
OpenLastWorkspaceOnStartup = false 或用户按住后续设置项时再考虑自动打开。
当前 v73 默认启动显示选择窗口。
```

如果不想改变字段含义，可以这样处理：

```text
1. 当前字段保留。
2. v73 暂不提供 UI 修改它。
3. 启动时仍显示选择窗口。
4. 未来再做“启动时自动进入上次工作区”的设置项。
```

### 9.2 启动选择流程伪代码

```csharp
protected override void OnStartup(StartupEventArgs e)
{
    base.OnStartup(e);

    var appSettingsService = new AppSettingsService();
    var appSettings = appSettingsService.LoadOrCreate(out var settingsWarning);
    var workspaceService = new WorkspaceService(appSettingsService.AppDataDirectory);
    var migrationService = new LegacyWorkspaceMigrationService(appSettingsService.AppDataDirectory, workspaceService);

    var migrationResult = migrationService.TryMigrate(appSettings);
    workspaceService.EnsureDefaultWorkspace(appSettings);
    appSettingsService.Save(appSettings);

    var selectorViewModel = new WorkspaceSelectorViewModel(
        appSettings,
        appSettingsService,
        workspaceService,
        new DialogService());

    var selectorWindow = new WorkspaceSelectorWindow(selectorViewModel);
    var result = selectorWindow.ShowDialog();

    if (result != true || selectorViewModel.SelectedWorkspaceContext is null)
    {
        Shutdown();
        return;
    }

    OpenMainWindow(selectorViewModel.SelectedWorkspaceContext);
}
```

建议把打开主窗口抽成方法：

```csharp
private void OpenMainWindow(
    AppSettings appSettings,
    AppSettingsService appSettingsService,
    WorkspaceContext workspaceContext)
```

方便主界面切换工作区复用。

## 10. 主界面切换工作区入口

### 10.1 放置位置

在主界面顶部第二行按钮区增加：

```text
工作区
```

或者增加两个按钮：

```text
切换工作区
打开工作区文件夹
```

推荐最小方案：

```text
新增一个“工作区”按钮，点击后打开工作区选择窗口。
```

原因：

```text
顶部按钮已经较多，一个入口更稳。
```

如果现有按钮区更适合直接放两个按钮，也可以：

```text
[工作区] [打开工作区文件夹]
```

本规格建议：

```text
第二行工具区新增“工作区”按钮。
```

点击行为：

```text
打开 WorkspaceSelectorWindow。
用户选择另一个工作区并确认后，关闭当前 MainWindow，重新创建 MainWindow。
```

### 10.2 切换时的保存顺序

切换工作区前必须：

```text
1. 保存当前窗口布局。
2. 保存地图窗口状态。
3. 关闭地图窗口。
4. 释放当前全局快捷键注册。
5. 关闭当前主窗口。
6. 使用新 WorkspaceContext 创建新 MainWindow。
```

注意：

当前 MainWindow 的 `Closing` 事件默认会拦截关闭并最小化到托盘。  
切换工作区时必须走“真正关闭”逻辑，不能被托盘逻辑拦截。

建议 MainWindow 新增方法：

```csharp
public bool RequestSwitchWorkspace()
```

或者内部方法：

```csharp
private void SwitchWorkspace()
```

切换时需要设置：

```csharp
_isExitRequested = true;
```

避免 Closing 被取消。

### 10.3 切换逻辑推荐放置

推荐把主窗口切换逻辑放在 `App` 中集中管理。

新增：

```csharp
public void SwitchWorkspace(Window owner)
```

或：

```csharp
internal void ShowWorkspaceSelectorAndOpenMainWindow(Window? owner, bool shutdownOnCancel)
```

原因：

```text
App 已经持有启动编排逻辑。
MainWindow 不应该自己负责创建另一个 MainWindow 的完整生命周期。
```

推荐结构：

```text
App:
  Load services
  Show selector
  Open main window
  Switch workspace

MainWindow:
  点击工作区按钮 -> ((App)Application.Current).ShowWorkspaceSelectorForSwitch(this)
```

新增方法：

```csharp
internal void SwitchWorkspace(MainWindow currentWindow)
```

切换伪代码：

```csharp
internal void SwitchWorkspace(MainWindow currentWindow)
{
    var selectedContext = ShowWorkspaceSelector(currentWindow, shutdownOnCancel: false);
    if (selectedContext is null)
    {
        return;
    }

    if (selectedContext.Id == currentWindow.WorkspaceId)
    {
        return;
    }

    currentWindow.PrepareForWorkspaceSwitch();
    OpenMainWindow(selectedContext);
    currentWindow.Close();
}
```


## 14. WorkspaceSelectorViewModel 详细规则

### 14.1 初始化列表

初始化时：

```text
1. 从 appSettings.Workspaces 读取列表。
2. 过滤不可用工作区。
3. 不可用工作区可以显示为灰色，也可以跳过。
```

推荐本阶段：

```text
显示所有工作区。
不可用工作区禁用“打开”，并在路径旁显示“路径不存在”。
```

如果实现成本过高，可以先：

```text
跳过不可用工作区。
```

但需要注意：

```text
如果 LastWorkspaceId 对应路径不存在，用户至少还能看到 Default。
```

### 14.2 默认选中项

打开选择窗口时默认选中：

```text
appSettings.LastWorkspaceId 对应的工作区。
```

如果找不到：

```text
选中第一个可用工作区。
```

### 14.3 打开工作区

打开时：

```text
1. 校验 SelectedWorkspace 不为空。
2. 校验目录存在。
3. 调用 WorkspaceService.Resolve 或 ToContext。
4. 设置 appSettings.LastWorkspaceId。
5. appSettingsService.Save(appSettings)。
6. SelectedWorkspaceContext = context。
7. RequestClose(true)。
```

如果保存失败：

```text
提示保存程序配置失败，不关闭选择窗口。
```

### 14.4 新建工作区

新建时：

```text
1. 弹出 WorkspaceNameDialog。
2. 用户输入名称。
3. 校验名称。
4. 调用 WorkspaceService.CreateWorkspace(appSettings, name)。
5. 设置 appSettings.LastWorkspaceId = context.Id。
6. appSettingsService.Save(appSettings)。
7. 刷新列表。
8. 选中新建工作区。
```

新建后不强制立即打开。

推荐行为：

```text
新建后保持在选择窗口，用户可以看到新工作区，再点击打开或双击打开。
```

也可以新建后自动打开，但本阶段推荐不自动打开，避免误操作。

## 15. WorkspaceService 建议补充方法

当前 WorkspaceService 已有：

```csharp
EnsureDefaultWorkspace
CreateWorkspace
ResolveStartupWorkspace
IsWorkspaceUsable
```

v73 建议新增：

```csharp
public WorkspaceContext ToContext(WorkspaceInfo workspace)
```

当前 `ToContext` 是 private。  
选择窗口需要把选中的 `WorkspaceInfo` 转成 `WorkspaceContext`。

也可以新增：

```csharp
public WorkspaceContext ResolveWorkspace(WorkspaceInfo workspace)
```

推荐：

```csharp
public WorkspaceContext ResolveWorkspace(WorkspaceInfo workspace)
{
    if (!IsWorkspaceUsable(workspace))
    {
        throw new InvalidOperationException("工作区不可用。");
    }

    EnsureWorkspaceFiles(workspace);
    return ToContext(workspace);
}
```

如果 `EnsureWorkspaceFiles` 当前是 private，可以继续由 `ResolveWorkspace` 内部调用。

## 19. 风险点

### 19.1 切换工作区导致托盘图标重复

风险：

```text
旧 MainWindow 没有释放 NotifyIcon，新 MainWindow 又创建一个 NotifyIcon。
```

规避：

```text
切换前必须调用 DisposeTrayIcon。
```

### 19.2 切换工作区被 Closing 事件拦截

风险：

```text
当前 MainWindow Closing 默认取消关闭并隐藏到托盘。
```

规避：

```text
切换前设置 _isExitRequested = true。
```

### 19.3 当前布局未保存

风险：

```text
用户切换工作区后当前窗口位置、列宽、地图状态丢失。
```

规避：

```text
切换前调用 SaveWindowLayoutImmediately。
```

### 19.4 热键重复注册

风险：

```text
旧 MainWindow 未 Dispose GlobalHotkeyService，新窗口注册失败。
```

规避：

```text
切换前调用 _hotkeyService.Dispose。
```

### 19.5 新建工作区名称非法

风险：

```text
非法字符导致目录创建失败。
```

规避：

```text
输入名称先校验，再调用 WorkspaceService.CreateWorkspace。
```
