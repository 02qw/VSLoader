# v106 主界面手动检测更新按钮编码规格说明

## 1. 背景

当前 VSLoader 已有后台自动检测更新能力。

后台逻辑位于：

```text
VSLoader/ViewModels/MainViewModel.cs
```

相关方法：

```csharp
StartUpdateCheckLoop()
RunUpdateCheckLoopAsync()
CheckUpdatesOnceAsync()
ApplyUpdateCheckResult()
```

底层检测算法位于：

```text
VSLoader/Models/Services/UpdateCheckService.cs
```

当前检测内容包括：

- rules 批量规则文件。
- map 地图配置文件。
- 软件更新 manifest 文件。

用户希望在主界面第二行按钮区新增一个：

```text
检测更新
```

按钮。用户点击后，不需要等待后台 10 分钟轮询，可以主动强制发起一次更新检测。

## 2. 目标

新增主界面“检测更新”按钮：

- 用户点击按钮后，立即主动检测一次更新状态。
- 检测底层算法复用现有 `UpdateCheckService.Check()`。
- 检测结果继续复用现有 `ApplyUpdateCheckResult()`。
- 如果检测到更新，继续显示现有顶部更新公告栏。
- 如果检测失败，继续显示现有红色失败提示栏。
- 如果没有发现更新，给用户一个短状态提示，避免点击后像无反应。
- 手动检测期间暂停后台异步倒计时检测循环。
- 手动检测结束后恢复后台 10 分钟检测循环。
- 避免手动检测和后台检测并发执行。
- 不改变现有后台自动检测规则和检测间隔。

## 3. 非目标

本次不做：

- 不改变 `UpdateCheckService.Check()` 的检测算法。
- 不改变 `updateTime.json` 的数据结构。
- 不新增新的更新提示 UI 样式。
- 不改变“关闭更新提醒即确认本次检测结果”的既有逻辑。
- 不改变软件自动更新按钮的下载/安装逻辑。
- 不把“检测更新”按钮做成倒计时显示。
- 不弹出额外确认框。
- 不在检测失败时弹窗，继续使用现有失败提示栏。

## 4. 当前代码定位

### 4.1 主界面按钮区域

文件：

```text
VSLoader/MainWindow.xaml
```

第二行按钮区当前包含：

```text
工作区
新增
更新软件
导出全局配置
导入全局配置
批量新增识别
自动获取连接
地图
AdminUI
...
```

建议新增按钮放在：

```text
更新软件
检测更新
```

之间或紧邻“更新软件”之后。

推荐：

```xml
<Button Width="104"
        Height="36"
        Margin="0,0,10,8"
        Command="{Binding ManualCheckUpdatesCommand}"
        Content="检测更新" />
```

按钮宽度与“更新软件”保持一致。

### 4.2 后台检测循环

文件：

```text
VSLoader/ViewModels/MainViewModel.cs
```

现有循环：

```csharp
private async Task RunUpdateCheckLoopAsync(CancellationToken cancellationToken)
{
    await Task.Delay(TimeSpan.FromSeconds(5), cancellationToken);

    while (!cancellationToken.IsCancellationRequested)
    {
        await CheckUpdatesOnceAsync(cancellationToken);
        await Task.Delay(TimeSpan.FromMinutes(10), cancellationToken);
    }
}
```

手动检测需要复用：

```csharp
CheckUpdatesOnceAsync(...)
```

但需要避免和后台循环并发。

### 4.3 检测结果显示

当前结果应用：

```csharp
public void ApplyUpdateCheckResult(UpdateCheckResult result)
```

逻辑：

- `result.UpdatedItems.Count > 0`：显示更新公告栏。
- `result.Failures.Count > 0`：显示失败提示栏。
- 两者可以独立存在。

本次继续复用该逻辑。

## 5. 推荐设计

### 5.1 新增命令

在 `MainViewModel` 中新增：

```csharp
[RelayCommand(CanExecute = nameof(CanRunGlobalCommand))]
private async Task ManualCheckUpdatesAsync()
```

命令命名建议：

```text
ManualCheckUpdatesCommand
```

### 5.2 防并发字段

建议新增字段：

```csharp
private bool _isManualUpdateCheckRunning;
```

防止用户快速连点按钮导致多次检测。

如果使用 `IsBusy` 包裹手动检测，则可以依赖 `IsBusy` 禁用按钮。

推荐手动检测期间设置：

```csharp
IsBusy = true;
BusyMessage = "正在检测更新...";
```

但不需要显示复杂进度条。

如果不希望出现全屏忙碌遮罩，则至少需要 `_isManualUpdateCheckRunning` 控制按钮不可重复触发。

结合现有按钮 `CanRunGlobalCommand()` 已依赖 `!IsBusy`，推荐复用 `IsBusy`，保持所有全局操作一致。

### 5.3 手动检测流程

推荐流程：

```csharp
private async Task ManualCheckUpdatesAsync()
{
    if (IsBusy)
    {
        return;
    }

    IsBusy = true;
    BusyMessage = "正在检测更新...";
    BusyProgressText = string.Empty;
    BusyCurrentItemText = string.Empty;

    try
    {
        await StopUpdateCheckLoopAsync(TimeSpan.FromSeconds(2));
        await CheckUpdatesOnceAsync(CancellationToken.None);

        if (!HasUpdateNotice && !HasUpdateFailure)
        {
            ShowTemporaryStatus("已完成检测，当前没有发现更新。");
        }
    }
    finally
    {
        IsBusy = false;
        StartUpdateCheckLoop();
    }
}
```

注意：

- `finally` 中必须恢复后台循环。
- 即使检测失败，也应该恢复后台循环。
- 如果程序正在退出，不应重新启动后台循环。

### 5.4 避免退出时重启循环

如果当前 ViewModel 没有退出标志，主窗口关闭时会调用：

```csharp
StopUpdateCheckLoop()
```

手动检测过程中一般不会退出。

为稳妥起见，可新增：

```csharp
private bool _isUpdateCheckLoopStoppedByShutdown;
```

但第一阶段不建议引入额外状态。

更保守做法：

```csharp
if (!IsUpdateCheckLoopRunning)
{
    StartUpdateCheckLoop();
}
```

不过 `StopUpdateCheckLoopAsync()` 后循环必然停止。手动检测结束恢复即可。

如果后续发现退出时重启问题，再单独修复。

### 5.5 CheckUpdatesOnceAsync 保持私有复用

`CheckUpdatesOnceAsync` 目前为私有方法。

本次只在 `MainViewModel` 内部新增命令，因此无需改为 public。

### 5.6 无更新提示

如果检测完成后：

```csharp
HasUpdateNotice == false
HasUpdateFailure == false
```

说明：

- 没检测到更新。
- 没检测失败。

应显示临时状态栏提示：

```text
已完成检测，当前没有发现更新。
```

优先复用现有状态栏临时提示能力。

如果现有只有 `ShowTemporaryStatus(...)` 私有方法，则直接在命令内调用。

### 5.7 检测失败提示

如果路径不存在，例如截图中的：

```text
更新检测失败：rules 文件不存在、map 文件不存在、软件更新 manifest 文件不存在
```

保持现有红色失败提示栏。

不额外弹窗。

## 6. 按钮交互规则

### 6.1 正常状态

按钮可点击。

点击后：

- 暂停后台检测循环。
- 发起一次检测。
- 更新 UI 提示。
- 恢复后台检测循环。

### 6.2 忙碌状态

如果当前：

```csharp
IsBusy == true
```

按钮不可点击。

保持和其他全局按钮一致。

### 6.3 手动检测进行中

手动检测进行中：

- 按钮不可重复点击。
- 其他全局按钮也按现有 `IsBusy` 规则禁用。
- 检测结束后恢复。

### 6.4 后台正在检测

如果后台刚好正在检测：

- 手动检测先调用 `StopUpdateCheckLoopAsync(...)`。
- 尽量等待后台检测停止。
- 再执行手动检测。

这样避免两个检测同时读写 `updateTime.json`。

### 6.5 检测完成后

检测完成：

- 有更新：显示更新公告栏。
- 有失败：显示失败提示栏。
- 无更新且无失败：显示短状态提示。
- 后台检测循环重新开始，重新进入 5 秒首次延迟和 10 分钟间隔逻辑。

## 7. 代码修改点

### 7.1 MainWindow.xaml

新增按钮：

```xml

        Height="36"

        Command="{Binding ManualCheckUpdatesCommand}"
        Content="检测更新" />
```

建议位置：紧跟“更新软件”按钮之后。

### 7.2 MainViewModel.cs

新增命令：

```csharp
[RelayCommand(CanExecute = nameof(CanRunGlobalCommand))]
private async Task ManualCheckUpdatesAsync()
```

`IsBusy` 属性上的 `[NotifyCanExecuteChangedFor(...)]` 需要增加：

```csharp
[NotifyCanExecuteChangedFor(nameof(ManualCheckUpdatesCommand))]
```

否则忙碌状态变化时按钮可用状态不会自动刷新。

### 7.3 可测试辅助方法

建议新增内部静态方法：

```csharp
internal static bool ShouldShowNoUpdateStatus(UpdateCheckResult result)
{
    return result.UpdatedItems.Count == 0 && result.Failures.Count == 0;
}
```

或改造 `CheckUpdatesOnceAsync` 返回 `UpdateCheckResult`，便于手动检测知道是否显示“无更新”提示。

推荐更稳的最小改造：

```csharp
private async Task<UpdateCheckResult> CheckUpdatesOnceAsync(CancellationToken cancellationToken)
```

原后台循环无需关心返回值：

```csharp
await CheckUpdatesOnceAsync(cancellationToken);
```

手动检测可用返回值判断：

```csharp
var result = await CheckUpdatesOnceAsync(CancellationToken.None);
if (ShouldShowNoUpdateStatus(result))
{
    ShowTemporaryStatus("已完成检测，当前没有发现更新。");
}
```

异常时也返回包含 Failure 的 `UpdateCheckResult`。
