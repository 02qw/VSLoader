# v133 更新软件按钮绿色引导态编码规格说明

## 1. 背景

当前 VSLoader 主界面已经有两个与更新相关的按钮：

```text
更新软件
检测更新
```

当前“检测更新”会检查：

```text
1. 全局配置包更新
2. 软件版本更新
```

检测到更新后，主界面顶部会显示黄色横幅：

```text
检测到更新：全局配置
检测到更新：软件版本
检测到更新：全局配置、软件版本
```

但是当前 `更新软件` 按钮本身没有状态变化。用户即使看到“软件版本”更新，也需要主动理解并找到按钮。

本次需求是：

```text
当检测到软件版本更新时，让“更新软件”按钮变成绿色强调态，引导用户点击。
```

绿色状态只表达一件事：

```text
当前检测结果中存在软件版本更新，并且用户尚未确认或处理掉这次提醒。
```

## 2. 当前代码现状

### 2.1 更新检测入口

文件：

```text
VSLoader/ViewModels/MainViewModel.cs
```

手动检测入口：

```csharp
ManualCheckUpdatesAsync()
```

内部逻辑：

```text
1. 暂停后台检测循环
2. 调用 CheckUpdatesOnceAsync(...)
3. 将结果交给 ApplyUpdateCheckResult(...)
4. 恢复后台检测循环
```

后台检测循环同样会调用：

```csharp
CheckUpdatesOnceAsync(...)
ApplyUpdateCheckResult(...)
```

因此按钮绿色状态必须统一放在：

```csharp
ApplyUpdateCheckResult(UpdateCheckResult result)
```

不要在手动检测和后台检测里各写一套逻辑。

### 2.2 更新结果模型

文件：

```text
VSLoader/Models/Services/UpdateCheckResult.cs
```

当前结果中有：

```csharp
public List<string> UpdatedItems { get; } = new();
public List<string> Failures { get; } = new();
public string DetectedSoftwareVersion { get; set; } = string.Empty;
```

判断是否存在软件更新时，优先使用结构化字段：

```csharp
!string.IsNullOrWhiteSpace(result.DetectedSoftwareVersion)
```

不要依赖：

```csharp
result.UpdatedItems.Contains("软件版本")
```

原因：

```text
UpdatedItems 是展示文案，未来文案改名会影响判断。
DetectedSoftwareVersion 是明确的软件更新状态字段，更稳定。
```

### 2.3 当前横幅关闭逻辑

文件：

```text
VSLoader/ViewModels/MainViewModel.cs
```

当前关闭黄色更新横幅的方法：

```csharp
CloseUpdateNotice()
```

当前逻辑会调用：

```csharp
_updateCheckService.AcknowledgeDetectedUpdates(_updateTimePath, _lastUpdateCheckResult)
```

这代表用户点击“我知道了”后，本次检测到的更新会被写入 `updateTime.json` 基线。

本次新增的绿色按钮状态必须与这个行为保持一致：

```text
用户点击“我知道了”后，更新软件按钮恢复普通样式。
```

### 2.4 当前更新软件按钮

文件：

```text
VSLoader/MainWindow.xaml
```

当前按钮：

```xml
<Button Style="{StaticResource ModernButtonStyle}"
        Width="104"
        Height="36"
        Margin="0,0,10,8"
        Command="{Binding UpdateSoftwareCommand}"
        Content="更新软件" />
```

当前使用固定普通按钮样式，不会根据更新状态变化。

## 3. 总体目标

### 3.1 用户目标

当检测到软件版本更新时：

```text
更新软件按钮变成绿色强调态。
```

当没有软件版本更新、用户确认提醒、或确认当前已经是最新版本时：

```text
更新软件按钮恢复普通样式。
```

### 3.2 技术目标

1. 新增一个只表示“软件更新按钮是否需要绿色引导”的 ViewModel 状态。
2. 该状态由更新检测结果统一驱动。
3. 后台检测和手动检测使用同一套状态更新逻辑。
4. 黄色横幅“我知道了”成功关闭后，绿色按钮状态同步清除。
5. 点击“更新软件”发现当前已经是最新版本后，绿色按钮状态同步清除。
6. 检测失败、用户取消更新、更新准备失败时，不要误清绿色状态。
7. 绿色样式使用现有现代化视觉体系，不能破坏主界面按钮排版。

## 4. 状态设计

### 4.1 新增 ViewModel 属性

文件：

```text
VSLoader/ViewModels/MainViewModel.cs
```

新增：

```csharp
[ObservableProperty]
private bool hasSoftwareUpdateNotice;
```

语义：

```text
true  = 当前检测到软件版本更新，更新软件按钮应展示绿色强调态。
false = 当前没有需要引导的软件版本更新。
```

该状态不持久化到配置文件。

原因：

```text
按钮绿色状态是本次运行中的 UI 引导状态，应完全由最新检测结果推导。
如果持久化，容易出现下次启动后按钮仍然绿色，但服务器版本或本地基线已经变化的错乱。
```

### 4.2 状态来源

只允许以下入口修改 `HasSoftwareUpdateNotice`：

```text
1. ApplyUpdateCheckResult(...)
2. CloseUpdateNotice()
3. UpdateSoftwareAsync() 中“当前已是最新版本”的分支
```

不要在 XAML code-behind 或其他服务层直接修改这个状态。

## 5. 状态流转规则

### 5.1 检测到软件更新

入口：

```csharp
ApplyUpdateCheckResult(UpdateCheckResult result)
```

规则：

```text
如果 result.DetectedSoftwareVersion 不为空：
    HasSoftwareUpdateNotice = true
否则如果 result 没有检测失败：
    HasSoftwareUpdateNotice = false
```

注意：

```text
如果 result.Failures.Count > 0 且没有新的软件版本结果，不要强行清除旧的 HasSoftwareUpdateNotice。
```

原因：

```text
检测失败不等于没有更新。
例如网络断开或 manifest 路径暂时不可访问，此时清掉绿色按钮会误导用户。
```

推荐逻辑：

```csharp
if (!string.IsNullOrWhiteSpace(result.DetectedSoftwareVersion))
{
    HasSoftwareUpdateNotice = true;
}
else if (result.Failures.Count == 0)
{
    HasSoftwareUpdateNotice = false;
}
```

### 5.2 只有全局配置更新

如果检测结果只有：

```text
全局配置
```

则：

```text
显示黄色横幅。
更新软件按钮保持普通样式。
```

原因：

```text
更新软件按钮只服务于软件版本更新，不能被全局配置更新驱动。
```

### 5.3 同时有全局配置和软件版本更新

如果检测结果包含：

```text
全局配置
软件版本
```

则：

```text
黄色横幅显示：检测到更新：全局配置、软件版本
更新软件按钮显示绿色强调态。
```

### 5.4 用户点击“我知道了”

入口：

```csharp
CloseUpdateNotice()
```

当 `AcknowledgeDetectedUpdates(...)` 成功后：

```text
HasUpdateNotice = false
HasSoftwareUpdateNotice = false
```

如果 `AcknowledgeDetectedUpdates(...)` 失败：

```text
保留黄色横幅。
保留绿色按钮状态。
显示红色失败横幅。
```

原因：

```text
基线没有成功写入时，不能假装用户已经确认了这次提醒。
```

### 5.5 用户点击“更新软件”但当前已经最新

入口：

```csharp
UpdateSoftwareAsync()
```

当：

```csharp
availability.UpdateAvailable == false
```

当前逻辑会显示：

```text
当前已是最新版本。
```

本次需要补充：

```text
HasSoftwareUpdateNotice = false
```

原因：

```text
已经确认当前版本最新，绿色引导态应恢复普通。
```

### 5.6 用户取消更新

当用户在确认弹窗中选择取消：

```text
不要清除 HasSoftwareUpdateNotice。
```

原因：

```text
取消只表示用户暂时不更新，不代表软件更新已经处理完成。
```

### 5.7 更新准备失败或启动更新器失败

以下情况都不要清除 `HasSoftwareUpdateNotice`：

```text
manifest 读取失败
更新包下载失败
SHA 校验失败
更新器缺失
更新器启动失败
```

原因：

```text
失败说明更新没有完成，用户仍然需要重试或处理错误。
```

### 5.8 启动更新器成功

当更新器启动成功后，主程序会退出：

```text
不需要额外处理 HasSoftwareUpdateNotice。
```

原因：

```text
主程序即将退出，该 UI 状态不会继续展示。
更新完成后重新启动，新的状态应由后续检测重新计算。
```

## 6. UI 设计

### 6.1 按钮样式

新增或复用一个绿色强调按钮样式。

推荐命名：

```text
ModernSuccessButtonStyle
```

或更语义化：

```text
ModernUpdateAvailableButtonStyle
```

建议使用语义化命名：

```text
ModernUpdateAvailableButtonStyle
```

颜色建议：

```text
默认背景：#16A34A
Hover 背景：#15803D
Pressed 背景：#166534
禁用背景：沿用普通禁用态
文字颜色：White
```

不要使用闪烁动画。

原因：

```text
按钮绿色已经足够提示，闪烁会显得廉价，也会影响长期使用体验。
```

### 6.2 XAML 绑定方式

文件：

```text
VSLoader/MainWindow.xaml
```

推荐使用按钮内联 Style，根据 `HasSoftwareUpdateNotice` 切换 `BasedOn` 或直接设置属性。

更稳妥的实现方式：

```xml
<Button Width="104"
        Height="36"
        Margin="0,0,10,8"
        Command="{Binding UpdateSoftwareCommand}"
        Content="更新软件">
    <Button.Style>
        <Style TargetType="Button" BasedOn="{StaticResource ModernButtonStyle}">
            <Style.Triggers>
                <DataTrigger Binding="{Binding HasSoftwareUpdateNotice}" Value="True">
                    <Setter Property="Background" Value="#16A34A" />
                    <Setter Property="BorderBrush" Value="#15803D" />
                    <Setter Property="Foreground" Value="White" />
                </DataTrigger>
            </Style.Triggers>
        </Style>
    </Button.Style>
</Button>
```

如果现有 `ModernButtonStyle` 的模板没有正确响应 `Background` / `BorderBrush`，则应在样式资源中新增完整按钮样式：

```text
VSLoader/Styles/ModernTheme.xaml
```

或当前按钮样式实际所在资源文件。

实现前必须先确认 `ModernButtonStyle` 所在文件和模板结构。

### 6.3 可访问性

绿色状态不能只依赖颜色。

建议为按钮增加 Tooltip：

```text
普通状态：检查并安装软件更新
绿色状态：检测到新版本，点击更新软件
```

可通过绑定实现，也可以先保持静态 Tooltip：

```text
检查并安装软件更新
```

本次最小实现可以只做颜色变化，不强制新增动态 Tooltip。

## 9. 边界情况清单

实现完成后必须逐条确认：

```text
1. 只有全局配置更新：横幅显示，更新软件按钮不变绿。
2. 只有软件版本更新：横幅显示，更新软件按钮变绿。
3. 全局配置和软件版本都更新：横幅显示两项，更新软件按钮变绿。
4. 没有任何更新：无横幅，更新软件按钮普通。
5. 检测失败：显示失败横幅，不误清已有绿色按钮状态。
6. 点击“我知道了”成功：黄色横幅关闭，绿色按钮恢复普通。
7. 点击“我知道了”失败：黄色横幅保留，绿色按钮保留，显示失败横幅。
8. 点击“更新软件”发现当前已是最新：提示最新，绿色按钮恢复普通。
9. 点击“更新软件”后用户取消：绿色按钮保留。
10. 点击“更新软件”后准备更新失败：绿色按钮保留。
11. 后台自动检测到软件更新：更新软件按钮也会变绿。
12. 手动检测和后台检测不会产生两套互相冲突的状态逻辑。
```

## 10. 不做的事情

本次不做：

```text
1. 不新增绿色按钮状态持久化。
2. 不改变 updateTime.json 的数据结构。
3. 不改变软件更新 manifest 判断算法。
4. 不改变全局配置包更新检测算法。
5. 不改变“我知道了”写入基线的方案 B 语义。
6. 不新增闪烁动画或弹跳动画。
```

## 11. 预期效果

完成后用户体验为：

```text
用户点击“检测更新”。
如果检测到软件版本更新，顶部横幅提示，同时“更新软件”按钮变成绿色。
用户可以很自然地点击绿色按钮去更新。
如果用户点击“我知道了”，说明本次提醒已确认，绿色按钮恢复普通。
如果用户点击“更新软件”后发现已经是最新版本，绿色按钮也恢复普通。
```

整体逻辑保持：

```text
横幅负责告诉用户“检测到了什么更新”。
绿色按钮只负责引导用户处理“软件版本更新”。
```
