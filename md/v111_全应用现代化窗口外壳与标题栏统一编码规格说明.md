# v111 全应用现代化窗口外壳与标题栏统一编码规格说明

## 1. 背景

v109 已经完成了主窗口、工作区窗口、设置窗口、批量新增窗口、弹窗等内容区域的现代化视觉重构。

但当前仍存在一个明显割裂点：

- 页面内容区已经是浅蓝白、白色面板、现代按钮。
- 窗口最外层标题栏仍是 Windows / WPF 默认系统外壳。
- 默认标题栏显示为灰色，和 VSLoader 现代化内容区不统一。
- 主窗口、工作区窗口、设置窗口等都仍能看到旧式窗口边框和标题栏。

代码现状：

```text
VSLoader/MainWindow.xaml
VSLoader/Views/WorkspaceSelectorWindow.xaml
VSLoader/Views/SettingsWindow.xaml
VSLoader/Views/BatchImportWindow.xaml
VSLoader/Views/ShortcutEditWindow.xaml
VSLoader/Views/WorkspaceNameDialog.xaml
VSLoader/Views/FactoryMapWindow.xaml
```

上述窗口基本仍使用默认 WPF `Window` 外壳。

目前只有：

```text
VSLoader/Views/MessageDialogWindow.xaml
```

已经使用：

```xml
WindowStyle="None"
AllowsTransparency="True"
Background="Transparent"
```

也就是说，v109 改的是“窗口里面”，本次 v111 要解决的是“窗口外壳”。

## 2. 目标

统一 VSLoader 全应用窗口外壳和标题栏：

- 去掉默认灰色系统标题栏的割裂感。
- 绘制 VSLoader 自己的现代化标题栏。
- 标题栏颜色、文字、图标、按钮和 v109 视觉语言统一。
- 保留 Windows 窗口的基础能力：
  - 拖动窗口。
  - 缩放窗口。
  - 最小化。
  - 最大化 / 还原。
  - 贴边吸附。
  - 任务栏行为。
  - DPI 缩放稳定。
- 尽量不影响现有窗口布局、位置持久化、地图窗口跟随逻辑。
- 不改变业务逻辑。

## 3. 非目标

本次不做：

- 不重新设计窗口内容区。
- 不改变按钮、表格、设置项、地图节点等内容 UI。
- 不改变窗口默认位置比例算法。
- 不改变窗口布局配置文件结构。
- 不改变主窗口最小化到托盘逻辑。
- 不改变地图窗口最小化等同关闭逻辑。
- 不引入第三方 UI 框架。
- 不实现复杂动画。
- 不做深色模式。

## 4. 技术方案

### 4.1 推荐方案：WindowChrome

推荐使用 WPF 内置：

```text
System.Windows.Shell.WindowChrome
```

不要直接对所有窗口简单使用：

```xml
WindowStyle="None"
AllowsTransparency="True"
```

原因：

- `AllowsTransparency=True` 可能影响渲染性能。
- 自己完整接管拖拽、缩放、最大化边界、DPI、贴边会增加很多细节风险。
- 主窗口和地图窗口已有窗口位置/大小持久化逻辑，不能引入不稳定外壳。

`WindowChrome` 可以让应用自绘标题栏，同时尽量保留系统窗口行为。

### 4.2 基础窗口属性建议

对需要现代外壳的窗口设置：

```xml
WindowStyle="None"
ResizeMode="CanResize"
Background="{StaticResource ModernAppBackgroundBrush}"
```

并增加：

```xml
<WindowChrome.WindowChrome>
    <WindowChrome CaptionHeight="44"
                  CornerRadius="0"
                  GlassFrameThickness="0"
                  ResizeBorderThickness="6"
                  UseAeroCaptionButtons="False" />
</WindowChrome.WindowChrome>
```

说明：

- `CaptionHeight=44`：标题栏可拖拽高度。
- `GlassFrameThickness=0`：不使用系统玻璃区域。
- `ResizeBorderThickness=6`：保留可拖拽缩放边缘。
- `UseAeroCaptionButtons=False`：使用自定义按钮。

### 4.3 无缩放弹窗

对于不可调整大小窗口：

```text
ShortcutEditWindow
WorkspaceNameDialog
MessageDialogWindow
```

保留：

```xml
ResizeMode="NoResize"
```

`WindowChrome` 可使用较小 ResizeBorder 或不允许缩放。

## 5. 统一标题栏设计

### 5.1 标题栏视觉

推荐：

```text
高度：44
背景：#F8FAFC 或 #FFFFFF
底部分隔线：#E3EAF3
标题文字：#172033
弱标题文字：#64748B
按钮 hover：#EEF6FF
关闭按钮 hover：#FEE2E2
关闭按钮文字 hover：#DC2626
```

标题栏组成：

```text
左侧图标 + 窗口标题
中间弹性空白
右侧最小化 / 最大化还原 / 关闭按钮
```

### 5.2 标题栏按钮

按钮尺寸：

```text
宽：44
高：44
```

按钮文本：

```text
最小化：—
最大化：□
还原：❐ 或根据状态切换
关闭：×
```

说明：

- 字符按钮足够轻量，不引入图标库。
- 关闭按钮 hover 使用浅红背景。
- 最大化按钮对 `ResizeMode="NoResize"` 的窗口隐藏。
- 对 `ShowInTaskbar="False"` 的附属窗口仍可保留最小化按钮或按现有需求隐藏。

### 5.3 点击穿透

自定义标题栏中的按钮区域必须设置：

```xml
WindowChrome.IsHitTestVisibleInChrome="True"
```

否则按钮点击可能被当成拖动窗口。

## 6. 建议新增共享组件

## 8. 代码实现细节

### 8.1 标题栏按钮命令

每个窗口 code-behind 可实现：

```csharp
private void MinimizeButton_Click(object sender, RoutedEventArgs e)
{
    WindowState = WindowState.Minimized;
}

private void MaximizeRestoreButton_Click(object sender, RoutedEventArgs e)
{
    WindowState = WindowState == WindowState.Maximized
        ? WindowState.Normal
        : WindowState.Maximized;
}

private void CloseButton_Click(object sender, RoutedEventArgs e)
{
    Close();
}
```

但主窗口需要特别注意：

- 主窗口已有关闭到托盘逻辑。
- 标题栏关闭按钮调用 `Close()` 即可，让原有 `Closing` 事件接管。
- 不要绕过现有关闭逻辑。

地图窗口也需要特别注意：

- 如果已有“最小化等同关闭”逻辑，最小化按钮应执行现有关闭地图方法，而不是让窗口缩成系统小窗口。
- 或者直接隐藏地图窗口最小化按钮。

### 8.2 标题栏拖动

使用 `WindowChrome` 时，标题栏空白区域通过 `CaptionHeight` 支持拖动。

按钮区域必须设置：

```xml
WindowChrome.IsHitTestVisibleInChrome="True"
```

### 8.3 最大化边界

使用 `WindowChrome` 后要手动验证：

- 最大化时内容不能压到任务栏下面。
- 最大化后还原正常。
- 拖到屏幕边缘贴靠正常。

如出现最大化覆盖任务栏问题，再考虑添加 `WindowChrome` 推荐的最大化修正逻辑。

## 11. 风险与规避

### 11.1 关闭逻辑风险

风险：

- 自定义关闭按钮绕过原来的关闭到托盘逻辑。

规避：

- 自定义关闭按钮只调用 `Close()`。
- 不直接调用 `Application.Current.Shutdown()`。

### 11.2 地图窗口风险

风险：

- 地图窗口是附属窗口，有特殊位置和关闭逻辑。

规避：

- 地图窗口最后阶段再改。
- 改之前先阅读 `FactoryMapWindow.xaml.cs` 和 `MainWindow.xaml.cs` 中地图窗口管理逻辑。

### 11.3 最大化/贴边风险

风险：

- 自绘标题栏可能影响 Windows 贴边和最大化边界。

规避：

- 使用 `WindowChrome`，不使用全透明窗口方案。
- 手动验证最大化和贴边。

### 11.4 测试覆盖不足

风险：

- 窗口外壳主要靠手动视觉验证。

规避：

- 使用文本级测试锁定关键 XAML 属性。
- 全量 build/test 保证 XAML 编译。
- 必须手动验证窗口拖动、缩放、关闭。
