# v125 地图快捷键与输入法冲突防误输入编码规格说明

## 1. 背景

v104 之后，程序增加了地图快捷键能力：

```text
默认按 M 键快速打开/关闭工厂地图。
```

v113 之后，工厂地图已经从主窗口附属窗口调整为独立任务栏窗口。

当前用户反馈：

```text
打开地图窗口后，连续按两次 M，有时不会正常开关地图，而是突然出现文字输入框/输入法状态，像进入了打字模式，影响地图开关。
```

用户关心的问题是：

```text
这是程序 bug，还是 Windows 输入法问题？
```

结合当前代码判断，这不是单纯 Windows 输入法问题，而是程序对“无修饰键单字母快捷键”和输入法交互的边界处理不足。

## 3. 问题描述

当前默认地图快捷键是：

```text
M
```

这是一个无修饰键普通字母。

在中文输入法开启时，用户按 `m` 可能会被 Windows/IME 解释为：

```text
开始输入拼音 m
```

此时 WPF 可能出现两类情况：

- `e.Key` 不是 `Key.M`，而是 `Key.ImeProcessed`。
- 输入法在当前可聚焦窗口中启动文本组合状态，表现为“突然进入打字模式”。

地图窗口本身不是文本输入场景，因此在地图窗口中按 `M` 应优先作为地图快捷键，而不应该进入输入法文字输入状态。

但主窗口不同：

```text
主窗口搜索框、设置窗口、编辑快捷项窗口都需要正常输入文字。
```

因此不能全局禁用输入法，也不能取消主窗口中“焦点在输入框时不触发地图快捷键”的保护逻辑。

## 4. 根因分析

根因是两个设计叠加：

### 4.1 地图快捷键使用无修饰键单字母

`M` 本质上既是快捷键，也是普通文本输入字符。

这和 `Alt+M`、`Ctrl+M` 不同。

裸字母快捷键天然容易和输入法/文本框焦点发生冲突。

### 4.2 地图窗口没有声明“这里不是输入场景”

地图窗口当前只设置了：

```csharp
Focusable = true;
```

但没有在地图窗口或地图视口上禁用输入法输入上下文。

因此当地图窗口获得焦点后，中文输入法仍可能把 `M` 当成文本输入。

## 5. 目标

本次目标：

- 地图窗口处于前台时，按地图快捷键 `M` 应稳定打开/关闭地图。
- 地图窗口内不应因为按 `M` 进入输入法打字状态。
- 中文输入法开启时，地图窗口仍能识别 `M` 快捷键。
- 主窗口搜索框中输入 `m` 不应触发地图开关。
- 设置窗口、编辑快捷项窗口、工作区命名弹窗等输入框仍应正常使用中文输入法。
- 不改变地图节点、连线、缩放、拖拽、右键菜单等业务逻辑。
- 不改变主快捷键打开/隐藏主程序的逻辑。
- 不改变地图快捷键默认值。

## 6. 非目标

本次不做以下事项：

- 不把地图快捷键默认值改成 `Alt+M` 或 `Ctrl+M`。
- 不重构全局快捷键服务。
- 不全局禁用输入法。
- 不修改主窗口搜索框输入逻辑。
- 不修改设置页快捷键录制 UI。
- 不改变 `MapHotkeyConfig` 配置结构。
- 不引入 Win32 键盘钩子。
- 不新增配置项。

## 7. 推荐方案

### 7.1 只在地图窗口禁用输入法上下文

在：

```text
VSLoader/Views/FactoryMapWindow.xaml
```

给地图窗口根节点增加输入法禁用声明：

```xml
InputMethod.IsInputMethodEnabled="False"
```

推荐放在 `Window` 节点上：

```xml
<Window x:Class="VSLoader.Views.FactoryMapWindow"
        ...
        ShowInTaskbar="True"
        InputMethod.IsInputMethodEnabled="False">
```

原因：

- 地图窗口没有文本输入控件。
- 地图窗口中的按钮、画布、节点都不需要中文输入法。
- 作用域只限地图窗口，不影响主窗口和其他弹窗。

如果实现者担心作用域过大，也可以只加在地图视口：

```xml
<Grid x:Name="MapViewport"
      ...
      InputMethod.IsInputMethodEnabled="False">
```

但推荐加在 `Window`，因为问题发生在地图窗口整体焦点层级。

### 7.2 兼容 `Key.ImeProcessed`

在：

```text
VSLoader/MainWindow.xaml.cs
```

当前逻辑：

```csharp
var key = e.Key == Key.System ? e.SystemKey : e.Key;
```

需要改为通过统一方法提取真实按键：

```csharp
var key = ResolveHotkeyKey(e);
```

新增内部静态方法：

```csharp
internal static Key ResolveHotkeyKey(System.Windows.Input.KeyEventArgs e)
{
    if (e.Key == Key.System)
    {
        return e.SystemKey;
    }

    if (e.Key == Key.ImeProcessed)
    {
        return e.ImeProcessedKey;
    }

    return e.Key;
}
```

说明：

- `Key.System` 用于兼容 Alt 相关按键，保留原逻辑。
- `Key.ImeProcessed` 用于兼容中文输入法处理后的真实按键。
- 该方法不改变修饰键判断，仍由 `MapHotkeyService.IsMatch(...)` 校验。

### 7.3 保留主窗口输入框保护

不要修改：

```csharp
IsTextInputFocused()
ShouldToggleFactoryMapFromHotkey(...)
```

当前逻辑中：

```csharp
&& !isTextInputFocused
```

必须保留。

这样可以保证：

```text
主窗口搜索框里按 m => 输入 m
地图窗口里按 M => 切换地图
```

### 7.4 地图窗口转发逻辑保持原语义

不要改变：

```csharp
FactoryMapWindow_PreviewKeyDown(...)
ShouldForwardMapHotkey(...)
```

这些保护仍然合理：

- 拖动地图时不触发快捷键。
- 拖动节点时不触发快捷键。
- 框选节点时不触发快捷键。
- 正在连线时不触发快捷键。
- 右键菜单打开时不触发快捷键。
- 业务忙碌遮罩显示时不触发快捷键。

本次只增强“按键识别”和“地图窗口禁用输入法上下文”。

## 11. 风险与边界

### 11.1 为什么不影响主窗口搜索框

本方案只修改：

```text
FactoryMapWindow.xaml
MainWindow.xaml.cs 中按键解析方法
```

不修改：

```text
MainWindow.xaml
SettingsWindow.xaml
ShortcutEditWindow.xaml
WorkspaceNameDialog.xaml
```

并且主窗口仍保留：

```csharp
IsTextInputFocused()
```

因此主窗口文本输入不受影响。

### 11.2 为什么不全局禁用输入法

全局禁用会破坏：

- 搜索框中文输入。
- 设置页中文输入。
- 编辑快捷项备注中文输入。
- 工作区中文显示名称输入。

所以必须局部处理地图窗口。

### 11.3 为什么不直接把默认快捷键改成 Alt+M

`Alt+M` 的确是更传统、更不容易冲突的方案。

但用户当前明确希望保留快速按键体验，本次只修复裸 `M` 在地图窗口中误入输入法的问题，不改变默认配置。

## 12. 验收标准

实现完成后必须满足：

- 地图窗口 XAML 中存在 `InputMethod.IsInputMethodEnabled="False"`。
- `MainWindow.xaml.cs` 中存在 `ResolveHotkeyKey(...)`。
- `ResolveHotkeyKey(...)` 支持 `Key.ImeProcessed -> e.ImeProcessedKey`。
- `TryToggleFactoryMapFromHotkey(...)` 使用 `ResolveHotkeyKey(e)`。
- 主窗口输入框保护逻辑未删除。
- 地图窗口现有拖动/连线/多选/右键菜单快捷键屏蔽逻辑未删除。
- 新增或更新测试通过。
- 全量测试通过。
- Debug 构建通过。
