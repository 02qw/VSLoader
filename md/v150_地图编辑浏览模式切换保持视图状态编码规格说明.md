# v150 地图编辑浏览模式切换保持视图状态编码规格说明

## 1. 背景

当前地图窗口存在一个交互问题：

```text
用户在地图编辑模式下调整了视图比例或拖拽了地图位置。
切换回浏览模式后，地图会突然缩放到很小的比例。
```

排查后确认，这不是连线端口模型导致的问题，而是编辑模式切换逻辑主动触发了视图重新适配。

当前关键逻辑位于：

```text
VSLoader\Views\FactoryMapWindow.xaml.cs
EditModeButton_Click
```

现有逻辑大意：

```csharp
RenderCurrentMap(resetView: false);
if (!isEditMode)
{
    hasUserViewState = false;
    RequestFitMapToView();
}
```

这段逻辑的问题是：

```text
退出编辑模式时，程序强行清空用户视图状态。
随后重新执行 FitMapToView。
FitMapToView 会重置 userScale，并重新计算 fitScale 和 offset。
```

因此用户原本的缩放/平移状态会被丢掉。

## 2. 根因说明

地图视图由几部分共同决定：

```text
fitScale：自动适配比例。
userScale：用户滚轮缩放比例。
mapOffsetX/mapOffsetY：用户拖拽后的偏移。
hasUserViewState：是否已经有用户主动调整过视图。
```

正常情况下：

```text
用户缩放或拖拽后，hasUserViewState = true。
后续普通重绘不应该重置视图。
```

但退出编辑模式时，当前代码主动执行：

```text
hasUserViewState = false
RequestFitMapToView()
```

这相当于告诉程序：

```text
用户没有自己的视图状态，请重新自动适配。
```

同时浏览模式下 `FitMapToView` 使用：

```csharp
isEditMode ? bounds : ToSquareBounds(bounds)
```

也就是说，浏览模式会把内容范围转成正方形后再适配。

当地图内容宽而不高时，正方形高度会明显变大，最终适配比例会被压小，所以用户看到地图突然变小。

## 3. 本阶段目标

本阶段目标：

```text
1. 编辑模式和浏览模式切换时保持当前地图视图比例。
2. 切换模式只改变交互层和视觉层，不重置缩放/平移状态。
3. 退出编辑模式时不再强制 hasUserViewState = false。
4. 退出编辑模式时不再主动 RequestFitMapToView。
5. 保留首次打开地图时的自动适配能力。
6. 保留导入地图、重新加载地图等明确重置场景的自动适配能力。
7. 保留用户主动拖拽、滚轮缩放后的视图状态保存逻辑。
8. 补充回归测试，防止后续再次把模式切换和视图重置绑在一起。
```

用户体验目标：

```text
用户正在看地图某个区域。
从编辑模式切到浏览模式后，看到的仍然是同一个区域、同一个大致比例。
界面只少了编辑网格、端口、折点控制等编辑 UI。
```

## 4. 非目标

本阶段不做：

```text
1. 不修改地图窗口独立窗口逻辑。
2. 不修改地图快捷键逻辑。
3. 不修改连线四端口模型。
4. 不修改连接点模型。
5. 不调整 FitMapToView 的数学算法。
6. 不取消首次打开地图的自动适配。
7. 不取消导入地图后的自动适配。
8. 不新增新的“适配视图”按钮。
9. 不改变浏览模式下是否使用 ToSquareBounds 的策略。
```

说明：

```text
本阶段只修复“编辑/浏览模式切换不应该重置用户视图”这个边界。
```

## 5. 正确行为定义

### 5.1 首次打开地图

首次打开地图时，仍然应该自动适配：

```text
Loaded -> RequestFitMapToView
ContentRendered -> RequestFitMapToView
RenderMap(resetView: true) -> RequestFitMapToView
```

这部分不改。

### 5.2 用户缩放或拖拽后

用户缩放或拖拽后：

```text
hasUserViewState = true
保存当前 fitScale/userScale/offset
```

后续普通重绘必须保留该状态。

### 5.3 进入编辑模式

从浏览模式切到编辑模式：

```text
1. isEditMode = true。
2. 更新按钮样式。
3. 绘制编辑网格、端口、折点控制等编辑 UI。
4. 不重置 fitScale。
5. 不重置 userScale。
6. 不重置 mapOffsetX/mapOffsetY。
7. 不调用 RequestFitMapToView。
```

### 5.4 退出编辑模式

从编辑模式切到浏览模式：

```text
1. isEditMode = false。
2. 关闭 isConnectMode。
3. 关闭 isMultiSelectMode。
4. 清理编辑态选择、端口起点、框选矩形、折点拖动状态。
5. 更新按钮样式。
6. 重绘地图。
7. 不清空 hasUserViewState。
8. 不调用 RequestFitMapToView。
9. 不重置用户当前缩放和偏移。
```

## 6. 代码修改范围

主要修改文件：

```text
VSLoader\Views\FactoryMapWindow.xaml.cs
```

重点修改方法：

```text
EditModeButton_Click
```

需要移除或调整的逻辑：

```csharp
if (!isEditMode)
{
    hasUserViewState = false;
    RequestFitMapToView();
}
```

建议改为：

```csharp
RenderCurrentMap(resetView: false);
```

模式切换只走普通重绘。

不要在退出编辑模式时设置：

```text

```

不要在退出编辑模式时调用：

```text
RequestFitMapToView()
```

## 7. 需要保留的自动适配入口

不能误删以下入口：

```text
Loaded += (_, _) => RequestFitMapToView();
ContentRendered += (_, _) => RequestFitMapToView();
RenderMap(map, resetView: true)
ShowEmptyState(...)
导入地图后 RenderMap(loadResult.Map)
```

这些入口的语义是：

```text
地图首次出现、地图内容整体换了、空状态需要居中显示。
```

这些场景可以自动适配。

编辑/浏览模式切换不是内容整体换了，因此不应该自动适配。

## 10. 人工验收


## 11. 风险与边界

### 11.1 编辑模式画布更大

编辑模式下画布可能因为 `EditCanvasBuffer` 更大。

浏览模式下画布可能变小。

切换时普通重绘可能改变 `MapCanvas.Width/Height`，但不应改变：

```text
fitScale
userScale
mapOffsetX
mapOffsetY
```

只要缩放和平移不被重置，用户感受就不会突然“缩到很小”。

### 11.2 用户没有手动调整过视图

如果用户没有手动缩放或拖拽过，切换模式也不应强制重新适配。

原因：

```text
模式切换本身不是内容变化。
```

首次打开地图已经完成过适配。

### 11.3 后续如果需要主动适配

如果后续希望用户可以主动回到全图视图，应新增明确按钮，例如：

```text
适配视图
重置视图
```

不要把主动适配隐藏在“退出编辑模式”这个动作里。

## 12. 完成标准

本阶段完成标准：

```text
1. EditModeButton_Click 不再清空 hasUserViewState。
2. EditModeButton_Click 不再调用 RequestFitMapToView。
3. 模式切换仍然会 RenderCurrentMap(resetView: false)。
4. 编辑态 UI 清理逻辑不受影响。
5. 相关测试通过。
6. Debug 构建通过。
```

本阶段的核心原则：

```text
模式切换只切换模式，不替用户重新决定视角。
```
