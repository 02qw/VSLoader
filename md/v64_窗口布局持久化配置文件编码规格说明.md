# v64 窗口布局持久化配置文件编码规格说明

## 1. 需求背景

当前 VSLoader 已经实现过运行期内存 Session 窗口状态：

```text
1. 程序启动后，主窗口按默认比例显示。
2. 本次运行期间，用户移动/缩放主窗口后，内存中保存主窗口 Bounds。
3. 本次运行期间，用户打开并移动/缩放地图窗口后，内存中保存地图窗口 Bounds。
4. 程序真正退出后，内存状态丢失。
```

当前问题：

```text
用户希望窗口位置关系符合自己的使用习惯。
仅靠本次运行期间的内存 Session 无法跨程序重启保留。
并且每次真正退出后重新打开，默认布局仍可能因为环境或启动时序差异出现不稳定。
```

新需求：

```text
将窗口位置和大小从“内存 Session”升级为“持久化窗口布局配置文件”。
```

## 2. 需求目标

完成后：

```text
1. 程序启动时先读取窗口布局配置文件。
2. 如果配置文件存在且有效，则按配置恢复主窗口位置和大小。
3. 如果配置文件不存在，则按默认比例生成一份窗口布局配置文件。
4. 用户移动/缩放主窗口后，后台异步保存最新窗口布局。
5. 用户移动/缩放地图窗口后，后台异步保存最新地图窗口布局。
6. 下次程序启动后继续恢复用户上一次使用习惯的位置关系。
```

## 3. 非目标范围

本次不实现：

```text
1. 配置中心手动编辑窗口布局。
2. 重置窗口布局按钮。
3. 多套布局方案。
4. 多显示器精细化记忆。
5. 云同步窗口布局。
6. 修改快捷项数据结构。
7. 修改地图节点布局 JSON。
8. 修改地图连线、拖拽、多选功能。
```

本次只做：

```text
1. 新增窗口布局配置文件。
2. 启动读取。
3. 不存在时创建默认配置。
4. 窗口移动/缩放时异步保存。
5. 配置损坏时安全恢复。
```

## 4. 配置文件位置

窗口布局配置文件存放在：

```text
%AppData%\VSLoader\window-layout.json
```

示例实际路径：

```text
C:\Users\<用户名>\AppData\Roaming\VSLoader\window-layout.json
```

说明：

```text
与现有 config.json、factory-map.layout.json 位于同一个 VSLoader 应用数据目录。
```

## 5. 数据结构设计

### 5.1 新增模型文件

新增：

```text
VSLoader/Models/WindowLayoutConfig.cs
VSLoader/Models/WindowBoundsConfig.cs
VSLoader/Models/FactoryMapViewStateConfig.cs
```

### 5.2 WindowLayoutConfig

建议结构：

```csharp
namespace VSLoader.Models;

public sealed class WindowLayoutConfig
{
    public WindowBoundsConfig? MainWindow { get; set; }

    public WindowBoundsConfig? FactoryMapWindow { get; set; }

    public bool WasFactoryMapOpen { get; set; }

    public FactoryMapViewStateConfig? FactoryMapView { get; set; }
}
```

### 5.3 WindowBoundsConfig

建议结构：

```csharp
namespace VSLoader.Models;

public sealed class WindowBoundsConfig
{
    public double Left { get; set; }

    public double Top { get; set; }

    public double Width { get; set; }

    public double Height { get; set; }
}
```

### 5.4 FactoryMapViewStateConfig

建议结构：

```csharp
namespace VSLoader.Models;

public sealed class FactoryMapViewStateConfig
{
    public double FitScale { get; set; }

    public double UserScale { get; set; }

    public double OffsetX { get; set; }

    public double OffsetY { get; set; }
}
```

说明：

```text
本次建议同时持久化地图内部缩放和平移状态。
原因是用户明确希望维护“符合自己使用习惯的位置关系配置”，地图窗口和地图视角通常是一起使用的。
```

## 6. 服务设计

### 6.1 新增服务

新增：

```text
VSLoader/Services/WindowLayoutService.cs
```

职责：

```text
1. 解析 window-layout.json 路径。
2. 读取 WindowLayoutConfig。
3. 保存 WindowLayoutConfig。
4. 配置不存在时创建默认配置。
5. 配置损坏时备份并返回默认配置。
```

### 6.2 推荐方法

```csharp
public sealed class WindowLayoutService
{
    public string LayoutPath { get; }

    public WindowLayoutConfig LoadOrCreateDefault(Func<WindowLayoutConfig> defaultFactory, out string? warningMessage);

    public Task SaveAsync(WindowLayoutConfig config);
}
```

### 6.3 配置损坏处理

如果 `window-layout.json` 存在但读取失败：

```text
1. 将损坏文件备份为 window-layout.broken-yyyyMMddHHmmss.json。
2. 使用 defaultFactory 创建默认配置。
3. 保存新的 window-layout.json。
4. 返回 warningMessage。
```

是否弹窗提示：

```text
本次可不弹窗，只允许写状态栏或静默恢复。
```

如果现有 DialogService 方便接入，也可提示：

```text
窗口布局配置损坏，已恢复默认布局。
```

但不应阻止程序启动。

## 7. MainWindow 改造

### 7.1 替换纯内存 Session 来源

当前字段：

```csharp
private readonly RuntimeLayoutState _runtimeLayoutState = new();
```

可保留作为运行期缓存，也可以替换为：

```csharp
private readonly WindowLayoutService _windowLayoutService = new();
private WindowLayoutConfig _windowLayoutConfig = new();
```

推荐做法：

```text
保留 RuntimeLayoutState 概念会导致两套状态混杂。
本次建议将主窗口/地图窗口位置状态统一改为 WindowLayoutConfig。
```

但为了最小修改，可以：

```text
保留 RuntimeLayoutState 作为内存镜像。
启动时从 WindowLayoutConfig 填充 RuntimeLayoutState。
窗口变化时更新 RuntimeLayoutState 并保存 WindowLayoutConfig。
```

推荐采用最小风险方案：

```text
RuntimeLayoutState 继续作为运行期内存镜像。
WindowLayoutService 负责跨启动读写。
```

### 7.2 启动读取

程序启动时：

```text
1. 构造 MainWindow。
2. 计算默认窗口布局配置。
3. 调用 WindowLayoutService.LoadOrCreateDefault。
4. 将读取到的配置应用到 RuntimeLayoutState。
5. ContentRendered 后执行 ApplyDefaultWindowLayoutOnce。
```

注意：

```text
如果配置文件存在，则 RuntimeLayoutState.HasMainWindowBounds = true。
ApplyDefaultWindowLayoutOnce 会恢复配置文件中的主窗口 Bounds。
```

### 7.3 默认配置生成

如果配置文件不存在：

```text
使用当前默认比例算法生成 MainWindow 默认 Bounds。
生成 window-layout.json。
```

默认配置至少包含：

```text
MainWindow
```

地图窗口可以暂时不生成，或按默认右侧布局生成。

推荐：

```text
首次启动只生成 MainWindow。
首次打开地图时再生成 FactoryMapWindow。
```

原因：

```text
地图默认布局依赖主窗口实际位置和地图窗口 MinWidth/MinHeight。
首次未打开地图前不必提前保存。
```

### 7.4 保存主窗口 Bounds

当前：

```csharp
SaveMainWindowBoundsToSession()
```

需要改造为：

```text
1. 更新 RuntimeLayoutState。
2. 调度异步保存 window-layout.json。
```

注意：

```text
不能在 LocationChanged / SizeChanged 中同步写文件。
```

### 7.5 保存地图窗口 Bounds 和 View

当前：

```csharp
SaveFactoryMapStateToSession(bool includeViewState = true)
```

需要改造为：

```text
1. 更新 RuntimeLayoutState 中 FactoryMapWindow Bounds。
2. 如果 includeViewState 为 true 且地图有用户视图状态，则更新 FactoryMapView。
3. 调度异步保存 window-layout.json。
```

## 8. 异步保存策略

### 8.1 不能每个事件同步写文件

窗口拖动/缩放会触发大量事件：

```text
LocationChanged
SizeChanged
地图窗口 LocationChanged
地图窗口 SizeChanged
```

如果每次同步写 JSON，会造成卡顿。

### 8.2 推荐 Debounce 保存

MainWindow 中新增：

```csharp
private CancellationTokenSource? _layoutSaveDebounceCts;
```

保存入口：

```csharp
private void ScheduleWindowLayoutSave()
{
    _layoutSaveDebounceCts?.Cancel();
    _layoutSaveDebounceCts = new CancellationTokenSource();
    var token = _layoutSaveDebounceCts.Token;

    _ = Task.Run(async () =>
    {
        try
        {
            await Task.Delay(500, token);
            var config = BuildWindowLayoutConfigSnapshot();
            await _windowLayoutService.SaveAsync(config);
        }
        catch (OperationCanceledException)
        {
        }
        catch
        {
            // 保存失败不应打断用户操作。
        }
    });
}
```

注意：

```text
BuildWindowLayoutConfigSnapshot 不应在后台线程直接读取 WPF 控件属性。
应在 UI 线程中先更新 RuntimeLayoutState，再从 RuntimeLayoutState 构造快照。
```

### 8.3 退出前强制保存一次

在真正退出前：

```text
CloseFactoryMapForExit()
MainWindow_Closed
ExitApplication
```

应确保：

```text
保存最后一次窗口布局。
```

推荐新增：

```csharp
private void SaveWindowLayoutImmediately()
```

该方法同步或等待异步保存均可。

因为退出频率低，可以同步保存一次。

## 9. WorkArea 边界校正

读取配置后必须执行：

```csharp
ClampBoundsToWorkArea(...)
```

原因：

```text
1. 用户可能更换显示器。
2. 分辨率可能变化。
3. 任务栏位置可能变化。
4. 配置文件可能记录了屏幕外坐标。
```

规则：

```text
1. Width 不小于 MinWidth。
2. Height 不小于 MinHeight。
3. Left / Top 不允许让窗口完全跑出 WorkArea。
4. 如果配置窗口尺寸大于当前 WorkArea，则压缩到当前 WorkArea 可用范围。
```

现有：

```csharp
ClampBoundsToWorkArea(Rect bounds, double minWidth, double minHeight)
```

可继续复用。

## 10. 地图窗口打开状态

配置中有：

```csharp
WasFactoryMapOpen
```

本次建议：

```text
保存该值，但启动时不自动打开地图。
```

原因：

```text
用户之前明确接受“地图默认关闭，点击地图后显示”的模式。
自动打开地图可能打扰启动体验。
```

因此：

```text
WasFactoryMapOpen 可用于未来扩展。
本次启动时仍默认地图关闭。
点击地图后，如果 FactoryMapWindow Bounds 存在，则恢复位置大小。
```

## 11. 地图视图状态

如果配置中存在：

```text
FactoryMapView
```

点击地图打开后：

```text
RenderMap(resetView: false)
RestoreViewState(FactoryMapView)
```

如果不存在：

```text
RenderMap(resetView: true)
执行默认 Fit。
```

这与当前 v58 逻辑一致，只是数据来源由内存改成文件。

## 12. 文件写入格式

JSON 使用缩进格式，便于用户排查：

```json
{
  "mainWindow": {
    "left": 20,
    "top": 90,
    "width": 980,
    "height": 680
  },
  "factoryMapWindow": {
    "left": 1000,
    "top": 90,
    "width": 950,
    "height": 900
  },
  "wasFactoryMapOpen": false,
  "factoryMapView": {
    "fitScale": 0.449,
    "userScale": 1.0,
    "offsetX": 120,
    "offsetY": 80
  }
}
```

实际字段名可以使用 C# 默认 PascalCase：

```json
{
  "MainWindow": {},
  "FactoryMapWindow": {}
}
```

为保持与现有 .NET 默认序列化风格一致，本次推荐 PascalCase。

## 13. 错误处理

### 13.1 文件不存在

行为：

```text
1. 生成默认 WindowLayoutConfig。
2. 保存 window-layout.json。
3. 使用默认配置启动。
```

### 13.2 文件损坏

行为：

```text
1. 备份损坏文件。
2. 生成默认配置。
3. 保存新的 window-layout.json。
4. 程序继续启动。
```

### 13.3 保存失败

行为：

```text
1. 不阻塞用户操作。
2. 可写 Debug 日志。
3. 不弹频繁错误窗口。
```

保存失败常见原因：

```text
1. AppData 权限异常。
2. 文件被占用。
3. 磁盘异常。
```

## 14. 手工验收

### 14.1 首次没有配置文件

步骤：

```text
1. 删除 %AppData%\VSLoader\window-layout.json。
2. 启动 VSLoader。
```

期望：

```text
1. 程序正常启动。
2. 主窗口使用默认比例布局。
3. 生成 window-layout.json。
```

### 14.2 主窗口位置持久化

步骤：

```text
1. 启动 VSLoader。
2. 移动并缩放主窗口。
3. 等待 1 秒。
4. 托盘右键退出。
5. 重新启动。
```

期望：

```text
主窗口恢复到上次移动/缩放后的位置和大小。
```

### 14.3 地图窗口位置持久化

步骤：

```text
1. 打开地图。
2. 移动并缩放地图窗口。
3. 等待 1 秒。
4. 关闭程序。
5. 重新启动。
6. 点击地图。
```

期望：

```text
地图窗口恢复到上次位置和大小。
```

### 14.4 地图视图持久化

步骤：

```text
1. 打开地图。
2. 滚轮缩放并拖拽平移地图。
3. 等待 1 秒。
4. 关闭程序。
5. 重新启动。
6. 点击地图。
```

期望：

```text
地图恢复上次缩放和平移状态。
```

### 14.5 配置损坏恢复

步骤：

```text
1. 手动破坏 window-layout.json。
2. 启动 VSLoader。
```

期望：

```text
1. 程序不崩溃。
2. 损坏文件被备份。
3. 生成新的 window-layout.json。
4. 使用默认布局启动。
```

### 14.6 分辨率变化

步骤：

```text
1. 在大屏幕保存窗口位置。
2. 切换到小屏幕或调整分辨率。
3. 启动 VSLoader。
```

期望：

```text
窗口不会跑到屏幕外。
会被 Clamp 到当前 WorkArea 内。
```

## 16. 验收标准

最终必须满足：

```text
1. window-layout.json 不存在时自动生成。
2. window-layout.json 存在时启动读取并恢复主窗口 Bounds。
3. 主窗口移动/缩放后异步保存。
4. 地图窗口移动/缩放后异步保存。
5. 地图缩放/平移后可持久化恢复。
6. 配置损坏时不影响程序启动。
7. 窗口恢复时不会跑出当前屏幕 WorkArea。
8. 不影响原有 config.json。
9. 不影响地图布局 factory-map.layout.json。
10. dotnet test 通过。
11. dotnet build 0 错误。
```
