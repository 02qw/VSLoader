# v100 自定义提示弹窗无系统边框外壳编码规格说明

## 1. 背景

当前点击“更新软件”后会弹出确认窗口：

```text
确定要更新 VSLoader 吗？
更新过程中主程序会暂时关闭，并由更新器接管。
```

该确认窗口底部可见一条黑色细线或阴影，视觉上像是窗口下边框异常。

代码排查后确认该弹窗来自：

```csharp
DialogService.Confirm(...)
```

实际窗口为：

```csharp
MessageDialogWindow
```

当前 `MessageDialogWindow.xaml` 使用 WPF 默认系统窗口外壳：

```xml
<Window ... ResizeMode="NoResize">
```

没有自定义 `DropShadowEffect`，也没有在内容区设置黑色底边。因此这条黑线不是业务逻辑，也不是手写阴影，而是默认系统窗口边框或 DWM 阴影在底部的表现。

## 2. 目标

重构 `MessageDialogWindow` 的窗口外壳，让提示弹窗完全由应用自身控制视觉边界。

目标效果：

- 去掉默认系统窗口底部黑线。
- 保留标题栏区域、图标、标题文字、关闭按钮。
- 保留原有确认、提示、错误三类弹窗行为。
- 保持弹窗以 VSLoader 主窗口为中心显示。
- 保持轻量，不引入复杂主题框架。

## 3. 设计原则

### 3.1 只改弹窗外壳，不改业务调用

本次只修改：

- `VSLoader/Views/MessageDialogWindow.xaml`
- `VSLoader/Views/MessageDialogWindow.xaml.cs`

原则上不修改：

- `DialogService.Confirm(...)`
- `DialogService.ShowInfo(...)`
- `DialogService.ShowError(...)`
- `MainViewModel.UpdateSoftwareAsync()`
- 软件更新业务逻辑

这样可保证所有现有弹窗入口继续沿用原接口。

### 3.2 不使用系统默认边框

`MessageDialogWindow` 改为无系统边框窗口：

```xml
WindowStyle="None"
AllowsTransparency="True"
Background="Transparent"
ResizeMode="NoResize"
```

窗口内容由自定义根容器绘制：

- 白色背景
- 浅灰边框
- 可控圆角
- 可控标题栏

这样可以彻底避开默认系统底部黑线。

### 3.3 轻量实现

不引入新依赖。

不实现复杂窗口拖拽、缩放、动画。

弹窗只是确认和提示，不需要可调整大小。

## 4. 影响范围

直接影响：

- 更新软件确认弹窗
- 删除快捷项确认弹窗
- 普通信息提示弹窗
- 错误提示弹窗

这些弹窗都通过 `MessageDialogWindow` 显示，因此都会统一获得新的外壳样式。

不影响：

- 系统文件选择框
- 文件夹选择框
- 工作区删除确认中的系统 `MessageBox`
- 更新器独立窗口
- 批量新增窗口
- 主界面忙碌遮罩

## 5. 当前代码定位

更新软件确认入口：

```csharp
MainViewModel.UpdateSoftwareAsync()
```

其中调用：

```csharp
_dialogService.Confirm("确定要更新 VSLoader 吗？\n更新过程中主程序会暂时关闭，并由更新器接管。")
```

`DialogService.Confirm()` 创建：

```csharp
new MessageDialogWindow(message, MessageDialogKind.Confirm)
```

当前 `MessageDialogWindow.xaml`：

- 使用默认系统窗口样式。
- 内容根节点为 `Border Background="White"`。
- 底部按钮区域为 `Background="#F3F4F6"`。
- 没有显式阴影。
- 没有显式黑色底边框。

因此黑线来源应视为默认窗口外框或系统阴影。

## 6. UI 设计

### 6.1 窗口整体

窗口属性建议：

```xml
WindowStyle="None"
AllowsTransparency="True"
Background="Transparent"
ResizeMode="NoResize"
ShowInTaskbar="False"
WindowStartupLocation="CenterOwner"
SizeToContent="Height"
```

根容器：

```xml
<Border Background="White"
        BorderBrush="#D1D5DB"
        BorderThickness="1"
        CornerRadius="8">
```

不加 `DropShadowEffect`。

理由：

- 当前问题就是底部视觉阴影/黑线干扰。
- 优先保持干净稳定。
- 如后续需要阴影，可单独设计柔和阴影，但本次不加。

### 6.2 自定义标题栏

增加顶部标题栏，高度建议 40：

- 左侧显示 tomato 图标。
- 中间显示 `VSLoader`。
- 右侧显示关闭按钮 `×`。

关闭按钮行为：

- 对确认弹窗等价于点击“否”。
- 对普通提示/错误弹窗等价于关闭弹窗。

标题栏背景建议：

```text
#F9FAFB
```

底部分隔线建议：

```text
#E5E7EB
```

### 6.3 内容区

保留当前内容区结构：

- 左侧圆形图标
- 右侧消息文本

确认弹窗图标：

- 蓝色圆形
- 文本 `?`

错误弹窗图标：

- 红色圆形
- 文本 `!`

信息弹窗图标：

- 蓝色圆形
- 文本 `i`

### 6.4 按钮区

底部按钮区域保留浅灰背景：

```text
#F3F4F6
```

按钮布局继续右对齐。

确认弹窗：

- 显示“否”
- 显示“是”
- 隐藏“确定”

信息/错误弹窗：

- 隐藏“否”
- 隐藏“是”
- 显示“确定”

### 6.5 尺寸

保持当前尺寸策略：

```xml
Width="420"
MinHeight="180"
MaxWidth="560"
SizeToContent="Height"
```

避免扩大本次改动范围。

## 7. 行为要求

### 7.1 确认弹窗

点击“是”：

- `Confirmed = true`
- `DialogResult = true`
- 关闭窗口

点击“否”：

- `Confirmed = false`
- `DialogResult = false`
- 关闭窗口

点击右上角关闭按钮：

- `Confirmed = false`
- `DialogResult = false`
- 关闭窗口

### 7.2 信息/错误弹窗

点击“确定”：

- `DialogResult = true`
- 关闭窗口

点击右上角关闭按钮：

- `DialogResult = false`
- 关闭窗口

### 7.3 Owner 和居中

继续由 `DialogService.CreateMessageDialog()` 设置 Owner：

```csharp
dialog.Owner = owner;
dialog.WindowStartupLocation = WindowStartupLocation.CenterOwner;
```

本次不改变弹窗居中逻辑。

### 7.4 Esc 键

建议增加 Esc 键关闭逻辑：

- 确认弹窗等价于“否”
- 信息/错误弹窗等价于关闭

该行为符合常见弹窗习惯，但不强制影响业务。

## 8. 实现方案

### 8.1 修改 MessageDialogWindow.xaml

将默认窗口改成透明无边框。

根节点从单纯白色 `Border` 改成自绘窗口壳：

```xml
<Border Background="White"
        BorderBrush="#D1D5DB"
        BorderThickness="1"
        CornerRadius="8">
    <Grid>
        标题栏
        内容区
        按钮区
    </Grid>
</Border>
```

注意：

- 根 Border 不能再出现黑色底边。
- 不要添加阴影。
- 标题栏和底部按钮区都必须裁剪在圆角内，避免角落露色。

### 8.2 修改 MessageDialogWindow.xaml.cs

新增关闭按钮事件：

```csharp
private void CloseButton_Click(object sender, RoutedEventArgs e)
```

建议复用一个方法：

```csharp
private void CancelDialog()
```

确认弹窗：

```csharp
Confirmed = false;
DialogResult = false;
Close();
```

普通弹窗：

```csharp
DialogResult = false;
Close();
```

如果实现 Esc 键，则在构造函数中注册：

```csharp
PreviewKeyDown += MessageDialogWindow_PreviewKeyDown;
```

### 8.3 可选拖动能力

如果自定义标题栏后用户希望拖动窗口，可以在标题栏 `MouseLeftButtonDown` 中调用：

```csharp
DragMove();
```

本次可以实现轻量拖动，但不是核心验收条件。

## 9. 测试建议

该改动主要是 XAML 视觉和窗口交互，自动化测试成本较高。

建议至少做：

1. 编译验证：

```powershell
dotnet build .\VSLoader.sln -c Debug --no-restore
```

2. 单元测试回归：

```powershell
dotnet test .\VSLoader.sln -c Debug --no-restore
```

3. 手动验证：

- 点击“更新软件”，确认弹窗底部不再有黑线。
- 点击“是”，仍然进入更新流程。
- 点击“否”，不会更新。
- 点击右上角关闭按钮，不会更新。
- 触发普通信息提示，点击“确定”可关闭。
- 触发错误提示，点击“确定”可关闭。

## 10. 验收标准

满足以下条件即完成：

- 更新软件确认弹窗底部黑线消失。
- 弹窗仍然以 VSLoader 主窗口为中心。
- 标题栏显示 VSLoader 与关闭按钮。
- 关闭按钮行为安全，不会误触发确认。
- 确认、取消、确定三类按钮行为保持原有语义。
- 不修改软件更新业务流程。
- 不影响其他窗口。
- `dotnet build .\VSLoader.sln -c Debug --no-restore` 通过。
- `dotnet test .\VSLoader.sln -c Debug --no-restore` 通过。
