# v52 工厂地图显示裁剪运行时诊断编码规格说明

## 1. 问题背景

v50 实现了工厂地图轻量拖拽编辑器。

v51 针对地图首次打开右侧裁剪问题做过修复：

```text
延迟适配地图视口
调整地图窗口 Show / Refresh 顺序
基于设备内容边界计算缩放
显式关闭 MapCanvas 自身裁剪
```

但用户确认运行 Debug 最新版本后，问题仍然存在：

```text
地图右侧仍然像“禁区”一样。
右侧区域属于窗口背景，但设备节点没有显示。
不是单纯缩放问题。
不是画布配置宽度不足。
```

因此本次不继续盲目修改算法，而是增加运行时诊断能力，采集真实布局数据。

## 2. 已确认事实

当前用户布局文件：

```text
%AppData%\VSLoader\factory-map.layout.json
```

数据检查结果：

```text
canvas = 1600 x 900
devices = 53
设备 x 坐标包含：80 / 290 / 500 / 710 / 920 / 1130
设备最右边界约为：1280
画布右侧剩余约为：320
```

因此可以排除：

```text
不是布局 JSON 里缺少右侧设备。
不是设备坐标全部集中在左侧。
不是 canvas.width 小于设备最右边界。
```

## 3. 当前最可疑方向

需要通过运行时数据确认以下问题：

1. `MapViewport.ActualWidth` 是否真的覆盖整个地图窗口内容区域。
2. `MapCanvas.Width` 和 `MapTransformHost.Width` 是否为预期值。
3. `fitScale` 是否按内容边界正确计算。
4. `mapOffsetX` 是否把地图内容移到了错误位置。
5. 设备内容边界是否在运行时被正确识别。
6. WPF 视觉树中是否有某个内部容器产生裁剪。

用户截图中右侧区域看起来是窗口背景，但不显示设备，所以高度怀疑：

```text
MapViewport 实际宽度小于视觉上看到的地图窗口宽度
或某个内部容器在运行时发生了裁剪
```

## 4. 本次目标

增加轻量运行时诊断能力，用于定位地图右侧裁剪真实原因。

目标：

1. 在地图每次渲染和适配后记录关键尺寸。
2. 记录当前设备内容边界。
3. 记录缩放比例和平移偏移。
4. 记录最左、最右、最上、最下设备信息。
5. 记录地图窗口、视口、画布、承载层的真实尺寸。
6. 诊断信息写入本地日志文件。
7. 可选：在底部状态栏追加简短诊断摘要。

## 5. 日志文件位置

推荐写入：

```text
%AppData%\VSLoader\factory-map.debug.log
```

说明：

1. 日志仅用于诊断。
2. 每次启动或每次地图窗口创建时可以覆盖旧日志。
3. 不要无限追加导致文件膨胀。
4. 每条日志带时间戳。

示例：

```text
[2026-06-10 16:20:31.123] RenderMap
Window Actual=760x880
MapViewport Actual=736x780
MapCanvas Size=1600x900
MapTransformHost Size=1600x900
ContentBounds L=32.34 T=0.94 R=1280.00 B=842.00 W=1247.66 H=841.06
fitScale=0.531
userScale=1.000
totalScale=0.531
offsetX=19.00
offsetY=166.00
minXDevice=3D-X-RAY-NG下料机_006
maxXDevice=PIN超声焊_004
```

## 6. 诊断触发点

需要在以下位置记录日志：

1. `RenderMap()` 开始。
2. `RenderCurrentMap(resetView: true)` 完成绘制后。
3. `ScheduleResetMapView()` 被调用时。
4. `ResetMapView()` 因 `IsMapReady() == false` 返回时。
5. `ResetMapView()` 成功计算并应用变换后。
6. `MapViewport_SizeChanged()` 触发时。
7. 用户滚轮缩放后。
8. 用户拖动画布后。
9. 用户拖动设备并保存后。

第一版最低要求：

```text
RenderCurrentMap 完成后记录一次。
ResetMapView 成功后记录一次。
MapViewport_SizeChanged 记录一次。
```

## 7. 需要记录的字段

### 7.1 窗口尺寸

```text
Window.ActualWidth
Window.ActualHeight
Window.Width
Window.Height
```

### 7.2 地图视口尺寸

```text
MapViewport.ActualWidth
MapViewport.ActualHeight
MapViewport.RenderSize.Width
MapViewport.RenderSize.Height
```

### 7.3 地图内容层尺寸

```text
MapTransformHost.Width
MapTransformHost.Height
MapTransformHost.ActualWidth
MapTransformHost.ActualHeight
MapCanvas.Width
MapCanvas.Height
MapCanvas.ActualWidth
MapCanvas.ActualHeight
```

### 7.4 变换数据

```text
fitScale
userScale
totalScale
MapScaleTransform.ScaleX
MapScaleTransform.ScaleY
mapOffsetX
mapOffsetY
MapTranslateTransform.X
MapTranslateTransform.Y
```

### 7.5 内容边界

通过当前已有或新增的 `TryGetContentBounds(out Rect bounds)` 记录：

```text
bounds.Left
bounds.Top
bounds.Right
bounds.Bottom
bounds.Width
bounds.Height
```

### 7.6 设备坐标摘要

记录：

```text
设备总数
最小 X 设备名称和 X
最大 X 设备名称和 X
最小 Y 设备名称和 Y
最大 Y 设备名称和 Y
```

## 8. 代码设计建议

在：

```text
VSLoader/Views/FactoryMapWindow.xaml.cs
```

新增方法：

```csharp
private void WriteMapDebugLog(string stage)
```

职责：

1. 组装诊断文本。
2. 确保 `%AppData%\VSLoader` 目录存在。
3. 写入 `factory-map.debug.log`。
4. 捕获并忽略日志写入异常，不能影响主功能。

新增辅助方法：

```csharp
private string BuildMapDebugSnapshot(string stage)
```

职责：

1. 只负责组装字符串。
2. 不做文件写入。
3. 便于后续单元测试或手工检查。

## 9. 日志生命周期

推荐：

1. `FactoryMapWindow` 构造函数中清理旧日志。
2. 清理失败不影响程序运行。
3. 后续本窗口生命周期内追加日志。

示例：

```csharp
public FactoryMapWindow(...)
{
    ...
    InitializeComponent();
    ResetMapDebugLog();
}
```

## 10. 状态栏诊断摘要

可选但推荐在 Debug 版本中追加简短摘要：

```text
设备：53 | 连线：0 | vp:736x780 | scale:0.531 | bounds:1248x841
```

注意：

1. 不要占用太多状态栏空间。
2. Release 版本可以不显示。
3. 日志文件才是完整诊断来源。

可以使用条件编译：

```csharp
#if DEBUG
StatusText.Text += $" | vp:{MapViewport.ActualWidth:0}x{MapViewport.ActualHeight:0} | scale:{GetTotalScale():0.###}";
#endif
```

## 11. 非目标范围

本次不继续修改：

1. 不修改地图缩放算法。
2. 不修改地图拖拽算法。
3. 不修改设备布局 JSON。
4. 不修改连线算法。
5. 不新增用户可见设置项。
6. 不把诊断功能做成正式产品功能。

本次只做：

```text
采集运行时数据，定位地图显示裁剪真实原因。
```

## 15. 验收标准

最低验收：

1. 程序能正常构建。
2. 测试全部通过。
3. 打开地图后生成：

```text
%AppData%\VSLoader\factory-map.debug.log
```

4. 日志包含：

```text
RenderCurrentMap
ResetMapView
MapViewport.ActualWidth
MapCanvas.Width
ContentBounds
fitScale
mapOffsetX
```

5. 日志写入失败不影响地图窗口打开。

最终目的：

```text
用真实运行时数据判断右侧“禁区”到底来自视口尺寸、内容边界、缩放偏移，还是某个 WPF 容器裁剪。
```
