# v131 全局配置导出内容优化与地图快捷键补齐编码规格说明

## 1. 背景

当前 VSLoader 已经支持“导出全局配置 / 导入全局配置”：

```text
导出：将当前工作区的核心配置整理成一个 JSON 配置包。
导入：将配置包写入当前工作区，并对本机路径做预检提示。
```

这个功能的目标是让其他用户首次使用时，只需要导入一份配置文件，就可以尽量直接开始使用。

但结合当前代码检查后，有两个需要优化的点：

```text
1. 当前 AppConfig 已经包含 MapHotkey，但 GlobalConfigPackageService.CloneWorkspaceConfig 没有导出 MapHotkey。
2. 导入后虽然会尝试注册主快捷键和地图快捷键，但配置包内容边界、快捷键冲突和导入结果提示需要更清晰。
```

本次需求不重构全局配置导入导出的整体架构，只做最小、干净、可验证的补齐和边界优化。

## 2. 当前代码现状

### 2.1 配置包模型

文件：

```text
VSLoader/Models/GlobalConfigPackage.cs
```

当前配置包结构：

```csharp
public sealed class GlobalConfigPackage
{
    public int SchemaVersion { get; set; } = 1;
    public string AppName { get; set; } = "VSLoader";
    public string ExportedAt { get; set; } = string.Empty;
    public GlobalProgramSettings ProgramSettings { get; set; } = new();
    public AppConfig WorkspaceConfig { get; set; } = new();
    public FactoryMapLayoutConfig? FactoryMapLayout { get; set; }
}
```

### 2.2 工作区配置模型

文件：

```text
VSLoader/Models/AppConfig.cs
```

当前工作区配置字段：

```csharp
public sealed class AppConfig
{
    public string VSCodePath { get; set; } = string.Empty;
    public List<ShortcutItem> Shortcuts { get; set; } = new();
    public AdminUiConfig AdminUi { get; set; } = new();
    public HotkeyConfig Hotkey { get; set; } = new();
    public MapHotkeyConfig MapHotkey { get; set; } = new();
    public BatchImportConfig BatchImport { get; set; } = new();
    public WebUiConfig WebUi { get; set; } = new();
    public UpdateCheckConfig UpdateCheck { get; set; } = new();
}
```

### 2.3 当前导出克隆逻辑

文件：

```text
VSLoader/Models/Services/GlobalConfigPackageService.cs
```

当前 `CloneWorkspaceConfig(...)` 会导出：

```text
VSCodePath
Shortcuts
AdminUi
Hotkey
BatchImport
WebUi
UpdateCheck
```

但没有导出：

```text
MapHotkey
```

这是本次必须修复的核心遗漏。

## 3. 总体目标

### 3.1 用户目标

用户 A 配好当前工作区后，点击：

```text
导出全局配置
```

得到一份配置包。

用户 B 在自己的工作区导入这份配置包后，应尽量具备：

```text
1. 快捷项列表可用。
2. 地图节点和连线可用。
3. AdminUI 拼接、密码自动粘贴配置可用。
4. WebUI 拼接配置可用。
5. 批量新增识别路径和 CSV 规则路径被带入。
6. 更新检测 rules/map 路径和软件更新 manifest 路径被带入。
7. 主窗口快捷键配置被带入。
8. 地图全局快捷键配置被带入。
9. 本机无效路径能明确提示，不静默失败。
```

### 3.2 技术目标

1. 补齐 `MapHotkey` 的导出、导入、规范化链路。
2. 保持现有配置包结构，不新增复杂打包格式。
3. 导入仍然只写当前工作区，不污染其他工作区。
4. 程序级配置仍然只允许受控写入：
   - `VSCodePath`
   - `SoftwareUpdateManifestPath`
5. 导入完成后继续刷新主界面，并重新注册主快捷键和地图快捷键。
6. 如果主快捷键和地图快捷键冲突，必须给用户明确提示。
7. 不导出个人窗口布局、更新基线等本机状态。

## 4. 数据边界

### 4.1 应该导出的内容

配置包应包含：

```text
SchemaVersion
AppName
ExportedAt
ProgramSettings
WorkspaceConfig
FactoryMapLayout
```

其中 `ProgramSettings` 包含：

```text
VSCodePath
SoftwareUpdateManifestPath
```

其中 `WorkspaceConfig` 包含：

```text
VSCodePath
Shortcuts
AdminUi
Hotkey
MapHotkey
BatchImport
WebUi
UpdateCheck
```

其中 `FactoryMapLayout` 包含：

```text
Canvas
Devices
Edges
```

### 4.2 不应该导出的内容

本次仍然不导出：

```text
window-layout.json
updateTime.json
workspace.json
app-settings.json 的工作区列表
UIdownload 文件夹
```

原因：

```text
window-layout.json 是个人窗口位置、大小、列宽、地图视口等本机使用习惯。
updateTime.json 是当前用户对更新提醒的确认/使用基线。
workspace.json 和工作区列表属于本机工作区管理信息。
UIdownload 是运行期下载产物，不属于配置。
```

这些内容导入到其他用户电脑后，反而可能造成窗口错位、更新误判或工作区污染。

## 5. 具体改动

### 5.1 GlobalConfigPackageService.CloneWorkspaceConfig

文件：

```text
VSLoader/Models/Services/GlobalConfigPackageService.cs
```

当前逻辑：

```csharp
return new AppConfig
{
    VSCodePath = config.VSCodePath,
    Shortcuts = config.Shortcuts.Select(shortcut => shortcut.Clone()).ToList(),
    AdminUi = config.AdminUi.Clone(),
    Hotkey = config.Hotkey.Clone(),
    BatchImport = config.BatchImport.Clone(),
    WebUi = config.WebUi.Clone(),
    UpdateCheck = config.UpdateCheck.Clone()
};
```

需要改为：

```csharp
return new AppConfig
{
    VSCodePath = config.VSCodePath,
    Shortcuts = config.Shortcuts.Select(shortcut => shortcut.Clone()).ToList(),
    AdminUi = config.AdminUi.Clone(),
    Hotkey = config.Hotkey.Clone(),
    MapHotkey = config.MapHotkey.Clone(),
    BatchImport = config.BatchImport.Clone(),
    WebUi = config.WebUi.Clone(),
    UpdateCheck = config.UpdateCheck.Clone()
};
```

### 5.2 GlobalConfigPackageService.NormalizeWorkspaceConfig

文件：

```text
VSLoader/Models/Services/GlobalConfigPackageService.cs
```

当前规范化逻辑中需要补齐：

```csharp
config.MapHotkey ??= new MapHotkeyConfig();
```

并复用现有 `ConfigService` 中对旧地图快捷键的迁移规则。

建议做法：

```text
把 MapHotkey 规范化规则抽成可复用静态方法，或在 GlobalConfigPackageService 内保持同等逻辑。
```

要求：

```text
1. 旧配置包没有 MapHotkey 时，使用默认 Alt + X。
2. 旧配置包如果是单键 M，迁移为 Alt + X。
3. 旧配置包如果是单键 N 这类自定义键，迁移为 Alt + N。
4. 已经包含 Ctrl/Alt/Shift 修饰键的配置保持不变。
```

### 5.3 导入后的快捷键注册和冲突提示

文件：

```text
VSLoader/ViewModels/MainViewModel.cs
```

当前导入完成后会执行：

```csharp
LoadConfig();
TryRegisterImportedHotkey(result);
```

保留这个流程。

要求：

```text
1. 导入包写入 config.json 后，LoadConfig() 必须读到 Hotkey 和 MapHotkey。
2. TryRegisterImportedHotkey(...) 必须同时注册主快捷键和地图快捷键。
3. 如果主快捷键与地图快捷键冲突，导入结果弹窗必须提示。
4. 如果快捷键被系统或其他软件占用，导入结果弹窗必须提示。
5. 快捷键注册失败不能导致导入失败，配置文件仍然保留，但用户必须知道原因。
```

冲突处理原则：

```text
导入配置本身可以完成。
运行期注册失败则作为 warning 告知用户。
用户后续可进入设置调整快捷键。
```

### 5.4 导出结果提示

导出成功后仍然显示：

```text
全局配置导出完成。
文件：xxx
```

如果当前工作区没有地图布局文件，继续提示：

```text
当前工作区没有地图布局文件，本次未包含地图布局。
```

不需要额外提示 `MapHotkey`，因为它属于工作区配置的一部分。

### 5.5 导入结果提示

导入成功后继续显示：

```text
已导入：
1. 工作区配置
2. 地图布局
3. VSCode 路径
4. 软件更新路径
```

如果出现以下情况，加入“需要检查”：

```text
1. VSCode 路径无效，且未能自动识别。
2. 软件更新 manifest 路径不存在。
3. 批量识别父级文件夹不存在。
4. 批量识别 CSV 文件不存在。
5. UpdateCheck rules 文件不存在。
6. UpdateCheck map 文件不存在。
7. 有快捷项目标路径当前不可访问。
8. 地图中有节点未匹配到快捷项。
9. 主快捷键或地图快捷键注册失败。
10. 主快捷键和地图快捷键冲突。
```

## 6. 兼容旧配置包

### 6.1 旧包没有 MapHotkey

如果旧配置包没有 `WorkspaceConfig.MapHotkey`：

```text
导入时使用默认地图快捷键 Alt + X。
```

### 6.2 旧包有单键地图快捷键

如果旧包中存在旧格式地图快捷键：

```text
Enabled = true
Key = M
Ctrl = false
Alt = false
Shift = false
```

导入后应迁移为：

```text
Alt + X
```

如果是其他单键：

```text
N -> Alt + N
```

### 6.3 旧包包含 SoftwareVersionFilePath

`UpdateCheckConfig.SoftwareVersionFilePath` 属于旧字段。

本次不重新启用它。

导入时不需要校验该 txt 路径，也不要因为它不存在产生 warning。

软件版本检测继续以程序级：

```text
SoftwareUpdateManifestPath -> manifest.json -> version
```

为准。

## 7. 不做的事情

本次不做：

```text
1. 不把全局配置包改成 zip。
2. 不打包真实 rules/map/manifest 文件内容。
3. 不复制 UIdownload 中已下载的 JNLP 文件。
4. 不迁移工作区列表。
5. 不迁移窗口位置、地图缩放比例、列宽。
6. 不迁移 updateTime.json。
7. 不改变导入导出按钮 UI。
8. 不改变已有 AdminUI/WebUI/批量识别算法。
```

## 8. 风险点

### 8.1 路径在别人电脑上不可达

导出的很多路径可能是：

```text
本机 C 盘路径
网络共享路径
服务器路径
```

导入时不能假设它们一定存在。

处理方式：

```text
不阻止导入，但必须 warning。
```

### 8.2 快捷键冲突

导入别人的快捷键后，可能和当前用户电脑已有软件冲突。

处理方式：

```text
导入成功，注册失败则 warning。
```

### 8.3 地图布局和快捷项不匹配

地图节点使用 `Key` 匹配快捷项 `TargetPath`。

如果导入包中地图节点找不到对应快捷项：

```text
提示地图中有 N 个节点未匹配到快捷项。
```

不自动删除节点，不自动修改连线。

### 8.4 程序级软件更新路径会影响所有工作区

`SoftwareUpdateManifestPath` 位于 `AppSettings`，不是当前工作区独占配置。

导入后如果路径有效，会写入程序级配置。

必须继续提示：

```text
软件更新路径属于程序级配置，导入后会影响所有工作区。
```

## 11. 验收标准

完成后应满足：

```text
1. 导出的全局配置包中包含 WorkspaceConfig.MapHotkey。
2. 导入后当前工作区 config.json 中包含 MapHotkey。
3. 旧全局配置包仍然能导入。
4. 主快捷键和地图快捷键能在导入后重新注册。
5. 快捷键注册失败或冲突时，用户能在导入结果中看到明确提示。
6. 导入不修改其他工作区。
7. 导入不修改窗口布局文件。
8. 导入不修改 updateTime.json。
9. 所有新增/相关测试通过。
10. Debug 构建通过。
```

## 12. 实现优先级

建议按以下顺序实现：

```text
1. 补齐 GlobalConfigPackageService 对 MapHotkey 的 Clone 和 Normalize。
2. 补测试，先覆盖导出包包含 MapHotkey。
3. 补测试，覆盖导入后当前工作区包含 MapHotkey。
4. 检查 TryRegisterImportedHotkey 的 warning 行为，必要时补充冲突测试。
5. 跑定向测试。
6. 跑全量测试。
7. 构建 Debug。
```
