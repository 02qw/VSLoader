# v160 地图端口感知正交路由与线路整理编码规格说明

## 1. 背景

当前工厂地图已经完成 Version 5 点线拓扑、Junction 分支连接点和浏览/编辑双模式。

当前节点四侧 Attached 连接点坐标是准确的：

```text
Top    -> 节点上边中点
Right  -> 节点右边中点
Bottom -> 节点下边中点
Left   -> 节点左边中点
```

但当前 `FactoryMapTopologyService.ConnectPoints` 对两个非共线连接点只创建一个固定折点：

```csharp
X = to.X;
Y = from.Y;
```

得到的路径固定为：

```text
起点 -> (终点.X, 起点.Y) -> 终点
```

该算法只保证水平或垂直，不理解 Attached 连接点位于节点的哪一侧，也不检查节点矩形。

因此会出现：

```text
1. 顶部连接点没有先向上离开节点，而是沿节点上边框横向移动。
2. 左侧连接点没有从左侧外部进入，而是沿节点左边框移动。
3. 点击起点和终点的先后顺序会改变折线方向和贴边对象。
4. 线段贴在节点边框上时，因为线路先绘制、节点后绘制，部分线段会被节点遮住。
5. 被遮住后视觉上像是线段没有连接到圆形连接点。
6. 节点移动后的 `RepairOrthogonality` 使用同样的固定折点，问题会再次出现。
```

本次需要把“只保证正交”升级为“端口方向正确、避开节点、结果稳定”的端口感知正交路由。

同时增加用户主动入口：

```text
整理线路
```

用于重新计算旧地图或手工调整后出现的贴边、不自然线路。

## 2. 核心结论

本次必须遵循：

```text
Attached 连接点的第一段线必须沿端口方向向节点外部离开。
Attached 连接点的最后一段线必须从节点外部沿端口反方向进入。
线路不得穿过节点矩形。
线路不得沿节点边框重叠移动。
点击起点和终点的顺序不得改变线路质量。
Free 和 Junction 不需要节点逃逸段，但仍使用正交路径。
新建连接和节点移动后的局部修复必须使用同一个路由服务。
旧地图不得在打开时被静默重排。
只有用户点击“整理线路”并确认后，才允许全图重新布线。
```

## 3. 目标

本次必须实现：

```text
1. 新增端口感知正交路由服务。
2. Attached 上下左右四个端口具备明确的向外方向。
3. Attached 端口生成固定长度的节点逃逸段。
4. 路由候选必须避开全部节点矩形和节点边框。
5. 起点、终点点击顺序反转时，线路几何结果保持等价。
6. ConnectPoints 使用新路由服务生成零个或多个 Bend。
7. 点到线、线到点、线到线继续通过现有连接草稿原子完成。
8. 节点移动后只重新计算受影响的逻辑线路。
9. Free/Junction 移动后只重新计算相邻逻辑线路。
10. 不再使用固定 `(to.X, from.Y)` 作为通用修复策略。
11. 地图工具栏新增“整理线路”按钮。
12. 整理线路不移动节点、Free、Junction，也不改变连接关系。
13. 整理线路只重建逻辑线路内部的 Bend 和 Segment。
14. 整理线路全程使用快照、校验、一次保存和失败回滚。
15. 旧地图 Version 5 文件继续兼容，不升级布局版本。
```

## 4. 非目标

本次不做：

```text
1. 不实现斜线或曲线。
2. 不实现用户自定义端口逃逸距离。
3. 不实现持续后台自动整理。
4. 不在地图打开时自动改写旧线路。
5. 不因为视觉交叉自动创建 Junction。
6. 不因为视觉重叠合并不同拓扑关系。
7. 不移动节点、Free、Junction 的用户坐标。
8. 不改变 JunctionAxis。
9. 不改变浏览/编辑双模式。
10. 不修改地图快捷键、窗口状态和全局配置结构。
11. 不引入重量级第三方图形路由引擎。
12. 不实现完整撤销/重做栈。
```

## 5. 当前问题的技术根因

### 5.1 固定单折点

当前：

```text
from -> Bend(to.X, from.Y) -> to
```

该规则没有读取：

```text
from.Side
to.Side
from.OwnerNodeId
to.OwnerNodeId
节点矩形范围
其他节点障碍物
```

### 5.2 Attached 端口方向丢失

Attached 已保存：

```text
OwnerNodeId
Side
X
Y
```

但当前路径生成只使用 `X/Y`，没有使用 `Side`。

### 5.3 绘制顺序放大了视觉问题

当前拓扑地图绘制顺序：

```text
1. 线段
2. 节点
3. 连接点
```

当线段沿节点边框或进入节点内部时，节点会覆盖线路。

不得通过简单提高线段 ZIndex 解决，因为那会让线路显示在节点内容上方。正确修复是让路径离开节点边界。

### 5.4 节点移动会重新制造问题

当前 `FactoryMapMovementService.RepairOrthogonality` 遇到斜线时，也会创建：

```text
Bend(to.X, from.Y)
```

所以只修改首次连接逻辑不够。

## 6. 路由基础模型

### 6.1 端口方向

新增或集中定义端口方向向量：

```text
Top    -> ( 0, -1)
Right  -> ( 1,  0)
Bottom -> ( 0,  1)
Left   -> (-1,  0)
```

建议由 `FactoryMapEndpointGeometryService` 提供：

```csharp
public static Vector GetOutwardDirection(string side)
```

未知 Side 必须返回失败，不得保守默认为 Right 后继续路由。

### 6.2 节点矩形

使用当前统一尺寸：

```text
DeviceWidth  = 150
DeviceHeight = 58
```

节点矩形：

```text
[device.X, device.Y, DeviceWidth, DeviceHeight]
```

路由碰撞检测使用扩展矩形：

```text
节点矩形向外扩展 RoutingClearance。
```

### 6.3 路由间距

建议第一阶段使用：

```csharp
RoutingClearance = Math.Max(gridSize * 2, 20d);
```

默认网格为 10 时，端口逃逸距离为 20。

该值必须集中定义，不得在窗口、拓扑服务和移动服务中分别写死。

### 6.4 逃逸点

Attached 起点逃逸点：

```text
startEscape = startPoint + startDirection * RoutingClearance
```

Attached 终点逃逸点：

```text
endEscape = endPoint + endDirection * RoutingClearance
```

完整路径：

```text
起点端口
-> 起点逃逸点
-> 中间正交路径
-> 终点逃逸点
-> 终点端口
```

Free/Junction 没有所属节点：

```text
escapePoint = 自身坐标
不强制端口方向
```

若 Top/Left 端口距离地图零坐标边界不足，导致逃逸点小于 0：

```text
不得把端口方向偷偷改成其他方向。
不得生成负坐标。
本次路由失败并提示用户将节点向地图内部移动。
```

## 7. 新增路由服务

新增：

```text
VSLoader\Models\Services\FactoryMapOrthogonalRouterService.cs
VSLoader\Models\FactoryMapRouteResult.cs
```

建议接口：

```csharp
FactoryMapRouteResult Route(
    FactoryMapDeviceViewData map,
    FactoryMapConnectionPoint from,
    FactoryMapConnectionPoint to,
    double gridSize)
```

结果模型：

```csharp
public sealed class FactoryMapRouteResult
{
    public bool Success { get; init; }
    public string? ErrorMessage { get; init; }
    public IReadOnlyList<FactoryMapPoint> Points { get; init; } = [];
}
```

`Points` 必须包含完整路径坐标：

```text
第一个点 = from 精确坐标
最后一个点 = to 精确坐标
中间点 = 需要创建 Bend 的坐标
```

路由服务不得直接修改地图集合。

两个不同连接点坐标完全相同时，必须返回失败，不得创建零长度线路。

## 8. 候选路径生成

### 8.1 基础候选

在两个逃逸点之间生成有限数量候选：

```text
1. 直接水平或垂直连接。
2. Horizontal -> Vertical 单折线路径。
3. Vertical -> Horizontal 单折线路径。
4. 使用中间 X 的双折线路径。
5. 使用中间 Y 的双折线路径。
```

中间坐标：

```text
middleX = Snap((startEscape.X + endEscape.X) / 2)
middleY = Snap((startEscape.Y + endEscape.Y) / 2)
```

### 8.2 外围绕行候选

当基础候选被节点阻挡时，增加四个外围通道：

```text
所有相关障碍物左侧
所有相关障碍物右侧
所有相关障碍物上方
所有相关障碍物下方
```

外围坐标必须：

```text
位于障碍物扩展矩形之外。
吸附到网格。
不小于 0。
```

### 8.3 同侧端口

例如两个 Top 端口连接时，不允许直接从一个 Top 端口穿向另一个节点内部。

应生成 U 形路径：

```text
Top端口A -> 向上逃逸 -> 横向通道 -> 向下进入Top端口B
```

Left/Right/Bottom 同理。

### 8.4 相邻方向端口

例如 Top -> Left：

```text
Top 端口必须先向上。
Left 端口必须从左侧外部进入。
中间可以使用一个或多个正交折点。
不得沿任一节点边框移动。
```

### 8.5 相反方向端口

例如 Right -> Left：

```text
若中间空间无障碍，可以直接连接。
若有节点阻挡，必须选择上方或下方外围通道。
```

## 9. 候选路径校验

每条候选必须依次校验：

```text
1. 所有坐标有限且不小于 0。
2. 每段必须水平或垂直。
3. 不得包含零长度线段。
4. 第一段必须符合起点 Attached 的向外方向。
5. 最后一段必须从外部进入终点 Attached。
6. 除端口接触点外，不得进入任何节点原始矩形。
7. 中间线段不得进入任何节点扩展矩形。
8. 不得与节点任意边框产生非零长度重叠。
9. 不得在同一坐标重复创建连续折点。
```

### 9.1 起点方向判定

若起点是 Attached：

```text
firstSegmentDirection == GetOutwardDirection(from.Side)
```

### 9.2 终点方向判定

若终点是 Attached：

```text
lastSegmentDirection == -GetOutwardDirection(to.Side)
```

### 9.3 自身节点例外

起点端口到起点逃逸点、终点逃逸点到终点端口允许接触各自节点边界。

除此之外，候选路径不得再次进入这两个节点的扩展矩形。

## 10. 候选评分和稳定性

候选必须使用确定性评分，不得依赖集合遍历顺序或随机数。

推荐按以下优先级排序：

```text
1. 校验通过。
2. 折点数量更少。
3. 总曼哈顿长度更短。
4. 与其他线段重叠长度更少。
5. 坐标序列按固定规则排序，作为最终稳定 tie-break。
```

点击顺序反转时：

```text
Route(A, B) 的坐标序列
应与 Route(B, A) 的坐标序列反向后等价。
```

不得继续使用：

```text
始终优先 (to.X, from.Y)
```

## 11. 路径归一化

选定候选后执行：

```text
删除连续重复点。
删除处于同一直线上的中间点。
保留 Attached 精确端口坐标。
中间 Bend 坐标吸附到网格。
不得为了吸附改变 Attached 坐标。
```

节点宽度为 150，因此节点中心端口可能位于 `X + 75`。

Attached 不要求落在 10px 网格上，线路必须以 Attached 的真实坐标为准，不能把端口强行改到相邻网格线上。

## 12. ConnectPoints 接入

修改：

```text
VSLoader\Models\Services\FactoryMapTopologyService.cs
```

`ConnectPoints` 保留现有校验：

```text
连接点存在。
不能连接自己。
不能创建重复路径。
Bend 不能直接形成非法分支。
```

通过校验后：

```text
1. 调用 FactoryMapOrthogonalRouterService.Route。
2. 对路径中的每个中间坐标创建 Kind = Bend 的连接点。
3. 按路径顺序创建 Segment。
4. 保留递增 ZIndex。
5. ValidateTopology。
6. 校验成功后一次提交。
```

若路由失败：

```text
不得修改 map.ConnectionPoints。
不得修改 map.Segments。
返回可追溯错误信息。
```

点到线、线到点和线到线无需在窗口中重复路由逻辑，因为现有 `FactoryMapConnectionDraftService` 最终调用 `ConnectPoints`。

## 13. 逻辑线路定义

为了支持节点移动和整理线路，需要定义“逻辑线路链”。

逻辑锚点：

```text
Attached
Free
Junction
```

内部控制点：

```text
Bend
```

一条逻辑线路链是：

```text
锚点A -> 零个或多个 Bend -> 锚点B
```

要求：

```text
内部 Bend 的 degree 必须为 2。
遇到 Free、Junction、Attached 时结束当前链。
Junction 的每个相邻方向分别形成独立逻辑线路链。
同一 Segment 不得被重复归入多条链。
```

若发现以下异常：

```text
只有 Bend 组成且没有锚点的闭环。
Bend degree 不等于 2。
Segment 引用不存在的连接点。
同一 Segment 被重复遍历。
```

必须返回可追溯错误，不得猜测连接关系或静默删除对象。

建议新增：

```text
VSLoader\Models\Services\FactoryMapLogicalRouteService.cs
```

职责：

```text
枚举全部逻辑线路链。
查找与指定连接点相邻的逻辑线路链。
返回链的端点、内部 Bend 和 Segment IDs。
```

## 14. 节点和连接点移动后的局部重路由

修改：

```text
VSLoader\Models\Services\FactoryMapMovementService.cs
```

### 14.1 节点移动

节点移动后：

```text
1. 更新该节点四个 Attached 坐标。
2. 查找以这些 Attached 为端点的逻辑线路链。
3. 只重建这些链的内部 Bend 和 Segment。
4. 不重排不相关线路。
5. 校验并一次提交。
```

### 14.2 Free 移动

Free 移动后：

```text
只重建以该 Free 为端点的逻辑线路链。
不移动其他 Free/Junction。
```

### 14.3 Junction 移动

继续遵守 v159：

```text
Horizontal Junction 只改变 X。
Vertical Junction 只改变 Y。
Locked Junction 不移动。
```

移动成功后，只重建 Junction 的支线路径和必要边界链，不得破坏其主干共线关系。

### 14.4 线段通道拖动

用户显式拖动线段通道属于手工布局操作。

第一阶段：

```text
保持 v159 的通道移动语义。
不得在鼠标松开后立即对整个通道自动整理。
只修复因边界端点变化产生的必要局部链。
```

### 14.5 删除旧固定修复策略

`RepairOrthogonality` 不得再对 Attached 相关线路使用：

```text
Bend(to.X, from.Y)
```

可以保留一个纯拓扑防御分支，但最终仍必须调用统一路由服务。

## 16. 整理线路服务

新增：

```text
VSLoader\Models\Services\FactoryMapLineArrangementService.cs
VSLoader\Models\FactoryMapLineArrangementResult.cs
```

建议接口：

```csharp
FactoryMapLineArrangementResult ArrangeAll(
    FactoryMapDeviceViewData map,
    double gridSize)
```

服务必须在克隆拓扑上工作：

```text
1. 克隆 ConnectionPoints、Segments 和必要节点数据。
2. 枚举全部逻辑线路链。
3. 逐条调用统一路由服务。
4. 删除每条链原有内部 Bend 和 Segment。
5. 创建新的 Bend 和 Segment。
6. 保留所有锚点 ID 和坐标。
7. ValidateTopology。
8. 全部成功后才替换原 map 集合。
```

返回结果至少包含：

```text
Success
ErrorMessage
ArrangedRouteCount
RemovedBendCount
CreatedBendCount
```

### 16.1 原子性

任意一条逻辑线路无法生成合法路径时：

```text
整体失败。
原 map 不变。
不得只保存部分线路。
```

### 16.2 空地图

没有线段时：

```text
返回成功。
ArrangedRouteCount = 0。
窗口提示“当前没有需要整理的线路”。
不写入无意义文件。
```

### 16.3 ZIndex

重建一条逻辑线路链时：

```text
优先保留原链最大 ZIndex 作为基线。
新 Segment 按路径顺序递增。
不得修改其他链的 ZIndex。
```

## 17. 异步执行与遮罩

全图整理可能扫描多个节点和逻辑线路。

窗口应复用现有 Busy 遮罩：

```text
BusyMessage = 正在整理地图线路...
显示当前处理数量和总线路数量。
阻止用户继续拖动、导入、切换模式或关闭连接草稿。
```

建议流程：

```text
1. UI 线程捕获拓扑快照和纯数据克隆。
2. Task.Run 在后台克隆上执行 ArrangeAll。
3. 后台不得访问 WPF 控件。
4. Dispatcher 回到 UI 线程提交结果。
5. ValidateTopology 后调用一次 saveLayout。
```

关闭窗口或程序退出时：

```text
取消未完成任务。
不得在窗口销毁后回写 UI。
原地图和文件保持不变。
```

后台任务必须保存操作序号和当前地图实例标识。回到 UI 线程提交前再次检查：

```text
窗口仍然有效。
操作序号仍是当前任务。
currentMap 仍是启动整理时的地图。
期间没有导入或重新加载地图。
```

任一条件不满足时丢弃后台结果，不保存文件。

## 18. 保存和回滚

### 18.1 新建连接

沿用现有拓扑原子提交：

```text
路由失败 -> map 不变。
拓扑校验失败 -> map 不变。
保存失败 -> 恢复窗口拓扑快照。
```

### 18.2 节点移动

```text
移动前捕获快照。
更新 Attached 和局部线路。
一次校验。
一次保存。
失败恢复节点坐标、Bend、Segment 和 JunctionAxis。
```

### 18.3 整理线路

```text
确认后捕获完整拓扑快照。
后台只修改克隆。
成功后一次替换集合。
一次保存。
保存失败恢复完整快照。
```

失败弹窗必须包含具体阶段：

```text
线路枚举失败。
第 N 条逻辑线路无法路由。
拓扑校验失败。
地图文件保存失败。
```

## 20. 性能约束

```text
1. 普通新建连接只计算当前两个锚点之间的候选。
2. 节点移动只重建与该节点 Attached 相邻的逻辑线路链。
3. Free/Junction 移动只处理相邻逻辑线路链。
4. MouseMove 中不得运行全量路由。
5. 鼠标释放后最多执行一次局部重路由和防抖保存。
6. 全图整理必须在后台克隆上运行。
7. 候选数量必须有固定上限，不实现无限搜索。
8. 节点矩形碰撞检测可先使用线性扫描。
9. 若后续节点超过 500 个，再考虑空间索引，不在本次提前引入。
10. 不增加持续运行的定时器或后台扫描线程。
```

## 21. UI 和交互要求

```text
1. “整理线路”使用普通命令按钮，不是模式切换按钮。
2. 点击后按钮不保持蓝色 Active 状态。
3. Busy 期间按钮禁用。
4. 成功提示显示整理线路数量。
5. 失败时保留用户原有地图和选择状态。
6. 整理成功后可以清除线段/Bend 选择，节点选择可保留。
7. 不新增虚线框或装饰性动画。
8. 不改变浏览、编辑按钮状态语义。
9. 不改变滚轮缩放、触控板滚动和地图平移。
```

```text
已整理 12 条线路，移除 18 个旧折点，创建 9 个新折点。
```

## 23. 测试要求

### 23.1 端口方向

```text
Top 第一段向上。
Right 第一段向右。
Bottom 第一段向下。
Left 第一段向左。
终点 Attached 从节点外部进入。
未知 Side 被拒绝。
```

### 23.2 图中问题回归

必须加入与用户截图等价的布局：

```text
底部节点 Top -> 右上节点 Left。
```

断言：

```text
第一段向上离开底部节点。
最后一段从左侧进入右上节点。
没有任何线段沿底部节点上边框移动。
没有任何线段沿右上节点左边框移动。
```

再加入：

```text
底部节点 Top -> 上方 Free。
```

断言线路精确结束在 Top Attached 圆点坐标，不存在被节点遮住的贴边短线。

### 23.3 点击顺序

```text
Route(A, B) 与 Route(B, A) 反向后坐标等价。
创建的连接关系一致。
不存在一个方向正常、反向贴边的情况。
```

### 23.4 端口组合

至少覆盖：

```text
Top -> Top
Top -> Bottom
Top -> Left
Right -> Left
Right -> Right
Attached -> Free
Attached -> Junction
Free -> Free
Free -> Junction
```

### 23.5 障碍物

```text
两个节点之间存在第三个节点时，线路绕开第三个节点。
基础候选全部阻挡时使用外围通道。
线路不穿过任何节点原始矩形。
线路不与任何节点边框重叠。
无合法候选时返回失败并保持地图不变。
Top/Left 端口靠近零坐标边界且无法向外逃逸时安全失败。
```

### 23.6 拓扑生成

```text
每个中间坐标创建一个 Bend。
Bend degree 等于 2。
Segment 数量等于路径点数量减 1。
无重复 Bend。
无零长度 Segment。
无斜线 Segment。
连接草稿仍保持原子性。
```

### 23.7 节点移动

```text
节点移动后 Attached 坐标更新。
相邻逻辑线路重新路由。
不相关线路的 Bend、Segment ID 和坐标不变。
移动失败整体回滚。
不会重新生成贴边固定折点。
```

### 23.8 整理线路

```text
整理全部逻辑线路链。
节点坐标不变。
Free 坐标和 ID 不变。
Junction 坐标、ID、JunctionAxis 不变。
连接关系不变。
旧 Bend 被正确删除。
新 Bend 满足端口方向和避障规则。
任意一路失败时整体不修改地图。
没有线路时返回成功且不保存。
```

### 23.9 UI 回归

```text
工具栏出现“整理线路”。
浏览模式下按钮禁用。
编辑模式且地图有效时按钮可用。
连接草稿或拖动期间按钮禁用。
点击后显示确认弹窗。
用户取消不修改地图。
执行时显示 Busy 遮罩。
成功后只保存一次。
保存失败恢复快照并显示错误。
滚轮缩放、平移、导入导出和自动获取连接不受影响。
```

## 25. 人工验收

```text

11. 完成后确认节点、Free、Junction 坐标未改变。
12. 确认旧贴边线路已重新布线。
13. 关闭并重新打开地图，确认整理结果已保存。
```
