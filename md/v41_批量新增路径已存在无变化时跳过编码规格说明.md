# v41 批量新增路径已存在无变化时跳过编码规格说明

## 1. 需求背景

v40 已经实现批量新增识别按 `TargetPath` 去重，并在同一路径已存在时显示：

```text
可更新
```

该改动解决了 CSV 规则变化后，同一个源文件夹被重复新增的问题。

但当前实现存在一个新问题：

只要扫描到的 `TargetPath` 已经存在，预览结果就会显示为 `可更新`。

这会导致用户再次扫描同一个父级目录时，即使当前 CSV 规则生成结果与主列表中已有快捷项完全一致，也会全量显示 `可更新`。

这并不符合用户预期。

## 2. 需求目标

批量新增识别应区分以下三种情况：

```text
路径不存在 -> 可新增
路径已存在且结果有变化 -> 可更新
路径已存在且结果无变化 -> 已跳过
```

换句话说：

```text
TargetPath 已存在
```

只能说明这是同一个源文件夹，不能直接说明它需要更新。

只有当前 CSV 规则生成的新结果和已有快捷项不同，才显示 `可更新`。

## 3. 当前代码问题

当前代码位置：

`VSLoader/Models/Services/BatchImportService.cs`

当前逻辑：

```csharp
if (existingShortcutForPath is not null)
{
    items.Add(new BatchImportPreviewItem
    {
        Status = StatusUpdate,
        Message = $"目标路径已存在，将更新：{existingShortcutForPath.Name} -> {generatedName}",
        CanImport = true,
        IsSelected = true,
        IsUpdate = true
    });
    continue;
}
```

问题是：

```text
existingShortcutForPath is not null
```

只代表路径已存在，没有判断是否真的发生变化。

## 4. 正确判断规则

当 `TargetPath` 已存在时，需要比较当前扫描生成结果和已有快捷项。

建议比较字段：

1. `Name`
2. `Description`
3. `TargetPath` 归一化后的路径

生成结果：

```text
GeneratedName = 当前 CSV 规则生成的名称
GeneratedDescription = 批量新增：FolderName
GeneratedTargetPath = 当前扫描得到的目录路径
```

已有项：

```text
ExistingName = existingShortcut.Name
ExistingDescription = existingShortcut.Description
ExistingTargetPath = existingShortcut.TargetPath
```

如果三者都一致：

```text
已跳过
```

如果任意一个不同：

```text
可更新
```

## 5. 字段比较细节

### 5.1 Name

名称比较：

```text
Trim 后，不区分大小写
```

示例：

```text
银烧结_001
银烧结_001
```

视为一致。

### 5.2 Description

批量导入生成的备注是：

```text
批量新增：{FolderName}
```

比较时：

```text
Trim 后，区分大小写或不区分大小写均可
```

推荐不区分大小写，保持 Windows 场景宽松一致。

### 5.3 TargetPath

路径比较必须继续使用 v40 的归一化逻辑：

```csharp
NormalizePathKey(path)
```

以下应视为同一路径：

```text
C:\Root\3134_TSSP001
C:\Root\3134_TSSP001\
C:/Root/3134_TSSP001
```

## 6. 预览状态规则

### 6.1 路径不存在

状态：

```text
可新增
```

属性：

```csharp
CanImport = true
IsSelected = true
IsUpdate = false
```

### 6.2 路径已存在且结果有变化

状态：

```text
可更新
```

属性：

```csharp
CanImport = true
IsSelected = true
IsUpdate = true
```

Message 示例：

```text
目标路径已存在，将更新：银烧结_001 -> amx银烧结_001
```

如果名称没变但备注或路径格式变了，也可以显示：

```text
目标路径已存在，将同步最新信息。
```

### 6.3 路径已存在且结果无变化

状态：

```text
已跳过
```

属性：

```csharp
CanImport = false
IsSelected = false
IsUpdate = false
```

Message：

```text
目标路径已存在，且当前规则结果无变化。
```

## 7. 推荐实现方法

在 `BatchImportService` 中新增辅助方法：

```csharp
private static bool HasBatchImportChanges(
    ShortcutItem existingShortcut,
    string generatedName,
    string generatedTargetPath,
    string generatedDescription)
```

建议逻辑：

```csharp
return !string.Equals(existingShortcut.Name.Trim(), generatedName.Trim(), StringComparison.OrdinalIgnoreCase)
    || !string.Equals(existingShortcut.Description.Trim(), generatedDescription.Trim(), StringComparison.OrdinalIgnoreCase)
    || !string.Equals(NormalizePathKey(existingShortcut.TargetPath), NormalizePathKey(generatedTargetPath), StringComparison.OrdinalIgnoreCase);
```

在 `BuildPreview` 中生成：

```csharp
var generatedDescription = $"批量新增：{folderName}";
```

然后：

```csharp
if (existingShortcutForPath is not null)
{
    if (!HasBatchImportChanges(existingShortcutForPath, generatedName, directory, generatedDescription))
    {
        // 已跳过
    }

    // 可更新
}
```

## 8. 与名称重复逻辑的关系

当前仍然需要保留：

```text
路径不同但名称相同 -> 名称重复
```

但对于路径相同的已有项：

```text
不应因为自己的旧名称而判定名称重复
```

这个规则 v40 已经处理，本次不要破坏。

## 9. 与确认导入逻辑的关系

路径已存在且无变化的项：

```text
CanImport = false
IsSelected = false
```

因此不会进入：

```csharp
CreateApplyItems
```

也不会触发 `MainViewModel` 更新。

只有真正 `可更新` 的项才会更新 `UpdatedAt`。

这很重要：如果无变化项也更新，会导致用户每次扫描都刷新更新时间，反而误导用户。

## 11. 验收场景

手工验收：

1. 使用 CSV 批量新增一批快捷项。
2. 不修改 CSV，再次点击批量新增识别并扫描预览。
3. 已存在且无变化的项应显示：

```text
已跳过
```

4. 不应全量显示 `可更新`。
5. 修改 CSV 中某个规则的 `DisplayName`。
6. 再次扫描。
7. 只有受影响的源文件夹显示 `可更新`。
8. 确认导入后，只有这些项更新名称和更新时间。

## 15. 最终效果

批量新增识别再次扫描时，不会把所有已存在路径都显示为 `可更新`。

只有当前 CSV 规则生成结果与已有快捷项不同的项目，才显示为 `可更新`。

已经是最新结果的项目显示为 `已跳过`，避免用户误以为所有快捷项都需要更新。
