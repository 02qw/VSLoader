# v65 窗口布局启动恢复期间防误保存编码规格说明

## 1. 需求背景

当前 VSLoader 已经实现窗口布局持久化：

```text
1. 主窗口位置和大小保存到 %AppData%\VSLoader\window-layout.json。
2. 地图窗口位置和大小保存到同一份配置文件。
3. 地图内部缩放和平移状态也保存到同一份配置文件。
4. 用户移动或缩放窗口后，使用 500ms 防抖写入配置文件。
5. 程序真正退出时，会立即保存一次最终窗口布局。
```

当前发现的问题：

```text
用户移动主窗口后等待超过 500ms，再从托盘区真正退出程序。
重新打开程序后，主窗口位置没有恢复到退出前的位置。
```

结合当前代码分析，问题不在配置字段不足，也不是 500ms 防抖本身失效，而是启动阶段存在误保存风险：

```text
1. 程序启动时先读取 window-layout.json。
2. 配置中的主窗口 Bounds 被写入 RuntimeLayoutState。
3. 但是窗口渲染完成前，WPF 可能触发 LocationChanged / SizeChanged。
4. 当前 MainWindow_LocationOrSizeChanged 会直接调用 SaveMainWindowBoundsToSession。
5. 这会把启动阶段的临时窗口位置或 XAML 默认尺寸写回 RuntimeLayoutState。
6. 等 ContentRendered 阶段真正恢复窗口位置时，RuntimeLayoutState 可能已经被污染。
7. 后续保存又会把污染后的窗口布局写回 window-layout.json。
```

因此本次修复目标是：

```text
启动恢复期间禁止窗口位置变化事件写入 RuntimeLayoutState 和 window-layout.json。
```

## 2. 需求目标

完成后：

```text
1. 程序启动读取 window-layout.json 后，不会被启动期间的临时窗口事件覆盖。
2. 首次 ContentRendered / ApplicationIdle 恢复布局完成前，不保存主窗口 Bounds。
3. 恢复布局完成后，用户真实移动或缩放主窗口，仍然正常 500ms 防抖保存。
4. 点击关闭按钮最小化到托盘时，仍然保存当前主窗口 Bounds。
5. 从托盘区右键退出程序时，仍然最终立即保存窗口布局。
6. 不改变 window-layout.json 的现有字段结构。
7. 不改变地图窗口、快捷项、AdminUI、WebUI、批量新增等业务逻辑。
```

## 6. 根因说明

当前 `_isApplyingRuntimeLayout` 只能保护 `ApplyWindowBounds(...)` 方法内部主动设置窗口 Bounds 的过程：

```csharp
private void ApplyWindowBounds(Window window, Rect bounds)
{
    _isApplyingRuntimeLayout = true;
    try
    {
        window.Left = bounds.Left;
        window.Top = bounds.Top;
        window.Width = bounds.Width;
        window.Height = bounds.Height;
    }
    finally
    {
        _isApplyingRuntimeLayout = false;
    }
}
```

但是程序启动过程中，WPF 自身也可能触发 `LocationChanged` / `SizeChanged`。这类事件不一定发生在 `ApplyWindowBounds(...)` 内部，所以不会被 `_isApplyingRuntimeLayout` 拦住。

因此需要增加一个更高层级的启动恢复保护状态。

## 7. 推荐实现方案

### 7.1 新增字段

在 `MainWindow` 类字段区域新增：

```csharp
private bool _isInitialLayoutRestoring = true;
```

含义：

```text
程序启动后，默认认为正在进行首次布局恢复。
首次布局恢复完成之前，主窗口位置和大小变化不允许写入 RuntimeLayoutState，也不允许触发 window-layout.json 保存。
```

### 7.2 修改 ApplyDefaultWindowLayoutOnce

将首次布局恢复过程包在 `try/finally` 中，确保无论使用配置布局还是默认布局，最后都会解除启动保护。

推荐实现：

```csharp
private void ApplyDefaultWindowLayoutOnce()
{
    if (_hasAppliedDefaultLayout || WindowState != WindowState.Normal)
    {
        return;
    }

    _hasAppliedDefaultLayout = true;
    try
    {
        if (_runtimeLayoutState.HasMainWindowBounds)
        {
            RestoreMainWindowBoundsFromSession();
            return;
        }

        ApplyDefaultMainWindowLayout();
    }
    finally
    {
        _isInitialLayoutRestoring = false;
    }
}
```

说明：

```text
1. 读取到配置时，调用 RestoreMainWindowBoundsFromSession。
2. 没有配置时，调用 ApplyDefaultMainWindowLayout。
3. 无论走哪个分支，首次布局应用完成后都解除 _isInitialLayoutRestoring。
```

### 7.3 修改 SaveMainWindowBoundsToSession

在保存主窗口 Bounds 的保护条件中增加 `_isInitialLayoutRestoring`：

```csharp
private void SaveMainWindowBoundsToSession()
{
    if (_isInitialLayoutRestoring || _isApplyingRuntimeLayout || WindowState != WindowState.Normal)
    {
        return;
    }

    var width = ActualWidth > 0 ? ActualWidth : Width;
    var height = ActualHeight > 0 ? ActualHeight : Height;
    if (width <= 0 || height <= 0)
    {
        return;
    }

    _runtimeLayoutState.HasMainWindowBounds = true;
    _runtimeLayoutState.MainLeft = Left;
    _runtimeLayoutState.MainTop = Top;
    _runtimeLayoutState.MainWidth = width;
    _runtimeLayoutState.MainHeight = height;
    ScheduleWindowLayoutSave();
}
```

这样可以防止启动期间的初始事件污染持久化布局。

### 7.4 防止异常情况下永远不保存

如果 `ApplyDefaultWindowLayoutOnce()` 因为 `WindowState != WindowState.Normal` 提前返回，则 `_isInitialLayoutRestoring` 仍为 `true`，后续可能导致一直不保存。

为了更稳，建议将早退条件也处理成可恢复状态：

推荐最终版本：

```csharp
private void ApplyDefaultWindowLayoutOnce()
{
    if (_hasAppliedDefaultLayout)
    {
        return;
    }

    if (WindowState != WindowState.Normal)
    {
        _isInitialLayoutRestoring = false;
        return;
    }

    _hasAppliedDefaultLayout = true;
    try
    {
        if (_runtimeLayoutState.HasMainWindowBounds)
        {
            RestoreMainWindowBoundsFromSession();
            return;
        }

        ApplyDefaultMainWindowLayout();
    }
    finally
    {
        _isInitialLayoutRestoring = false;
    }
}
```

说明：

```text
正常启动时窗口通常是 Normal。
这段只是防御性处理，避免异常状态下保存功能被永久关闭。
```

## 8. 地图窗口逻辑是否需要修改

本次建议不改地图窗口保存逻辑。

原因：

```text
1. 当前问题主要表现为主窗口启动位置不对。
2. 地图窗口不是程序启动时默认创建并显示。
3. 地图窗口显示时已经由 PositionFactoryMapWindow 和 RestoreViewState 控制。
4. 本次应保持最小修改，避免影响地图拖拽、缩放、编辑、连线等功能。
```

如果后续发现地图窗口也存在启动恢复期间误保存，再单独处理地图窗口的恢复保护。

## 11. 风险点

### 11.1 风险：启动保护没有解除

如果 `_isInitialLayoutRestoring` 一直保持 `true`，用户后续移动窗口也不会保存。

规避：

```text
ApplyDefaultWindowLayoutOnce 必须在 finally 中解除。
WindowState 非 Normal 的早退分支也必须解除。
```

### 11.2 风险：默认布局第一次创建后不写入

如果没有 `window-layout.json`，`WindowLayoutService.LoadOrCreateDefault` 会创建默认配置。  
本次修改不影响这个逻辑。

### 11.3 风险：用户移动窗口太快后立刻退出

当前已有 `SaveWindowLayoutImmediately()`，托盘真正退出时会强制保存最终快照。  
本次修改不应破坏这个逻辑。

3. 用户移动/缩放主窗口后，仍然约 500ms 后写入 window-layout.json。
