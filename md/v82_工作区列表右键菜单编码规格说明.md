# v82 工作区列表右键菜单编码规格说明

## 1. 文档目的

本文件用于指导编程 Agent 在“选择工作区”窗口中，为工作区列表项增加右键菜单。

核心目标：

```text
用户右键某个工作区列表项时，弹出纯白紧凑右键菜单。
菜单项依次为：打开、重命名、打开工作区文件夹、删除。
每个菜单项功能与窗口底部现有按钮完全一致。
```

## 2. 背景说明

当前“选择工作区”窗口已经有底部按钮：

```text
新建工作区
重命名
删除
打开工作区文件夹
取消
打开
```

其中本次右键菜单需要复用的功能是：

```text
打开
重命名
打开工作区文件夹
删除
```

当前用户如果想操作某个工作区，需要先左键选中，再点击底部按钮。  
新增右键菜单后，用户可以直接右键某一项并操作，交互更符合 Windows 列表使用习惯。

## 4. 需求目标

完成后应满足：

```text
1. 用户右键任意工作区列表项时，弹出右键菜单。
2. 右键菜单项目顺序固定为：打开、重命名、打开工作区文件夹、删除。
3. 用户右键某个工作区时，该工作区应先成为 SelectedWorkspace。
4. 点击“打开”等同于底部“打开”按钮。
5. 点击“重命名”等同于底部“重命名”按钮。
6. 点击“打开工作区文件夹”等同于底部“打开工作区文件夹”按钮。
7. 点击“删除”等同于底部“删除”按钮，仍然弹确认框。
8. 菜单样式模仿主界面快捷项右键菜单/地图右键菜单的纯白紧凑风格。
9. 不影响双击打开工作区。
10. 不影响底部按钮原有功能。
```

## 6. 交互逻辑

### 6.1 右键先选中

用户右键某个工作区列表项时，必须先把该项设置为当前选中项：

```text
SelectedWorkspace = 被右键的工作区
```

原因：

```text
底部按钮和现有命令都是基于 SelectedWorkspace 工作。
如果右键不先选中，菜单可能误操作旧选中的工作区。
```

### 6.2 菜单项功能映射

菜单项与现有命令对应关系：

```text
打开 -> OpenSelectedWorkspaceCommand
重命名 -> StartRenameWorkspaceCommand
打开工作区文件夹 -> OpenWorkspaceFolderCommand
删除 -> StartDeleteWorkspaceCommand
```

### 6.3 禁用规则

应沿用现有命令的 CanExecute：

```text
打开：工作区可用时可执行。
重命名：有选中工作区时可执行。
打开工作区文件夹：有选中工作区时可执行，路径不存在时由原逻辑提示。
删除：有选中工作区时可执行，具体能否删除由 DeleteSelectedWorkspace 逻辑判断。
```

说明：

```text
删除当前正在使用的工作区、删除最后一个工作区等规则保持原样。
点击删除后仍由现有确认弹窗与业务逻辑处理。
```

## 7. 样式要求

右键菜单样式应模仿主界面快捷项右键菜单和地图右键菜单的纯白紧凑风格。

参考代码位置：

```text
VSLoader\Views\FactoryMapWindow.xaml.cs
```

其中已有类似方法：

```text
CreateCompactContextMenuTemplate
CreateCompactMenuItemTemplate
```

视觉要求：

```text
1. 菜单背景纯白。
2. 边框浅灰。
3. 不出现系统默认菜单左侧灰色图标槽。
4. 菜单项文字左对齐。
5. 菜单项 hover 为浅蓝色。
6. 菜单项高度紧凑但不拥挤。
7. 禁用项文字变浅。
```

推荐样式参数：

```text
ContextMenu.Background = White
ContextMenu.BorderBrush = #D1D5DB
ContextMenu.BorderThickness = 1
MenuItem.MinWidth = 140
MenuItem.Padding = 14,8,14,8
MenuItem.Foreground = #111827
Hover 背景 = #E5F1FB
Disabled 前景 = #9CA3AF
```

## 8. 实现方案

### 8.1 推荐实现方式

优先在 `WorkspaceSelectorWindow.xaml.cs` 中实现右键菜单创建逻辑。

原因：

```text
1. 当前 WorkspaceSelectorWindow 已经在 code-behind 中处理双击、弹窗、删除确认。
2. 右键菜单样式需要复用类似 FactoryMapWindow 的 ControlTemplate 代码。
3. 右键先选中目标项，用 code-behind 处理更直接。
```

### 8.2 XAML 事件绑定

目标文件：

```text
VSLoader\Views\WorkspaceSelectorWindow.xaml
```

在 `ListBoxItem` 的 `ItemContainerStyle` 中增加右键事件：

```xml
<EventSetter Event="PreviewMouseRightButtonDown"
             Handler="WorkspaceItem_PreviewMouseRightButtonDown" />
<EventSetter Event="ContextMenuOpening"
             Handler="WorkspaceItem_ContextMenuOpening" />
```

也可以只使用一个右键事件并手动打开菜单。  
推荐方式：

```text
PreviewMouseRightButtonDown：负责选中右键项。
ContextMenuOpening：负责创建并弹出菜单。
```

如果采用手动 `ContextMenu.IsOpen = true`，需要设置：

```text
e.Handled = true
```

避免系统默认菜单逻辑重复触发。

### 8.3 选中右键项

在 `WorkspaceSelectorWindow.xaml.cs` 中新增：

```csharp
private void WorkspaceItem_PreviewMouseRightButtonDown(object sender, MouseButtonEventArgs e)
{
    if (sender is ListBoxItem item && item.DataContext is WorkspaceListItemViewModel workspace)
    {
        item.IsSelected = true;
        if (DataContext is WorkspaceSelectorViewModel viewModel)
        {
            viewModel.SelectedWorkspace = workspace;
        }
    }
}
```

注意：

```text
必须确保右键菜单命令作用于当前右键项。
```

### 8.4 创建菜单

在 `WorkspaceSelectorWindow.xaml.cs` 中新增：

```csharp
private ContextMenu CreateWorkspaceContextMenu()
```

菜单项顺序：

```text
打开
重命名
打开工作区文件夹
删除
```

每项绑定或点击调用现有命令：

```csharp
menu.Items.Add(CreateWorkspaceMenuItem("打开", viewModel.OpenSelectedWorkspaceCommand));
menu.Items.Add(CreateWorkspaceMenuItem("重命名", viewModel.StartRenameWorkspaceCommand));
menu.Items.Add(CreateWorkspaceMenuItem("打开工作区文件夹", viewModel.OpenWorkspaceFolderCommand));
menu.Items.Add(CreateWorkspaceMenuItem("删除", viewModel.StartDeleteWorkspaceCommand));
```

或者使用 `Click` 事件手动执行命令：

```csharp
if (command.CanExecute(null))
{
    command.Execute(null);
}
```

推荐使用命令绑定或统一 helper，避免复制业务逻辑。

### 8.5 菜单禁用状态

菜单项创建时应根据命令 CanExecute 设置：

```csharp
IsEnabled = command.CanExecute(null)
```

如果希望菜单打开时状态实时同步，可在创建菜单时每次重新读取 CanExecute。

因为菜单是右键时临时创建，推荐：

```text
每次右键打开菜单时重新创建菜单。
```

这样状态自然最新。

## 11. 手工验收

### 场景一：右键普通工作区

操作：

```text
1. 打开选择工作区窗口。
2. 右键某个普通工作区。
```

预期：

```text
1. 该工作区被选中。
2. 弹出右键菜单。
3. 菜单项顺序为：打开、重命名、打开工作区文件夹、删除。
4. 菜单为纯白紧凑风格，没有左侧灰槽。
```

### 场景二：右键未选中的工作区并删除

操作：

```text
1. 当前选中工作区 A。
2. 右键工作区 B。
3. 点击删除。
```

预期：

```text
1. 删除确认弹窗显示工作区 B 的名称。
2. 确认后删除工作区 B。
3. 不误删工作区 A。
```

### 场景三：右键打开工作区文件夹

操作：

```text
1. 右键某个工作区。
2. 点击打开工作区文件夹。
```

预期：

```text
打开该工作区对应真实目录。
```

### 场景四：不可用工作区

操作：

```text
1. 选择一个路径不存在的工作区。
2. 右键打开菜单。
```

预期：

```text
打开项不可用或执行后提示不可用，行为与底部按钮一致。
打开工作区文件夹仍按原有逻辑提示路径不存在。
```

## 12. 风险点

### 12.1 右键操作旧选中项

风险：

```text
用户右键 B，但命令作用到旧选中的 A。
```

规避：

```text
PreviewMouseRightButtonDown 必须先选中右键项。
```

### 12.2 删除绕过确认

风险：

```text
右键删除直接删除，不弹确认。
```

规避：

```text
右键删除必须调用 StartDeleteWorkspaceCommand，让现有确认弹窗处理。
```

### 12.3 菜单样式退回系统默认

风险：

```text
出现系统默认灰色左侧图标槽或旧式灰底。
```

规避：

```text
使用自定义 ContextMenu / MenuItem ControlTemplate。
```

### 12.4 禁用状态不一致

风险：

```text
底部打开按钮不可用，但右键打开仍可点。
```

规避：

```text
菜单项 IsEnabled 根据对应命令 CanExecute 设置。
```
