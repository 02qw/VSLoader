# v94 更新器更新内容延迟展示编码规格说明

## 1. 背景

当前 `VSLoader.Updater` 启动后，主界面中的“本次更新内容”区域会先显示默认文案：

```text
本次更新未填写更新说明。
```

随后当更新器读取到 `manifest.json` 中的 `releaseNotes` 字段后，再刷新为真实的更新内容。

这会造成一个短暂但明显的 UI 误导：用户会先看到“没有更新说明”，再看到真实内容，容易误以为更新内容缺失或程序读取异常。

## 2. 目标

优化更新器中 `releaseNotes` 的展示时机：

- 在 `manifest.json` 尚未读取完成前，不展示“本次更新内容”的默认空文案。
- 读取到 `releaseNotes` 后，再展示“本次更新内容”区域。
- 如果 `manifest.json` 已读取完成，但 `releaseNotes` 确实为空，再展示“本次更新未填写更新说明。”。
- 更新完成确认弹窗中的更新内容也必须使用最终读取结果，不能使用启动时的空默认值。
- 不改动软件更新的核心流程，包括版本判断、SHA 校验、解压、替换、回滚、启动主程序等逻辑。

## 3. 影响范围

主要修改：

- `VSLoader.Updater/MainWindow.xaml`
- `VSLoader.Updater/MainWindow.xaml.cs`
- `VSLoader.Updater/UpdateCompletedDialog.xaml`
- `VSLoader.Updater/UpdateCompletedDialog.xaml.cs`

如需补充测试，可增加或调整：

- `VSLoader.Tests` 中与更新器 releaseNotes 展示状态相关的单元测试。

## 4. 当前问题定位

`MainWindow.xaml.cs` 当前存在类似逻辑：

```csharp
private string releaseNotesText = NormalizeReleaseNotes(null);
```

而 `NormalizeReleaseNotes(null)` 会返回：

```text
本次更新未填写更新说明。
```

因此更新器窗口一创建，界面就已经绑定到了“未填写更新说明”的文字。后续 `UpdaterUpdateService` 读取 `manifest.json` 后，通过进度回调或结果对象再覆盖该值。

问题的根因不是 manifest 读取失败，而是 UI 初始状态过早给出了“无更新说明”的结论。

## 5. 设计方案

### 5.1 MainWindow 增加展示状态

在 `MainWindow.xaml.cs` 中增加一个布尔属性：

```csharp
public bool ShowReleaseNotes { get; private set; }
```

初始值为 `false`。

含义：

- `false`：manifest 尚未完成有效读取，主窗口不展示“本次更新内容”区域。
- `true`：manifest 已读取完成，可以展示 releaseNotes 区域。

### 5.2 releaseNotes 文案状态

`releaseNotesText` 初始值改为空字符串，不再在字段初始化阶段调用 `NormalizeReleaseNotes(null)`。

建议逻辑：

```csharp
private string releaseNotesText = string.Empty;
```

`ReleaseNotesText` 的 setter 仍可调用 `NormalizeReleaseNotes(value)`，但只有在确认 manifest 已读取后才写入。

### 5.3 读取到 manifest 后再展示

当 `UpdaterProgress.ReleaseNotes` 有值时：

```csharp
ReleaseNotesText = updateProgress.ReleaseNotes;
ShowReleaseNotes = true;
```

当更新服务返回 `UpdaterUpdateResult` 后，无论成功、已是最新版本，还是可携带 manifest 信息的失败结果，只要结果中包含 releaseNotes 或已确认 manifest 读取完成，都应统一调用一个方法设置展示状态。

建议封装方法：

```csharp
private void ApplyReleaseNotes(string? releaseNotes)
{
    ReleaseNotesText = releaseNotes;
    ShowReleaseNotes = true;
}
```

注意：如果 manifest 读取失败，且没有 releaseNotes 来源，则不要调用该方法，避免错误场景下显示“本次更新未填写更新说明。”。

### 5.4 XAML 控制显示

`MainWindow.xaml` 中“本次更新内容”的 `GroupBox` 绑定 `ShowReleaseNotes`：

```xml
Visibility="{Binding ShowReleaseNotes, Converter={StaticResource BooleanToVisibilityConverter}}"
```

这样 updater 刚启动时，界面只展示进度条、状态文本和滚动详情；等 manifest 读取完成后，才出现更新内容区域。

### 5.5 完成确认弹窗

`UpdateCompletedDialog` 也应避免无条件展示空更新内容。

建议给弹窗增加：

```csharp
public bool ShowReleaseNotes { get; }
```

构造时根据传入内容判断：

- 如果传入的 releaseNotes 为空字符串或空白，仍可显示规范化后的“本次更新未填写更新说明。”，但前提是调用方已经确认 manifest 读取完成。
- 如果调用方没有 releaseNotes 来源，则不展示更新内容区域。

为了逻辑清晰，建议将构造函数调整为：

```csharp
public UpdateCompletedDialog(string titleText, string messageText, string releaseNotesText, bool showReleaseNotes)
```

主窗口调用时传入当前 `ShowReleaseNotes`。

### 5.6 确认弹窗展示规则

- 更新成功：显示 releaseNotes 区域。
- 当前已是最新版本：显示 releaseNotes 区域，因为 manifest 已读取完成。
- manifest 读取失败：一般不会进入完成确认弹窗，而是进入错误展示，不显示 releaseNotes 区域。
- 其他读取 manifest 后发生的失败：如未来需要弹窗，也应使用已经读取到的 releaseNotes。

## 6. 不做的事情

本次不做以下改动：

- 不修改 manifest 文件格式。
- 不修改 `releaseNotes` 字段名。
- 不修改版本判断逻辑。
- 不修改更新包下载、解压、SHA 校验、文件替换、回滚逻辑。
- 不改变“更新完成后用户点击确认再启动 VSLoader”的既有交互。

## 7. 测试要求

至少完成以下验证：

1. `manifest.json` 中存在 `releaseNotes`
   - updater 启动初期不显示“本次更新未填写更新说明。”
   - 读取 manifest 后显示真实 releaseNotes。
   - 更新完成确认弹窗显示真实 releaseNotes。

2. `manifest.json` 中 `releaseNotes` 为空
   - updater 启动初期不显示默认空文案。
   - manifest 读取完成后显示“本次更新未填写更新说明。”。
   - 更新完成确认弹窗同样显示该文案。

3. `manifest.json` 读取失败
   - updater 显示明确错误原因。
   - 不额外展示“本次更新未填写更新说明。”，避免误导。

4. 当前已是最新版本
   - updater 不执行替换流程。
   - 确认弹窗显示“当前已是最新版本”。
   - 如果 manifest 有 releaseNotes，则显示 releaseNotes。
